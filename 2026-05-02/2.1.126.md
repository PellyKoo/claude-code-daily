# Claude Code 2.1.126 社区实用技巧 - 2026-05-02

## 1. 上下文衰减警告：300-400k token 后手动压缩
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 50.7k stars
- **摘要**: 当会话超过 300-400k token 时，Claude 的推理质量会明显下降（"上下文衰减"）。不要依赖自动压缩，而是主动使用 `/compact` 并附带提示词来引导压缩方向，保留关键上下文。
- **代码示例**:
```
/compact 保留当前的数据库迁移方案和 API 设计决策
```

## 2. 用子代理隔离探索性工作，防止主上下文污染
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 50.7k stars
- **摘要**: 将文件搜索、试错等探索性工作交给子代理（subagent）执行，只让结论返回主会话。这样主上下文不会被失败尝试和大量文件内容污染，保持高质量推理。

## 3. 垂直切片优于水平分层：用"穿透弹"式 PR 拆分任务
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 50.7k stars
- **摘要**: 将 PRD 拆分为贯穿所有层（数据库 + 服务 + UI）的垂直切片，而不是按层分阶段实现。这样能更早获得端到端反馈，减少返工。每个 PR 就是一个可验证的功能切片。

## 4. PreToolUse Hook 拦截危险操作
- **来源**: [ChrisWiles](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 5.9k stars
- **摘要**: 使用 hooks 在 Claude 执行工具前自动拦截危险操作（如在主分支直接编辑文件）。Hook 是确定性的——与 CLAUDE.md 中的建议性指令不同，hook 保证每次都会执行。
- **代码示例**:
```json
{
  "hooks": {
    "PreToolUse": [{
      "matcher": "Edit|Write",
      "hooks": [{
        "type": "command",
        "command": "bash -c 'branch=$(git branch --show-current); if [ \"$branch\" = \"main\" ]; then echo \"blocked: do not edit on main\"; exit 1; fi'"
      }]
    }]
  }
}
```

## 5. Skills 文件夹化：用子目录实现渐进式披露
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 50.7k stars
- **摘要**: 在 `.claude/skills/` 下为每个技能创建文件夹而非单个文件，包含 `references/`、`scripts/`、`examples/` 子目录。这样 Claude 可以按需加载详细信息，避免一次性加载过多上下文。
- **代码示例**:
```
.claude/skills/
├── testing-patterns/
│   ├── SKILL.md
│   ├── references/
│   ├── scripts/
│   └── examples/
└── api-design/
    ├── SKILL.md
    └── examples/
```

## 6. 自动权限模式替代危险标志
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 50.7k stars
- **摘要**: 不要使用 `--dangerously-skip-permissions`，而是通过 `/permissions` 设置通配符规则（如 `Bash(npm run *)`）配合模型自动审批。既保持安全边界，又减少手动确认中断。
- **代码示例**:
```
/permissions
> 添加规则: Bash(npm run *)
> 添加规则: Bash(git diff *)
> 添加规则: Read(*)
```

## 7. CLAUDE.md 保持精简：200 行以内，迭代添加规则
- **来源**: [ChrisWiles](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 5.9k stars
- **摘要**: CLAUDE.md 不是百科全书。保持在 200 行以内，从基础开始（技术栈、关键命令、代码风格），在实际使用中发现问题后再逐步添加规则。使用层级化的 CLAUDE.md（根目录 + 子目录各一份）实现关注点分离。
- **代码示例**:
```markdown
# Project Name
## Quick Facts
- **Stack**: React, TypeScript, Node.js
- **Test**: `npm run test`
- **Lint**: `npm run lint`

## Code Style
- 使用函数组件 + hooks
- 文件名使用 kebab-case
```

## 8. 每轮对话后有意识地选择下一步操作
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 50.7k stars
- **摘要**: 把每次 Claude 回复视为一个分支点。根据需要有意识地选择：继续（保持上下文）、`/rewind`（回退上一步）、`/clear`（全新开始）、`/compact`（压缩保留）、或启动子代理（隔离执行）。不要无脑连续对话。

## 9. 快速原型优于详细规格文档
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 50.7k stars
- **摘要**: 与其花时间写详细的 PRD 规格文档，不如直接让 Claude 构建 20-30 个原型版本。因为 AI 编码成本极低，多次尝试比精心规划更高效——"多打几枪"策略。

## 10. MCP 集成外部工具实现 ticket-to-PR 自动化流程
- **来源**: [ChrisWiles](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 5.9k stars
- **摘要**: 通过 `.mcp.json` 配置连接 JIRA、GitHub、Slack 等外部工具，实现从工单到 PR 的无缝自动化流程。配合自定义 slash 命令（如 `/ticket`）一键启动完整工作流。
- **代码示例**:
```json
{
  "mcpServers": {
    "jira": {
      "command": "npx",
      "args": ["-y", "@anthropic/mcp-server-jira"],
      "env": {
        "JIRA_URL": "https://your-team.atlassian.net",
        "JIRA_TOKEN": "${JIRA_TOKEN}"
      }
    }
  }
}
```
