# Claude Code 2.1.150 社区实用技巧 - 2026-05-26

## 1. 上下文 40% 警戒线：超过就该压缩
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 55.2k stars
- **摘要**: 社区实测发现 Claude Code 的"变笨区间"大约在上下文占用 40% 时开始出现——响应质量下降、遗忘之前的指令、重复犯错。最佳实践是积极将上下文控制在 30% 以下，一旦接近 40% 就手动 `/compact`，不要等自动压缩触发（自动压缩不知道该保留什么）。
- **代码示例**:
```bash
# 查看当前上下文占用（状态栏会显示百分比）
# 当接近 40% 时主动压缩

# 带提示的定向压缩 - 告诉 Claude 保留什么
/compact 保留当前任务目标、已完成的步骤和关键设计决策，丢弃调试日志和中间尝试

# 切换任务时先压缩再继续
/compact 只保留项目架构概览和 API 接口定义，准备切换到前端开发
```

## 2. PreToolUse Hook 保护主分支不被误改
- **来源**: [ChrisWiles](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 5.9k stars
- **摘要**: 通过 `settings.json` 中的 PreToolUse Hook，在 Claude 每次调用 Edit 或 Write 工具前自动检查当前分支，如果在 main 分支上就拒绝执行。这是一个零成本的安全网，防止 Claude 在主分支上直接修改代码，强制走分支开发流程。
- **代码示例**:
```json
// .claude/settings.json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [
          {
            "type": "command",
            "command": "[ \"$(git branch --show-current)\" != \"main\" ]"
          }
        ]
      }
    ]
  }
}
```

## 3. CLAUDE.md 用条件标签避免指令被忽略
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 55.2k stars
- **摘要**: CLAUDE.md 超过 80 行后 Claude 开始选择性忽略内容。解决方案是用 `<important if="...">` 条件标签包裹特定领域的规则，只在相关场景下激活。这样既能保持文件精简（建议控制在 60 行以内），又能在需要时加载详细指令。
- **代码示例**:
```markdown
<!-- CLAUDE.md -->
# 项目规范

## 通用规则（始终生效）
- 使用 TypeScript strict mode
- 所有 PR 必须有测试

<important if="涉及数据库操作或迁移">
## 数据库规范
- 所有迁移必须可回滚
- 禁止在迁移中使用 DROP TABLE，改用软删除
- 大表变更必须分批执行，单批不超过 10000 行
</important>

<important if="涉及 API 接口开发">
## API 规范
- RESTful 命名，复数名词
- 所有端点必须有 rate limiting
- 响应格式统一使用 { data, error, meta } 结构
</important>
```

## 4. Memory Bank 双层记忆架构跨会话保持上下文
- **来源**: [centminmod](https://github.com/centminmod/my-claude-code-setup) on GitHub | ⭐ 2.4k stars
- **摘要**: 将项目知识拆分为多个专用记忆文件（决策记录、踩坑记录、代码模式），由 CLAUDE.md 按需引用。Claude 不需要每次都加载全部上下文，只在遇到相关问题时才读取对应的记忆文件，大幅减少 token 消耗，同时保留完整的项目知识库。
- **代码示例**:
```
project/
├── CLAUDE.md                    # 主入口，60 行以内
├── .claude/
│   ├── CLAUDE-decisions.md      # 架构决策记录（为什么选 X 不选 Y）
│   ├── CLAUDE-patterns.md       # 代码模式（项目中反复出现的实现方式）
│   └── CLAUDE-troubleshooting.md # 踩坑记录（遇到过的问题及解决方案）
```

```markdown
<!-- CLAUDE.md 中按需引用 -->
遇到架构决策问题时，先阅读 .claude/CLAUDE-decisions.md
遇到已知问题时，先查阅 .claude/CLAUDE-troubleshooting.md
编写新代码时，参考 .claude/CLAUDE-patterns.md 中的项目约定
```

## 5. Git Worktree 实现多个 Claude 会话并行开发
- **来源**: [centminmod](https://github.com/centminmod/my-claude-code-setup) on GitHub | ⭐ 2.4k stars
- **摘要**: 用 Git Worktree 为每个 Claude Code 会话创建独立的工作目录，共享同一个 Git 历史但文件状态完全隔离。这样可以同时开多个终端窗口，让不同的 Claude 实例并行处理前端、后端、测试等任务，互不干扰。
- **代码示例**:
```bash
# 创建并行工作区
git worktree add ../project-frontend feature/new-ui
git worktree add ../project-backend feature/api-v2
git worktree add ../project-tests feature/e2e-tests

# 在不同终端中分别启动 Claude Code
# 终端 1：前端开发
cd ../project-frontend && claude

# 终端 2：后端开发
cd ../project-backend && claude

# 终端 3：测试编写
cd ../project-tests && claude

# 完成后清理工作区
git worktree remove ../project-frontend
```

## 6. Commands → Agents → Skills 渐进式自动化路径
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 55.2k stars
- **摘要**: 社区总结的自动化升级路径：先把重复操作写成 Slash Commands（简单的提示词模板），当命令需要多步协调时升级为 Subagent（独立上下文、可并行），最终将成熟的流程封装为 Skill（带触发条件、自动激活）。不要一开始就写 Skill，从最简单的 Command 开始迭代。
- **代码示例**:
```bash
# 阶段 1: Slash Command（最简单）
# .claude/commands/review.md
# 内容：Review the current diff for bugs, focusing on error handling and edge cases.

# 阶段 2: Subagent（需要独立上下文时）
# .claude/agents/security-reviewer.md
# ---
# description: "安全审查代理"
# model: opus
# ---
# 专注于 OWASP Top 10 漏洞检查...

# 阶段 3: Skill（自动触发）
# .claude/skills/pre-deploy-check.md
# ---
# description: "当用户提到部署、发布、上线时自动触发"
# ---
# !npm test 2>&1 | tail -5
# !git status --short
# 根据以上结果评估部署风险...
```

## 7. 子代理独立验证：让另一个 Claude 审查代码
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 55.2k stars
- **摘要**: 将验证工作分离到独立的子代理上下文中——一个 Claude 写代码，另一个 Claude 在全新的上下文中审查。因为审查者没有见过生成过程中的"思考惯性"，能以更客观的视角发现问题。这比同一个上下文中的自我检查效果显著更好。
- **代码示例**:
```markdown
<!-- .claude/agents/code-reviewer.md -->
---
description: "独立代码审查代理"
model: opus
---

你是一个严格的代码审查者。审查标准：
1. 逻辑正确性 - 是否有边界条件遗漏
2. 安全性 - 是否有注入、XSS、信息泄露
3. 性能 - 是否有 N+1 查询、不必要的重复计算
4. 可维护性 - 命名是否清晰、抽象是否合理

只报告真正的问题，不要提风格建议。
```

## 8. MCP 集成外部工具链实现端到端工作流
- **来源**: [ChrisWiles](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 5.9k stars
- **摘要**: 通过 `.mcp.json` 配置将 JIRA、Sentry、Datadog 等外部工具接入 Claude Code，实现"看 JIRA 需求→写代码→查 Sentry 报错→修 Bug"的全链路不离开终端。配合环境变量管理敏感凭据，避免将 token 硬编码到配置文件中。
- **代码示例**:
```json
// .mcp.json
{
  "mcpServers": {
    "jira": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@anthropic/mcp-jira"],
      "env": {
        "JIRA_HOST": "${JIRA_HOST}",
        "JIRA_EMAIL": "${JIRA_EMAIL}",
        "JIRA_API_TOKEN": "${JIRA_API_TOKEN}"
      }
    },
    "sentry": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@anthropic/mcp-sentry"],
      "env": {
        "SENTRY_AUTH_TOKEN": "${SENTRY_AUTH_TOKEN}"
      }
    }
  }
}
```
