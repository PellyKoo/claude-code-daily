## 1. CLAUDE.md 防御性编写技巧：让 Claude 真正听话
- **来源**: [Santiago](https://x.com/svpino/status/2018682144361734368) on X | 🔥 高互动
- **摘要**: 在 CLAUDE.md 中加入明确的行为约束指令，可以显著提升 Claude Code 的可控性。关键技巧包括：要求 Claude 在写代码前先描述方案并等待批准；对模糊需求主动提出澄清问题；限制单次修改不超过 3 个文件以保持变更可审查；如果任务需要改 5 个以上文件，先停下来制定计划。
- **代码示例**:
```markdown
# CLAUDE.md 行为约束示例
- Before writing any code, describe your approach and wait for approval.
- Always ask clarifying questions before writing code if requirements are ambiguous.
- If a task requires changes to more than 3 files, stop and outline a plan first.
- Never modify test files without explicit permission.
```

## 2. 让 Claude 自我验证：质量提升 2-3 倍的关键
- **来源**: [Shruti](https://x.com/heyshrutimishra/status/2018368588432978151) on X | 🔥 高互动
- **摘要**: Boris（Claude Code 创始人）分享的 10 条高级技巧中，最重要的一条是：给 Claude 提供自我验证的手段（测试、浏览器自动化、hooks）。这可以让输出质量提升 2-3 倍。本质上是将 "写完即交" 变成 "写完、测试、修复、再交"的闭环工作流。
- **代码示例**:
```bash
# 在 .claude/settings.json 中配置 hooks 实现自动验证
# 每次编辑文件后自动运行相关测试
{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Edit|Write",
      "command": "npm test -- --related"
    }]
  }
}
```

## 4. 创始人内部工作流 CLAUDE.md 模板泄露

## 5. shanraisshan 最佳实践：57.6k Star 的社区标杆
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 57.6k stars, 5.8k forks
- **摘要**: 目前 GitHub 上最受欢迎的 Claude Code 最佳实践仓库。核心建议：CLAUDE.md 保持在 200 行以内（60 行更佳）；使用 `.claude/rules/*.md` 按领域拆分规则并支持懒加载；使用 `<important if="...">` 标签防止长文件中指令被忽略；上下文使用率超过 40% 时性能会显著下降，应及时归档或重启会话。
- **代码示例**:
```markdown
# .claude/rules/testing.md （按领域拆分的规则文件）
<important if="editing test files">
- Use vitest, not jest
- Follow AAA pattern (Arrange, Act, Assert)
- Mock external services, never hit real APIs
</important>
```

## 6. Matt Pocock 踩坑：workflow 关键词触发意外行为
- **来源**: [Matt Pocock](https://x.com/mattpocockuk/status/2061120343922614519) on X | 🔥 高互动
- **摘要**: 知名 TypeScript 教育者发现的实际使用陷阱：在提示中使用 "workflow" 一词（比如要创建 GitHub workflow 文件时）会意外触发 Claude Code 的 workflow 模式，导致它自动启动大量子代理来执行任务。解决方案是避免在提示中直接使用该关键词，改用更具体的描述如 "GitHub Actions CI config"。
- **代码示例**:
```
# ❌ 会触发 workflow 模式
> create a GitHub workflow for CI

# ✅ 避免误触发
> create a GitHub Actions CI configuration file at .github/actions/ci.yml
```
