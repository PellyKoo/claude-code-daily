## 3. CLAUDE.md 最佳实践：建议用 CLAUDE.md，强制用 Hooks

- **摘要**: CLAUDE.md 中的指导大约 80% 的时间会被遵循，适合放建议性规则。必须 100% 执行的规则应该用 hooks 实现，因为 hooks 是确定性执行的。推荐在 CLAUDE.md 中加入"先描述方案再写代码"和"需求模糊时先问问题"等指令。

```markdown

1. 写代码前先描述方案，等待确认
2. 需求模糊时先问清楚再动手
3. 如果任务需要改多个文件，先列出修改计划
```

## 4. Dynamic Workflows：让 Claude 自己编写多代理调度器
- **来源**: [Thariq (@trq212)](https://x.com/trq212/article/2061907337154367865) on X | 🔥 深度技术文章
- **摘要**: 动态工作流是 Claude Code 的重大能力升级——让 Claude 根据任务自动编写定制化的多代理调度脚本。支持 generate-and-filter（生成筛选）和 tournament（锦标赛）等模式，适合代码审查、批量重构等需要并行处理的场景。
- **代码示例**:
```javascript
export const meta = {
  name: 'tournament-review',
  description: 'Tournament-style code review',
  phases: [{ title: 'Generate' }, { title: 'Compare' }, { title: 'Select' }],
}
const candidates = await parallel(
  APPROACHES.map(a => () => agent(a.prompt, {phase: 'Generate'}))
)
const winner = await agent(
  `Compare these approaches and pick the best: ${JSON.stringify(candidates)}`,
  {phase: 'Select'}
)
```

## 6. 给 Claude 一种检查自身输出的方法：验证驱动开发
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 热门实践仓库
- **摘要**: 验证是投资回报率最高的实践。在 CLAUDE.md 中指定测试和 lint 命令，让 Claude 每次修改后自动运行验证。对 UI 类工作，集成 Playwright MCP 服务器让 Claude 能直接看到页面效果。作者报告这带来了 2-3 倍的输出质量提升。

```markdown
- `npm run typecheck` - 类型检查通过
- `npm run lint -- --fix` - 代码规范修复
- `npm test -- --changed` - 运行受影响的测试
```

## 8. 并行工作流：用 Git Worktree 同时运行多个 Claude 实例
- **来源**: [MuhammadUsmanGM/claude-code-best-practices](https://github.com/MuhammadUsmanGM/claude-code-best-practices) on GitHub | ⭐ 综合指南仓库
- **摘要**: 使用 `git worktree` 为每个 Claude 实例创建隔离的工作目录，避免多个实例编辑同一文件产生冲突。建议从两个并行会话开始，熟练后再增加。每个 worktree 可以处理独立的功能分支，最后合并回主分支。
- **代码示例**:
```bash
# 创建隔离的工作目录
git worktree add ../feature-auth feature/auth
git worktree add ../feature-api feature/api

# 在不同终端分别启动 Claude Code
cd ../feature-auth && claude
cd ../feature-api && claude

# 完成后清理
git worktree remove ../feature-auth
```
