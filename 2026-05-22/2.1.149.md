# Claude Code 2.1.149 社区实用技巧 - 2026-05-22

## 1. 规划-审查双 Agent 模式——代码质量翻倍
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 54.6k stars
- **摘要**: 社区验证的最高效工作流：永远不要让 Claude 直接写代码。先用一个 Claude 会话进入 Plan Mode 起草方案，再用第二个会话"以 Staff Engineer 身份"审查方案。两轮确认无误后才开始实现。这种双 Agent 审查模式显著减少返工，尤其适合复杂功能开发。
- **代码示例**:
```bash
# 会话 1：规划 Agent
"进入 Plan Mode。为用户认证模块设计方案，包括技术选型、
数据模型、API 设计、安全考虑。不要写任何代码。"

# 会话 2：审查 Agent
"以 Staff Engineer 身份审查以下设计方案，指出潜在问题：
[粘贴方案内容]"

# 两轮审查通过后，才开始实现
"方案已审查通过，现在按方案逐步实现。"
```

## 2. 上下文精简术——先瘦后补，按需加载
- **来源**: [Anubhav](https://medium.com/data-science-collective/i-spent-6-months-tuning-claude-code-heres-the-exact-setup-that-finally-worked-b41c67628478) on Medium | 🔥 高互动长文
- **摘要**: 6 个月调优经验总结的核心原则：启动会话时只给目标、约束和最小代码面，不要一次性灌入所有文件。当 Claude 主动要求更多信息时再按需补充。用结构化摘要替代原始日志——显式列出决策要点而非粘贴完整 transcript。这种"先瘦后补"策略能让上下文利用率提升 2-3 倍。
- **代码示例**:
```markdown
<!-- 好的提示：精简启动 -->
目标：修复用户登录超时问题
约束：不能改动 session middleware
相关文件：src/auth/login.ts（第 45-80 行）
错误日志摘要：JWT 验证在 token 过期后未正确刷新

<!-- 坏的提示：信息过载 -->
"这是我们整个 auth 模块的所有代码 [500 行]，
还有完整的错误日志 [200 行]，帮我看看哪里有问题"
```

## 3. `/btw` 侧问命令——不打断主任务流
- **来源**: [XDA Developers](https://www.xda-developers.com/claude-codes-creator-keeps-sharing-tips-and-they-all-made-my-experience-better/) | 🔥 热门技术文章
- **摘要**: Claude Code 创始人分享的实用命令：`/btw` 允许你在 Claude 执行任务中途插入一个快速问题，Claude 会回答后自动回到原任务继续执行。比如 Claude 正在重构数据库层时，你可以 `/btw 这个表有索引吗？` 得到答案后它继续原来的重构工作，不会丢失上下文或中断执行流。
- **代码示例**:
```bash
# Claude 正在执行复杂重构任务...
# 你突然想确认一个细节：

/btw 这个项目的 Node.js 最低版本要求是多少？

# Claude 快速回答后，自动继续之前的重构任务
# 无需重复之前的指令或重新建立上下文
```

## 4. 自定义 Skill 持久化——一次编写，永久生效
- **来源**: [XDA Developers](https://www.xda-developers.com/the-claude-skill-i-built-for-myself-is-the-only-productivity-hack-that-stuck/) | 🔥 热门技术文章
- **摘要**: 与其每次手动输入复杂提示词，不如把最常用的工作流封装成 Skill。开发者分享了一个自建 Skill 案例：将日常的代码审查、测试生成、文档更新等流程打包成可复用的 Skill 文件，配合 `context: fork` 在独立上下文中执行，既保持主会话清洁又确保一致性。这是唯一"用了就回不去"的生产力技巧。
- **代码示例**:
```markdown
<!-- .claude/skills/quick-review/SKILL.md -->
---
name: quick-review
description: 快速代码审查，聚焦安全和性能
context: fork
---

## 审查清单
1. 检查 SQL 注入、XSS、CSRF 等安全漏洞
2. 识别 N+1 查询和不必要的循环
3. 验证错误处理是否完整
4. 检查是否有硬编码的密钥或凭证

输出格式：按严重级别（Critical/Warning/Info）分类
```

## 5. 代码库预分析——让 Claude 先"看地图"再动手
- **来源**: [shinpr](https://github.com/shinpr/claude-code-workflows) on GitHub | ⭐ 376 stars
- **摘要**: 在开始任何实现之前，先运行 codebase-analyzer Agent 扫描现有模块和依赖关系。这能防止 Claude 重复造轮子或与现有代码产生冲突。分析结果包括模块依赖图、已有的工具函数、API 端点清单等，让后续的设计和实现有据可依。
- **代码示例**:
```bash
# 使用 shinpr/claude-code-workflows 的预分析命令
/recipe-implement "添加用户认证功能"

# 系统自动执行：
# 1. codebase-analyzer 扫描现有模块和依赖
# 2. 基于分析结果生成设计文档
# 3. 设计审查通过后才开始实现
# 4. 实现完成后自动验证质量

# 前端专用流程
/recipe-front-design "构建用户资料仪表板"
# 自动生成 UI 状态矩阵（loading × error × empty）
# 捕获非 happy-path 的集成问题
```

## 6. UI 状态矩阵映射——告别"只管 Happy Path"
- **来源**: [shinpr](https://github.com/shinpr/claude-code-workflows) on GitHub | ⭐ 376 stars
- **摘要**: 前端开发的经典问题是只实现了正常流程，忽略了加载中、错误、空数据等状态组合。该工作流自动生成 UI 状态矩阵，穷举 `loading × error × empty × success` 的所有组合，在实现之前就发现集成缺口。社区反馈这个方法将前端 Bug 率降低了约 40%。
- **代码示例**:
```markdown
<!-- UI 状态矩阵示例 -->
| 状态 | loading | error | empty | success |
|------|---------|-------|-------|---------|
| 初始加载 | Skeleton | ErrorBanner + Retry | EmptyState | DataTable |
| 刷新 | Spinner overlay | Toast + 保留旧数据 | — | 更新 DataTable |
| 分页 | 行级 Skeleton | Toast + 保留当前页 | "没有更多" | 追加数据 |
| 筛选 | 全表 Skeleton | ErrorBanner | "无匹配结果" | 过滤后 DataTable |
```

## 7. 逆向工程遗留代码——让老系统变得 AI 友好
- **来源**: [shinpr](https://github.com/shinpr/claude-code-workflows) on GitHub | ⭐ 376 stars
- **摘要**: 面对没有文档的遗留代码，使用 `/recipe-reverse-engineer` 命令自动生成 PRD（产品需求文档）和设计文档。这个工作流让 Claude 先理解现有代码的结构和逻辑，再输出结构化文档，使遗留系统变得可维护、可迭代。对于接手他人项目或处理技术债务特别有效。
- **代码示例**:
```bash
# 对遗留模块进行逆向工程
/recipe-reverse-engineer

# 系统自动执行：
# 1. 扫描代码结构和调用关系
# 2. 识别核心业务逻辑和数据流
# 3. 生成 PRD 文档（产品视角）
# 4. 生成设计文档（技术视角）
# 5. 标注技术债务和重构建议

# 输出示例：
# docs/reverse-engineered/
#   ├── PRD.md          # 产品需求还原
#   ├── Design.md       # 技术设计文档
#   └── TechDebt.md     # 技术债务清单
```

## 8. `/usage` 分类统计——精准掌控 Token 开销
- **来源**: [Claude Code v2.1.149 更新](https://github.com/anthropics/claude-code/releases) | 🔥 v2.1.149 新功能
- **摘要**: v2.1.149 新增的 `/usage` 命令支持按类别分解 Token 消耗，让你清楚知道上下文中哪些内容最"烧钱"——是代码文件、对话历史、还是工具调用结果。配合 `/compact` 使用，可以有针对性地压缩高消耗类别，而不是盲目清理，实现更精细的成本控制。
- **代码示例**:
```bash
# 查看当前会话的 Token 使用分布
/usage

# 输出示例：
# Token Usage Breakdown:
#   Code files:     45% (12,340 tokens)
#   Conversation:   30% (8,230 tokens)
#   Tool results:   20% (5,490 tokens)
#   System prompt:   5% (1,370 tokens)

# 发现 Tool results 占比过高时，使用 /compact 压缩
/compact "保留核心决策和代码变更，压缩工具输出"
```
