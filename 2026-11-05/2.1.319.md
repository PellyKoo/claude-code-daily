# Claude Code 2.1.319 社区实用技巧 - 2026-11-05

## 1. 子代理成本削减 99%：三个关键设置
- **来源**: [Vox](https://x.com/Voxyz_ai/status/2118387877939921361) on X | 🔥 高互动推文
- **摘要**: Anthropic 大幅降低了 Claude Code 后台子代理状态更新的成本。如果你的用量配额紧张，可以利用三个设置来最大化节省：(1) 内置 Explore 代理使用与 Haiku 相同的模型，成本极低；(2) 子代理可设置 `omitClaudeMd: true` 跳过加载 CLAUDE.md 文件；(3) 合理配置子代理的工具权限，只给必要的工具。
- **代码示例**:
```json
// .claude/agents/quick-search.md frontmatter
---
model: haiku
tools: ["Glob", "Grep", "Read"]
---
```

## 2. 用 git worktree 实现真正的并行开发
- **来源**: [Boris Cherny](https://x.com/bcherny/status/2038454353787519164) on X | 🔥 Claude Code 创始人亲授
- **摘要**: Claude Code 内置了对 git worktree 的深度支持。用 `claude -w` 启动新会话，每个会话在独立的 worktree 中工作，互不干扰。适合同时处理多个功能分支或让多个 Claude 实例并行开发同一仓库的不同部分。
- **代码示例**:
```bash
# 在新 worktree 中启动 Claude Code 会话
claude -w

# 或在 Agent 工具中指定 worktree 隔离
# isolation: "worktree"
```

## 3. CLAUDE.md 写法黄金法则：用陈述句，不用命令句
- **来源**: [socialwithaayan](https://x.com/socialwithaayan/article/2089647610122662164) on X | 🔥 热门长文
- **摘要**: CLAUDE.md 中的规则应写成事实陈述句而非命令式指令。命令式语句（如"你必须…"）可能触发 Claude 的 prompt injection 防御机制，导致规则被忽略。保持文件在 200 行以内，路径相关的规则放到 `.claude/rules/` 目录中按路径匹配加载。
- **代码示例**:
```markdown
<!-- 推荐写法 -->
测试使用 pytest 运行，命令为 `npm run test`
代码风格遵循 ESLint 配置，缩进为 2 空格

<!-- 不推荐写法 -->
你必须使用 pytest 运行测试！
绝对不要使用 4 空格缩进！
```

## 4. Hooks 才是真正的"强制执行"层
- **来源**: [Addy Osmani](https://x.com/addyosmani/status/2064127981161959567) on X | 🔥 Google 工程师分享
- **摘要**: CLAUDE.md 是"建议"，遵守率约 80%；Hooks 是"强制执行"。对于必须每次都执行的操作（如保存后自动格式化、提交前运行 lint），应该配置为 hooks 而不是写在 CLAUDE.md 里。Hooks 支持 SessionStart、SubagentStart/Stop、WorktreeCreate 等事件。
- **代码示例**:
```json
// .claude/settings.json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "command": "npx prettier --write $CLAUDE_FILE_PATH"
      }
    ]
  }
}
```

## 5. Plan Mode：多文件修改前必用
- **来源**: [XDA Developers](https://www.xda-developers.com/rebuilt-my-claude-code-workflow-around-its-creators-advice/) | 🔥 热门技术文章
- **摘要**: 在涉及多文件或架构级改动时，先用 Plan Mode 让 Claude 规划方案，审查后再执行。这避免了 Claude 直接动手改代码后发现方向错误，浪费大量上下文和 token。Boris Cherny 本人也推荐这种"先规划后执行"的工作流。
- **代码示例**:
```
# 在 Claude Code 中切换到 Plan Mode
# 使用 Shift+Tab 切换模式，或输入：
/plan 重构认证模块，将 JWT 验证逻辑从中间件移到独立服务
```

## 6. 将重复工作流封装为 Skills
- **来源**: [cogsec](https://x.com/affaan/status/2012378465664745795) on X | 🔥 Claude Code 速查指南
- **摘要**: 如果你经常重复相同的操作流程（如部署、代码审查、数据库迁移），把它们封装为 `.claude/skills/` 下的 Markdown 文件。通过 `/skill-name` 直接调用，避免每次重新描述完整流程，减少 token 消耗。
- **代码示例**:
```markdown
<!-- .claude/skills/deploy.md -->
---
description: 部署到生产环境
---
1. 运行 `npm run build`
2. 运行 `npm run test`
3. 确认所有测试通过后执行 `npm run deploy:prod`
4. 验证部署状态
```

## 7. 自定义子代理：给不同任务分配专用角色
- **来源**: [Vishwas](https://x.com/CodevolutionWeb/status/2034683638382506063) on X | 🔥 50 Tips 合集
- **摘要**: 在 `.claude/agents/` 目录下创建 Markdown 文件定义专用子代理，限制其可用工具和模型。只读搜索任务用 Haiku + 只读工具，复杂推理用 Opus。这样既节省成本又保持主会话上下文整洁。
- **代码示例**:
```markdown
<!-- .claude/agents/code-reviewer.md -->
---
model: sonnet
tools: ["Read", "Grep", "Glob"]
description: 专注代码审查，不做修改
---
审查代码时关注：安全漏洞、性能问题、可维护性。
只报告发现，不直接修改代码。
```
