## 1. 自定义状态栏：一眼掌握会话全貌
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 9.5k stars
- **摘要**: 用自定义 bash 脚本替换默认状态栏，实时显示当前模型、Git 分支、未提交文件数、同步状态和 token 使用百分比。支持 10 种配色主题，还能显示上一条消息摘要，方便多窗口切换时快速找回上下文。
- **代码示例**:
```bash
# 安装 ykdojo 的状态栏脚本

# 状态栏显示内容示例：
# [opus-4] ~/my-project (main) | 3 uncommitted | 18% context | "fix auth bug"
```

- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 9.5k stars
- **摘要**: 遇到耗时较长的 bash 命令时，按 Ctrl+B 将其移到后台执行。Claude 通过 BashOutput 工具管理后台进程，稍后自动检查进度。Subagent 同样支持后台运行，可以并行分析大型代码库的不同模块。
- **代码示例**:
```
# 运行中的命令按 Ctrl+B 移到后台
# Claude 会自动追踪并在完成后汇报结果

# 也可以主动要求并行处理
"Spawn 3 background subagents to analyze the auth, billing, and notification modules independently."
```

## 3. Vertical Slice 规划法：按功能切片而非按层开发
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 63.6k stars
- **摘要**: AI 默认倾向于先写完所有数据库层，再写所有 API 层，最后写 UI 层。这种水平分层开发推迟了端到端验证。正确做法是按 "垂直切片" 规划：每个功能从 DB → Service → UI 完整贯穿，先跑通一条完整链路再扩展。灵感来自 Matt Pocock 和《程序员修炼之道》的 "曳光弹" 理念。
- **代码示例**:
```
# 错误方式：水平分层
"First create all database models, then create all API endpoints, then create all UI components."

# 正确方式：垂直切片
"Implement the user registration feature end-to-end:
1. User model + migration
2. Registration API endpoint
3. Registration form UI
4. Integration test
Then move to the next feature."
```

## 4. 多账户快速切换：工作和个人号一键切换
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 9.5k stars
- **摘要**: 通过环境变量 `CLAUDE_CODE_OAUTH_TOKEN` 覆盖默认账户，实现工作账号和个人账号的一键切换。Token 可以安全存储在系统钥匙串（macOS）或凭据文件中，避免明文暴露。
- **代码示例**:
```bash
# macOS：将 token 存入 Keychain
security add-generic-password -s claude-token-work -a "$USER" -w "your-work-token"
security add-generic-password -s claude-token-personal -a "$USER" -w "your-personal-token"

# 在 .zshrc 中添加快捷函数
clw() { CLAUDE_CODE_OAUTH_TOKEN="$(security find-generic-password -s claude-token-work -a "$USER" -w)" claude "$@"; }
clp() { CLAUDE_CODE_OAUTH_TOKEN="$(security find-generic-password -s claude-token-personal -a "$USER" -w)" claude "$@"; }

# 使用
clw  # 工作账号
clp  # 个人账号
```

## 5. TDD 驱动 AI 开发：先写测试让 Claude 有靶可打
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 9.5k stars
- **摘要**: 先写测试再让 Claude 实现功能，是目前社区公认最有效的 AI 编程模式。测试定义了明确的 "验收标准"，Claude 有了具体目标后代码质量显著提高，而且可以自行运行测试验证实现是否正确，形成完整的 write-test 闭环。
- **代码示例**:
```
# 第一步：写测试
"Write comprehensive tests for a user authentication service that supports
email/password login, OAuth, and rate limiting. Include edge cases."

# 第二步：让 Claude 实现
"Now implement the AuthService to make all these tests pass."

# Claude 会自动运行测试、修复失败、直到全部通过
```

## 6. Workflow 深度实践：非技术任务也能编排
- **来源**: [Thariq](https://x.com/trq212/status/2061907538741006796) on X | 🔥 高互动推文
- **摘要**: Workflows 是继 Skills 和 Subagent 之后 Claude Code 最大的能力升级。Thariq（Anthropic 工程师）指出 Workflows 不仅适用于代码任务，还能编排非技术工作流：如批量整理文档、审计依赖项、生成多语言翻译等。关键是用 `pipeline()` 替代 `parallel()` 作为默认模式，避免不必要的同步屏障。
- **代码示例**:
```javascript
// 示例：多语言文档翻译 workflow
export const meta = {
  name: 'translate-docs',
  description: 'Translate docs to multiple languages',
  phases: [{ title: 'Translate' }, { title: 'Review' }],
}

const LANGS = ['zh', 'ja', 'ko', 'es', 'fr']
const results = await pipeline(
  LANGS,
  lang => agent(`Translate README.md to ${lang}`, {
    phase: 'Translate', label: `translate:${lang}`
  }),
  (translation, lang) => agent(`Review ${lang} translation for accuracy`, {
    phase: 'Review', label: `review:${lang}`
  })
)
```

## 7. 双 Agent 对审模式：生成与审查分离提升代码质量
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 63.6k stars
- **摘要**: 利用 "测试时计算" 原理，让一个 Agent 写代码，另一个独立的全新上下文 Agent 做代码审查。两个 Agent 使用相同模型但互不共享上下文，能有效发现单一 Agent 的盲点。这个模式可以通过 Subagent 或 Workflow 轻松实现。
- **代码示例**:
```
# 方式一：手动双 Agent
# 会话 1 - 实现功能
claude "Implement the payment processing module"

# 会话 2 - 独立审查（全新上下文）
claude "Review the payment processing module for bugs, security issues, and edge cases. You did NOT write this code."

# 方式二：用 Workflow 自动化
# 在 workflow 脚本中
const code = await agent('Implement payment module', {label: 'writer'})
const review = await agent('Review this implementation independently', {label: 'reviewer'})
```
