## 1. Santiago 的 20 条 Claude Code 快捷操作速查
- **来源**: [Santiago (@svpino)](https://x.com/svpino/status/2050563493708112190) on X | 🔥 高互动推文（大量转发/点赞）
- **摘要**: Santiago 分享了 20 条实用快捷操作，其中最亮眼的三个：`Esc+Esc` 回退到任意历史检查点（相当于免费的撤销，放心让 agent 尝试高风险改动）；`Ctrl+V` 直接粘贴截图到终端（调试 UI 问题超方便）；`Ctrl+G` 打开编辑器编写长提示词而不是在终端里打字。这些快捷键大幅降低了使用门槛。
- **代码示例**:
```bash
# 常用快捷键速查
Esc+Esc    # 回退到历史检查点（免费撤销）
Ctrl+V     # 粘贴截图到 Claude Code
Ctrl+G     # 打开编辑器写长提示词
Shift+Tab  # 切换 Plan Mode（按两次）
!command   # 直接在 shell 运行命令，节省 token
```

## 2. CLAUDE.md 最佳实践：控制在 200 行以内 + 路径作用域规则
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 活跃社区仓库
- **摘要**: 该仓库总结了 CLAUDE.md 的核心原则：主文件控制在 200 行以内以保证 Claude 遵循度；详细说明移到独立文件用 `@filename` 引入；使用 `.claude/rules/*.md` 配合 `paths:` YAML 前置元数据实现按文件路径懒加载规则。对于 monorepo，建议在子目录中放置各自的 CLAUDE.md，支持祖先/后代加载机制。
- **代码示例**:
```markdown
# 主 CLAUDE.md（保持精简）
## 项目概述
React + TypeScript 前端，Node.js API 后端

## 关键命令
- 测试: `npm test`
- 构建: `npm run build`
- Lint: `npm run lint`

## 核心规则
- 所有 API 响应使用统一的 Result<T> 类型
- 参考 @docs/api-conventions.md 了解详细规范
```

```yaml
# .claude/rules/frontend.md — 仅在修改前端文件时加载
---
paths:
  - "src/components/**"
  - "src/pages/**"
---
- 组件使用函数式写法 + hooks
- 样式使用 Tailwind，不写自定义 CSS
```

## 3. 上下文管理：在 60% 容量时执行 /compact
- **来源**: [mindstudio.ai 指南](https://www.mindstudio.ai/blog/tag/workflows/4) | 🔥 社区推荐文章
- **摘要**: 多位开发者反馈，等到上下文快满才压缩会导致"上下文腐蚀"——Claude 开始遗忘早期指令。最佳实践是在约 60% 上下文容量时主动执行 `/compact`，并附带聚焦指令告诉 Claude 保留哪些关键信息。另外，不相关任务之间使用 `/clear` 彻底清空，避免旧上下文干扰新任务。
- **代码示例**:
```bash
# 上下文管理三板斧
/compact "保留 auth 模块重构的所有决策和文件路径"  # 带聚焦指令压缩
/clear                                              # 切换不相关任务时清空
/rewind                                             # 回退到某个节点重新开始
```

## 4. Git Worktree 并行开发：多会话互不干扰
- **来源**: [mvanhorn](https://x.com/mvanhorn/article/2035857346602340637) on X | 🔥 长文合集（高互动）
- **摘要**: 使用 `claude --worktree` 启动会话，Claude 会自动创建 git worktree 在独立分支上工作，多个会话可以同时运行互不干扰。适合并行处理多个 feature 或同时进行代码审查和开发。配合系统通知和编号标签页管理多个终端会话。
- **代码示例**:
```bash
# 终端 1: 主功能开发
claude --worktree
> "实现用户认证模块"

# 终端 2: 同时修 bug（独立分支）
claude --worktree
> "修复 #234 支付回调超时问题"

# 终端 3: 代码审查（不影响开发分支）
claude --worktree
> "审查 PR #56 的安全性"
```

## 5. Hooks 替代 CLAUDE.md 规则：确定性行为用 hooks 强制执行
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 完整配置示例仓库
- **摘要**: CLAUDE.md 中的规则是"建议性"的，Claude 可能忽略；而 hooks 是确定性执行的 shell 命令，适合格式化、lint、测试等必须执行的操作。该仓库展示了完整的 hooks + skills + agents + GitHub Actions 配置示例，是目前最全面的 Claude Code 项目配置参考。
- **代码示例**:
```json
// .claude/settings.json — hooks 配置示例
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "command": "npx prettier --write $CLAUDE_FILE_PATH"
      }
    ],
    "PostCommit": [
      {
        "command": "npm run lint -- --fix"
      }
    ]
  }
}
```

## 6. 验证循环：不要相信 Claude 的自我报告
- **来源**: [Boris Cherny (Claude Code 创建者) 访谈总结](https://whyaiman.substack.com/p/tips-for-working-with-claude-code) | 🔥 高阅读量文章
- **摘要**: Claude Code 的创建者 Boris Cherny 强调"验证能力是最重要的质量杠杆"。他建议：给 Claude 提供测试命令让它自己跑测试；直接粘贴原始错误日志而非自己描述问题；使用独立的审查 pass 而非信任 Claude 的自我报告。他自己会使用浏览器扩展让 Claude 测试 UI 变更，而不是仅依赖截图。
- **代码示例**:
```markdown
# 在 CLAUDE.md 中添加验证规则
## 验证要求
- 每次代码修改后运行 `npm test` 验证
- UI 改动必须启动 dev server 实际测试，不能只看代码
- 提交前运行完整 lint + type check: `npm run check`
- 出错时直接粘贴完整错误日志，不要自己描述
```
