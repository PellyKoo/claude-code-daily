## 1. Trail of Bits 安全配置模板：沙箱 + 安全钩子 + MCP 服务器
- **来源**: [trailofbits](https://github.com/trailofbits/claude-code-config) on GitHub | ⭐ 2,000 stars
- **摘要**: 安全公司 Trail of Bits 开源了他们的 Claude Code 配置方案。核心亮点：使用 `--dangerously-skip-permissions` 搭配 `/sandbox` 命令实现 OS 级沙箱隔离（macOS 用 Seatbelt，Linux 用 bubblewrap）；Pre-execution hooks 拦截危险命令（如 `rm -rf`、直接 push 到 main）；推荐 Context7 和 Exa 作为必装全局 MCP 服务器。
- **代码示例**:
```json
// .claude/settings.json - 安全钩子示例
{
  "hooks": {
    "preExec": {
      "block_patterns": ["rm -rf /", "git push origin main"],
      "action": "deny"
    }
  },
  "deny": [
    "~/.ssh/*",
    "~/.aws/*",
    "~/.config/gcloud/*"
  ]
}
```

## 5. Worktree 自动化钩子：解决环境文件和端口冲突
- **来源**: [tfriedel](https://github.com/tfriedel/claude-worktree-hooks) on GitHub | ⭐ 24 stars
- **摘要**: 解决并行 worktree 开发的痛点：新建的 worktree 缺少 `.env` 文件、缺少 `node_modules`、多个会话端口冲突。这个项目通过 WorktreeCreate 和 WorktreeRemove 钩子自动化处理：自动复制环境文件、安装依赖、并使用分支名 MD5 哈希生成确定性端口号（3100-9999范围），确保同一分支每次获得相同端口。
- **代码示例**:
```bash
#!/bin/bash
# .claude/hooks/worktree-create.sh
# WorktreeCreate 钩子 - 自动初始化新 worktree

INPUT=$(cat -)
WORKTREE_NAME=$(echo "$INPUT" | jq -r '.name')
WORKTREE_PATH="../worktrees/$WORKTREE_NAME"

# 创建 worktree
git worktree add "$WORKTREE_PATH" -b "$WORKTREE_NAME" 2>/dev/tty

# 复制环境文件
cp .env "$WORKTREE_PATH/.env" 2>/dev/tty
cp .env.local "$WORKTREE_PATH/.env.local" 2>/dev/tty

# 安装依赖
cd "$WORKTREE_PATH" && npm install 2>/dev/tty

# 确定性端口分配（基于分支名哈希）
PORT=$((16#$(echo -n "$WORKTREE_NAME" | md5sum | cut -c1-4) % 6900 + 3100))
echo "PORT=$PORT" >> "$WORKTREE_PATH/.env"

# 输出 worktree 路径（必须是 stdout 唯一输出）
echo "$WORKTREE_PATH"
```

## 6. CLAUDE.md 分层管理：全局 + 项目 + 本地三级配置
- **来源**: [abhishekray07](https://github.com/abhishekray07/claude-md-templates) on GitHub | ⭐ 开源模板集
- **摘要**: Claude Code 从三个位置读取指令，各有不同作用域：`~/.claude/CLAUDE.md`（全局个人偏好）、`.claude/CLAUDE.md`（项目上下文，团队共享）、`./CLAUDE.local.md`（本地覆盖，不提交）。关键发现：项目 CLAUDE.md 超过80行后 Claude 会开始忽略部分内容，HumanLayer 团队将其控制在60行以内作为最佳实践。
- **代码示例**:
```markdown
<!-- ~/.claude/CLAUDE.md - 全局配置 -->
偏好中文注释
使用 Conventional Commits 格式
代码风格：简洁优先，避免过度抽象

<!-- .claude/CLAUDE.md - 项目配置（<60行） -->
技术栈: Next.js 15 + TypeScript + Prisma
测试: vitest, 运行 npm test
Lint: npm run lint
数据库迁移: npx prisma migrate dev
PR 描述必须包含测试计划

<!-- CLAUDE.local.md - 本地覆盖（gitignore） -->
使用本地 Postgres: DATABASE_URL=postgresql://localhost:5432/dev
跳过 CI 相关检查
```

- **代码示例**:
```bash
# 核心原则：给 Claude 验证自己工作的能力

# 1. 测试驱动 - 让 Claude 写完代码后自行验证

# 2. 浏览器自动化 - UI 变更后自动截图验证
# .claude/hooks/post-edit-ui.sh

  npx playwright screenshot http://localhost:3000 /tmp/ui-check.png
fi

# 3. Lint 钩子 - 每次编辑后自动检查代码质量
# .claude/settings.json
{
  "hooks": {
    "postEdit": "npx eslint --fix $FILE && npx tsc --noEmit"
  }
}
```
