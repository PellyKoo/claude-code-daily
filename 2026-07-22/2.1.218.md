## 1. Tracer Bullet 垂直切片：别按层写代码，按功能穿透所有层
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 63.4k stars
- **摘要**: 让 Claude Code 开发新功能时，不要按传统的水平分层（先写数据库、再写后端、最后前端），而是用 Tracer Bullet 方法——每次实现一个功能的完整垂直切片，从 UI 到 API 到数据库一次性打通。这样每一步都能验证整个链路是否可行，避免在最后集成时才发现架构不匹配。核心提示词："Build this as a tracer bullet — one vertical slice through all layers, end to end."
- **代码示例**:
```bash
# ❌ 水平分层（容易在集成时翻车）
> First create the database schema for users
> Now build the API endpoints
> Finally create the React components
# 问题：直到第三步才发现 schema 设计和 UI 需求不匹配

# ✅ Tracer Bullet 垂直切片
> Build a tracer bullet for user registration:
  DB table + API endpoint + React form + E2E test.
  Minimal but working end-to-end.

# 然后逐步加厚：
> Now add email validation to the registration flow
  (update all layers).
> Add OAuth support (update all layers).

# 每一步都是可运行、可验证的完整功能
```

## 2. `<important if="...">` 条件标签：阻止 Claude 忽略关键规则
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 63.4k stars
- **摘要**: 当 CLAUDE.md 超过 80-100 行时，Claude 会开始选择性忽略部分规则。社区发现用 `<important>` 标签包裹关键规则可以显著提高遵守率，而 `if` 属性可以让规则仅在特定条件下激活。这个技巧来自对 Claude 注意力机制的实战经验——被标签包裹的内容在模型的注意力权重分配中会获得更高优先级。
- **代码示例**:
```markdown
<!-- CLAUDE.md -->

# Project: E-commerce Platform

## Stack
- Next.js 15, TypeScript, Prisma, PostgreSQL

<important>
NEVER modify migration files that have already been applied.
ALWAYS run `pnpm test` before marking any task as complete.
</important>

<important if="editing files in src/payments/">
PCI compliance is mandatory. Never log credit card numbers,
CVVs, or full card details. Use Stripe tokens exclusively.
All payment logic must have 100% test coverage.
</important>

<important if="creating API routes">
All API routes must use the withAuth() middleware.
Rate limiting is required for public endpoints.
Return standardized { data, error, meta } envelope.
</important>

## General Guidelines
- Use Tailwind for styling
- Prefer server components where possible
```

## 3. MCP 安全审计清单：5 分钟排查恶意服务器
- **来源**: [FlorianBruniaux](https://github.com/FlorianBruniaux/claude-code-ultimate-guide) on GitHub | ⭐ 5.5k stars
- **摘要**: 截至 2026 年 7 月，社区已追踪到 28 个 MCP 相关 CVE 和 655 个恶意 skill。在批准任何 MCP 服务器前，应执行一个 5 分钟安全清单：检查 npm 包发布者历史、审查工具权限范围、验证是否有已知漏洞、确认数据流向。claude-code-ultimate-guide 仓库提供了 38 个生产级安全 hook（包括危险操作拦截器、prompt 注入检测器、Unicode 注入扫描器、输出密钥扫描器），可以直接集成到项目中作为安全防线。
- **代码示例**:
```bash
# MCP 服务器 5 分钟安全审计清单

# 1. 检查 npm 包信息
npm info <mcp-package> --json | jq '{
  author, license,
  maintainers: .maintainers[].name,
  published: .time.modified,
  weekly_downloads: .downloads
}'

# 2. 审查工具权限（安装前先看它要什么权限）
npx <mcp-package> --list-tools 2>/dev/null

# 3. 启用安全 hook 防护
# .claude/settings.json
{
  "hooks": {
    "PreToolUse": [
      {
        "command": "node .claude/hooks/dangerous-actions-blocker.js",
        "description": "Block destructive file/git operations"
      },
      {
        "command": "node .claude/hooks/prompt-injection-detector.js",
        "description": "Scan for prompt injection in tool inputs"
      }
    ],
    "PostToolUse": [
      {
        "command": "node .claude/hooks/output-secrets-scanner.js",
        "description": "Detect leaked secrets in tool outputs"
      }
    ]
  }
}
```

## 4. 多文件记忆银行：跨会话保持项目上下文不丢失
- **来源**: [centminmod](https://github.com/centminmod/my-claude-code-setup) on GitHub | ⭐ 2.5k stars
- **摘要**: 单一 CLAUDE.md 在复杂项目中容易变得臃肿或丢失信息。Memory Bank 模式将项目上下文拆分为多个专用记忆文件：`memory/decisions.md`（架构决策记录）、`memory/patterns.md`（代码模式和约定）、`memory/troubleshooting.md`（排障经验）。每次任务完成后执行 "update memory bank" 让 Claude 自动更新相关记忆文件。这样即使开新会话，Claude 也能通过读取记忆文件快速恢复项目上下文，无需重复解释。
- **代码示例**:
```markdown
<!-- CLAUDE.md（主入口，保持精简） -->
# Project: MyApp

## Memory Bank
Read these files at session start for full context:
- memory/decisions.md - Architecture decisions and rationale
- memory/patterns.md - Code patterns and conventions
- memory/troubleshooting.md - Known issues and fixes

## Commands
- `pnpm dev` - Start dev server
- `pnpm test` - Run tests
- `pnpm lint` - Run linter

<!-- memory/decisions.md -->
# Architecture Decisions

## 2026-07-20: 选择 Drizzle 替代 Prisma
- 原因: 更好的 Edge Runtime 支持，bundle 更小
- 影响: 所有新数据库操作使用 Drizzle schema
- 回退方案: Prisma 代码暂时保留在 src/legacy/

## 2026-07-18: API 路由迁移到 App Router
- 原因: 利用 React Server Components 减少客户端 bundle
- 进度: 80% 完成，剩余 /api/legacy/* 路由

<!-- memory/troubleshooting.md -->
# Known Issues & Fixes

## Drizzle + Edge Runtime
- 问题: `dynamic = 'force-dynamic'` 必须设置
- 修复: 在每个使用 DB 的 route.ts 顶部添加 export
```

## 5. GitHub Actions + Claude Code：$10/月的自动化开发运维
- **来源**: [ChrisWiles](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 6k stars
- **摘要**: 通过 GitHub Actions 触发 Claude Code 执行定期维护任务，实现低成本的自动化开发运维。包括：每次 PR 自动代码审查（$0.05-$0.50/次）、每周代码质量扫描（$1-$5/次）、每月文档同步（$0.50-$2/次）、双周依赖安全审计（$0.20-$1/次）。总月成本仅 $10-50，但能持续保持代码质量和文档一致性。配合 MCP 集成 JIRA/Linear，还能实现"读 ticket → 实现 → 更新状态"的全自动开发循环。
- **代码示例**:
```yaml
# .github/workflows/weekly-quality-scan.yml
name: Weekly Code Quality Scan
on:
  schedule:
    - cron: '0 9 * * 1'  # 每周一上午 9 点
  workflow_dispatch:

jobs:
  quality-scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: anthropics/claude-code-action@v1
        with:
          prompt: |
            Scan the codebase for:
            1. Dead code and unused exports
            2. TODO/FIXME items older than 30 days
            3. Dependencies with known vulnerabilities
            4. Test coverage gaps in recently changed files
            Create a GitHub issue summarizing findings.
          max_turns: 10

# .github/workflows/pr-review.yml
name: Auto PR Review
on:
  pull_request:
    types: [opened, synchronize]

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: anthropics/claude-code-action@v1
        with:
          prompt: |
            Review this PR for logic errors, security
            issues, and test coverage. Post as a review.
```

## 6. 图片驱动开发：截图 → 计划 → 代码一步到位
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 63.4k stars
- **摘要**: Claude Code 支持直接粘贴或拖入图片（截图、设计稿、错误信息、Slack 对话截图等），并基于图片内容生成开发计划和代码。社区最受欢迎的用法是：拖入 Figma 设计稿截图让 Claude 生成对应组件代码，或者截取 bug 报告让 Claude 直接定位和修复问题。比起手动描述 UI 布局或错误场景，图片输入能减少 60-70% 的 prompt 编写时间，且 Claude 对视觉信息的理解准确率远超纯文本描述。
- **代码示例**:
```bash
# 用法 1：设计稿 → 组件代码
# 直接把 Figma 截图拖入 Claude Code 终端
> [粘贴截图] Build this component with Tailwind CSS.
  Match the exact spacing, colors, and typography.
  Use shadcn/ui components where applicable.

# 用法 2：Bug 截图 → 自动修复
> [粘贴错误截图] Fix this error. The screenshot shows
  the exact error message and stack trace.

# 用法 3：架构图 → 代码骨架
> [粘贴架构图] Implement the service layer shown in
  this diagram. Create interfaces and stub implementations
  for each component.

# 用法 4：Slack/邮件截图 → 任务拆解
> [粘贴 Slack 对话] Extract the requirements from this
  conversation and create a task list with implementation
  plan.
```

## 7. 20-30 个原型迭代代替详细规格文档
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 63.4k stars
- **摘要**: 在 AI 辅助开发时代，社区经验表明"快速原型迭代"比"详细规格文档"更有效率。与其花 2 天写技术方案文档，不如用 Claude Code 在 2 小时内构建 20-30 个快速原型版本，每个版本探索不同的架构方向。利用 `/clear` 开新会话尝试全新方案，用 git stash 保存有潜力的版本。最终从多个原型中挑选最佳方案进行打磨。这种"广度优先探索"策略充分利用了 AI 的低成本优势，显著降低了选错方案的风险。
- **代码示例**:
```bash
# 原型迭代工作流

# 第 1 轮：探索不同架构
> Build a REST API for user auth using Express + JWT
> /clear
> Build user auth using tRPC + session tokens
> /clear
> Build user auth using GraphQL + OAuth

# 每个原型完成后：
git stash push -m "prototype-rest-jwt"
git stash push -m "prototype-trpc-session"
git stash push -m "prototype-graphql-oauth"

# 第 2 轮：对比评估
> Compare these three approaches for our use case:
  - 50k DAU, mobile-first
  - Need offline support
  - Team of 3 backend devs
  Which approach and why?

# 第 3 轮：打磨最佳方案
git stash pop  # 恢复选定方案
> Now harden this: add rate limiting, input validation,
  error handling, logging, and comprehensive tests.
```
