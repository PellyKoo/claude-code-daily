## 1. Dynamic Workflows：让 Claude 自动编排数百个并行 Agent
- **来源**: [Greg Isenberg](https://x.com/gregisenberg/status/2060072130339873093) on X | 🔥 高互动热推
- **摘要**: Claude Code 新增的"动态工作流"功能引发社区热议。只需在提示词中输入 "create a workflow" 或在 effort 菜单中开启 "ultracode"，Claude 就会自动生成一个多阶段编排方案，启动数百个并行 Agent 互相检查彼此的工作。这将单次能交付的工作量从"一个文件"提升到"一整个功能模块"，彻底改变了大规模代码任务的处理方式。
- **代码示例**:
```
# 在提示词中使用 ultracode 关键词即可触发
ultracode 请重构整个认证模块，包括：
1. 将 session-based auth 迁移到 JWT
2. 更新所有 API 路由的中间件
3. 修改前端的 token 管理逻辑
4. 更新所有相关测试

# Claude 会自动创建工作流，启动并行 Agent 处理各部分
```

## 3. 上下文腐烂阈值：300-400K Token 是危险区
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 64.4k stars, 6.4k forks
- **摘要**: 这个 64K+ star 的社区最佳实践仓库近期更新了关键发现："上下文腐烂"（context rot）在 300-400K token 时开始显现（即使模型支持 1M token）。社区专家建议在复杂任务中将上下文利用率控制在 30% 以下，并在 70% 时使用 `/compact`，90% 时使用 `/clear`。这颠覆了"上下文窗口越大越好"的直觉。
- **代码示例**:
```bash
# 上下文管理最佳实践
# 1. 新任务 → 新会话（不要复用旧上下文）
# 2. 70% 上下文使用率 → 运行 /compact
# 3. 90% 上下文使用率 → 运行 /clear
# 4. 复杂任务保持 30% 以下利用率
```

## 4. Skill 触发词设计：写"何时触发"而非"功能摘要"
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 64.4k stars
- **摘要**: 社区发现大多数人写 Skill 描述时犯了一个关键错误：写的是"这个 Skill 做什么"（功能摘要），而不是"何时应该触发"（触发条件）。正确写法应像触发器一样描述——例如"当用户提到部署、发布、上线时触发"而非"帮助部署应用的 Skill"。同时要在 Skill 中包含 gotchas（易错点）和具体脚本，避免给出死板的分步指南。
- **代码示例**:
```markdown
<!-- .claude/skills/deploy.md -->
---
description: 当用户提到"部署""发布""上线""deploy""push to prod"时触发
---
# 部署技巧
## Gotchas
- 部署前必须确认 .env.production 存在
- 数据库 migration 必须在应用启动前完成
- CDN 缓存需要手动刷新
```

## 6. 垂直切片法：一次贯穿所有层，而非逐层推进
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 64.4k stars
- **摘要**: 社区共识的工作流架构：Research → Plan → Execute → Review → Ship。但关键不是水平分层（先做完所有数据库、再做完所有 API、再做完所有前端），而是垂直切片（tracer bullet）——一次性贯穿数据库→API→前端做完一个完整功能点。垂直切片能更快获得反馈，发现架构问题，比水平分层效率高出数倍。
- **代码示例**:
```
# ❌ 水平分层（慢，反馈延迟）
第一步：创建所有数据库表
第二步：实现所有 API 端点
第三步：构建所有前端页面

# ✅ 垂直切片（快，即时反馈）
第一步：用户注册功能（数据库 + API + 前端 + 测试）
第二步：用户登录功能（数据库 + API + 前端 + 测试）
第三步：用户资料页面（数据库 + API + 前端 + 测试）
```

## 7. 20 个键盘快捷键：Santiago 的速查指南
- **来源**: [Santiago (@svpino)](https://x.com/svpino/status/2050563493708112190) on X | 🔥 高互动
- **摘要**: 知名开发者 Santiago 分享了 20 个 Claude Code 快捷键和技巧的合集。社区反馈最有用的几个：`Esc+Esc` 回退到任意检查点（相当于免费的 undo）、`Ctrl+V` 直接粘贴截图、`Ctrl+G` 打开编辑器撰写长提示词、`Ctrl+R` 搜索历史提示词、`/rewind` 回滚到检查点后给出更具体的反馈重新尝试。
- **代码示例**:
```
# 最实用的快捷键
Esc+Esc    → 回退到任意检查点（免费 undo）
Ctrl+V     → 粘贴截图
Ctrl+G     → 打开编辑器写长提示词
Ctrl+R     → 搜索提示词历史
/rewind    → 回滚变更到检查点
Shift+Tab  → 切换 Plan/Act 模式
```

## 8. 子 Agent 隔离研究：保护主上下文窗口
- **来源**: [Claude Code Workflow Best Practices](https://dev.to/galian/claude-code-workflow-best-practices-that-ship-code-na) on DEV Community | 🔥 广泛引用
- **摘要**: 社区强调的高级技巧：将"信息搜集"和"代码编辑"分离到不同的上下文中。对于需要大量阅读代码的研究任务，使用子 Agent（subagent）在独立上下文中完成，只将精炼后的结论返回主会话。这样主上下文窗口始终保持干净，专注于实际的代码修改，避免因阅读大量文件导致的上下文腐烂。
- **代码示例**:
```
# 在 Claude Code 中使用子 Agent
# 方法1：直接在提示词中指定
"请用子 Agent 研究一下 src/ 目录下所有使用了 deprecated API 的文件，
然后给我一份简短报告，不要在主会话中展开每个文件的内容"

# 方法2：使用并行 Agent 在 git worktree 中工作
# Claude 会自动在隔离的 worktree 中运行子 Agent
# 避免多个 Agent 同时修改同一文件产生冲突
```
