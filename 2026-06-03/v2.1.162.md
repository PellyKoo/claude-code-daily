## 1. 动态工作流（Dynamic Workflows）— 让 Claude 自动编排数百个并行 Agent
- **来源**: [Min Choi](https://x.com/minchoi/status/2060226858994565563) on X | [Greg Isenberg](https://x.com/gregisenberg/status/2060072130339873093) on X
- **摘要**: Claude Code 新增"动态工作流"功能。设置 `/model` 为 Opus 4.8，将 `/effort` 调为 "ultracode"，然后在提示词中包含 "workflow" 关键词，Claude 就会自动编写编排脚本、启动子 Agent 集群、交叉验证结果并汇总报告。适合将整个功能模块级别的工作一次性交给 Claude 完成。
- **代码示例**:
```
/model opus 4.8
/effort ultracode
> "Create a workflow to refactor the authentication module, add tests, and update docs"
```

## 2. Boris Cherny（Claude Code 创建者）的五终端并行工作流
- **来源**: [Boris Cherny](https://x.com/bcherny/status/2007179832300581177) on X | [Aakash Gupta](https://x.com/aakashgupta/status/2007347705945944153) on X
- **摘要**: Claude Code 的创建者 Boris 分享了他的日常工作流：同时开启 5 个终端标签页运行 Claude，每个在独立的 git checkout 中工作以避免冲突，再加上 5-10 个 Web/移动端实例。使用 Opus 4.5 并开启思考模式 — 虽然单次响应较慢，但因为需要更少的人工干预，整体效率反而更高。
- **代码示例**:
```bash
# 为每个 Claude 实例创建独立的 git worktree
git worktree add ../project-task1 -b task1
git worktree add ../project-task2 -b task2
git worktree add ../project-task3 -b task3
# 在每个 worktree 目录中启动 Claude Code
```

## 3. 两阶段工作法：先规划，再执行
- **来源**: [Boris Cherny](https://x.com/bcherny/status/2007179832300581177) on X | [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | 56.4k stars
- **摘要**: Boris 的核心工作方法 — 先进入 Plan 模式与 Claude 反复迭代方案直到满意，然后切换到自动接受编辑模式让 Claude 一次性执行整个方案。社区最佳实践仓库进一步建议：将工作拆分为跨全栈的垂直切片（DB→API→UI），避免水平分层导致的反馈延迟。
- **代码示例**:
```
# 第一阶段：Plan 模式
> /plan "Implement user authentication with OAuth2"
# 反复迭代方案...

# 第二阶段：执行模式（自动接受编辑）
> shift+tab  # 切换到自动接受模式
> "Execute the plan we just created"
```

## 4. 让 Claude 自我验证 — 质量提升 2-3 倍的秘诀
- **来源**: [Boris Cherny](https://x.com/bcherny/status/2007179832300581177) on X | [Josh](https://x.com/joshycodes/status/2008019582150426799) on X
- **摘要**: Boris 的头号技巧：给 Claude 提供自我验证的方式（测试、浏览器自动化、hooks），这一个做法就能让输出质量提升 2-3 倍。自我纠正循环是关键 — 让 Claude 写完代码后自动运行测试，失败了就自动修复，形成闭环。
- **代码示例**:
```json
// .claude/settings.json — PostToolUse hook 自动运行测试
{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Edit|Write",
      "command": "npm test -- --bail 2>&1 | tail -20"
    }]
  }
}
```

## 5. CLAUDE.md 控制在 200 行以内，用 rules/ 做延迟加载
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | 56.4k stars
- **摘要**: CLAUDE.md 文件过长会导致 Claude 忽略你的指令。社区最佳实践建议：主 CLAUDE.md 控制在 200 行以内，只放全局适用的规则；领域特定的知识用 `.claude/rules/*.md` 文件实现按需加载。关键规则用 `<important if="...">` 标签包裹防止被忽略。每一行都要问自己："删掉这行会不会导致 Claude 犯错？"
- **代码示例**:
```
# .claude/rules/testing.md — 仅在涉及测试时加载
---
description: "Testing patterns and conventions"
globs: ["**/*.test.ts", "**/*.spec.ts"]
---
- Use vitest for all tests
- Follow AAA pattern (Arrange, Act, Assert)
- Mock external services, never hit real APIs
```

## 6. 上下文管理：40% 是"变笨线"，保持在 30% 以下
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | 56.4k stars
- **摘要**: 社区经验总结：当上下文窗口使用达到约 40% 时，Claude 的表现会明显下降（"Dumb zone"）。有经验的用户会将上下文使用控制在 30% 以下。实操建议：任务中途用 `/compact` 加提示词压缩上下文；切换任务时用 `/clear` 清空；失败的尝试用 `/rewind` 回退而不是留在上下文中污染后续推理。
- **代码示例**:
```
# 任务中途压缩上下文
> /compact "Focus on the auth module refactor, discard UI discussion"

# 切换任务时清空
> /clear

# 回退失败的尝试
> /rewind
```

## 7. Hooks 自动化：用 PreToolUse 防护，PostToolUse 自动格式化
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | 5.9k stars
- **摘要**: Claude Code Showcase 仓库展示了完整的 hooks 自动化体系：PreToolUse 阻止危险操作（如在 main 分支上编辑），PostToolUse 在每次修改后自动运行测试/格式化/lint，UserPromptSubmit 自动添加上下文和推荐技能，Stop hook 决定 Agent 是否应该继续。退出码 2 表示阻止操作，0 表示放行。
- **代码示例**:
```json
{
  "hooks": {
    "PreToolUse": [{
      "matcher": "Edit|Write",
      "command": "git branch --show-current | grep -q '^main$' && echo 'BLOCKED: Do not edit on main' && exit 2 || exit 0"
    }],
    "PostToolUse": [{
      "matcher": "Edit|Write",
      "command": "prettier --write $CLAUDE_FILE_PATH && eslint --fix $CLAUDE_FILE_PATH"
    }]
  }
}
```

## 8. Skills + Agents + Commands 三层架构：构建可复用的 AI 工程体系
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | 5.9k stars | [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | 56.4k stars
- **摘要**: 社区总结的 Claude Code 高阶架构：Commands（斜杠命令）触发工作流，Agents（子代理）处理专业任务并拥有聚焦的上下文，Skills（技能）提供可复用的领域知识。每个 Skill 用独立的 SKILL.md 定义，通过 frontmatter 中的 `allowed-tools` 限制工具范围。真正的效率飞跃来自"构建一套可复用的 Skills 加上针对常见任务的专用 Agents"。
- **代码示例**:
```
# .claude/skills/react-patterns/SKILL.md
---
name: react-patterns
description: "React component patterns and conventions"
allowed-tools: ["Read", "Edit", "Write", "Glob", "Grep"]
---
- Use functional components with hooks
- Implement loading/error/empty states for all async components
- Use React.lazy for code splitting
```
