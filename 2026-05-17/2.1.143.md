## 1. /insights 自我诊断：让 Claude 教你用 Claude
- **来源**: [Santiago](https://x.com/svpino/status/2050925859465461915) on X | 🔥 高互动热门推文
- **摘要**: 最被低估的 Claude Code 技巧：用 Claude Code 来指导你如何更好地使用 Claude Code。运行 `/insights` 会生成一份使用模式报告（工具调用频率、时间分布等），然后在新会话中附上这份报告，让 Claude 分析你的使用习惯并给出改进建议。相当于给自己的开发工作流做一次"体检"。
- **代码示例**:
```bash
# 步骤 1：生成使用分析报告
> /insights

# 步骤 2：找到生成的报告文件
# 步骤 3：在新的 Claude 会话中
> 请分析这份报告，找出我使用 Claude Code 的低效模式，
> 并给出 5 个具体的改进建议。
# Claude 会针对你的实际使用数据给出个性化优化方案
```

## 2. Ctrl+G 编辑器模式：告别终端里写长提示词
- **来源**: [Santiago](https://x.com/svpino/status/2046568153124327461) on X | 🔥 高互动实用技巧
- **摘要**: 需要写复杂提示词时，按 `Ctrl+G` 会打开你的默认编辑器（vim、VS Code 等），在编辑器里写完后保存关闭，内容自动发送给 Claude Code。比在终端里写长文本体验好 100 倍——支持多行编辑、语法高亮、撤销重做。特别适合编写包含代码片段或多步骤指令的复杂提示词。
- **代码示例**:
```bash
# 在 Claude Code 终端中按 Ctrl+G
# 自动打开 $EDITOR（默认编辑器）

# 在编辑器中写复杂提示词：
# "请重构 src/auth/ 目录下的所有文件：
#  1. 将 session 管理从 cookie-based 迁移到 JWT
#  2. 添加 refresh token 轮换机制
#  3. 更新所有相关测试
#  4. 确保向后兼容现有 API"

# 保存并关闭编辑器 → 自动发送给 Claude
```

## 3. Claude Code 四层架构心智模型
- **来源**: [Python Developer](https://x.com/Python_Dv/status/2041437070221070376) on X | 🔥 热门架构解析
- **摘要**: Claude Code 不是一个终端聊天机器人，而是一个四层系统：① `CLAUDE.md` 是项目的持久记忆层；② `Skills` 是自动触发的知识包；③ `Hooks` 是事件驱动的自动化守卫；④ `Commands` 是可复用的工作流模板。理解这四层的关系，才能从"用 Claude 写代码"升级到"用 Claude 构建工程系统"。
- **代码示例**:
```
四层架构：

┌─────────────────────────────┐
│  Commands (/)               │ ← 用户触发的工作流
├─────────────────────────────┤
│  Skills                     │ ← 自动匹配的知识包
├─────────────────────────────┤
│  Hooks (Pre/Post)           │ ← 事件驱动的守卫
├─────────────────────────────┤
│  CLAUDE.md                  │ ← 持久记忆与项目规则
└─────────────────────────────┘

# 实践：为每一层配置对应内容
# CLAUDE.md → 项目规则、代码风格、架构约定
# Hooks → lint、format、安全检查
# Skills → 框架特定知识、API 文档
# Commands → /deploy、/review、/test 等工作流
```

## 4. 上下文窗口管理：40% 是性能悬崖
- **来源**: [claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 53.6K stars
- **摘要**: 社区大量实测发现：当上下文使用率超过 40% 时，Claude 的代码质量会明显下降；经验丰富的用户会将使用率控制在 30% 以下。关键策略：用 `/compact` 时附带具体提示（告诉它保留什么），而不是让它自动压缩；用 subagent 隔离中间产物，避免污染主上下文；对不同任务开新会话而非在同一会话中堆积。
- **代码示例**:
```bash
# ❌ 错误：无提示的自动压缩
> /compact

# ✅ 正确：带具体指示的压缩
> /compact 保留数据库 schema 设计决策和 API 接口定义，
>          压缩掉调试日志和中间尝试过程

# ✅ 用 subagent 隔离大量中间工作
> 启动一个子代理来分析 node_modules 的依赖树，
> 只把最终结论返回给我，不要把中间分析过程放在主上下文中

# ✅ 在上下文使用率接近 30% 时主动压缩
# 关注终端底部的上下文使用率指示器
```

## 5. /last 30 days 研究技能：一句话做完市场调研
- **来源**: [The Startup Ideas Podcast](https://x.com/startupideaspod/status/2036896888507818099) on X | 🔥 热门工作流分享
- **摘要**: 一个 Claude Code skill 替代了整个研究工作流。输入 `/last 30 days` 加任意主题，它会自动拉取过去 30 天内 Reddit 帖子、X 推文、网页搜索结果，并综合成一份专家级分析报告。实测案例：输入"highest performing landing pages"，几分钟内得到完整的市场分析和设计建议。
- **代码示例**:
```bash
# 使用 /last 30 days skill
> /last 30 days highest performing landing pages

# Claude 会自动：
# 1. 搜索 Reddit 近 30 天相关讨论
# 2. 拉取 X/Twitter 上的热门帖子
# 3. 搜索网页结果
# 4. 综合分析并生成报告

# 其他使用场景：
> /last 30 days React Server Components production issues
> /last 30 days startup monetization strategies SaaS
> /last 30 days Claude Code tips and tricks
```

## 6. Matt Van Horn 的 Claude Code 技巧全集（2026年3月版）
- **来源**: [Matt Van Horn](https://x.com/mvanhorn/status/2035857346602340637) on X | 🔥 高互动合集帖
- **摘要**: 开发者 Matt Van Horn 整理了他所知道的所有 Claude Code 技巧，涵盖：tmux 远程开发（解决弱网问题）、截图直接粘贴到 Claude Code（Cmd+Shift+4 截图 → Ctrl+V 粘贴）、用 `/ce:plan` 做错误修复规划、多 worktree 并行会话管理等。其中截图粘贴功能被社区认为是最被忽视的生产力提升点——错误截图、设计稿、Slack 对话都可以直接喂给 Claude。
- **代码示例**:
```bash
# 技巧 1：tmux 远程开发（解决弱网）
ssh mac-mini
tmux new -s claude
claude  # 在远程机器上运行，断网也不影响

# 技巧 2：截图直接粘贴
# Cmd+Shift+4 截图 → Ctrl+V 粘贴到 Claude Code
> 这个错误怎么修？[粘贴截图]

# 技巧 3：Plan 模式修 Bug
> /ce:plan 分析这个截图中的错误，给出修复方案

# 技巧 4：会话管理
> /rename auth-refactor    # 给当前会话命名
> /resume auth-refactor    # 之后恢复到这个会话
```

## 7. 渐进式 Skills 文件夹结构：知识包的正确组织方式
- **来源**: [claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 53.6K stars
- **摘要**: 社区验证的 Skills 最佳组织方式：将每个 skill 做成文件夹而非单文件，采用渐进式披露结构——主文件只包含触发描述和核心指令，`references/` 放参考文档，`scripts/` 放自动化脚本，`examples/` 放用例。关键洞察：skill 的描述应该写成"模型的触发条件"而非"功能摘要"，这样 Claude 才能在正确的时机自动激活它。
- **代码示例**:
```
.claude/skills/
└── deploy/
    ├── skill.md           # 核心指令 + 触发描述
    ├── references/
    │   ├── aws-config.md  # AWS 部署配置参考
    │   └── rollback.md    # 回滚流程文档
    ├── scripts/
    │   ├── pre-deploy.sh  # 部署前检查脚本
    │   └── health-check.sh
    └── examples/
        ├── staging.md     # staging 部署示例
        └── production.md  # 生产部署示例

# skill.md 中的描述（作为触发条件）：
# ❌ "这是一个部署技能"
# ✅ "当用户提到部署、发布、上线、CI/CD、
#     或需要将代码推送到 staging/production 环境时触发"
```
