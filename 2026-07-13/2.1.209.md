## 1. CLAUDE.md 80 行规则：少即是多
- **来源**: [abhishekray07/claude-md-templates](https://github.com/abhishekray07/claude-md-templates) on GitHub | ⭐ 287 stars, 35 forks
- **摘要**: Claude Code 的系统提示已包含约 50 条内置指令，前沿模型总共只能可靠遵循约 150-200 条指令。因此项目 CLAUDE.md 应控制在 80 行以内。如果 Claude 不加提示就能正确执行的事项，就应从 CLAUDE.md 中删除或转为 hook。关键技巧：每次 Claude 犯错后，让它"更新 CLAUDE.md 以避免再犯"——这样 CLAUDE.md 会自我进化为精准的纠错文档。
- **代码示例**:
```markdown
<!-- CLAUDE.md 分层策略 -->

# 全局 (~/.claude/CLAUDE.md)：跨项目个人偏好
# 项目 (.claude/CLAUDE.md)：团队约定，提交到 git
# 本地 (./CLAUDE.local.md)：个人覆盖，加入 .gitignore
# 规则 (.claude/rules/*.md)：带 YAML paths: 前缀的领域规则，按需懒加载

<!-- 示例：精简的项目 CLAUDE.md（<80行） -->
# MyApp
TypeScript + React 项目

## 必须遵守
- 所有新函数必须有对应测试
- 使用 Zod 做运行时验证
- API 响应统一用 Result<T, E> 类型

## 命令
- `pnpm test` - 测试
- `pnpm lint` - 检查
```

## 2. PostToolUse Hook：写完文件自动格式化
- **来源**: [Boris Cherny](https://x.com/bcherny/status/2007179832300581177) on X, 收录于 [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) | ⭐ 62.6k stars
- **摘要**: 在 `.claude/settings.json` 中配置 `PostToolUse` hook，每次 Claude 写入文件后自动运行格式化工具（Prettier、Black 等）。这能捕获 Claude 遗漏的最后 10% 格式问题，防止 CI 失败。Hook 完全绕过上下文窗口——`PreToolUse` hook 返回退出码 2 可以在 Claude 处理之前直接阻止工具调用。
- **代码示例**:
```json
// .claude/settings.json
{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Write|Edit",
      "command": "npx prettier --write $CLAUDE_FILE_PATH"
    }],
    "PreToolUse": [{
      "matcher": "Bash",
      "command": "echo $CLAUDE_TOOL_INPUT | grep -q 'rm -rf /' && exit 2 || exit 0"
    }]
  }
}
```

## 3. 子代理是"上下文防火墙"
- **来源**: [Thariq Shihipar](https://x.com/trq212/status/2061907538741006796) on X | 🔥 高互动热帖
- **摘要**: 当 Claude 调查问题时读取数百个文件，会迅速填满主上下文窗口。解决方案：用子代理（subagent）在独立的上下文窗口中执行探索，只将最终摘要返回主会话。子代理可嵌套最多五层，v2.1.198 起默认在后台运行。核心概念区分：agents（`.claude/agents/`）用于隔离并行工作，skills（`.claude/skills/`）用于领域知识，commands（`.claude/commands/`）用于每天重复的提示模板。
- **代码示例**:
```markdown
<!-- .claude/agents/investigate-bug.md -->
你是一个 Bug 调查专家。
1. 搜索相关代码文件
2. 分析调用链
3. 找到根因
4. 返回简洁报告（不超过 200 字）

<!-- 使用方式 -->
> 用 investigate-bug agent 调查为什么用户登录偶尔超时
```

## 4. 全用 Opus——反而更快
- **来源**: [Boris Cherny](https://x.com/bcherny/status/2007179832300581177) on X | 🔥 6.3k likes, 49k retweets
- **摘要**: Boris 的反直觉建议："所有任务都用 Opus + thinking，即使它比 Sonnet 更大更慢，但你需要更少的纠正和引导，工具调用也更准确，所以总时间几乎总是更短。"关键洞察——更大的模型减少了总会话时间，因为它需要更少的返工。对应到实际工作：一次 Opus 调用解决问题 vs 三次 Sonnet 调用+两次人工纠正。
- **代码示例**:
```bash
# 设置默认模型为 Opus
claude config set model claude-opus-4-8

# 启用 extended thinking（默认开启）
# 在会话中确认：
> /model
# 应显示 opus 系列模型

# 对比效果：
# Sonnet: 写代码 → 发现 bug → 修复 → 再发现 → 再修复 (5 轮)
# Opus:   写代码 → 一次通过 (1 轮，总耗时更短)
```

## 5. 权限白名单：别用 --dangerously-skip-permissions
- **来源**: [Boris Cherny](https://x.com/bcherny/status/2007179832300581177) on X, 收录于 [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) | ⭐ 62.6k stars
- **摘要**: 用 `/permissions` 命令逐个审批安全的 bash 命令，而不是使用危险的 `--dangerously-skip-permissions` 核选项。将审批结果存储在 `.claude/settings.json` 中，这样整个团队都能共享同一套安全的权限配置。既保持了开发效率，又不牺牲安全性。
- **代码示例**:
```json
// .claude/settings.json - 团队共享权限白名单
{
  "permissions": {
    "allow": [
      "Bash(npm test)",
      "Bash(npm run lint)",
      "Bash(npm run build)",
      "Bash(npx prettier --write:*)",
      "Bash(git status)",
      "Bash(git diff:*)",
      "Bash(git log:*)",
      "Bash(python -m pytest:*)"
    ]
  }
}
```

## 6. settings.json 有 125+ 个隐藏配置项
- **来源**: [mculp](https://gist.github.com/mculp/c082bd1e5a439410158974de90c89db7) on GitHub Gist | ⭐ 7 stars, 最后更新 2026-07-11
- **摘要**: 大多数开发者只用了 settings.json 的少数几个配置项，但完整参考文档记录了 125+ 个可用键。值得关注的冷门配置包括：`advisorModel`（辅助顾问模型，v2.1.90 引入）、`spinnerVerbs`（自定义加载动画文本）、`effortLevel`（`fast`/`balanced`/`thorough` 三档）、`alwaysThinkingEnabled`（默认开启扩展推理）。深度定制这些配置可以显著优化日常开发体验。
- **代码示例**:
```json
// settings.json 冷门但实用的配置
{
  "effortLevel": "thorough",
  "alwaysThinkingEnabled": true,
  "advisorModel": "claude-sonnet-5",
  "spinnerVerbs": ["思考中", "分析中", "编码中", "搜索中"],
  "theme": "dark"
}
```

## 7. 自定义 Slash Commands 优化每日工作流
- **来源**: [Boris Cherny](https://x.com/bcherny/status/2007179832300581177) on X + [Vaibhav Sisinty](https://x.com/VaibhavSisinty/status/2067234559721361699) on X | 🔥 高互动热帖
- **摘要**: 在 `.claude/commands/` 目录下为每天重复的工作流创建自定义 slash commands。Boris 每天使用 `/commit-push-pr`。大多数人不知道的内置命令：`/compact` 在会话变慢时主动压缩上下文；`/clear` 在不相关任务间重置；`/rewind` 回滚而非堆积修正（防止失败尝试污染上下文）。Commands 提交到 git，整个团队共享。
- **代码示例**:
```markdown
<!-- .claude/commands/daily-review.md -->
# 每日代码审查流程
1. 运行 `git diff main --stat` 查看改动概览
2. 对每个改动文件执行安全审查
3. 运行测试套件确认无回归
4. 生成中文审查报告到 .claude/reports/

<!-- .claude/commands/commit-push-pr.md -->
1. 运行 git diff --cached 检查暂存内容
2. 生成符合 Conventional Commits 的提交信息
3. 提交并推送到当前分支
4. 用 gh 创建 PR，自动填充描述
```

## 8. 技能审计法：批量清理无用 Skills
- **来源**: [Prajwal Tomar](https://x.com/PrajwalTomar_/status/2074787074641899896) on X | 🔥 高互动热帖
- **摘要**: 不要只是阅读 Claude Code 技巧文章——把整篇文章粘贴到 Claude Code 会话中，然后说："通读这篇文章，列出我当前安装的所有 skill，与文章中的列表对比。卸载任何重叠的、从未触发的、或属于多余抽象的 skill。"这种方法让 Claude 自动审计和精简你的配置，避免工具膨胀——过多的 skill 和插件会增加上下文复杂度，降低响应质量。
- **代码示例**:
```bash
# 在 Claude Code 会话中执行技能审计
> 列出我当前安装的所有 skills 和 plugins

> 读取这篇文章 [粘贴文章内容]，
  对比我的已安装列表，
  给出建议：保留/卸载/替换

# 审计完成后清理
claude skill uninstall redundant-skill-1
claude skill uninstall redundant-skill-2

# 定期审计（推荐每月一次）
```
