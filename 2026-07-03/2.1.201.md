## 1. 跨模型路由：按任务类型自动选择最佳 AI 模型
- **来源**: [musistudio/claude-code-router](https://github.com/musistudio/claude-code-router) on GitHub | ⭐ 34k stars
- **摘要**: 通过 claude-code-router 将 Claude Code 的 API 请求路由到不同的模型提供商（DeepSeek、Gemini、Ollama 等），实现按任务类型自动选择最优模型。例如简单代码补全用轻量模型降低成本，复杂架构决策用 Opus，日常编码用 Sonnet。保留 Claude Code 的编排层不变，只替换底层推理模型。
- **代码示例**:
```json
{
  "routes": [
    {"pattern": "simple completion", "model": "deepseek-coder", "provider": "ollama"},
    {"pattern": "architecture|design", "model": "claude-opus-4-8", "provider": "anthropic"},
    {"pattern": "default", "model": "claude-sonnet-5", "provider": "anthropic"}
  ]
}
```

## 2. 对抗式自我质疑：让 Claude 反驳自己的方案
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 62k stars
- **摘要**: 与其让 Claude 直接实现功能，不如先让它质疑自己的设计。使用"Grill me on these changes and don't merge until I pass your test"或"Prove this works by diffing main vs. branch"等对抗式提示词，迫使 Claude 进行更深层的验证。社区发现这种模式能显著减少"看起来对但实际有隐藏 bug"的情况。
- **代码示例**:
```bash
# 让 Claude 扮演严格的 reviewer 质疑自己的实现
> Grill me on these changes and don't merge until I pass your test

# 用 diff 证明改动是正确的
> Prove this works by diffing main vs. branch

# 对抗式测试生成
> Write tests that try to break this implementation.
  Focus on edge cases and race conditions.
```

## 3. GitHub Actions 自动化：Claude 作为持续集成成员
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 6k stars
- **摘要**: 配置 4 种定时 GitHub Actions 工作流，让 Claude Code 成为团队的自动化成员：PR 自动审查（每次 $0.05-$0.50）、每周代码质量扫描（$1-$5）、每月文档同步（$0.50-$2）、双周依赖审计（$0.20-$1）。每月总成本仅 $10-$50，相当于雇了一个不知疲倦的初级工程师。
- **代码示例**:
```yaml
# .github/workflows/claude-pr-review.yml
name: Claude PR Review
on: [pull_request]
jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: anthropics/claude-code-action@v1
        with:
          prompt: |
            Review this PR for bugs, security issues,
            and style violations. Be specific and actionable.
```

## 4. 用 settings.json 替代 CLAUDE.md 中的硬性规则
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 62k stars
- **摘要**: 社区发现将确定性行为写在 `.claude/settings.json` 中比写在 CLAUDE.md 中更可靠。例如 `attribution.commit: ""` 比自然语言指令"NEVER add Co-Authored-By"可靠得多。CLAUDE.md 是"建议"，settings.json 是"配置"。环境变量、权限白名单、模型选择等都应该在 settings.json 中定义。
- **代码示例**:
```json
{
  "permissions": {
    "allow": ["Bash(npm test)", "Bash(npx prettier:*)", "Bash(npx eslint:*)"],
    "deny": ["Bash(rm -rf:*)"]
  },
  "env": {
    "NODE_ENV": "development",
    "DEBUG": "app:*"
  }
}
```

## 5. Chrome CDP 浏览器集成：68 条命令驱动真实浏览器
- **来源**: [chrome-cdp-ex](https://github.com/user/chrome-cdp-ex) via [awesome-claude-code](https://github.com/hesreallyhim/awesome-claude-code) on GitHub | 🔥 awesome-claude-code 精选推荐
- **摘要**: 通过 Chrome DevTools Protocol 将 Claude Code 连接到你的真实 Chrome 浏览器，提供 68 条 MCP 命令。Claude 可以直接操作浏览器进行布局检测、CSS 追踪、会话录制，并导出为 Playwright 测试脚本。相比截图方式，CDP 集成让 Claude 获得了真正的"感知层"，能理解页面的结构而不仅仅是像素。
- **代码示例**:
```bash
# 在 .mcp.json 中配置 Chrome CDP 服务器
{
  "mcpServers": {
    "chrome-cdp": {
      "command": "npx",
      "args": ["chrome-cdp-mcp-server"],
      "env": {"CHROME_DEBUG_PORT": "9222"}
    }
  }
}

# Claude 就可以使用如下命令
> 打开 localhost:3000, 检查登录页面的布局问题,
  并导出为 Playwright 测试
```

## 6. 双重记忆架构：Git 追踪 + 本地自动记忆
- **来源**: [centminmod/my-claude-code-setup](https://github.com/centminmod/my-claude-code-setup) on GitHub | ⭐ 2.5k stars
- **摘要**: 构建"双重记忆"系统：一层是 Git 追踪的 CLAUDE.md（团队共享知识），另一层是机器本地的自动记忆（个人上下文）。Git 追踪层确保团队协作一致性，本地层保留个人偏好和会话历史。两层结合既防止了跨会话的上下文丢失，又不会把个人习惯强加给团队成员。
- **代码示例**:
```bash
# Git 追踪层（团队共享）
CLAUDE.md                    # 项目级记忆，所有人共享
.claude/rules/api-design.md  # 领域规则，按路径自动加载

# 本地层（个人偏好，不提交）
~/.claude/CLAUDE.md           # 用户级全局偏好
.claude/.local/CLAUDE.md      # 项目级个人偏好（加入 .gitignore）
```

## 7. Skill 自动评估系统：根据提示词智能推荐技能
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 6k stars
- **摘要**: 通过 `UserPromptSubmit` Hook 实现 Skill 的自动评估和推荐。系统分析用户输入的关键词、正则模式、文件路径和意图，自动计算每个 Skill 的匹配置信度。例如提示中包含"test"且正在编辑 `.test.ts` 文件时，自动激活"testing-patterns"技能。这让 Claude 从"你需要手动调用技能"进化为"技能找到你"。
- **代码示例**:
```json
{
  "hooks": {
    "UserPromptSubmit": [
      {
        "hooks": [
          {
            "type": "command",
            "command": "node .claude/scripts/evaluate-skills.js \"$PROMPT\""
          }
        ]
      }
    ]
  }
}
```
