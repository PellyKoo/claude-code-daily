## 1. Dynamic Workflows + Ultracode：并行 Agent 群自动互审
- **来源**: [Greg Isenberg (@gregisenberg)](https://x.com/gregisenberg/status/2060072130339873093) on X | 🔥 高互动热帖
- **延伸**: [Min Choi (@minchoi)](https://x.com/minchoi/status/2060226858994565563) on X
- **摘要**: Claude Code 的 Dynamic Workflows 功能允许你一次性启动数百个并行 Agent，它们会互相检查彼此的输出结果后再汇报给你。开启方法：将 `/model` 设为 opus 4.8，将 `/effort` 设为 "ultracode"，然后在 prompt 中使用 "workflow" 关键词。适用于大规模迁移、代码审计、框架替换等原本需要按 sprint 规划的任务。
- **代码示例**:
```bash
# 进入 Claude Code 后设置
/model opus 4.8
/effort ultracode

# 然后在 prompt 中使用 "workflow" 触发
"Create a workflow to audit all API endpoints for security vulnerabilities"

# Claude 会自动：
# 1. 编写编排脚本
# 2. 启动多个子 Agent 并行工作
# 3. Agent 之间互相验证结果
# 4. 汇总报告
```

## 2. 技能审计法：用 Claude 自动清理冗余 Skills
- **来源**: [Prajwal Tomar (@PrajwalTomar_)](https://x.com/PrajwalTomar_/status/2074787074641899896) on X | 🔥 高互动
- **摘要**: 不要手动管理越来越膨胀的 skills 列表。把任何一篇 Claude Code 最佳实践文章完整粘贴到会话中，让 Claude 自动对比你当前已安装的 skills，识别重叠、从未触发、或已过时的 skill，然后一键清理替换。这是"用 AI 管理 AI 工具链"的典型应用。
- **代码示例**:
```
# 将最佳实践文章粘贴到 Claude Code 会话后：

"Read this article end to end. Then:
1. List every skill I currently have installed
2. Compare against this article's recommendations
3. Uninstall anything that overlaps, never triggers, or is outdated
4. Install replacements where appropriate"

# Claude 会自动执行 skills 的增删操作
```

## 3. Git Worktree 并行开发：多实例 Claude 零冲突协作
- **来源**: [centminmod/my-claude-code-setup](https://github.com/centminmod/my-claude-code-setup) on GitHub | ⭐ 2.5k stars
- **摘要**: 通过 Git Worktree 隔离机制，在同一仓库上同时运行多个 Claude Code 实例而不产生文件冲突。每个 worktree 拥有独立的文件状态但共享 Git 历史。配合 shell 函数（`clx feature-name` 或 `cx` 自动命名），可以一个实例做 feature 开发、另一个做 bug 修复，互不干扰。
- **代码示例**:
```bash
# 使用内置的 worktree 标志启动隔离实例
claude --worktree  # 或 claude -w

# 或使用 shell 函数快速创建命名 worktree
clx auth-refactor   # 创建名为 auth-refactor 的隔离工作区
cx                   # 自动以时间戳命名

# .worktreeinclude 文件指定哪些 .gitignore 文件需要复制到新 worktree
# 例如 .env 文件，确保环境变量在所有实例中可用
echo ".env" >> .worktreeinclude
echo ".env.local" >> .worktreeinclude
```

## 4. 管道式错误诊断：一行命令让 Claude 解读日志
- **来源**: [luongnv89/claude-howto](https://github.com/luongnv89/claude-howto) on GitHub | ⭐ 40.7k stars
- **摘要**: 利用 Claude Code CLI 的管道（pipe）功能，直接将错误日志、命令输出等传入 Claude 进行分析，无需复制粘贴。结合 `-p` 非交互模式和 `--output-format json` 输出格式，可以将 Claude 无缝嵌入 shell 脚本和 CI/CD 流水线。
- **代码示例**:
```bash
# 直接管道错误日志
cat error.log | claude -p "explain this error and suggest a fix"

# 分析测试失败
npm test 2>&1 | claude -p "analyze these test failures, prioritize by severity"

# 嵌入 CI 脚本，JSON 格式输出便于解析
git diff main | claude -p --output-format json "review this diff for bugs"

# 组合使用：获取最近的崩溃日志并分析
journalctl -u myapp --since "1 hour ago" | claude -p "identify the root cause"
```

## 5. Safety Net 插件：防止 Claude 执行破坏性命令
- **来源**: [centminmod/my-claude-code-setup](https://github.com/centminmod/my-claude-code-setup) on GitHub | ⭐ 2.5k stars
- **摘要**: 社区报告过 Claude Code 在无人看管时删除用户目录的案例。Safety Net 插件通过拦截危险命令（`rm -rf`、`git push --force`、`git branch -D` 等）来防止破坏性操作。这是生产环境中使用 Claude Code 的必备安全层，尤其在 `dontAsk` 或 `auto` 权限模式下。
- **代码示例**:
```bash
# 安装 Safety Net 插件
claude "/install-plugin centminmod/claude-code-safety-net"

# 插件会自动拦截以下类型的命令：
# - rm -rf / rm -r（递归删除）
# - git push --force（强制推送）
# - git branch -D（强制删除分支）
# - git reset --hard（硬重置）
# - git clean -f（强制清理）

# 当 Claude 尝试执行危险命令时，插件会：
# 1. 阻止执行
# 2. 显示警告信息
# 3. 建议更安全的替代方案
```

## 6. 完整代码审查工作流：Slash Command + Subagent + MCP 联动
- **来源**: [luongnv89/claude-howto](https://github.com/luongnv89/claude-howto) on GitHub | ⭐ 40.7k stars
- **摘要**: 通过组合 Slash Command、Subagent 和 MCP 协议，构建端到端的代码审查流水线。一个 `/review-pr` 命令触发完整流程：加载项目记忆 → 通过 GitHub MCP 获取 PR → 分发给 code-reviewer 和 test-engineer 两个专业子 Agent → 合成最终审查报告。这比手动审查节省 80% 时间。
- **代码示例**:
```bash
# 在 .claude/commands/review-pr.md 中定义
# ---
# description: Full PR review pipeline
# ---
# Review PR #$1 using the complete pipeline:
# 1. Load project memory from CLAUDE.md
# 2. Fetch PR details via GitHub MCP
# 3. Delegate to code-reviewer subagent for quality review
# 4. Delegate to test-engineer subagent for test coverage analysis
# 5. Synthesize findings into a single review report

# 使用方式
/review-pr 42

# 流程自动执行：
# CLAUDE.md 加载 → GitHub MCP 获取 PR #42 → 
# code-reviewer Agent 审查代码质量 → 
# test-engineer Agent 分析测试覆盖 → 
# 合成审查报告并提交 review
```

## 7. 重视应用创新而非配置调优
- **来源**: [dax (@thdxr)](https://x.com/thdxr/status/2080760584572706906) on X | 🔥 高互动
- **摘要**: SST 创始人 dax 指出一个社区普遍存在的误区：大家过于关注"让工具更好用的各种技巧"（配置优化、prompt 模板、hooks 设置），但真正的价值在于发现"将工具应用于工作的全新方式"。与其花时间打磨 CLAUDE.md 到完美，不如思考 Claude Code 能否重新定义你的开发流程——比如用它做需求分析、用户访谈总结、竞品代码逆向分析等非典型编码任务。
- **代码示例**:
```
# ❌ 常见误区：花大量时间在配置优化上
# "让我再调整一下 CLAUDE.md..."
# "换个 prompt 模板试试..."
# "再加一个 hook..."

# ✅ 更高价值：发现全新的应用场景

# 用 Claude Code 做竞品分析
"Clone competitor's open source SDK. Analyze their auth flow,
rate limiting strategy, and error handling patterns.
Compare with our implementation and suggest improvements."

# 用 Claude Code 做技术文档翻译+本地化
"Read our English API docs, translate to Chinese,
but adapt the examples to use local payment providers
(WeChat Pay, Alipay) instead of Stripe."

# 用 Claude Code 做架构决策记录
"Review our last 50 commits. Identify architectural decisions
that were made implicitly. Write ADRs for each one."
```
