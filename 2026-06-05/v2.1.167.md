# Claude Code v2.1.167 社区实用技巧 - 2026-06-05

## 1. Dynamic Workflows：让 Claude 自动编排数百个并行代理
- **来源**: [Greg Isenberg](https://x.com/gregisenberg/status/2060072130339873093) on X | 🔥 高互动热帖
- **摘要**: Claude Code 新推出的 Dynamic Workflows 功能允许你输入"create a workflow"或在 effort 菜单中开启"ultracode"，系统会自动生成数百个并行代理并互相检查工作。这将可委托的工作单元从"单个文件"提升到"整个功能模块"。
- **代码示例**:
```
# 在 effort 菜单中选择 ultracode 模式，或直接输入：
> create a workflow to refactor the entire authentication system

# Claude 会自动：
# 1. 分析任务并创建编排计划
# 2. 启动多个并行代理分别处理子任务
# 3. 代理之间互相审查代码质量
```

## 2. Auto Mode：Claude Code 创造者的第一建议
- **来源**: [Boris Cherny](https://x.com/bcherny/status/2058519809214607704) on X | 🔥 Claude Code 创造者亲自推荐
- **摘要**: Boris（Claude Code 创造者）表示，他目前最推荐的技巧就是使用 Auto Mode。Auto Mode 消除了所有权限确认弹窗，是实现"多 Claude 并行开发"的关键基石——启动一个会话后，可以在它运行的同时开启另一个会话处理不同任务。
- **代码示例**:
```bash
# 启用 auto mode
claude config set autoApprove true

# 多 Claude 并行工作流：
# 终端1: claude "重构用户模块"
# 终端2: claude "修复支付接口bug"
# 终端3: claude "编写集成测试"
# 三个会话同时运行，互不干扰
```

## 3. 并行 Worktrees：同时运行 3-5 个 Claude 会话
- **来源**: [Shruti Mishra](https://x.com/heyshrutimishra/status/2018368588432978151) on X | 🔥 高互动讨论帖
- **摘要**: Boris 分享的10个高级技巧中，排名第一的是并行 worktrees——同时运行3-5个 Claude 会话，每个在独立的 git worktree 中工作。这是一种完全不同的工作方式，也是大多数人忽略的最大生产力提升技巧。
- **代码示例**:
```bash
# 创建多个 worktree 并行开发
git worktree add ../feature-auth feature/auth
git worktree add ../feature-payments feature/payments
git worktree add ../bugfix-login bugfix/login

# 在每个 worktree 中启动独立的 Claude 会话
cd ../feature-auth && claude
cd ../feature-payments && claude
cd ../bugfix-login && claude

# 完成后清理
git worktree remove ../feature-auth
```

## 4. 双模式工作流：初始化代理 + 编码代理
- **来源**: [HackerRank](https://x.com/hackerrank/status/2016398850265935929) on X | 🔥 高互动技术帖
- **摘要**: 长时间运行任务的7条规则中最关键的一条：将工作流分为两个模式。Initializer Agent 负责搭建基础（项目设置、功能清单、git 初始化、进度追踪），Coding Agent 负责实际开发。这种分离避免了上下文污染，确保长任务不会丢失进度。
- **代码示例**:
```markdown
# CLAUDE.md 中定义双模式

## Initializer Agent 职责
- 分析需求并创建 feature-list.md
- 初始化项目结构和配置
- 创建 PROGRESS.md 追踪文件
- 设置 git 分支策略

## Coding Agent 职责
- 读取 feature-list.md 逐项实现
- 每完成一个功能更新 PROGRESS.md
- 运行测试并提交代码
- 遇到阻塞时记录到 BLOCKERS.md
```

## 5. Workflows 最佳实践：非技术任务也能搞定
- **来源**: [Thariq](https://x.com/trq212/status/2061907538741006796) on X | 🔥 深度分析帖
- **摘要**: Workflows 是自 skills 和 subagents 以来 Claude Code 最大的能力升级。Thariq 深入研究后发现，Workflows 不仅适用于技术开发，还能处理非技术任务（如文档整理、项目管理、数据分析等），大幅扩展了 Claude Code 的应用场景。
- **代码示例**:
```
# 技术任务 workflow
> create a workflow to migrate the database from MySQL to PostgreSQL

# 非技术任务 workflow
> create a workflow to audit all API endpoints and generate documentation
> create a workflow to analyze our test coverage and suggest improvements
```

## 7. 50 条 Claude Code 实战技巧合集
- **来源**: [Miles Deutscher](https://x.com/milesdeutscher/status/2014027971254952332) on X | 🔥 高互动长文帖
- **摘要**: 用 Claude 开发一年后总结的50条实战技巧，涵盖 Claude Code 隐藏功能、提示词技巧、工作流优化等。以快速问答形式呈现，是目前社区最全面的技巧合集之一。关键要点包括：善用 `/init` 生成 CLAUDE.md、利用 ultrathink 提升复杂推理、以及通过 hooks 实现自动化质量检查。
- **代码示例**:
```bash
# 技巧精选：
# 1. 用 /init 自动生成项目级 CLAUDE.md
/init

# 2. 复杂任务使用 ultrathink 模式
> ultrathink: 分析这个分布式锁的竞态条件并提出修复方案

# .claude/settings.json
{
  "hooks": {
    "postEdit": "npx eslint --fix $FILE"
  }
}
```

## 8. CLAUDE.md 精简原则：每行都问"删了会出错吗？"
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 56.5k stars
- **摘要**: CLAUDE.md 没有固定格式要求，但必须保持简短、易读。对每一行都问自己："删掉这行会导致 Claude 犯错吗？"如果不会，就删掉它。臃肿的 CLAUDE.md 会导致 Claude 忽略你真正重要的指令——少即是多。
- **代码示例**:
```markdown
# 好的 CLAUDE.md - 简洁明确
运行测试: npm test
Lint: npm run lint
构建: npm run build
提交前必须通过所有测试

# 坏的 CLAUDE.md - 冗长废话
本项目是一个使用 React 和 TypeScript 构建的...
（Claude 可以自己从代码中推断这些信息）
```
