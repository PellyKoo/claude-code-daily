# Claude Code 2.1.126 社区实用技巧 - 2026-04-30

## 1. CLAUDE.md 最佳实践：控制在 200 行以内
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 50.1k stars
- **摘要**: CLAUDE.md 是 Claude Code 的持久记忆文件，每次会话自动加载。社区经验表明，单个 CLAUDE.md 应控制在 200 行以内以保证效果。对于 monorepo 项目，可使用多个 CLAUDE.md 文件（祖先+后代自动加载），并通过 `.claude/rules/*.md` 实现按路径自动加载领域特定指令。
- **代码示例**:
```
项目结构:
├── CLAUDE.md                    # 全局规则 (<200行)
├── .claude/
│   ├── rules/
│   │   ├── frontend.md          # 前端规则 (自动加载)
│   │   └── backend.md           # 后端规则 (自动加载)
│   └── settings.json
└── packages/
    └── api/
        └── CLAUDE.md            # 子项目规则
```

## 2. 上下文窗口管理：避免进入"笨区"
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 50.1k stars
- **摘要**: 社区发现上下文在 300-400k token 时会出现明显退化，约 40% 上下文使用率时就会进入"笨区"（dumb zone）。建议主动使用 `/compact` 并附带提示语来精确控制压缩内容，比自动压缩效果更好。新任务应开启新会话，相关任务可复用上下文。
- **代码示例**:
```bash
# 手动压缩并附带提示
/compact 保留所有关于数据库迁移的上下文，压缩其他内容

# 会话管理
/rename 重要会话名称    # 命名重要会话
/resume                 # 恢复之前的会话
```

## 3. 系统提示词瘦身：从 19k 缩减到 9k tokens
- **来源**: [ykdojo](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 8k stars
- **摘要**: 通过精简 Claude Code 的系统提示词，可以将开销从约 19k tokens 削减到约 9k tokens，节省近 50% 的上下文开销。这意味着更多的上下文窗口可以用于你的实际代码和对话，显著延长有效会话时长。
- **代码示例**:
```
优化前: ~19,000 tokens 系统提示词开销
优化后: ~9,000 tokens 系统提示词开销
节省:   ~10,000 tokens (~50%)
```

## 5. 用 Hooks 修复 Skills 自动触发不可靠的问题
- **来源**: [Aakash Gupta](https://x.com/aakashgupta/status/2040888715003019433) on X/Twitter | 🔥 高互动
- **摘要**: Claude Code 的 Skills 经常无法可靠地自动触发——即使你写了"当用户提到 slides 时使用"，也有一半的概率被忽略。解决方案是使用 Hooks（钩子脚本），它可以在特定事件（消息发送前、压缩后、响应返回时）精确触发，比 Skills 的语义匹配更可靠。
- **代码示例**:
```json
// .claude/settings.json
{
  "hooks": {
    "on_message_send": [
      {
        "match": "slides|presentation|deck",
        "command": "cat .claude/skills/slides/SKILL.md"
      }
    ]
  }
}
```

## 6. Claude Code 四层架构思维
- **来源**: [Python Developer](https://x.com/Python_Dv/status/2041437070221070376) on X/Twitter | 🔥 高互动
- **摘要**: Claude Code 不是简单的终端聊天机器人，而是一个四层系统：CLAUDE.md（持久记忆层）、Skills（知识包层，自动触发）、Hooks（事件脚本层）、Permissions（权限控制层）。理解这四层架构是高效使用 Claude Code 的关键。
- **代码示例**:
```
🧠 CLAUDE.md    → 项目持久记忆，每次会话自动加载
📦 Skills       → 领域知识包，按语义匹配自动调用
🔗 Hooks        → 事件驱动脚本，精确触发
🔒 Permissions  → 权限控制，安全边界
```

## 7. Subagent 隔离策略：保护主上下文
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 50.1k stars
- **摘要**: 使用子代理（Subagent）将中间工作与主上下文隔离，避免研究和探索性任务污染主会话的上下文窗口。推荐主会话使用 Opus 进行复杂推理，子代理使用 Sonnet 执行聚焦任务，兼顾质量和成本。Boris Cherny（Claude Code 创建者）建议"用 commands 而不是 sub-agents 来处理你的工作流"。
- **代码示例**:
```bash
# 主会话 (Opus) - 复杂架构决策
> 分析这个微服务的依赖关系并重构

# 子代理 (Sonnet) - 聚焦任务
> /research 查找所有使用 deprecated API 的文件
> /test 运行并分析测试覆盖率
```

## 8. Explore → Plan → Code 工作流
- **来源**: [Bilal Haidar](https://x.com/bhaidar/status/2015152391658611052) on X/Twitter | 🔥 高互动
- **摘要**: 社区推荐的三阶段工作流：先用 Explore 模式研究代码库，再用 Plan 模式让 Claude 制定完整方案（强制端到端思考，提前发现错误假设），最后再进入 Code 模式实现。配合 Rewind 检查点功能，可以无畏地进行实验。每个任务之间使用 Clear Session 清理上下文。
- **代码示例**:
```bash
# 阶段 1: 探索
> /explore 这个项目的认证系统是怎么实现的？

# 阶段 2: 计划
> /plan 将认证从 JWT 迁移到 OAuth2

# 阶段 3: 实现（带检查点）
> 按计划实现第一步
> /rewind    # 如果结果不满意，回退重来
```
