## 1. Skill 审计法：让 Claude 自动优化你的技能配置
- **来源**: [Prajwal Tomar](https://x.com/PrajwalTomar_/status/2074787074641899896) on X | 🔥 高互动热帖
- **摘要**: 将一篇 Claude Code 技巧文章整体粘贴到会话中，让 Claude 对比当前已安装的 skills 列表，自动卸载重叠/无效/劣质的 skill，并安装更优替代品。避免了"300 个 skill 争抢上下文"的常见问题——与其手动逐个比较，不如让 Claude 做一次系统性审计。
- **代码示例**:
```
# 将技巧文章粘贴后，输入以下提示：
> 读完这篇文章。然后列出我当前安装的所有 skill，
  逐一对比文章中的推荐列表。
  卸载任何重叠、从未触发、或有更好替代的 skill。
  安装推荐的替代品。

# Claude 会：
# 1. 运行 /skills list 获取当前配置
# 2. 对比文章推荐，识别冗余项
# 3. 卸载低效 skill，安装更优替代
# 4. 输出变更摘要
```

## 2. Workflows 最佳实践：从 Skill 到编排的升级路径
- **来源**: [Thariq](https://x.com/trq212/status/2061907538741006796) on X | 🔥 高互动热帖
- **摘要**: Workflows 是继 skills 和 subagents 后最大的能力跃升。核心发现：在提示中提到"workflow"即可触发动态编排计划，Claude 会严格按顺序执行每个阶段。特别值得关注的是非技术任务场景——市场调研、竞品分析、内容创作流水线等都可以用 workflow 编排，不再仅限于代码任务。
- **代码示例**:
```
# 非技术任务的 workflow 示例
> 创建一个 workflow：
  阶段1: 搜索竞品 X、Y、Z 的最新定价页面
  阶段2: 并行提取各家的功能对比矩阵
  阶段3: 汇总为一份中文对比报告，含推荐结论

# 技术任务的 workflow 最佳实践
> 创建一个 workflow：
  阶段1: 读取 src/ 下所有 API 路由文件
  阶段2: 为每个路由生成 OpenAPI spec
  阶段3: 合并为统一的 openapi.yaml
  阶段4: 验证 spec 合法性并修复错误
```

## 3. 并行 Worktrees：3-5 个 Claude 会话同时工作
- **来源**: [Shruti](https://x.com/heyshrutimishra/status/2018368588432978151) on X | 🔥 高互动热帖
- **摘要**: Boris（Claude Code 创始人）分享的 10 条进阶技巧中，并行 worktrees 被评为"最疯狂的生产力外挂"。方法：用 `git worktree` 创建 3-5 个独立工作目录，每个目录运行一个 Claude 会话，各自处理不同任务（前端/后端/测试/文档），互不干扰。等同于雇了一支小团队同时编码。
- **代码示例**:
```bash
# 创建多个 worktree，每个跑一个 Claude 会话
git worktree add ../project-auth feature/auth
git worktree add ../project-api feature/api
git worktree add ../project-tests feature/tests

# 在不同终端中分别启动 Claude
cd ../project-auth && claude "实现 OAuth2 登录流程"
cd ../project-api && claude "重构 REST API 为 GraphQL"
cd ../project-tests && claude "补全所有缺失的集成测试"

# 完成后合并
git worktree remove ../project-auth
git worktree remove ../project-api
git worktree remove ../project-tests
```

## 4. DX 插件：开发者体验工作流的瑞士军刀
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 高星标项目
- **摘要**: 40+ 技巧合集中最亮眼的是 dx 插件——一套开箱即用的开发者体验命令。`/dx:gha <url>` 自动分析 GitHub Actions 失败原因；`/dx:handoff` 生成上下文交接文档给下一个 agent；`/dx:review-claudemd` 从最近对话中提炼 CLAUDE.md 改进建议。另外附带的自定义状态栏脚本能实时显示 token 使用量、git 状态和模型信息。
- **代码示例**:
```bash
# 安装 dx 插件
claude plugin install dx@ykdojo

# 使用命令
/dx:gha https://github.com/org/repo/actions/runs/123  # 分析 CI 失败
/dx:handoff          # 生成交接文档，保持上下文连续性
/dx:clone            # 分支对话，探索替代方案
/dx:half-clone       # 只保留近期消息，减少上下文
/dx:review-claudemd  # 从对话中提炼 CLAUDE.md 改进

# 自定义状态栏（显示 token 进度条）
# 效果：██░░░░░░░░ 18% of 200k tokens | main +3 | claude-opus-4-6
ln -s ~/.claude/plugins/dx/scripts/context-bar.sh ~/.claude/scripts/
```

## 5. 上下文保鲜术：手动交接优于自动压缩
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 高星标项目
- **摘要**: 上下文"像牛奶一样——越新鲜越浓缩越好"。与其依赖自动 compaction（会丢失细节），不如在切换任务前手动创建交接文档，再开新会话加载。配合 `/branch` 命令分叉会话探索替代方案，避免在主线程浪费上下文。另外，为自主任务提供验证机制（tmux + Playwright），让 Claude 能独立运行 `git bisect` 等复杂操作。
- **代码示例**:
```bash
# 手动上下文交接流程
# 1. 在当前会话中生成交接文档
/dx:handoff
# 输出 → .claude/handoff/2026-07-11-auth-refactor.md

# 2. 开新会话，加载交接文档继续工作
claude --resume .claude/handoff/2026-07-11-auth-refactor.md

# 3. 用 /branch 探索替代方案（不污染主对话）
/branch "尝试用 Passport.js 替代自定义 auth 中间件"

# 4. 为自主任务提供验证环境
# CLAUDE.md 中添加：
## 自主验证
- 使用 tmux 运行交互式进程
- Playwright 验证 UI 变更
- `git bisect` 定位回归点
```

## 6. 小改动大收益：工作流微调清单
- **来源**: [Taylor Poindexter](https://x.com/engineering_bae/status/2074323810690478198) on X | 🔥 高互动热帖
- **摘要**: 一份经过验证的"微调清单"——每项改动都很小，但累积效果显著。核心思路：不需要大规模重构工作流，只需在关键点添加几行配置。包括：设置 `allowedTools` 白名单减少权限弹窗、用 `env` 字段注入环境变量避免硬编码、配置 `PostToolUse` hook 在每次文件修改后自动运行 linter。
- **代码示例**:
```json
// .claude/settings.json - 微调配置
{
  "permissions": {
    "allow": [
      "Bash(npm test:*)",
      "Bash(npx eslint *)",
      "Bash(git status)",
      "Bash(git diff *)",
      "Bash(git log *)"
    ]
  },
  "env": {
    "NODE_ENV": "development",
    "DEBUG": "app:*"
  },
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "command": "npx eslint --fix $CLAUDE_FILE_PATH 2>/dev/null || true"
      }
    ]
  }
}
```

## 7. 从 Vibe Coding 到 Agentic Engineering 的实践路径
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 高星标项目
- **摘要**: "Vibe coding"（随性编码）和"Agentic engineering"（代理工程）之间的差距，靠几个关键模式来弥合：精简的 CLAUDE.md、正确的权限模式、防错 hooks、重复任务的 skills、以及可预测的成本模型。核心建议：先把 CLAUDE.md 当作"团队新人的 onboarding 文档"来写，包含架构决策、命名约定、测试策略，然后逐步添加自动化层。
- **代码示例**:
```markdown
<!-- CLAUDE.md - "新人 onboarding" 结构 -->
# 项目概述
TypeScript monorepo，pnpm workspace

## 架构决策
- API: Express + Zod validation
- DB: Drizzle ORM + PostgreSQL
- 前端: Next.js App Router + Tailwind

## 命名约定
- 文件: kebab-case (user-profile.ts)
- 组件: PascalCase (UserProfile.tsx)
- 函数: camelCase, 动词开头 (getUserById)

## 测试策略
- 单元测试: vitest, 覆盖率 > 80%
- 集成测试: 真实数据库, testcontainers
- E2E: Playwright, 仅覆盖关键路径

## 常用命令
- `pnpm test` - 运行所有测试
- `pnpm typecheck` - 类型检查
- `pnpm lint:fix` - 修复 lint 错误
- `pnpm db:migrate` - 运行数据库迁移
```
