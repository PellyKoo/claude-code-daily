## 1. Claude Code 入门避坑：我希望第一天就知道的技巧
- **来源**: [Marmelab](https://marmelab.com/blog/2026/04/24/claude-code-tips-i-wish-id-had-from-day-one.html) on Blog | 🔥 社区热文
- **摘要**: 作者总结了初学 Claude Code 时踩过的坑。核心建议：不要在 CLAUDE.md 中用 `@docs/api-guide.md` 引用文档（会每次会话都把整个文件嵌入上下文），而应该描述"什么时候读这个文档"。用 Esc 键中断当前操作（保留会话上下文），而不是 Ctrl+C（会杀掉整个进程）。
- **代码示例**:
```markdown
<!-- CLAUDE.md 错误写法 -->
@docs/api-guide.md

<!-- CLAUDE.md 正确写法 -->
## API 参考
当需要调用支付相关 API 时，阅读 docs/api-guide.md 获取端点信息
```

## 2. 探索-规划-编码：三阶段工作流
- **来源**: [Medium - Data Science Collective](https://medium.com/data-science-collective/effective-claude-code-workflows-in-2026-what-changed-and-what-works-now-c93ebc6f8f50) on Medium | 🔥 高阅读量文章
- **摘要**: 2026 年社区公认的最有效工作模式——先探索代码库、再制定计划、最后编码。使用 `/plan` 命令让 Claude 在大型任务前生成结构化方案，避免直接动手导致的方向错误。作者强调"一个任务一个会话"比"所有工作塞一个长会话"效果更好。
- **代码示例**:
```
# 阶段 1：探索
> 阅读 src/auth/ 目录，了解当前认证流程的架构

# 阶段 2：规划
> /plan 重构认证模块，支持 OAuth2 和 SAML

# 阶段 3：编码
> 按照上面的计划，从第一步开始实现
```

## 3. CLAUDE.md 模板库：按技术栈快速配置
- **来源**: [abhishekray07/claude-md-templates](https://github.com/abhishekray07/claude-md-templates) on GitHub | ⭐ 模板仓库
- **摘要**: 提供 React、Python/FastAPI、Go、Rust 等常见技术栈的 CLAUDE.md 模板。每个模板都包含构建命令、测试命令、代码风格要求和项目特定约定。避免从零编写 CLAUDE.md，直接复制适合你项目的模板并微调即可。
- **代码示例**:
```markdown
<!-- React 项目 CLAUDE.md 模板示例 -->
## 构建与测试
- `npm run build` - 构建项目
- `npm test -- --watchAll=false` - 运行测试
- `npm run lint` - 检查代码规范

## 代码风格
- 使用函数式组件和 hooks
- 组件文件使用 PascalCase 命名
- 测试文件放在 __tests__/ 目录
```

## 4. Claude Code + Cursor 双工具协同工作流
- **来源**: [Kunal Ganglani](https://www.kunalganglani.com/blog/ai-coding-workflow-2026) on Blog | 🔥 实战经验分享
- **摘要**: 作者提出将 Claude Code 和 Cursor 结合使用的工作流：用 Claude Code 做架构设计、重构和复杂功能实现（擅长长链推理和跨文件修改），用 Cursor 做快速编辑、行内补全和小修改（擅长即时响应）。两者各有所长，不必二选一。
- **代码示例**:
```bash
# Claude Code 负责大任务
claude "重构整个 API 层，从 REST 迁移到 GraphQL"

# Cursor 负责快速调整
# 在编辑器内用 Cmd+K 做行内小修改
```

## 5. 记忆银行系统：为 Claude Code 建立持久上下文
- **来源**: [centminmod/my-claude-code-setup](https://github.com/centminmod/my-claude-code-setup) on GitHub | ⭐ 配置分享仓库
- **摘要**: 一套完整的 Claude Code 配置模板，核心是"记忆银行"系统——在 `.claude/memory/` 目录下维护项目决策记录、架构概述和进度追踪文件。Claude 在每次会话开始时读取这些文件，实现跨会话的上下文保持。解决了"每次新会话都要重新解释项目背景"的痛点。
- **代码示例**:
```
.claude/
├── memory/
│   ├── architecture.md    # 项目架构概述
│   ├── decisions.md       # 技术决策记录
│   ├── progress.md        # 当前开发进度
│   └── conventions.md     # 项目约定和偏好
```

## 7. .NET 开发者的 30 个高级技巧
- **来源**: [codewithmukesh](https://codewithmukesh.com/blog/claude-code-tips-advanced/) on Blog | 🔥 垂直领域深度指南
- **摘要**: 专为 .NET 开发者编写的 Claude Code 深度指南。核心观点：给 Claude 一种验证自身输出的方法是投资回报率最高的实践。在 CLAUDE.md 中配置 `dotnet build`、`dotnet test` 作为自动验证命令。用 headless 模式（`claude -p`）配合 `--allowedTools` 和 `--max-turns` 做批量代码审查，严格控制成本。
- **代码示例**:
```bash
# 批量审查多个文件，限制工具和轮次
claude -p "Review this file for security issues" \
  --allowedTools "Read,Grep,Glob" \
  --max-turns 5 \
  --output json \
  < src/Controllers/AuthController.cs
```

## 8. 12 个真实项目的 CLAUDE.md 实例分析
- **来源**: [AYAutomate](https://www.ayautomate.com/blog/best-claude-md-examples) on Blog | 🔥 案例分析文章
- **摘要**: 从 12 个真实开源项目中提取 CLAUDE.md 的最佳实践。关键发现：最有效的 CLAUDE.md 按任务分区（构建、测试、lint、提交），而不是按功能模块分区。Anthropic 官方仓库 `anthropics/claude-code` 的 CLAUDE.md 就是按开发者任务来组织的。建议保持简洁，每条规则都能回答"如果删掉这条，Claude 会犯错吗？"。
- **代码示例**:
```markdown
<!-- 按开发者任务分区的 CLAUDE.md -->
## 构建
npm run build

## 测试
npm test -- --watchAll=false
单个测试：npm test -- --testPathPattern=文件名

## Lint
npm run lint -- --fix

## 提交规范
使用 conventional commits：feat|fix|docs|refactor(scope): 描述
```
