## 1. 并行会话 + Git Worktree：同时推进多个任务
- **来源**: [Prajwal Tomar (@PrajwalTomar_)](https://x.com/PrajwalTomar_/article/2063238968125333581) on X | 🔥 高互动深度文章
- **摘要**: Prajwal Tomar 在"Claude Code is INSANE Once You Set It Up Right"长文中重点推荐了并行会话工作流。核心思路：用 `git worktree` 为每个 Claude Code 会话创建独立的工作目录，这样多个会话可以同时在不同分支上工作而互不干扰。建议从 2 个并行会话开始，熟练后再增加。配合 tmux 或多终端窗口管理，可以让一个会话写功能代码、另一个写测试、第三个做重构，效率成倍提升。关键提醒：每个 worktree 需要自己的 CLAUDE.md 上下文，否则 Claude 可能混淆不同分支的状态。
- **代码示例**:
```bash
# 创建 Git Worktree 用于并行 Claude Code 会话
git worktree add ../project-feature-auth feature/auth
git worktree add ../project-fix-perf fix/performance

# 在不同终端中启动 Claude Code
# 终端 1:
cd ../project-feature-auth && claude

# 终端 2:
cd ../project-fix-perf && claude

# 完成后清理 worktree
git worktree remove ../project-feature-auth
git worktree remove ../project-fix-perf

# 查看所有 worktree
git worktree list
```

## 2. Skill 管理：定期审计已安装 Skill，删除冗余项
- **来源**: [Prajwal Tomar (@PrajwalTomar_)](https://x.com/PrajwalTomar_/status/2074787074641899896) on X | 🔥 实用维护技巧
- **摘要**: Prajwal Tomar 分享了一个容易被忽视的 Claude Code 维护技巧：定期审计你安装的 Skills。随着使用时间增长，你可能积累了大量重叠、过时或从不触发的 Skill，它们会占用上下文窗口、拖慢响应速度，甚至与其他 Skill 产生冲突。建议的做法是：把一篇全面的最佳实践文章直接粘贴到 Claude Code 会话中，让 Claude 对比你当前安装的 Skill 列表，自动识别重叠项和"僵尸"Skill，然后一次性清理。
- **代码示例**:
```bash
# 在 Claude Code 会话中执行 Skill 审计

# 第一步：查看当前安装的所有 Skill
/skills

# 第二步：粘贴最佳实践文章后让 Claude 对比分析
# "读完这篇文章，然后列出我当前安装的所有 Skill，
#  与文章推荐的列表对比。卸载任何：
#  1. 与其他 Skill 功能重叠的
#  2. 从未被触发过的
#  3. 已经是内置功能的"

# 常见可清理的 Skill 类型：
# - 与内置代码审查功能重叠的第三方审查 Skill
# - 旧版本模型的 workaround Skill（新模型已不需要）
# - 安装后从未触发过的 path-scoped Skill
```

## 3. 上下文管理三件套：/clear、/compact、/context
- **来源**: [dravenip (@dravenip)](https://x.com/dravenip/article/2104402058963026288) on X | 🔥 完整指南高阅读量
- **摘要**: dravenip 在"THE COMPLETE CLAUDE CODE GUIDE"中详细讲解了上下文管理的最佳实践。三个核心命令：`/clear` 完全清空会话上下文，适合切换到完全不相关的任务；`/compact` 压缩当前上下文，保留关键信息但释放 token 空间，适合长会话中途"瘦身"；`/context` 查看当前上下文使用情况。核心原则：不同任务之间一定要清理上下文，否则前一个任务的代码片段会"污染"后续任务的理解。很多人抱怨 Claude Code "不听话"，根源往往是上下文过载而非模型问题。
- **代码示例**:
```bash
# 上下文管理工作流

# 查看当前上下文占用
/context

# 场景 1：长会话中途压缩（保留摘要）
/compact
# Claude 会保留关键决策和文件修改记录
# 释放大量 token 空间

# 场景 2：完全切换任务
/clear
# 清空所有上下文，从零开始
# 适合从"修 bug"切换到"写新功能"

# 最佳实践：
# 1. 每完成一个独立任务后 /compact 或 /clear
# 2. 感觉 Claude 回答质量下降时先 /context 检查
# 3. 超过 50% 上下文占用时考虑 /compact
# 4. 跨模块工作时用 /clear 避免上下文串扰
```

## 6. 50 条 Claude Code 日常最佳实践精选
- **来源**: [Vishwas (@CodevolutionWeb)](https://x.com/CodevolutionWeb/status/2034683638382506063) on X | 🔥 高转发实用合集
- **摘要**: Vishwas 整理了 50 条 Claude Code 日常使用的最佳实践，从中精选几条最具价值的社区共识：(1) 用 `claude -p "指令"` 实现非交互式批量操作，适合在 CI/CD 中集成；(2) 避免在一个提示词中塞入多个不相关任务，拆分成独立的会话效果更好；(3) 使用 `--output-format json` 让 Claude Code 输出结构化数据，方便管道处理；(4) 在 CLAUDE.md 中用"绝不"（Never）标记硬性约束，比"尽量避免"更有效；(5) 善用 `--allowedTools` 限制 Claude 可用的工具集，减少意外操作风险。
- **代码示例**:
```bash
# 精选最佳实践示例

# 1. 非交互式模式用于 CI/CD
claude -p "检查 src/ 下所有 TODO 注释，输出 JSON 列表" \
  --output-format json > todos.json

# 2. 限制工具集（安全场景）
claude --allowedTools Read,Grep,Glob \
  -p "分析这个项目的依赖结构"
# 只允许读取操作，禁止写入

# 3. CLAUDE.md 中的硬性约束写法
# ❌ "尽量避免直接修改数据库"
# ✅ "Never：绝不直接在生产数据库执行 DELETE 或 DROP"
# ❌ "建议使用 TypeScript"
# ✅ "所有新文件必须使用 TypeScript，不接受 .js 文件"

# 4. 单任务单会话原则
# ❌ "修复登录 bug，然后重构 API，最后写文档"
# ✅ 会话 1: "修复登录页面的认证 bug"
# ✅ 会话 2: "重构 /api/users 端点"
# ✅ 会话 3: "为认证模块写 API 文档"
```

## 7. Hooks 实战：自动格式化 + 阻止危险命令
- **来源**: [mvanhorn (@mvanhorn)](https://x.com/mvanhorn/article/2035857346602340637) on X | 🔥 March 2026 高阅读量文章
- **摘要**: mvanhorn 在早期的"Every Claude Code Hack I Know"文章中详细讲解了 Hooks 的实战用法。Hooks 是 Claude Code 中被严重低估的功能——它们在工具执行前后自动运行 shell 命令，可以实现很多"CLAUDE.md 无法保证"的行为。两个最实用的场景：(1) PostToolUse Hook 在每次文件编辑后自动运行 formatter（如 prettier、black），确保代码风格一致；(2) PreToolUse Hook 在 Bash 命令执行前检查危险操作（如 `rm -rf`、`git push --force`），拦截潜在的破坏性命令。Hook 比 CLAUDE.md 中的文字指令可靠得多，因为它是强制执行的。
- **代码示例**:
```json
// .claude/settings.json - Hooks 配置示例
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "command": "prettier --write $CLAUDE_FILE_PATH 2>/dev/null || true"
      },
      {
        "matcher": "Edit|Write",
        "command": "if echo $CLAUDE_FILE_PATH | grep -q '\\.py$'; then black $CLAUDE_FILE_PATH 2>/dev/null || true; fi"
      }
    ],
    "PreToolUse": [
      {
        "matcher": "Bash",
        "command": "if echo \"$CLAUDE_TOOL_INPUT\" | grep -qE 'rm -rf /|git push.*--force.*main|drop table'; then echo 'BLOCKED: 危险命令被拦截' >&2; exit 1; fi"
      }
    ]
  }
}
```
