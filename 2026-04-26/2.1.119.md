## 1. 自定义状态栏：实时监控上下文使用率
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 8k stars
- **摘要**: 在 Claude Code 底部显示实时状态栏，包含上下文使用百分比、Git 分支名、未提交文件数和 token 消耗进度条。社区提供了 10 种配色主题的 bash 脚本，让你无需频繁执行 `/context` 就能掌握会话状态。当上下文接近阈值时一目了然，及时启动新会话避免进入"迟钝区"。
- **代码示例**:
```bash
# 在 settings.json 中启用自定义状态栏
# 状态栏显示：[上下文 23%] [main ±3] [tokens: ████░░░░]

# 安装 ykdojo 的状态栏脚本
git clone https://github.com/ykdojo/claude-code-tips
cd claude-code-tips
./setup.sh  # 一键配置，含 10 种配色方案

# 手动配置方式：在 .claude/settings.json 中添加
{
  "statusLine": "bash /path/to/status-line.sh"
}
```

## 2. 系统提示词瘦身：从 19K 压缩到 9K tokens
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 8k stars
- **摘要**: Claude Code 默认系统提示词占用约 19K tokens，社区发现可以通过补丁 CLI 包将其缩减至约 9K tokens，释放近 50% 的系统开销给实际工作。对于长对话场景尤其关键——每轮都节省的 10K tokens 累积下来意味着更长的有效上下文窗口。需要禁用自动更新以保持补丁不被覆盖。
- **代码示例**:
```json
// settings.json - 禁用自动更新以保留补丁
{
  "env": {
    "DISABLE_AUTOUPDATER": "1"
  }
}
```
```bash
# 同时启用 MCP 工具懒加载，减少每次会话的初始 token 开销
# 按需加载工具而非全部预加载
{
  "env": {
    "ENABLE_TOOL_SEARCH": "true"
  }
}
```

## 3. 上下文腐化阈值：保持在 30% 以下
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 48.6k stars
- **摘要**: 社区通过大量实践确定了"上下文腐化"的具体阈值：在 1M context 的模型上，300-400K tokens 时智能水平开始下降；激进的开发者将使用率控制在 30% 以下。当上下文变"脏"时，用 `/rewind` 回退比留着失败尝试更好——双击 Esc 清理上下文碎片比试图纠正更高效。每一轮对话都是分支点：继续、`/rewind`、`/clear`、`/compact` 还是生成子代理，需要根据当前状态决策。
- **代码示例**:
```bash
# 上下文管理决策树

# 状态良好 → 继续对话
# 偏离方向 → /rewind 回到正确节点
# 上下文臃肿 → /compact 压缩摘要
# 上下文 >30% → /clear 开新会话
# 需要探索 → 生成子代理（subagent）保护主上下文

# /rewind 比纠正更好的原因：
# 失败的尝试留在上下文中会"污染"后续推理
# /rewind 干净地回到分叉点，重新出发
```

## 4. Git Worktrees + tmux：并行开发多个功能
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 8k stars & [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 48.6k stars
- **摘要**: 用 Git worktrees 为每个功能分支创建独立的工作目录，配合 tmux 在多个窗口同时运行 Claude Code。每个会话在隔离环境中工作，互不干扰。主分支始终保持干净，功能开发并行推进。这比传统的 `git stash` + `git checkout` 工作流高效得多，尤其适合同时处理多个 PR review 或功能开发。
- **代码示例**:
```bash
# 为新功能创建独立 worktree
git worktree add ../feature-auth feature/auth
git worktree add ../feature-search feature/search

# 使用 tmux 并行开发
tmux new-session -s auth -c ../feature-auth
# 在 auth 窗口中启动 Claude Code
claude

# 新建 tmux 窗口处理另一个功能
tmux new-window -t auth -c ../feature-search
claude

# 主仓库目录始终保持在 main 分支
# 完成后清理 worktree
git worktree remove ../feature-auth
```

## 5. 子代理隔离模式：20 次文件读取只返回一份报告
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 48.6k stars
- **摘要**: 多代理架构的核心价值不只是并行——更重要的是上下文隔离。一个子代理执行 20 次文件读取、12 次 grep 搜索、3 次失败尝试，这些操作全部留在子代理的上下文中，只有最终结论返回主会话。同一模型在独立上下文中互相审查会产生更好的结果（test-time compute 效应）。用功能专用子代理替代通用人设，每个子代理只处理特定领域。
- **代码示例**:
```bash
# 主会话保持干净，子代理做脏活

# 场景：重构一个复杂模块
# 主会话中：
> 生成一个子代理来分析 src/legacy/ 目录的依赖关系，
  找出所有循环依赖和未使用的导出，
  输出一份重构建议报告

# 子代理内部（用户不可见）：
# - 读取 20+ 个文件
# - 执行多次 grep 搜索
# - 构建依赖图
# - 发现 3 个循环依赖
# - 返回精炼报告给主会话

# 主会话只收到：一份干净的重构建议
# 上下文消耗：极小（只有报告的 token）
```

## 6. Command → Agent → Skill 三层编排模式
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 48.6k stars
- **摘要**: 社区总结的工作流编排三层模型：Command（命令）向现有上下文注入知识，是简单模板；Agent（代理）在独立上下文中自主运行，拥有自定义工具和记忆；Skill（技能）提供渐进式披露，可预加载且自动发现。根据任务复杂度选择合适层级——简单查询用 Command，独立任务用 Agent，可复用知识用 Skill。避免所有东西都塞进 CLAUDE.md。
- **代码示例**:
```bash
# Command：注入知识到当前上下文（简单）
# .claude/commands/check-types.md
# 模板内容，直接在当前会话执行

# Agent：独立上下文自主运行（中等）
# 自动 fork 新上下文，不污染主会话
> 生成一个代理审查 PR #42 的安全问题

# Skill：按需加载的领域知识（高级）
# .claude/skills/api-design.md
# Claude 根据语义匹配自动决定何时加载
# trigger-rich 描述让匹配更精准

# 选择原则：
# 一次性操作 → Command
# 需要自主探索 → Agent
# 跨会话复用 → Skill
```

## 7. 语音输入替代打字：用 Whisper 本地转录驱动 Claude
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 8k stars
- **摘要**: 社区发现语音输入比打字更高效地与 Claude Code 交互。使用本地转录工具（Whisper、MacWhisper、SuperWhisper）将语音实时转为文本，直接输入 Claude Code。关键发现：Claude 能智能处理转录中的错字和语法问题，不影响理解。对于需要描述复杂需求或长指令的场景，语音输入速度远超键盘，且能更自然地表达设计意图。
- **代码示例**:
```bash
# 推荐的语音输入工具
# MacWhisper  - macOS 本地转录，无需联网
# SuperWhisper - 全局快捷键，任何应用中激活
# Whisper.cpp  - 开源方案，Linux/Windows 通用

# 典型工作流：
# 1. 按快捷键激活语音输入
# 2. 口述需求："重构这个函数，把回调改成 async await，
#    错误处理用 try catch 包裹，
#    并且加一个重试逻辑，最多重试三次，
#    每次间隔指数递增"
# 3. 转录文本自动输入 Claude Code
# 4. Claude 完美理解并执行

# 即使转录有小错误，Claude 也能正确理解意图
```

## 8. 容器化沙箱：在 Docker 中无限制运行 Claude Code
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 8k stars
- **摘要**: 对于需要无人值守运行的场景（批量代码分析、大规模重构、实验性操作），社区推荐在 Docker 容器中使用 `--dangerously-skip-permissions` 标志运行 Claude Code。容器提供天然的隔离层，即使 Claude 执行了危险操作也不会影响宿主机。适用于系统提示词实验、多模型编排、自动化研究等场景。务必只在容器内使用此标志，永远不要在主机上直接使用。
- **代码示例**:
```dockerfile
# Dockerfile - Claude Code 沙箱环境
FROM node:20-slim

RUN npm install -g @anthropic-ai/claude-code
WORKDIR /workspace

# 挂载项目代码（只读）和输出目录
# docker run -v $(pwd):/workspace:ro \
#            -v ./output:/output \
#            claude-sandbox

# 容器内启动（仅限容器环境！）
# claude --dangerously-skip-permissions \
#   "分析 /workspace 中的所有 TypeScript 文件，
#    找出潜在的内存泄漏，报告写入 /output/report.md"
```
```bash
# 安全使用原则：
# ✅ Docker 容器内 + --dangerously-skip-permissions
# ✅ 项目目录只读挂载
# ✅ 输出目录独立挂载
# ❌ 永远不要在宿主机上使用 --dangerously-skip-permissions
```
