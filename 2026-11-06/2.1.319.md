## 1. Boris Cherny 最新建议：Auto Mode 优于手动 Plan Mode
- **来源**: [XDA Developers](https://www.xda-developers.com/rebuilt-my-claude-code-workflow-around-its-creators-advice/) | 🔥 热门技术文章
- **摘要**: Claude Code 创始人 Boris Cherny 近期改变了他自己的工作流建议——现在他更推荐直接使用 Auto Mode 而非手动切换 Plan Mode。原因是 Auto Mode 下 Claude 会自动判断何时需要规划、何时直接执行，减少了人工干预。对于大多数任务，让 Claude 自行决定比显式切换模式效率更高。
- **代码示例**:
```
# 直接在 Auto Mode 下给出完整需求，Claude 自动规划+执行
重构用户认证模块：将 session-based 认证迁移到 JWT，
确保所有现有测试通过，新增 token 刷新的单元测试
```

## 2. 把错误记录到 CLAUDE.md 防止重蹈覆辙
- **来源**: [XDA Developers](https://www.xda-developers.com/rebuilt-my-claude-code-workflow-around-its-creators-advice/) | 🔥 Boris Cherny 亲述
- **摘要**: 当 Claude 犯了一个错误（比如用了错误的 API 写法、生成了过时的语法），不要只是纠正它——把这个错误和正确做法记录在 CLAUDE.md 中。这样在后续会话中 Claude 不会再犯同样的错误。这是创始人自己推荐的"持续改进"工作流。
- **代码示例**:
```markdown
<!-- CLAUDE.md 中的错误记录段 -->
## 已知陷阱
- 不要使用 `fs.exists()`，已废弃。用 `fs.access()` 或 `fs.stat()` 代替
- Prisma 查询中 `findUnique` 不支持 `orderBy`，需要改用 `findFirst`
- 本项目的 React 版本不支持 `useOptimistic`，用 `useState` + 手动乐观更新
```

## 3. Esc 双击回退：比 Ctrl+Z 更强的时间机器
- **来源**: [agentsroom.dev](https://agentsroom.dev/claude-code-tips) | 🔥 50 Tips 合集（高星收藏）
- **摘要**: 连续按两次 Esc 键可打开 /rewind 检查点菜单，选择回退到之前的任意节点。与普通的撤销不同，这会同时回退代码文件变更和对话上下文，让你回到一个"干净"的状态重新尝试不同方案。当 Claude 走错方向时，这比在错误基础上追加修正更有效。
- **代码示例**:
```bash
# 在 Claude Code 会话中：
# 1. 按 Esc Esc 打开 rewind 菜单
# 2. 选择要回退到的检查点
# 3. 可选择只回退对话 / 只回退代码 / 两者都回退
# 等同于命令：/rewind
```

## 4. 验证前置：让 Claude 先写测试再改代码
- **来源**: [Builder.io](https://www.builder.io/blog/claude-code-tips-best-practices) | 🔥 知名开发者博客（高分享量）
- **摘要**: 在第一条提示中就包含验证步骤——先写一个会失败的测试来复现 bug，或提供一个截图作为目标。这样 Claude 可以自己编辑、运行、读取失败信息、再次尝试，形成自动化的 TDD 循环，而不是改完代码等你手动检查。
- **代码示例**:
```
# 好的提示方式：内置验证步骤
修复用户注册时邮箱验证失败的 bug。
步骤：
1. 先写一个测试复现这个 bug（注册含 + 号的邮箱应该成功）
2. 运行测试确认失败
3. 修复代码
4. 再次运行测试确认通过
```

## 5. Shell 管道集成：用 `claude -p` 打通命令行工作流
- **来源**: [Coding Beauty](https://codingbeautydev.com/blog/claude-code-tricks-faster-workflow/) | 🔥 热门开发者博客
- **摘要**: `claude -p` 让 Claude Code 可以直接嵌入 shell 管道中，接收 stdin 输入并输出结果到 stdout。这使得 Claude 可以像 `grep`、`sed` 一样融入你的命令行工作流，自动化处理日志分析、代码转换等任务。在会话内部，用 `!` 前缀可以直接执行 shell 命令而不退出。
- **代码示例**:
```bash
# 分析错误日志
cat error.log | claude -p "总结这些错误的模式和根因"

# 批量转换代码风格
cat legacy.js | claude -p "将 CommonJS require 改为 ES module import" > modern.js

# 在 Claude 会话中直接跑 shell 命令
# 输入 !npm test 即可运行，无需退出会话
```

## 7. 自动化循环：让 Claude 在后台持续工作
- **来源**: [XDA Developers](https://www.xda-developers.com/rebuilt-my-claude-code-workflow-around-its-creators-advice/) | 🔥 Boris Cherny 最新推荐
- **摘要**: Boris Cherny 推荐使用自动化循环和 routines 来让 Claude 在后台持续执行任务。比如设置一个循环让 Claude 每隔几分钟检查 CI 状态、自动修复失败的测试、或监控 PR 评论并自动回复。这把 Claude 从"问答工具"升级为"持续工作的自动化代理"。
- **代码示例**:
```bash
# 使用 /loop 让 Claude 持续监控和修复
/loop 5m 检查 CI 状态，如果有失败的测试就自动修复并推送

# 或配置 routine 定时执行
# Claude Code 会在条件满足时自动触发代理工作
```

## 8. 分层 Rules 目录：按模块精细化管理编码规范
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 高星最佳实践仓库
- **摘要**: 不要把所有规则堆在一个 CLAUDE.md 里。使用 `.claude/rules/` 目录创建按路径匹配的规则文件，只在触及相关文件时才加载对应规则。这样既减少了每次会话的上下文消耗，又能对不同模块（前端、后端、测试）实施不同的编码标准。
- **代码示例**:
```
.claude/rules/
├── frontend.md          # 匹配 src/components/** 的前端规则
├── api.md               # 匹配 src/api/** 的后端规则
├── testing.md           # 匹配 **/*.test.* 的测试规则
└── database.md          # 匹配 prisma/** 的数据库规则
```
```markdown
<!-- .claude/rules/frontend.md -->
---
globs: ["src/components/**", "src/pages/**"]
---
组件使用函数式写法，不使用 class 组件
样式使用 Tailwind CSS，不使用内联 style
所有 props 必须定义 TypeScript 类型
```
