## 3. CLAUDE.md 黄金法则：先描述方案再动手写代码
- **来源**: [Santiago (@svpino)](https://x.com/svpino/status/2018682144361734368) on X | 🔥 高赞实战建议
- **摘要**: Santiago 分享了几条写进 CLAUDE.md 就能立竿见影的规则。最重要的一条："Before writing any code, describe your approach and wait for approval"——让 Claude 先描述方案、等你确认后再动手。第二条：需求模糊时必须先问澄清问题。第三条：如果任务需要多文件修改，先列出所有要改的文件和预期变更。这三条规则能大幅减少 Claude "写了一堆但方向错了"的浪费。
- **代码示例**:
```markdown
# CLAUDE.md 中添加以下规则：

## 工作流程
- Before writing any code, describe your approach and wait for approval.
- Always ask clarifying questions before writing any code if requirements are ambiguous.
- If a task requires changes to multiple files, list all files and expected changes first.
- After completing a task, summarize what was changed and why.
```

## 4. 自动化发布循环：Claude Code + CodeRabbit 的 PR 工作流
- **来源**: [Ankur (@TheAnkurTyagi)](https://x.com/TheAnkurTyagi/status/2017848734772514836) on X | 🔥 热门工作流
- **摘要**: Ankur 提出了一个极简但高效的 2026 年开发工作流：Claude Code 写代码并提交 PR → CodeRabbit 自动审查 → Claude Code 修复审查意见 → 循环直到 PR 绿灯可合并。核心观点是"代码本身是廉价的，架构和审查才是真正值钱的"。通过将 AI 审查器接入 PR 流程，形成自动化的质量把关闭环，把人的精力集中在架构决策上。
- **代码示例**:
```bash
# 自动化 PR 工作流
# 1. Claude Code 写代码并创建 PR
> "实现用户认证模块，完成后创建 PR"

# 2. CodeRabbit（或其他 AI 审查器）自动审查 PR
#    → 自动在 PR 上留下审查意见

# 3. Claude Code 订阅 PR 并自动修复
> "watch PR #42, fix review comments"

# 4. 循环直到审查通过
# 人只需要在最终合并前确认架构决策
```

## 5. 从创作者视角深度解读 Claude Code 的正确用法
- **来源**: [cyrilXBT (@cyrilXBT)](https://x.com/cyrilXBT/article/2085535666713104677) on X | 🔥 热门深度文章
- **摘要**: cyrilXBT 基于对 Claude Code 创作工程师访谈的内容，梳理了"从创造者本人那里学到的"使用方法。文章强调几个被忽视的要点：不要把 Claude Code 当简单的代码补全工具，而是当成需要"良好指令"的初级工程师；给出足够上下文但不要过载；善用 `@filename` 精确引用文件而非让 Claude 自己搜索；以及在 CLAUDE.md 中明确"不要做"的事情比"要做"的事情更重要。
- **代码示例**:
```markdown
# CLAUDE.md 反模式 vs 正确做法

# ❌ 模糊的规则
# "写好的代码"

# ✅ 精确的边界
# ## 禁止事项
# - 不要修改 generated/ 目录下的任何文件
# - 不要删除已有的测试用例
# - 不要在没有 @filename 引用的情况下猜测文件内容
# - 不要添加新的 npm 依赖，除非我明确同意

# ✅ 精确的引用
> "@src/auth/handler.ts 这个文件的第 42 行有个 bug，token 过期逻辑不对"
```

## 7. Awesome CLAUDE.md：社区精选的 CLAUDE.md 模板库
- **来源**: [TakatoPhy](https://github.com/TakatoPhy/awesome-claude-md) on GitHub | ⭐ 精选模板合集
- **摘要**: 一个专门收集 CLAUDE.md 最佳实践和模板的社区仓库。亮点是按场景分类的具体示例：如何写好 commit message 的规则（包含正反对比）、如何限定代码风格、如何定义 "don't do" 边界、以及如何用具体示例取代抽象规则。每个模板都附有真实项目的使用场景说明，不是泛泛而谈的建议。
- **代码示例**:
```markdown
# CLAUDE.md 模板片段 - Commit Message 规则

## Git Commit 规范
Good: "fix: resolve token expiration race condition in auth middleware"
Bad: "fixed stuff" / "update code" / "WIP"

格式: <type>(<scope>): <description>
type: feat|fix|refactor|test|docs|chore
scope: 可选，受影响的模块名
description: 用现在时态，说明 WHY 而非 WHAT
```

## 8. Claude Code 零基础入门完整指南（2026 终端新手版）

cd my-project
claude

# 3. 或者用远程模式（无需本地终端）
claude remote-control
# 然后在 claude.ai/code 或手机 app 上连接

# 4. 第一个命令
> "帮我分析这个项目结构，告诉我每个目录的作用"
