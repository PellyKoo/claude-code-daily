## 1. 两阶段代理模式：Initializer + Coding Agent 分工协作
- **来源**: [HackerRank](https://x.com/hackerrank/status/2016398850265935929) on X | 🔥 高互动
- **摘要**: 针对长时间运行任务，社区推荐将工作流拆分为两个阶段：Initializer Agent 负责项目搭建、功能清单、Git 初始化和进度追踪；Coding Agent 负责读取计划、编码、测试和提交。用 JSON 功能清单替代 Markdown，每个功能带 `"passes": false` 字段，因为 LLM 对结构化数据的执行比 Markdown 更精确。
- **代码示例**:
```json
// features.json - 结构化功能清单
{
  "features": [
    {
      "name": "用户认证模块",
      "description": "JWT + refresh token 双令牌认证",
      "passes": false,
      "test_file": "tests/auth.test.ts"
    },
    {
      "name": "API 速率限制",
      "description": "滑动窗口限流，每用户 100 次/分钟",
      "passes": false,
      "test_file": "tests/rate-limit.test.ts"
    }
  ]
}
// Coding Agent 完成一项后将 passes 设为 true
// 确保每个功能都有对应测试文件验证
```

## 2. 上下文保鲜法则：AI 上下文如牛奶，越新鲜越好
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 8k stars
- **摘要**: 社区广泛认同的经验法则："AI context is like milk — best served fresh and condensed"。随着对话变长，Claude 的表现会下降——它可能忘记早期指令、重复错误或偏离方向。最佳实践是频繁开启新会话，每次聚焦一个明确任务，完成后提交代码，再启动新会话处理下一个任务。短会话的成功率远高于马拉松式长对话。
- **代码示例**:
```bash
# 推荐工作节奏
claude                     # 新会话：实现功能 A
# ... 完成后 ...
git add -A && git commit   # 提交检查点
exit                       # 结束会话

claude                     # 新会话：实现功能 B
# ... 完成后 ...
git add -A && git commit   # 提交检查点

# 如果结果不理想，回滚比修复更高效
git reset --hard HEAD~1    # 回到上一个检查点
claude                     # 全新会话重新开始
```

## 3. /fork 会话分叉：从任意节点分支对话
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 8k stars
- **摘要**: 使用 `/fork` 命令可以从当前对话的任意节点创建分支，保留之前的上下文但不影响原始会话。适用于探索不同实现方案——先让 Claude 分析问题，然后分叉出多个会话分别尝试不同方向，最后比较结果选择最优方案。DX 插件还提供了更高级的克隆脚本，支持从特定对话点分叉。
- **代码示例**:
```bash
# 场景：探索两种架构方案

claude
> 分析当前数据库瓶颈，给出优化方向

# Claude 分析完毕后，分叉出两个方向
/fork                      # 分叉 A：尝试读写分离方案
> 按读写分离方案实现，使用 Redis 缓存热数据

# 回到原会话
/fork                      # 分叉 B：尝试分库分表方案
> 按分库分表方案实现，按用户 ID 取模分片

# 比较两个分叉的结果，选择更优方案
```

## 4. CLAUDE.md 断舍离：每行都问"删了会出错吗？"
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 22k+ stars
- **摘要**: 社区反复验证的教训：臃肿的 CLAUDE.md 会让 Claude 忽略你的实际指令。最佳写法是对每一行自问"如果删掉这行，Claude 会犯错吗？"——如果不会，就删掉。保持文件简短、可读，只写 Claude 必须知道的约束和规范。项目特定的领域知识应该放在 `.claude/skills/` 目录下的 SKILL.md 文件中，而不是全部塞进 CLAUDE.md。
- **代码示例**:
```markdown
# CLAUDE.md - 精简示例（好的写法）

## 构建和测试
- `npm run build` 构建项目
- `npm test` 运行所有测试
- `npm run test:unit -- path/to/file` 运行单个测试

## 代码规范
- TypeScript strict 模式，禁止 any
- 使用 zod 做运行时类型验证
- 错误处理使用 Result 模式，不要 throw

## 架构约束
- API 路由在 src/routes/，业务逻辑在 src/services/
- 数据库操作必须通过 repository 层
```

## 5. SKILL.md 技能文件：给 Claude 可复用的领域知识
- **来源**: [Reddit r/ClaudeAI](https://www.reddit.com/r/ClaudeAI/) 社区讨论 | 🔥 多帖高赞
- **摘要**: 在 `.claude/skills/` 目录下创建 SKILL.md 文件，将可复用的领域知识和工作流模板独立管理。与 CLAUDE.md 不同，skills 按需加载而非全局注入，避免上下文污染。Reddit 社区推荐为常见任务（数据库迁移、API 设计、性能调优等）各创建独立的 skill 文件，让 Claude 在需要时自动引用对应知识。
- **代码示例**:
```markdown
# .claude/skills/database-migration.md

## 数据库迁移规范

### 创建迁移文件
1. 使用 `npm run migration:create <name>` 生成迁移
2. 每个迁移必须包含 up() 和 down()
3. 大表变更必须使用分批处理，每批 1000 行

### 安全检查清单
- [ ] 不能在生产环境直接 DROP COLUMN
- [ ] 添加 NOT NULL 列必须先设默认值
- [ ] 索引创建使用 CONCURRENTLY 避免锁表

### 测试要求
- 迁移前后都要运行 `npm run db:validate`
- 使用测试数据库验证 down() 能完全回滚
```

## 6. /gha 命令：一键排查 GitHub Actions CI 失败
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 8k stars
- **摘要**: 社区开发的 `/gha` 自定义命令专门用于调试 GitHub Actions 失败。它能自动获取失败的 workflow 日志、检测 flaky test、定位导致失败的 commit、分析错误模式并给出修复建议。DX 插件将此功能内置，省去手动配置。对于频繁遇到 CI 问题的团队，这个命令可以大幅缩短排查时间。
- **代码示例**:
```bash

# 1. 调用 gh run list --status failure 获取失败记录
# 2. 下载并分析日志
# 3. 区分 flaky test 和真实失败
# 4. 定位触发失败的 commit
# 5. 生成修复建议

# DX 插件安装（包含 /gha 和其他实用命令）
# 详见 github.com/ykdojo/claude-code-tips
```

## 7. TDD 驱动开发：先写测试，让 Claude 自我验证
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 8k stars
- **摘要**: 社区强烈推荐的开发模式：先让 Claude 写测试，确认测试失败，再让 Claude 实现代码直到测试通过。这样 Claude 能自我验证工作是否完成，而不是依赖人工检查。配合 hooks 在每次代码修改后自动运行测试，形成"红-绿-重构"的完整 TDD 循环。比直接让 Claude 写代码的成功率高出显著。
- **代码示例**:
```bash
# TDD with Claude Code 工作流

# 第一步：让 Claude 写测试
> 为用户注册功能编写测试用例，覆盖：
  1. 正常注册流程
  2. 重复邮箱注册
  3. 密码强度不足
  4. 邮箱格式非法

# 第二步：确认测试失败
npm test                   # 应该全部 FAIL

# 第三步：让 Claude 实现代码
> 现在实现注册功能，让所有测试通过

# 第四步：验证
npm test                   # 应该全部 PASS

# 可通过 hooks 自动化这个循环
```

## 8. claude-devtools 会话分析：可视化上下文消耗和工具调用
- **来源**: [hesreallyhim/awesome-claude-code](https://github.com/hesreallyhim/awesome-claude-code) on GitHub | ⭐ 41.2k stars
- **摘要**: claude-devtools 是社区开发的会话日志分析工具，能解析 Claude Code 的会话记录，生成逐轮上下文数据、工具调用频率统计、压缩事件可视化等。帮助开发者理解 token 消耗模式，发现上下文浪费的环节，优化提示词和工作流。配合 ccxray（实时 API 仪表板）和 claude-pace（速率限制监控），形成完整的可观测性方案。
- **代码示例**:
```bash
# claude-devtools 使用示例

# 分析最近的会话日志
claude-devtools analyze ~/.claude/sessions/latest/

# 输出内容包括：
# - 每轮对话的 token 消耗趋势图
# - 工具调用频率和耗时统计
# - 压缩（compaction）事件时间线
# - 上下文利用率热力图

# 配套工具
# ccxray  - 实时 API 请求仪表板
# claude-pace - 速率限制剩余用量和燃烧率
# Claude HUD - 状态栏显示上下文、工具、待办等
```
