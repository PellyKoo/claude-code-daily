# Claude Code 2.1.226 社区实用技巧 - 2026-08-07

## 1. Dynamic Workflows：动态工作流编排
- **来源**: [cat (@_catwu)](https://x.com/_catwu/status/2060054180379689074) on X & [Thariq (@trq212)](https://x.com/trq212/status/2061907538741006796) on X | 🔥 社区热议新功能
- **摘要**: Claude Code 最强大的新功能之一——在 prompt 中提到"workflow"，Claude 会自动创建一个确定性的编排计划，严格按照步骤执行，即使跨越上百个 agent 也能保证每个阶段按正确顺序完成。Thariq 特别强调，Workflows 不仅适用于技术任务，还能处理非技术性的复杂多步骤工作。社区认为这是自 skills 和 subagents 以来最大的能力升级。
- **代码示例**:
```bash
# 在 prompt 中提到 "workflow" 触发动态编排
"use a workflow to review all changed files across
correctness, performance, and security dimensions,
then verify each finding adversarially"

# Claude 会自动生成类似这样的编排计划：
# Phase 1: 按维度并行 review
# Phase 2: 对每个发现进行对抗性验证
# Phase 3: 汇总确认的问题

# 也可以用 "ultracode" 关键词触发更彻底的多 agent 编排
"ultracode: 全面审计 src/auth/ 目录的安全性"
```

## 2. Skill 审计：清理你的技能库
- **来源**: [Prajwal Tomar (@PrajwalTomar_)](https://x.com/PrajwalTomar_/status/2074787074641899896) on X | 🔥 高互动实用技巧
- **摘要**: 一个被社区广泛转发的 PRO tip：不要盲目安装大量 skills，而是把介绍 skills 的文章整篇粘贴到 Claude Code 会话中，让 Claude 列出你当前已安装的所有 skill，与文章推荐的进行对比，然后卸载那些重叠的、从不触发的、或者争抢上下文的 skill。社区反馈：很多人装了 300+ 个 skill 后发现性能反而下降，因为过多的 skill 描述会占用宝贵的上下文窗口。
- **代码示例**:
```bash
# 步骤 1: 查看当前已安装的 skills
/skills

# 步骤 2: 把 skills 推荐文章粘贴到会话中
"Read this article end to end. Then list every
skill I currently have installed, and compare it
against this list. Uninstall anything that overlaps,
never triggers, or is fighting for context."

# 步骤 3: 定期审计，保持精简
# 建议：保留 10-15 个高频使用的 skill
# 删除：功能重叠的、3 周内未触发的
```

## 3. Subagent 上下文隔离：保护主会话的上下文
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 64.2k stars
- **摘要**: 社区验证的关键实践：将详细的中间工作路由到 subagent，避免污染主会话的上下文窗口。主会话的上下文利用率应保持在 40% 以下以获得最佳性能。当你需要做复杂的代码搜索、分析或调研时，用 subagent 完成后只把结论带回主会话。这样你的主会话能保持更长的有效生命周期，减少因上下文溢出导致的质量下降。
- **代码示例**:
```bash
# 错误做法：在主会话中做大量搜索
"搜索所有使用 deprecated API 的文件并列出来"
# → 大量搜索结果占满上下文

# 正确做法：委托给 subagent
"spawn a subagent to search all files using the
deprecated v1 API. Have it return only a summary:
file paths and line counts, grouped by API method."
# → 主会话只收到精简的摘要

# 在 skill 中使用 context: fork 隔离
# .claude/skills/research/SKILL.md
# ---
# context: fork
# ---
# 这个 skill 会在独立的 subagent 中运行
```

## 4. Git Worktree 并行开发：真正的隔离并行
- **来源**: [centminmod/my-claude-code-setup](https://github.com/centminmod/my-claude-code-setup) on GitHub | ⭐ 2.6k stars
- **摘要**: 比 tmux 多窗格更进一步的并行方案：使用 git worktree 为每个 Claude Code 会话创建完全隔离的工作目录副本。每个 agent 在自己的 worktree 中修改文件，互不干扰，不会出现文件冲突。Claude Code 原生支持 `--worktree` 参数。centminmod 提供了平台相关的 shell 函数封装，自动创建 worktree 并初始化 Claude Code 会话。
- **代码示例**:
```bash
# 方法 1: 使用 Claude Code 内置 worktree 支持
claude --worktree
# 自动创建隔离的 worktree 并启动会话

# 方法 2: 手动管理 worktree
git worktree add ../feature-auth -b feature/auth
git worktree add ../feature-api -b feature/api

# 在各自的 worktree 中启动独立的 Claude 会话
cd ../feature-auth && claude "实现 OAuth2 登录"
cd ../feature-api && claude "实现 REST API 端点"

# 完成后清理
git worktree remove ../feature-auth
git worktree remove ../feature-api

# 方法 3: 在 workflow 中使用 isolation: 'worktree'
# agent('重构认证模块', { isolation: 'worktree' })
```

## 5. Hooks 自动化守护：代码质量的自动护栏
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 6k stars
- **摘要**: Hooks 是 Claude Code 的自动化守护机制——在工具执行前后自动运行自定义脚本。ChrisWiles 的 showcase 展示了完整的 hooks 配置：文件保存后自动格式化、提交前自动跑 lint、禁止直接 push 到 main 分支等。社区把 hooks 比作"给 AI 装上安全带"，防止它做出破坏性操作。配合 skill 评估系统，可以根据 prompt 内容智能推荐相关 skill。
- **代码示例**:
```jsonc
// .claude/settings.json
{
  "hooks": {
    "afterToolExecution": [
      {
        "matcher": "Write|Edit",
        "command": "prettier --write $FILE_PATH"
      }
    ],
    "beforeToolExecution": [
      {
        "matcher": "Bash",
        "command": "echo $COMMAND | grep -q 'push.*main' && exit 1 || exit 0"
      }
    ],
    "afterSessionStart": [
      {
        "command": "npm test -- --silent 2>/dev/null; echo 'Tests: '$?"
      }
    ]
  }
}
```

## 6. CLAUDE.md 记忆库模板：跨会话记忆不丢失
- **来源**: [centminmod/my-claude-code-setup](https://github.com/centminmod/my-claude-code-setup) on GitHub | ⭐ 2.6k stars & [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 64.2k stars
- **摘要**: 社区总结出 CLAUDE.md 的最佳长度是 100-400 行——少于 100 行会缺少关键上下文，超过 400 行会浪费上下文窗口。centminmod 提供了三种模板变体：紧凑型（101 行）、双记忆架构（153 行）、渐进式展示（105 行）。核心理念是"双记忆架构"：git 共享的 CLAUDE.md 存团队约定，本地 auto-memory 存个人偏好和机器状态。shanraisshan 建议用 `.claude/rules/*.md` 配合 YAML frontmatter 实现路径级别的懒加载。
- **代码示例**:
```markdown
# CLAUDE.md 推荐结构（100-200 行）

## 项目概览
- 一句话描述项目
- 技术栈：Next.js 15 + TypeScript + Prisma + PostgreSQL

## 关键约定
- 包管理器: pnpm（绝不使用 npm/yarn）
- 测试: vitest，文件放在 __tests__/
- 提交格式: conventional commits

## 架构决策记录
- 2026-07: 从 REST 迁移到 tRPC（原因：类型安全）
- 2026-08: 认证改用 lucia-auth（原因：更轻量）

## 常见陷阱
- Prisma migrate 前必须先 generate
- 环境变量改动后需要重启 dev server
```

## 7. 手动 /compact 策略：别等上下文溢出
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 64.2k stars
- **摘要**: 社区发现一个关键性能技巧：不要依赖 Claude Code 的自动 compaction，而是在上下文使用率达到 50% 左右时主动执行 `/compact`。自动 compaction 会在快溢出时才触发，这时候已经来不及了——信息丢失更多、压缩质量更差。主动 compact 时可以添加 hint 告诉 Claude 哪些信息必须保留。搭配 `/rewind` 使用效果更好：发现走错方向时先 rewind 再 compact，而不是在错误的基础上层层纠正。
- **代码示例**:
```bash
# 在上下文达到 ~50% 时主动 compact
/compact 保留：当前任务目标、已修改的文件列表、未完成的步骤

# 带 hint 的 compact（告诉 Claude 什么必须记住）
/compact hint: 我们正在迁移 auth 模块到 lucia-auth，
已完成 login/register，还需要处理 session 和 middleware

# 配合 /rewind 的工作流
# 1. 发现 Claude 走错方向
/rewind
# 2. 选择正确的检查点
# 3. compact 掉错误的尝试
/compact 回到 auth 迁移任务，忽略之前错误的 OAuth 实现
# 4. 给出更明确的指令重新开始
```

## 8. GitHub Actions 自动化：让 Claude 替你值班
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 6k stars
- **摘要**: ChrisWiles 展示了四个生产级的 GitHub Actions 工作流，让 Claude Code 在 CI/CD 中自动执行周期性任务：每次 PR 自动 code review、每周代码质量扫描、每月文档对齐检查、每两周依赖更新。预估月成本仅 $10-$50。社区评价：这把 Claude 从"开发时的助手"变成了"全天候的代码守护者"，特别适合小团队没有专职 reviewer 的场景。
- **代码示例**:
```yaml
# .github/workflows/claude-pr-review.yml
name: Claude PR Review
on:
  pull_request:
    types: [opened, synchronize]

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Claude Code Review
        uses: anthropics/claude-code-action@v1
        with:
          prompt: |
            Review this PR for correctness bugs,
            security issues, and performance problems.
            Post findings as inline comments.

# 每周代码质量扫描
# cron: '0 9 * * 1'  # 每周一早上 9 点
# 每月文档对齐
# cron: '0 9 1 * *'  # 每月 1 号
```
