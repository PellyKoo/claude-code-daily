## 2. Karpathy 的 65 行 CLAUDE.md——10 万星的极简哲学
- **来源**: [Forrest Chang / Karpathy](https://miraflow.ai/blog/karpathy-claude-md-100k-github-stars-ai-coding-2026) on GitHub | ⭐ 100k+ stars
- **摘要**: 基于 Andrej Karpathy 对 AI 编码代理失败模式的观察，仅用 65 行总结了四大行为准则：编码前先思考、简洁优先、外科手术式修改、目标驱动执行。这个文件证明了 CLAUDE.md 不需要长篇大论——精炼的原则比详细的规则更有效。超过 80 行 Claude 就会开始忽略部分内容。
- **代码示例**:
```markdown
# CLAUDE.md（Karpathy 风格极简版）

## 核心原则
1. Think Before Coding - 动手前先在 <thinking> 中推演方案
2. Simplicity First - 用最少代码解决问题，拒绝过度工程
3. Surgical Changes - 只改必要的部分，不做附带"改进"
4. Goal-Driven Execution - 始终对照目标检查是否偏离

## 禁止行为
- 不要添加未要求的功能
- 不要重构无关代码
- 不要写超过一行的注释
```

## 4. Git Worktree 并行开发——同时跑 10-15 个会话
- **来源**: [Claude Code 团队实践](https://mindwiredai.com/2026/03/25/claude-code-creator-workflow-claudemd/) on MindwiredAI | 🔥 高引用
- **摘要**: Claude Code 创造者 Boris 的团队内部工作流曝光：使用 `git worktree` 为每个 Claude 会话创建独立工作目录，实现 10-15 个会话真正并行而互不冲突。每个 worktree 对应一个独立任务分支，完成后通过 PR 合并。这是团队公认的第一生产力技巧。
- **代码示例**:
```bash
# 为每个 Claude 会话创建独立 worktree
git worktree add ../feature-auth feature/auth
git worktree add ../feature-search feature/search
git worktree add ../bugfix-login bugfix/login

# 在不同终端 tab 中启动独立 Claude 会话
cd ../feature-auth && claude
cd ../feature-search && claude
cd ../bugfix-login && claude

# 完成后清理
git worktree remove ../feature-auth
```

## 5. 反馈循环验证法——质量提升 2-3 倍
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 54.6k stars
- **摘要**: 社区反复验证的核心模式：永远给 Claude 一个验证自身工作的反馈循环。让它写完代码后立即运行测试、或通过浏览器测试应用、或执行 linter 检查。相比"写完就交"，这种自验证模式能将代码质量提升 2-3 倍，因为 Claude 会在迭代中自我纠错。
- **代码示例**:
```markdown
# CLAUDE.md 反馈循环配置

## 验证规则
每次修改代码后，必须执行以下验证步骤：
1. 运行 `npm test` 确保无测试失败
2. 运行 `npm run lint` 确保代码风格一致
3. 如果是 UI 变更，启动 dev server 并在浏览器中验证
4. 如果测试失败，自行修复后重新验证，直到全部通过
```

## 6. lessons.md 自我进化模式——让 Claude 越用越聪明
- **来源**: [Builder.io](https://www.builder.io/blog/claude-code-tips-best-practices) on Web | 🔥 50 Tips 高流量文
- **摘要**: 每次 Claude 犯错被纠正后，立即让它在 `lessons.md` 中记录教训和正确做法。下次会话加载此文件，Claude 就不会重蹈覆辙。随着项目推进，这个文件会变成项目特有的"智慧结晶"，让 Claude 在你的代码库上表现越来越好。
- **代码示例**:
```markdown
# lessons.md - Claude 自我学习记录

## 2026-05-23
- ❌ 错误：在 auth 模块中使用了 bcrypt 同步方法
- ✅ 正确：必须使用 bcrypt.hash() 异步方法，避免阻塞事件循环

## 2026-05-22
- ❌ 错误：直接修改了 Redux store 中的状态对象
- ✅ 正确：始终返回新对象，使用展开运算符或 immer

## 使用方式：在 CLAUDE.md 中添加
# 加载历史教训
请先阅读 lessons.md，避免重复已知错误。
```
