## 1. 20 个必知快捷键与命令速查
- **来源**: [Santiago (@svpino)](https://x.com/svpino/status/2050563493708112190) on X | 🔥 高互动推文
- **摘要**: Santiago 整理了 20 个高效使用 Claude Code 的快捷键和命令。其中最实用的几个：`Esc+Esc` 回退到任意检查点（免费撤销）、`CTRL+V` 直接粘贴截图、`CTRL+G` 打开编辑器写长提示、`CTRL+R` 搜索历史提示。`/rewind` 可以回滚到检查点后给出更具体的反馈重试。这些快捷键极大提升了日常开发效率。
- **代码示例**:
```bash
# 快捷键速查
Esc+Esc    → 回退到任意检查点（自由撤销）
CTRL+V     → 粘贴截图到 Claude Code
CTRL+G     → 打开编辑器撰写长提示
CTRL+R     → 搜索提示历史
/rewind    → 回滚到检查点并重试
/compact   → 带提示压缩上下文（推荐主动使用而非等自动触发）
```

## 2. CLAUDE.md 最佳实践：控制在 200 行以内
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 64.7k stars, 6.4k forks
- **摘要**: 这个拥有 6.4 万星的仓库总结了 CLAUDE.md 的最佳实践。核心建议：每个文件控制在 200 行以内，超过则拆分为 `.claude/rules/*.md` 并使用 YAML frontmatter 按需懒加载。目标是"任何开发者启动 Claude 说'运行测试'就能直接工作"。同时建议上下文窗口使用量控制在 30-40% 以下，因为"40% 时就会进入降智区"。
- **代码示例**:
```yaml
# .claude/rules/testing.md — 按需加载规则示例
---
globs:
  - "**/*.test.ts"
  - "**/*.spec.ts"
---
# 测试规范
- 使用 vitest 而非 jest
- 每个测试文件必须有 describe 块
- mock 外部依赖，不 mock 内部模块
```

## 3. Hook 驱动自动化：提交前自动检查与格式化
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 6k stars, 567 forks
- **摘要**: 这个展示项目演示了 Claude Code 的完整 Hook 生命周期配置。通过 `PreToolUse` 阻止在 main 分支上的编辑、验证命令安全性；通过 `PostToolUse` 自动格式化代码、运行测试和 lint；通过 `UserPromptSubmit` 自动添加上下文和建议相关 skill。让 Claude Code 不只是写代码，而是融入整个开发流程的自动化管道。
- **代码示例**:
```jsonc
// .claude/settings.json — Hook 配置示例
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "command": "bash -c 'git branch --show-current | grep -q main && echo BLOCK: 禁止直接编辑 main 分支 && exit 1 || exit 0'"
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "command": "npx prettier --write $CLAUDE_FILE_PATH"
      }
    ]
  }
}
```

## 4. 上下文窗口管理：用子代理隔离中间结果
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 64.7k stars
- **摘要**: 社区总结的上下文管理策略：将工具调用的中间输出用子代理（subagent）隔离，避免污染主上下文窗口。推荐主动使用 `/compact` 加提示（而非等系统自动压缩），并将每次对话视为分支点——根据情况选择继续、`/rewind`、`/clear`、`/compact` 或委托子代理。"垂直切片"开发法（一次贯穿所有层）优于水平分层推进，能更早获得端到端反馈。
- **代码示例**:
```bash
# 上下文管理工作流
# 1. 在主会话中规划
"分析这个需求，列出实现步骤"

# 2. 用子代理执行具体任务（隔离中间输出）
"用子代理搜索所有使用了旧 API 的文件"

# 3. 主动压缩并给出提示
/compact 保留：API 迁移计划和受影响文件列表

# 4. 垂直切片实现
"先实现用户登录的完整流程（API → Service → Controller → 前端），不要一层层来"
```

## 5. 让 Claude 自我验证：最高杠杆的单一技巧
- **来源**: [Santiago (@svpino)](https://x.com/svpino/status/2050563493708112190) on X | 🔥 高互动推文
- **摘要**: Santiago 强调，给 Claude 提供自我验证的手段（测试、截图、预期输出）是单一最高杠杆的技巧。不要只让 Claude 写代码然后自己检查，而是让它写完后自己运行测试、截取截图、对比预期输出来验证自己的工作。这个习惯能大幅减少来回修改的次数，把 Claude Code 从"写代码助手"升级为"完整开发循环助手"。
- **代码示例**:
```markdown
# CLAUDE.md 中添加验证规则
## 验证要求
- 修改代码后必须运行相关测试：`npm test -- --related`
- 前端改动必须截图确认（使用 CTRL+V 粘贴截图）
- API 改动必须用 curl 验证返回值符合预期
- 每次改动后运行 `npm run typecheck` 确保类型安全
```

## 6. GitHub Actions 自动化：让 Claude Code 值守仓库
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 6k stars
- **摘要**: 展示项目演示了用 GitHub Actions 实现 Claude Code 自动化运维：每个 PR 自动触发代码审查、每月文档同步、每周代码质量扫描、每两周依赖审计。预估月成本仅 $10-50。这让 Claude Code 不只是开发时使用的工具，而是持续守护代码质量的"值班 AI"。
- **代码示例**:
```yaml
# .github/workflows/claude-review.yml
name: Claude Code Review
on:
  pull_request:
    types: [opened, synchronize]

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Claude Code Review
        uses: anthropics/claude-code-action@v1
        with:
          prompt: |
            审查这个 PR 的代码变更，关注：
            1. 安全漏洞
            2. 性能问题
            3. 代码风格一致性
            4. 测试覆盖率
```

## 7. 计划模式先行：先研究再规划再执行
- **来源**: [35+ Claude Code Tips (2026 Edition)](https://x.com/Suryanshti777/status/2029200211093201017) on X | 🔥 高互动长文
- **摘要**: 社区推荐的三阶段工作流：首先让 Claude 研究代码库（explore-first），然后进入 Plan Mode 制定方案，最后切回正常模式执行。这比直接让 Claude 开干效率高得多，特别是对于复杂任务。Plan Mode 会生成结构化的步骤计划，让你在执行前审查和调整，避免走弯路。
- **代码示例**:
```bash
# 三阶段工作流
# 阶段 1：研究（Explore）
"搜索整个代码库，找出所有支付相关的模块和它们的依赖关系"

# 阶段 2：规划（Plan Mode）
# 按 Shift+Tab 进入 Plan Mode
"基于刚才的分析，制定重构支付模块的详细计划"

# 阶段 3：执行（Normal Mode）
# 按 Shift+Tab 切回 Normal Mode
"按照计划执行第一步：抽取支付网关接口"
```
