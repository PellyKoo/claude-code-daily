## 1. 系统提示词瘦身：回收 50% 上下文空间
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 8.2k stars
- **摘要**: Claude Code 默认系统提示词约 19k token，其中包含大量冗余示例和重复描述。通过精简工具描述中的冗余文本，可以将开销降至约 9k token，释放近 10,000 token 给实际工作上下文。对长会话和大型代码库尤其有价值。
- **代码示例**:
```bash
# 查看当前系统提示词 token 用量
# Tip 15 提供了精简后的工具描述模板
# 精简前：~19,000 tokens 系统开销
# 精简后：~9,000 tokens 系统开销
# 节省的 10k tokens 可多读约 30 个源文件
```

## 2. Docker 容器沙盒：安全运行高风险自主任务
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 8.2k stars
- **摘要**: 将 Claude Code 放入 Docker 容器中运行，配合 `--dangerously-skip-permissions` 标志，让它在隔离环境中自由执行任务。即使出错也不会影响宿主机。适合探索性任务、批量重构、不确定结果的自动化流程。
- **代码示例**:
```dockerfile
FROM node:20
RUN npm install -g @anthropic-ai/claude-code
WORKDIR /workspace
COPY . .
CMD ["claude", "--dangerously-skip-permissions", "-p", "运行所有测试并修复失败的用例"]
```

## 3. /gha 命令：让 Claude Code 当 DevOps 工程师
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 8.2k stars
- **摘要**: 使用 `/gha` 斜杠命令自动调查 GitHub Actions 失败，Claude Code 会分析日志、定位根因、检测 flaky test，并给出修复建议。省去手动翻阅冗长 CI 日志的时间，特别适合复杂的多步骤流水线调试。
- **代码示例**:
```bash
# 在 Claude Code 中直接使用
/gha

# 或通过 dx 插件调用
/dx:gha

# Claude 会自动：
# 1. 拉取最近的 Actions 运行记录
# 2. 分析失败日志
# 3. 识别根本原因
# 4. 提出修复方案
```

## 4. 主分支保护 Hook：防止误操作 main 分支
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 5.9k stars
- **摘要**: 通过 PreToolUse hook 在 Claude Code 尝试编辑文件前检查当前分支，如果在 main/master 分支上则自动阻止写操作（exit code 2）。这是一个简单但关键的安全防护，避免 Claude 直接修改生产分支代码。
- **代码示例**:
```jsonc
// .claude/settings.json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "command": "bash -c 'branch=$(git branch --show-current); if [ \"$branch\" = \"main\" ] || [ \"$branch\" = \"master\" ]; then echo \"禁止在 $branch 分支上编辑文件\"; exit 2; fi'"
      }
    ]
  }
}
```

## 5. PostToolUse 自动格式化与测试 Hook
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 5.9k stars
- **摘要**: 配置 PostToolUse hook，在 Claude Code 每次修改文件后自动运行 lint 修复和单元测试。确保每次编辑都符合代码规范且不破坏现有功能，实现"编辑即验证"的持续质量保障。
- **代码示例**:
```jsonc
// .claude/settings.json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "command": "npm run lint -- --fix && npm test -- --bail"
      }
    ]
  }
}
```

## 6. Handover Document：上下文极限时的无损交接
- **来源**: [r/ClaudeAI](https://www.reddit.com/r/ClaudeAI/) on Reddit | 🔥 社区高频讨论技巧
- **摘要**: 当上下文窗口接近极限时，要求 Claude 生成一份"交接文档"（handover document），包含当前进度、已修改文件、未完成任务和关键决策。将此文档粘贴到新会话中，可以几乎无损地恢复工作状态，比依赖 `/compact` 保留更多细节。
- **代码示例**:
```
# 上下文快满时，输入：
请生成一份交接文档，包含：
1. 当前任务目标和整体进度
2. 已完成的修改（文件路径 + 变更摘要）
3. 未完成的工作项
4. 关键设计决策和原因
5. 需要注意的陷阱或边界情况

# 然后在新会话中：
claude
# 粘贴交接文档，继续工作
```

## 7. Rewind 回退：保留代码、撤销对话
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 52.8k stars
- **摘要**: Claude Code 的 Rewind 功能支持"仅回退对话"或"仅回退代码"两种模式。当发现 Claude 走错方向时，可以回退对话但保留已有的文件修改，避免"一错全删"。比传统的 undo 更灵活，是纠错的首选方式。
- **代码示例**:
```bash
# 使用方式：
# 1. 点击会话中想要回退到的消息
# 2. 选择回退模式：
#    - "Conversation only"  → 回退对话，保留文件修改
#    - "Code only"          → 回退文件，保留对话上下文
#    - "Both"               → 全部回退

# 场景：Claude 重构了 3 个文件，前 2 个正确，第 3 个出错
# → 回退到第 2 个文件修改后，重新提示第 3 个文件的需求
```

## 8. 快速原型迭代替代冗长 PRD
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 52.8k stars
- **摘要**: 社区共识：与其花大量时间写详细的产品需求文档（PRD），不如用 Claude Code 快速构建 20-30 个原型进行探索。每个原型的成本极低，通过实际运行比纸上推演更能发现问题。把 Claude Code 当作"思考工具"而非"执行工具"。
- **代码示例**:
```bash
# 快速原型工作流
# 1. 用一句话描述想法
claude -p "用 React 做一个拖拽排序的看板组件，支持多列"

# 2. 在浏览器中体验
# 3. 记录反馈，迭代下一版
claude -p "基于上一版，添加标签过滤和搜索功能"

# 4. 确定方向后再写正式代码
# 原型的目的是验证想法，不是写生产代码
```
