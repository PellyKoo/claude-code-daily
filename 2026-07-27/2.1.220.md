# Claude Code 2.1.220 社区实用技巧 - 2026-07-27

## 1. 用 Skills 审计清理你的 Claude Code 工具链
- **来源**: [Prajwal Tomar](https://x.com/PrajwalTomar_/status/2074787074641899896) on X | 🔥 高互动推文
- **摘要**: 把任何 Claude Code 技巧文章整段粘贴到会话中，让 Claude 列出你已安装的全部 skills，与文章对比后自动卸载重叠或从未触发的技能，并安装更优替代品。相当于一键做了工具链大扫除。
- **代码示例**:
```
"Read this article end to end. Then list every skill I currently have installed,
and compare it against this list. Uninstall anything that overlaps, never triggers,
or is outdated. Install replacements where available."
```

## 2. Dynamic Workflows：用 Ultracode 模式并行调度上百个 Agent
- **来源**: [Greg Isenberg](https://x.com/gregisenberg/status/2060072130339873093) on X | 🔥 高互动推文
- **摘要**: 在 effort 菜单开启 "ultracode" 或直接输入 "create a workflow"，Claude Code 会启动数百个并行 agent 并互相校验结果。工作单元从单文件跃升到整个功能模块，适合大规模重构和跨文件迁移。
- **代码示例**:
```
# 在 Claude Code 会话中直接输入
create a workflow

# 或在 effort 菜单切换到 ultracode 模式
# 然后像平常一样描述任务，系统自动编排多 agent 协作
```

## 3. Hooks 优先于 CLAUDE.md：100% 确定性 vs 80% 遵从率
- **来源**: [Claude Code Hacks 2026](https://youmind.com/landing/x-viral-articles/claude-code-hacks-2026-workflow) | 🔥 社区热议话题
- **摘要**: CLAUDE.md 是"建议性"的，Claude 大约 80% 会遵循；而 Hooks 是"确定性"的，100% 会执行。格式化、安全检查、lint 等必须每次都执行的操作应该配置为 hook 而不是写在 CLAUDE.md 里。
- **代码示例**:
```json
// .claude/settings.json
{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Write|Edit",
      "command": "npx prettier --write $CLAUDE_FILE_PATH"
    }]
  }
}
```

## 4. 上下文容量黄金法则：40% 是天花板
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 63.6k stars
- **摘要**: 会话超过 300-400k tokens 后推理质量显著下降。经验丰富的开发者将上下文使用量控制在 40% 以下（目标 30%）。70% 时应压缩会话，90%+ 时清空重开。用 `/rewind` 丢弃失败尝试而不是堆积修正。
- **代码示例**:
```
# 查看当前上下文使用情况
/stats

# 回退到失败前的状态，而不是在错误基础上继续修补
/rewind

# 写好交接摘要后开启新会话
"Write a handoff summary of our current progress, then I'll start a new session."
```

## 5. 自定义系统提示文件：一个工具变多个专家
- **来源**: [Ian Nuttall](https://x.com/iannuttall/status/2022991223535874180) on X | 🔥 高互动推文
- **摘要**: 通过 `--system-prompt-file` 参数为不同工作流加载不同的系统提示。测试、重构、代码审查各用一套提示文件，相当于把一个 Claude Code 变成多个专业化版本。
- **代码示例**:
```bash
# 用于测试的专用提示
claude -p --system-prompt-file ./prompts/testing.txt "Add unit tests for auth module"

# 用于重构的专用提示
claude -p --system-prompt-file ./prompts/refactor.txt "Simplify the data pipeline"

# 用于安全审计的专用提示
claude -p --system-prompt-file ./prompts/security.txt "Review this PR for vulnerabilities"
```

## 6. Subagent 上下文隔离：用 fork 模式保护主会话
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 63.6k stars
- **摘要**: 实现功能特定的 subagent（而非通用角色 agent），并使用 `context: fork` 让探索性工作在隔离的子进程中运行，不污染主上下文。架构模式为 Command → Agent → Skill，保持主会话精简。
- **代码示例**:
```yaml
# .claude/commands/investigate.md
---
context: fork
---
Investigate the following issue without affecting the main session context:
$ARGUMENTS

Summarize findings in 3-5 bullet points.
```

## 7. CLAUDE.md 瘦身术：200 行是上限
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 63.6k stars
- **摘要**: CLAUDE.md 应控制在 200 行以内。超出部分拆分到 `.claude/rules/` 目录。删除 Claude 能从代码推断的内容、通用编程规范、以及过去一个月没有影响过交互的条目。团队共享配置提交到版本控制，个人配置放 `.claude/CLAUDE.md` 并 gitignore。
- **代码示例**:
```
项目结构示例：
├── CLAUDE.md              # ≤200行，团队共享，提交到 git
├── .claude/
│   ├── CLAUDE.md          # 个人覆盖配置，已 gitignore
│   ├── rules/
│   │   ├── testing.md     # 测试相关规则
│   │   ├── api-design.md  # API 设计规范
│   │   └── security.md    # 安全策略
│   └── commands/
│       └── review.md      # 自定义命令
```

## 8. tmux 远程会话：解决不稳定网络下的断连问题
- **来源**: [Claude Code Hacks 2026](https://youmind.com/landing/x-viral-articles/claude-code-hacks-2026-workflow) | 🔥 社区热议话题
- **摘要**: Claude Code 在不稳定的 WiFi 下容易断连丢失会话。先通过 tmux 连接到远程机器（如 Mac Mini），会话运行在远程端，笔记本只是一个窗口。断网后重连 tmux 即可恢复，不丢失任何进度。
- **代码示例**:
```bash
# 在远程机器上创建 tmux 会话
ssh my-mac-mini
tmux new -s claude-work

# 启动 Claude Code
claude

# 断网后重连
ssh my-mac-mini
tmux attach -t claude-work
# 一切都还在，包括完整的会话历史
```
