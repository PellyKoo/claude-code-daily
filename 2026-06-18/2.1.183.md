# Claude Code 2.1.183 社区实用技巧 - 2026-06-18

## 1. 上下文窗口在 40% 时开始退化，保持在 30% 以下
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 58.3k stars
- **摘要**: 社区实测发现，Claude Code 的表现在上下文使用量达到约 40% 时会明显下降。资深用户建议将上下文使用率控制在 30% 以下，并在适当时机手动使用 `/compact` 命令配合提示词来压缩上下文，效果优于自动压缩。
- **代码示例**:
```
# 手动压缩并附带提示
/compact 保留所有关于认证模块的修改记录，忽略调试日志
```

## 2. 用 Git Worktree 实现多个 Claude 会话并行开发
- **来源**: [centminmod](https://github.com/centminmod/my-claude-code-setup) on GitHub | ⭐ 2.4k stars
- **摘要**: 通过 Git Worktree 创建独立工作目录，可以同时运行多个 Claude Code 会话处理不同功能分支，互不干扰。社区分享了一个便捷的 shell 函数来快速创建工作树并启动 Claude。
- **代码示例**:
```bash
clx() {
    local branch_name="${1:-worktree-$(date +%Y%m%d-%H%M%S)}"
    git worktree add "../$branch_name" -b "$branch_name" && cd "../$branch_name"
    claude --model opusplan --permission-mode plan
}
```

## 3. PreToolUse Hook 防止误改主分支
- **来源**: [ChrisWiles](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 6k stars
- **摘要**: 通过配置 PreToolUse 钩子，可以在 Claude 尝试编辑或写入文件时自动检查当前分支。如果在 main 分支上，操作会被自动阻止，避免直接修改主分支的意外事故。
- **代码示例**:
```json
{
  "hooks": {
    "PreToolUse": [{
      "matcher": "Edit|Write",
      "hooks": [{
        "type": "command",
        "command": "[$(git branch --show-current) != main] || exit 2"
      }]
    }]
  }
}
```

## 4. CLAUDE.md 控制在 200 行以内，用 .claude/rules/ 模块化拆分
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 58.3k stars
- **摘要**: 过长的 CLAUDE.md 会导致 Claude 忽略你的指令。社区最佳实践是将 CLAUDE.md 保持在 200 行以内，将不同领域的规则拆分到 `.claude/rules/` 目录下，通过路径匹配实现按需加载，避免每次会话都加载全部指令。
- **代码示例**:
```
# .claude/rules/ 目录结构示例
.claude/rules/
├── testing.md        # 测试相关规则
├── api-design.md     # API 设计规范
├── frontend.md       # 前端组件规则
└── database.md       # 数据库操作规范
```

## 5. Memory Bank 模式：跨会话保持项目记忆
- **来源**: [centminmod](https://github.com/centminmod/my-claude-code-setup) on GitHub | ⭐ 2.4k stars
- **摘要**: 使用多个 CLAUDE-*.md 文件构建"记忆库"系统，让 Claude 在每次任务完成后自动更新记忆文件，记录架构决策、调试经验和项目模式。新会话启动时自动加载这些记忆，实现跨会话的知识传承。
- **代码示例**:
```
# 记忆库文件结构
CLAUDE.md                    # 主配置文件
CLAUDE-ARCHITECTURE.md       # 架构决策记录
CLAUDE-TROUBLESHOOTING.md    # 故障排查经验
CLAUDE-PATTERNS.md           # 代码模式和约定
```

## 6. 用 /rewind 回退而非纠正错误，避免上下文污染
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 58.3k stars
- **摘要**: 当 Claude 走错方向时，不要试图在当前对话中纠正它——反复纠正会污染上下文，导致后续输出质量持续下降。更好的做法是使用 `/rewind` 回退到出错前的状态重新开始，保持上下文的清洁。
- **代码示例**:
```
# 错误做法：在错误基础上反复纠正
> 不对，你用错了API，应该用 v2 版本...
> 还是不对，你忘了处理错误...

# 正确做法：回退到出错前
/rewind
> 使用 v2 API 实现用户认证，确保包含错误处理
```

## 7. 创建专用功能子代理，而非通用角色代理
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 58.3k stars
- **摘要**: 使用子代理时，不要创建"QA代理"或"后端代理"这样的通用角色。更有效的方式是为每个具体功能创建专用子代理，并提供该功能所需的额外上下文。独立的上下文窗口也有助于提高 bug 检测率。
- **代码示例**:
```
# 不推荐：通用角色
Agent("QA代理", "测试所有代码")

# 推荐：专用功能代理
Agent("认证模块测试", "测试 src/auth/ 下的 JWT 验证逻辑，
       关注 token 过期、刷新和并发场景")
```

## 8. .worktreeinclude 自动同步环境文件到新工作树
- **来源**: [centminmod](https://github.com/centminmod/my-claude-code-setup) on GitHub | ⭐ 2.4k stars
- **摘要**: 使用 Git Worktree 并行开发时，新工作树不会包含 `.env` 等被 gitignore 的文件。通过创建 `.worktreeinclude` 文件，可以指定哪些被忽略的文件需要自动复制到新工作树中，解决环境配置缺失的问题。
- **代码示例**:
```
# .worktreeinclude
.env
.env.local
**/.claude/settings.local.json
```
