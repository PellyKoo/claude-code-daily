## 1. Handoff 文档：跨会话不丢上下文的秘诀
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 8.9k stars
- **摘要**: 在长任务中途需要开新会话时，让 Claude 生成一份 HANDOFF.md 文档，记录当前进度、已尝试的方案、失败原因和下一步计划。新会话启动时读取该文件即可无缝衔接。配合 dx 插件的 `/handoff` 斜杠命令可一键生成，避免在新会话中重复解释背景浪费 token。
- **代码示例**:
```markdown
<!-- HANDOFF.md 示例 -->
# 任务交接：用户权限模块重构

## 已完成
- 数据库 schema 迁移（见 migrations/0042_rbac.sql）
- Role 和 Permission 模型定义

## 未完成
- RoleService 的 CRUD 方法（已有接口定义，未实现）
- 中间件鉴权逻辑

## 注意事项
- 旧的 isAdmin 字段暂时保留，需要兼容 v1 API
- 测试数据库用 SQLite，生产用 PostgreSQL，注意语法差异
```
```bash
# 使用 dx 插件一键生成交接文档
/dx:handoff
```

## 3. 上下文压力管理"70/85/90 法则"
- **来源**: [FlorianBruniaux/claude-code-ultimate-guide](https://github.com/FlorianBruniaux/claude-code-ultimate-guide) on GitHub | ⭐ 5.2k stars
- **摘要**: 社区实测总结的上下文容量管理经验：70% 时精度开始下降，应主动执行 `/compact`；85% 时幻觉明显增多，必须压缩或拆分任务；90% 以上响应变得不稳定，应立即 `/clear` 开新会话。与其等系统自动压缩（往往丢失关键上下文），不如在 CLAUDE.md 中设置提醒规则，让 Claude 在达到阈值时主动告知。
- **代码示例**:
```markdown
<!-- 在 CLAUDE.md 中添加上下文管理规则 -->
## 上下文管理
- 当上下文使用率接近 70% 时，主动提醒我执行 /compact
- 压缩时保留：架构决策、API 接口定义、未完成任务清单
- 如果任务复杂度超出单次会话容量，主动建议拆分并生成 HANDOFF.md
```

## 4. Git Bisect 自动化：让 Claude 自主定位引入 Bug 的提交
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 8.9k stars
- **摘要**: 结合 tmux 会话和 Claude Code，可以实现全自动的 git bisect 流程。将 Claude 放在一个 tmux 会话中，让它自主运行 `git bisect`，在每个提交上执行测试并判断 good/bad，无需人工干预就能定位到引入 bug 的精确提交。对于大型仓库中的回归 bug 排查尤其高效。
- **代码示例**:
```bash
# 启动 tmux 会话让 Claude 自主运行 bisect
tmux new-session -d -s bisect

# 在 Claude 中给出指令
git bisect start
git bisect bad HEAD
git bisect good v2.0.0

# 让 Claude 自动化整个过程
git bisect run npm test -- --testPathPattern="auth.test"

# Claude 会自动分析每个提交的测试结果，最终报告：
# "引入 bug 的提交是 abc1234，作者 xxx，修改了 src/auth/token.ts"
```

## 5. 会话分叉 (Fork)：从任意节点创建分支对话
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 8.9k stars
- **摘要**: 当你想尝试不同的实现方向但又不想丢失当前进度时，使用 `/fork` 命令或 `--fork-session` 标志从当前对话的任意节点创建分支。原对话保持不变，分叉对话继承所有上下文。适合 A/B 测试不同方案——分别在两个分支中让 Claude 实现，然后比较结果。配合别名 `--fs` 可快速启动。
- **代码示例**:
```bash
# 方法一：在当前会话中分叉
/fork

# 方法二：从命令行启动分叉会话
claude --fork-session <session-id>
# 或使用简写
claude --fs <session-id>

# 实际应用场景：比较两种实现方案
# 原会话：用 Redis 实现缓存层
# 分叉会话：用本地 LRU Cache 实现
# 两者独立执行后比较性能测试结果
```

## 7. 用 cc-copilot-bridge 实现月费固定的无限量使用
- **来源**: [FlorianBruniaux/claude-code-ultimate-guide](https://github.com/FlorianBruniaux/claude-code-ultimate-guide) on GitHub | ⭐ 5.2k stars
- **摘要**: 社区开发的 cc-copilot-bridge 工具可将 Claude Code 的请求路由到 GitHub Copilot Pro+（月费 $10），实现接近 99% 的成本节省。支持在 Anthropic 直连、Copilot 路由和本地 Ollama 模式之间切换。适合个人开发者和小团队在预算有限时大量使用 Claude Code。注意：这是社区方案，需自行评估是否符合相关服务条款。
- **代码示例**:
```bash
# 安装 cc-copilot-bridge
npm install -g cc-copilot-bridge

# 配置多提供商切换
# 日常开发用 Copilot 路由（固定月费）
cc-bridge --provider copilot

# 关键任务切换回 Anthropic 直连（按量付费，质量最高）
cc-bridge --provider anthropic

# 离线或隐私敏感场景用本地模型
cc-bridge --provider ollama --model codellama
```
