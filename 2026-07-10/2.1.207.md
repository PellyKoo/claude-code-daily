## 1. Ultracode 模式：动态工作流的并行编排
- **来源**: [Greg Isenberg](https://x.com/gregisenberg/status/2060072130339873093) on X | 🔥 高互动热帖
- **摘要**: Claude Code 的"动态工作流"功能是一个重大升级。输入"create a workflow"或在 effort 菜单中开启"ultracode"模式，Claude 会自动生成数百个并行代理，彼此交叉检查工作成果。工作单元从"单个文件"跃升到"整个项目"级别——你可以一次性交出一整个功能模块的实现，而不只是逐文件修改。
- **代码示例**:
```
# 在 effort 菜单中开启 ultracode 模式，或在提示中触发：
> 创建一个 workflow：对整个 src/ 目录进行安全审计，
  从 bugs、性能、安全三个维度并行审查，
  然后交叉验证每个发现，最后汇总报告

# Claude 会自动：
# 1. 生成 workflow 编排脚本
# 2. 启动多个并行代理分别审查
# 3. 用对抗验证筛选误报
# 4. 合成最终报告
```

## 2. 创始人的工作流：Boris Cherny 的 Claude Code 使用哲学
- **来源**: [Boris Cherny](https://x.com/bcherny/status/2007179832300581177) on X | 🔥 高互动热帖
- **摘要**: Claude Code 创始人 Boris Cherny 分享了他的使用方式，出人意料地"原生态"——他几乎不做太多定制化配置。核心洞察：Claude Code 开箱即用就很好，没有唯一正确的使用方式。他的第一条建议：给 Claude 提供**自我验证的手段**（测试、浏览器自动化、hooks），这可以将输出质量提升 2-3 倍。与其花时间写复杂的提示词，不如让 Claude 自己检查自己。
- **代码示例**:
```json
// .claude/settings.json - 配置自动验证 hooks
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "command": "npm test -- --bail 2>/dev/null || echo 'TESTS FAILED'"
      }
    ]
  }
}
```
```markdown
<!-- CLAUDE.md - 最小化但有效的配置 -->
## 验证
- 每次修改后运行 `npm test`
- 使用 Playwright 验证 UI 变更
- 提交前确保 `npm run typecheck` 通过
```

## 3. 50 条 Claude Code 实战技巧精选
- **来源**: [Miles Deutscher](https://x.com/milesdeutscher/status/2014027971254952332) on X | 🔥 高互动热帖
- **摘要**: 使用 Claude 一年后沉淀的 50 条实战技巧，涵盖隐藏功能和提示词黑科技。几个亮点：①用 `/rewind` 回退失败尝试，而不是让修正指令污染上下文；②上下文利用率超过 40% 时效果开始衰减，保持在 30% 以下最佳；③用 Plan 模式先迭代方案到满意，再切换到自动执行模式一次性落地；④为重复任务创建 slash command 而非每次重新描述。
- **代码示例**:
```bash
# 高效的两阶段工作流
# 第一阶段：Plan 模式迭代方案
claude --plan "设计用户认证模块的架构"
# 反复讨论直到方案满意

# 第二阶段：切换到执行模式
# 开启 auto-accept，让 Claude 按方案一次性实现
claude --auto-accept

# 上下文管理
/compact  # 在长会话中压缩上下文
/clear    # 上下文过大时重置
/rewind   # 回退到上一个正确状态
```

## 4. Claude Howto：10 模块渐进式学习路径
- **来源**: [luongnv89/claude-howto](https://github.com/luongnv89/claude-howto) on GitHub | ⭐ 39.7k stars
- **摘要**: 近 40k star 的视觉化实战指南，提供 10 个结构化模块的即用配置模板：Slash Commands、Memory（持久化上下文）、Skills、Subagents、MCP 协议、Hooks、Plugins、Checkpoints、高级功能和 CLI 参考。独特价值在于**功能组合模式**——将 slash commands + memory + subagents + MCP 串联成完整流水线，例如自动化代码审查管道，从统一的 memory 上下文出发，委派多个专业代理并行工作。
- **代码示例**:
```bash
# 安装预置的 slash command 模板
mkdir -p .claude/commands
# 代码优化命令
cat > .claude/commands/optimize.md << 'EOF'
分析 $ARGUMENTS 中的代码，从以下维度优化：
1. 性能瓶颈（时间和空间复杂度）
2. 可读性和可维护性
3. 错误处理完整性
给出具体的重构建议和代码示例。
EOF

# API 文档生成命令
cat > .claude/commands/api-docs.md << 'EOF'
为 $ARGUMENTS 生成 API 文档：
- 接口签名和参数说明
- 请求/响应示例
- 错误码列表
- 使用注意事项
EOF
```

## 5. Claude Code 终极指南：38 个安全 Hooks 实战
- **来源**: [FlorianBruniaux/claude-code-ultimate-guide](https://github.com/FlorianBruniaux/claude-code-ultimate-guide) on GitHub | ⭐ 5.4k stars
- **摘要**: 430K+ 行的深度指南，最大亮点是 38 个生产级 hooks 示例和 74 个 skills 模板。安全类 hooks 特别实用：`dangerous-actions-blocker` 阻止危险操作、`prompt-injection-detector` 检测注入攻击、`unicode-injection-scanner` 扫描 Unicode 注入、`output-secrets-scanner` 防止密钥泄漏。另外提出了 MCP 服务器的 5 阶段审查流程——在信任外部服务器前必须做系统化审计（已追踪 28 个 CVE 和 655 个恶意 skill）。
- **代码示例**:
```json
// .claude/settings.json - 安全防护 hooks
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "command": "bash -c 'echo \"$CLAUDE_TOOL_INPUT\" | jq -r .command | grep -qiE \"rm\\s+-rf|drop\\s+table|--force|--no-verify\" && echo \"BLOCKED: 检测到危险命令\" && exit 1 || exit 0'"
      },
      {
        "matcher": "Edit|Write",
        "command": "bash -c 'echo \"$CLAUDE_TOOL_INPUT\" | grep -qiE \"(api_key|secret|password|token)\\s*=\\s*[^$]\" && echo \"BLOCKED: 检测到硬编码密钥\" && exit 1 || exit 0'"
      }
    ]
  }
}
```

## 6. Claude Code Showcase：智能 Skill 推荐系统
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 6k stars
- **摘要**: 综合展示项目，最亮眼的是**智能 Skill 评估系统**：通过 hook 分析用户提示词，基于关键词、文件路径和意图模式自动推荐相关 skill，并用置信度评分排序建议。另外展示了 PreToolUse hooks 实现分支保护（阻止在受保护分支上编辑）、PostToolUse hooks 自动格式化和测试、以及通过 `.mcp.json` 将 JIRA、GitHub、Slack 等工具集成到 Claude 工作流中。
- **代码示例**:
```markdown
<!-- .claude/skills/testing-strategy.md -->
---
description: "Jest 测试策略和模式 - 当用户编写测试、修复测试、
  讨论测试覆盖率或提到 Jest/testing 时触发"
---

# 测试策略
- 单元测试使用 `describe/it` 结构
- Mock 外部依赖：`jest.mock('./module')`
- 每个测试文件对应一个源文件：`foo.test.ts` → `foo.ts`
- 覆盖率阈值：行覆盖 > 80%，分支覆盖 > 70%
```

## 7. 35+ Claude Code 技巧速查手册
- **来源**: [Suryanshti777](https://x.com/Suryanshti777/status/2029200211093201017) on X | 🔥 高互动热帖
- **摘要**: 2026 版速查手册，强调渐进式采用策略：先用基础 CLAUDE.md + 几个命令，在生产环境测试 2 周，再按需添加 agents/skills。几个实用建议：①CLAUDE.md 保持在 200 行以内，每条规则有明确触发条件；②用 `.claude/rules/*.md` 实现规则的按需加载（通过 YAML frontmatter 中的 paths 字段）；③在 monorepo 中利用祖先/后代 CLAUDE.md 的层级加载机制，让每个子项目继承公共配置的同时保留自己的特殊规则。
- **代码示例**:
```markdown
<!-- .claude/rules/react-patterns.md -->
---
paths:
  - "src/components/**"
  - "src/pages/**"
---

# React 模式规则（仅在编辑 React 文件时加载）
- 函数组件优先，避免 class 组件
- 使用 React.memo 包裹纯展示组件
- 自定义 hook 以 use 开头，放在 src/hooks/
- 状态管理：局部用 useState，跨组件用 Context
```
```markdown
<!-- monorepo 结构示例 -->
# /CLAUDE.md          ← 全局配置（所有子项目继承）
# /apps/web/CLAUDE.md  ← Web 前端特定规则
# /apps/api/CLAUDE.md  ← API 后端特定规则
# /packages/shared/CLAUDE.md ← 共享库规则
```
