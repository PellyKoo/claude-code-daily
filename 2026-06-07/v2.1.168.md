## 1. Dynamic Workflows：输入提示即可编排数百个并行代理
- **来源**: [Greg Isenberg](https://x.com/gregisenberg/status/2060072130339873093) on X | 🔥 高互动热门帖
- **摘要**: Claude Code 推出的 Dynamic Workflows 功能让并行开发达到新高度。在提示中输入"create a workflow"或在 effort 菜单中开启"ultracode"，Claude 会自动编排数百个并行代理，代理之间互相审查工作。工作交付单位从"单个文件"跃升为"整个功能模块"，大幅提升复杂任务的完成效率。
- **代码示例**:
```bash
# 触发 Dynamic Workflow 的方式

# 方式1：在提示中自然提及
claude "create a workflow to refactor the authentication module,
       update all tests, and migrate the database schema"

# 方式2：在 effort 菜单中选择 ultracode 模式
# Claude 会自动拆分任务 → 分配子代理 → 并行执行 → 交叉审查

# 效果：Claude 自动创建编排计划，严格按步骤执行
# - Agent A: 重构认证逻辑
# - Agent B: 更新相关测试
# - Agent C: 编写迁移脚本
# - 审查代理: 交叉检查 A/B/C 的产出
```

## 2. Auto Mode：Claude Code 创造者的头号推荐
- **来源**: [Boris Cherny](https://x.com/bcherny/status/2058519809214607704) on X | 🔥 创造者亲自推荐
- **摘要**: Claude Code 创造者 Boris Cherny 被频繁问到"最大的使用建议是什么"，他的回答是：使用 Auto Mode。Auto Mode 消除了所有权限确认弹窗，是实现"多 Claude 并行开发"的关键基石——启动一个会话后，在它运行期间可以切到另一个会话继续工作，彻底改变了开发节奏。
- **代码示例**:
```bash
# 开启 Auto Mode 的多 Claude 并行工作流

# 终端1：启动会话处理后端任务（auto mode 无需确认权限）
claude --dangerously-skip-permissions "重构 API 路由并添加测试"

# 终端2：同时处理前端任务
claude --dangerously-skip-permissions "更新 Dashboard 组件样式"

# 终端3：同时处理文档
claude --dangerously-skip-permissions "根据代码变更更新 API 文档"

# 核心要点：Auto Mode 消除权限弹窗 → 会话无需人工干预 →
# 可同时运行多个会话 → 生产力指数级提升
```

## 4. 并行 Worktrees：同时运行 3-5 个 Claude 会话的生产力秘籍
- **来源**: [Shruti](https://x.com/heyshrutimishra/status/2018368588432978151) on X | 🔥 Boris 十大技巧解读帖
- **摘要**: Shruti 总结了 Boris（Claude Code 创造者）分享的 10 个高级用户技巧，其中排名第一的是并行 Worktrees：同时开启 3-5 个 git worktree，每个运行独立的 Claude 会话。这是"大多数人错过的生产力作弊码"，将开发从串行变为真正的并行，是一种完全不同的工作方式。
- **代码示例**:
```bash
# 并行 Worktrees 实战工作流

# 1. 创建多个 worktree
git worktree add ../feature-auth -b feature/auth
git worktree add ../feature-search -b feature/search
git worktree add ../bugfix-perf -b bugfix/performance

# 2. 每个 worktree 启动独立的 Claude 会话
# 终端1:
cd ../feature-auth && claude "实现 OAuth2 登录流程"
# 终端2:
cd ../feature-search && claude "添加全文搜索功能"
# 终端3:
cd ../bugfix-perf && claude "优化数据库查询性能"

# 3. 各会话独立运行，互不干扰
# 每个 worktree 有独立的文件系统，避免冲突
# 完成后合并回主分支
```

## 7. claude-code-best-practice：56.9k Star 社区第一最佳实践库
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 56.9k stars, 5.7k forks
- **摘要**: 社区 Star 数最高的 Claude Code 实践库（v2.1.168），覆盖子代理编排、Workflows、内存管理、会话管理和 Git 集成。核心建议包括：保持会话上下文在 40% 容量以下以维持最佳智能表现；用 `/compact` 带提示词而非自动压缩；用"垂直切片"（同时跨越所有架构层）而非水平分阶段来拆分需求；以及"挑战 Claude"验证法——让 Claude 在提 PR 前先严格测试自己的代码。
- **代码示例**:
```bash
# "挑战 Claude" 验证技巧
claude "实现用户权限系统。完成后，grill me on these changes —
       假装你是严格的 code reviewer，找出所有问题，
       don't make a PR until I pass your test"

# 垂直切片开发法
claude "用垂直切片方式实现'用户收藏'功能：
       1. 数据库 migration（Prisma schema）
       2. API 路由（GET/POST/DELETE）
       3. 前端组件（收藏按钮 + 列表页）
       4. 端到端测试
       一次性贯穿所有层级"

# 上下文管理最佳实践
/compact "保留 API 设计决策和数据模型，丢弃探索性对话"
```

## 8. CLAUDE.md 现代化模板：双记忆架构 + 渐进式披露
- **来源**: [claude-code-ultimate-guide](https://github.com/FlorianBruniaux/claude-code-ultimate-guide) on GitHub | ⭐ 社区推荐深度指南
- **摘要**: 该指南对 CLAUDE.md 模板进行了现代化重构，推出三个新变体，遵循官方最佳实践。核心概念包括：双记忆架构（CLAUDE.md 作为短期记忆 + `.claude/rules/` 作为长期规则库）；渐进式披露（基础规则放 CLAUDE.md，领域规则用路径匹配延迟加载）；以及独立行为规则（每条规则自包含，不依赖上下文）。建议先从基础 CLAUDE.md + 几个 commands 开始，生产环境测试两周后再按需添加 agents 和 skills。
- **代码示例**:
```markdown
<!-- CLAUDE.md - 短期记忆（<200行） -->
# 项目概览
Next.js 15 monorepo，TypeScript strict mode

# 关键命令
- 测试: pnpm test
- 构建: pnpm build
- Lint: pnpm lint

# 核心规则
所有 API 响应使用统一的 Result<T> 类型
数据库操作必须在 transaction 中执行
```
```markdown
<!-- .claude/rules/api-patterns.md -->
---
globs: ["src/api/**", "src/routes/**"]
---
- 所有路由使用 zod schema 验证输入
- 错误响应遵循 RFC 7807 Problem Details 格式
- 必须包含 rate limiting 中间件
```
```markdown
<!-- .claude/rules/testing.md -->
---
globs: ["**/*.test.*", "**/*.spec.*"]
---
- 使用 factory 函数创建测试数据，禁止硬编码
- 每个测试文件必须有 describe 块和清晰的测试名称
- Mock 外部依赖，不 mock 内部模块
```
