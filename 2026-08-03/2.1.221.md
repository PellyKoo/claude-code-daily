# Claude Code 2.1.221 社区实用技巧 - 2026-08-03

## 1. 上下文黄金区间：保持 30-40% 以内获取最佳输出
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 64k stars, 6.4k forks
- **摘要**: 社区最高星仓库（64k stars）总结了上下文使用率与输出质量的关系：30-40% 是峰值性能区，40-60% 开始出现"上下文腐烂"（context rot），超过 300-400k tokens 后智能敏感型任务明显退化。关键技巧是手动 `/compact` 并附带提示词（hints），效果远优于自动压缩。
- **代码示例**:
```bash
# 在上下文接近 40% 时主动压缩，附带提示词保留关键信息
/compact 保留当前的数据库 schema 设计决策和 API 接口约定

# 对比效果：
# ❌ 自动压缩：可能丢失关键上下文，导致 Claude 重复提问或偏离方向
# ✅ 手动 /compact + hints：精确保留你需要的上下文，释放无关信息

# 高级用法：长会话中在"上下文腐烂点"手动压缩
# 腐烂点判断：Claude 开始重复之前的错误、忘记已有约定、输出质量下降
```

## 2. Subagent 上下文隔离：让子代理替你"读文件"
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 64k stars
- **摘要**: 与其让主会话读取大量文件（每次 Read 操作都占用宝贵上下文），不如将工具探索委派给子代理。子代理可以读取 20+ 个文件并进行分析，但只有摘要结果返回主会话。一个代理发现 bug，另一个独立代理修复——分离上下文窗口反而提高了结果质量。
- **代码示例**:
```bash
# 在 prompt 中明确要求使用 subagent 隔离
"Spawn a subagent to read and analyze all files in src/models/,
then report back only: 1) the data flow diagram,
2) any circular dependencies found."

# 结果：主会话只接收摘要，上下文几乎不增长
# 而子代理独立读取了 20+ 个文件

# 更高级：双代理 bug 修复模式
# Agent A（只读）：定位 bug 并输出诊断报告
# Agent B（读写）：根据诊断报告实施修复
# 两个代理使用独立上下文，互不干扰
```

## 3. Plan Mode 面试法：让 Claude 反问你再动手
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 64k stars
- **摘要**: 在 plan mode 下，不要直接让 Claude 开始实现。而是让它用 AskUserQuestion 工具来"面试"你——确认需求边界、技术约束、验收标准。面试过程在一个会话中完成，实际执行在另一个新会话中启动（避免面试对话污染实现上下文）。这个"原型优于 PRD"的理念认为快速构建 20-30 个版本比写详细规格书更划算。
- **代码示例**:
```bash
# Step 1: 在 plan mode 会话中面试
claude --permission-mode plan
"我要给系统添加 SSO 登录功能。
请先面试我，确认所有关键决策后再出方案。"

# Claude 会依次询问：
# - 支持哪些 SSO 协议？(SAML / OIDC / 都要)
# - 现有用户体系是什么？(JWT / session)
# - 需要处理角色映射吗？
# - 有没有现成的 IdP 可以测试？

# Step 2: 面试完成后，在新会话中执行
# 将面试摘要复制到新会话的 prompt 中
```

## 4. 日常操作技能化：高频动作变成 Slash Command
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 64k stars & [mattpocock/skills](https://github.com/mattpocock/skills) on GitHub | ⭐ 199k stars
- **摘要**: 社区共识：任何每天做一次以上的操作都应该变成 skill 或 command。Matt Pocock 的 skills 仓库（199k stars）是目前最大的技能集合，包含 37 个开箱即用的技能。Commands 放在 `.claude/commands/` 里用于内循环工作流（记得提交到 git），Skills 用于领域特定的渐进式工具。两者的关键区别：commands 是简单指令，skills 支持渐进式信息披露。
- **代码示例**:
```bash
# 创建日常 command：快速生成 PR 描述
# .claude/commands/pr-summary.md
# ---
# 分析当前分支相对 main 的所有改动，
# 生成中英双语 PR 描述，包含：
# 1. 改动摘要（一句话）
# 2. 改动详情（按文件分组）
# 3. 测试建议
# 4. 潜在风险

# 使用：
/pr-summary

# 安装社区 skills
/install-skill mattpocock/skills
# 获得 37 个即用技能，包括 /simplify, /review 等
```

## 5. 跨模型路由：让不同任务用不同模型
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 64k stars & [musistudio/claude-code-router](https://github.com/musistudio/claude-code-router) on GitHub | ⭐ 34k stars
- **摘要**: Claude Code 支持三种跨模型集成机制：Plugin（其他模型的 CLI 在 Claude Code 内运行）、MCP（通过 Model Context Protocol 调用其他模型）、Router（API 端点切换到不同 provider）。musistudio 的路由器（34k stars）支持按任务类型自动选择模型——代码审查用 Codex，快速补全用 DeepSeek，复杂推理留给 Claude。
- **代码示例**:
```bash
# 方式一：Plugin 集成（其他模型 CLI 在 Claude Code 内运行）
/codex:review  # 调用 OpenAI Codex 进行代码审查

# 方式二：Router 按任务路由
# 安装 claude-code-router
npm install -g claude-code-router

# 配置路由规则（.claude/router.json）
{
  "rules": [
    {"task": "code-review", "model": "codex"},
    {"task": "quick-completion", "model": "deepseek"},
    {"task": "complex-reasoning", "model": "claude-opus-5"}
  ]
}
```

## 6. Tracer Bullet 开发法：垂直切片优于水平分层
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 64k stars
- **摘要**: 将 PRD 拆解成"垂直切片"（tracer bullets），每个切片贯穿所有层（DB → API → UI），而非按水平层分期。每个 phase 都附带单元测试、自动化测试和集成测试。这种方式让 Claude 在每个切片内有完整上下文，输出质量远高于"先做完所有 DB、再做所有 API"的水平拆分。
- **代码示例**:
```bash
# ❌ 水平分层（效果差）
"Phase 1: 创建所有数据库表
 Phase 2: 实现所有 API
 Phase 3: 构建所有 UI"
# Claude 到 Phase 3 时已忘记 Phase 1 的表结构

# ✅ 垂直切片（效果好）
"Phase 1: 用户注册功能
  - DB: users 表 + migration
  - API: POST /register endpoint
  - UI: 注册表单 + 验证
  - Tests: 单元 + 集成测试

Phase 2: 用户登录功能
  - DB: sessions 表
  - API: POST /login + JWT
  - UI: 登录页面
  - Tests: 完整测试覆盖"

# 每个 phase 都是可独立验证的完整功能
```

## 7. "Challenge Claude" 模式：让 Claude 审查自己的改动
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 64k stars
- **摘要**: 实现完成后，不要直接提 PR。先对 Claude 说 "Grill me on these changes" 或 "Diff main vs 当前分支，作为 Staff Engineer 审查"。开第二个 Claude 会话作为高级工程师审查你的方案。社区经验：用"Knowing everything now, implement the elegant version"可以在初版基础上获得显著更优的实现。
- **代码示例**:
```bash
# 实现完成后，让 Claude 自我审查
"Grill me on these changes. Act as a staff engineer
reviewing this PR. Focus on:
1. Edge cases I might have missed
2. Performance implications
3. Security vulnerabilities
4. API contract breaking changes"

# 或者：对比 diff 审查
"diff main vs current branch and review every change
as if you were a skeptical senior engineer"

# 终极技巧：基于完整上下文重新实现
"Knowing everything now about the requirements,
edge cases, and constraints we discovered,
implement the elegant version from scratch."
```

- **来源**: [Claude Code Changelog](https://github.com/anthropics/claude-code/releases) | 🔥 2.1.221 新功能
- **摘要**: Claude Code 2.1.221 在 VS Code 中新增了 Focus View 模式——通过 `Ctrl+Alt+F` 切换，将工具调用活动隐藏在可展开的每轮摘要后面，只显示一个实时运行工具的指示器。这让开发者可以专注于对话内容，而不被大量的文件读取和编辑操作干扰。适合演示、教学和需要清爽界面的场景。
- **代码示例**:
```bash
# 在 VS Code 中使用 Focus View
# 快捷键：Ctrl+Alt+F 切换 Focus View

# 效果对比：
# 普通模式：显示每一个 Read, Edit, Bash 工具调用的详细内容
# Focus 模式：
#   ▸ [5 tool calls] 分析了项目结构并修改了 3 个文件  ← 可展开
#   🔄 Running: Edit src/auth/jwt.ts                    ← 实时指示器
#   "我已经修复了 JWT 验证的 bug..."                     ← 对话内容

# 适用场景：
# - 向非技术人员演示 Claude Code 工作过程
# - 长时间编码会话，减少视觉噪音
# - 教学场景，聚焦思路而非工具细节
```
