## 1. Git Worktree 并行会话：同一仓库多个 Claude 同时工作
- **来源**: [centminmod/my-claude-code-setup](https://github.com/centminmod/my-claude-code-setup) on GitHub | ⭐ 2.6k stars
- **摘要**: 利用 Git Worktree 功能，可以在同一仓库上同时运行多个 Claude Code 会话而互不干扰。每个 worktree 是独立的工作目录，有自己的文件状态，非常适合同时进行功能开发、bug 修复和代码审查。配合 `.worktreeinclude` 配置文件控制哪些文件在 worktree 间共享。
- **代码示例**:
```bash
# 创建并行工作区
git worktree add ../my-project-feature feature-branch
git worktree add ../my-project-bugfix bugfix-branch

# 在不同终端分别启动 Claude Code
cd ../my-project-feature && claude   # 终端 1：做新功能
cd ../my-project-bugfix && claude    # 终端 2：修 bug

# 用 .git/info/exclude 做本地忽略（不影响共享的 .gitignore）
echo "*.local" >> .git/info/exclude

# 清理完成的 worktree
git worktree remove ../my-project-feature
```

## 2. Workflow 动态编排：Claude Code 最大能力升级
- **来源**: [Thariq](https://x.com/trq212/status/2061907538741006796) on X | 🔥 高互动讨论
- **摘要**: 开发者 Thariq 深入研究了 Claude Code 的 Workflow 功能，认为这是自 Skills 和 Subagents 以来最大的能力升级。Workflow 是 Claude 即时编写的 JavaScript 文件，使用 `agent()`、`parallel()`、`pipeline()` 来编排数百个子 Agent 协同工作，每个子 Agent 拥有独立的上下文窗口。尤其令人兴奋的是它为非技术任务打开了新可能——比如并行研究、批量内容生成、多维度代码审查等。
- **代码示例**:
```javascript
// Workflow 示例：多维度并行代码审查
export const meta = {
  name: 'multi-review',
  description: '多维度并行代码审查',
  phases: [
    { title: 'Review' },
    { title: 'Verify' }
  ]
}

const DIMENSIONS = [
  { key: 'security', prompt: '审查安全漏洞...' },
  { key: 'perf', prompt: '审查性能问题...' },
  { key: 'logic', prompt: '审查逻辑错误...' }
]

// 每个维度独立审查，发现即验证，无需等待
const results = await pipeline(
  DIMENSIONS,
  d => agent(d.prompt, { phase: 'Review' }),
  review => agent(`验证: ${review}`, { phase: 'Verify' })
)
```

## 3. Hooks 三阶段防护：构建自动化安全网
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 6k stars
- **摘要**: 这个 6k Star 的示范项目展示了 Hooks 的三阶段防护模式：`PreToolUse` 在执行前拦截危险操作（如阻止在 main 分支上编辑）；`PostToolUse` 在执行后自动格式化代码并运行测试；`UserPromptSubmit` 在用户提交提示时智能评估并推荐相关 Skill。三层配合构建了一个既安全又高效的自动化开发环境。
- **代码示例**:
```json
// .claude/settings.json - Hooks 三阶段配置
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit",
        "command": "bash -c 'branch=$(git branch --show-current); [ \"$branch\" = \"main\" ] && echo \"BLOCK: 禁止在 main 分支编辑\" && exit 1 || exit 0'"
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Edit",
        "command": "npx prettier --write $CLAUDE_FILE_PATH && npx eslint --fix $CLAUDE_FILE_PATH"
      },
      {
        "matcher": "Bash",
        "command": "npm run test:affected 2>/dev/null || true"
      }
    ],
    "UserPromptSubmit": [
      {
        "command": "bash -c 'echo \"建议：检查是否有相关 Skill 可用\"'"
      }
    ]
  }
}
```

## 4. Chain of Draft 模式：子 Agent 省 80% Token
- **来源**: [centminmod/my-claude-code-setup](https://github.com/centminmod/my-claude-code-setup) on GitHub | ⭐ 2.6k stars
- **摘要**: 该仓库实现了一种名为 "Chain of Draft" 的子 Agent 模式，将代码搜索类 Agent 的输出压缩到极简格式——只返回关键结果而非完整推理过程，实测可减少约 80% 的 Token 消耗。核心思路是在 Agent 的 Skill 定义中明确指定"只输出结构化结果，省略推理过程"，让子 Agent 像草稿链一样层层精炼而非展开。
- **代码示例**:
```markdown
<!-- .claude/skills/code-searcher.md -->
---
name: code-searcher
context: fork
description: 精简搜索 Agent
---

## 输出规则
- 只返回：文件路径 + 行号 + 匹配片段
- 不要解释为什么匹配
- 不要给出使用建议
- 格式：`path:line | snippet`

## 示例输出
```
src/auth.ts:42 | const token = jwt.sign(payload, secret)
src/middleware.ts:15 | if (!req.headers.authorization)
```

# Token 对比：
# 普通模式：~5000 tokens（含推理、解释、建议）
# Chain of Draft：~1000 tokens（仅结构化结果）
```

## 5. 20 个实战快捷键与会话管理技巧
- **来源**: [Santiago](https://x.com/svpino/status/2050563493708112190) on X | 🔥 热门推文
- **摘要**: 知名开发者 Santiago 分享了 20 个 Claude Code 实战技巧，覆盖快捷键、会话管理和高级用法。其中最实用的包括：`Esc+Esc` 回退到任意检查点（可以放心让 Agent 尝试激进操作）；`Ctrl+V` 直接粘贴截图进会话；`Ctrl+G` 打开编辑器撰写长提示；`/rewind` 后接"从这里总结"来回顾关键决策点。这些技巧组合使用可以显著提升日常效率。
- **代码示例**:
```bash
# Santiago 精选实战技巧

# 快捷键类：
Esc + Esc        # 回退到任意检查点（免费撤销，放心试错）
Ctrl + V         # 粘贴截图到会话（调试 UI 神器）
Ctrl + G         # 打开编辑器写长 prompt（替代终端输入）
Ctrl + R         # 搜索历史 prompt（复用之前的好指令）

# 会话管理类：
/rewind          # 回退到检查点，然后给更精确的反馈
/rewind → "Summarize from here"  # 回顾关键决策节点

# 高级用法：
claude --resume  # 恢复上次会话
claude -p "analyze this" file.py  # 非交互式单文件处理

# 组合技巧：
# 1. 让 Claude 尝试一个激进方案
# 2. 如果失败 → Esc+Esc 回退（不污染上下文）
# 3. 给更精确的指令重试
# 4. 如果成功 → 继续下一步
```

## 6. MCP 安全五步审查法：别让恶意 Server 进你的环境
- **来源**: [FlorianBruniaux/claude-code-ultimate-guide](https://github.com/FlorianBruniaux/claude-code-ultimate-guide) on GitHub | ⭐ 5.7k stars
- **摘要**: 这个 430K+ 行的终极指南编目了 655 个恶意 Skill 的攻击模式和 28 个 CVE 映射漏洞，并提出了系统化的 MCP Server 安全审查五步法：(1) 来源验证——检查维护者身份和仓库历史；(2) 代码审查——审查工具定义和数据流；(3) 权限审计——最小权限原则；(4) 沙箱测试——在隔离环境中试运行；(5) 持续监控——定期复审已安装的 Server。在 MCP 生态野蛮生长的今天，这套流程非常必要。
- **代码示例**:
```bash
# MCP Server 安全审查清单

# 步骤 1：来源验证
# ✅ 检查 GitHub 仓库的 star、commit 历史、维护者
# ✅ 查看 issue/PR 是否有安全报告
# ❌ 避免：无 README、低 star、新创建的账号

# 步骤 2：代码审查
# 重点检查工具定义中的数据流向
grep -r "fetch\|exec\|spawn\|eval" src/  # 搜索危险调用

# 步骤 3：权限审计
# MCP Server 声明了哪些权限？是否超出必要？
cat mcp-config.json | jq '.tools[].permissions'

# 步骤 4：沙箱测试
# 在隔离环境中先试运行
claude --sandbox --mcp-config test-mcp.json

# 步骤 5：持续监控
# 定期检查已安装 Server 的更新和安全公告
claude /doctor   # 环境诊断
```

## 7. Usage Limit 滚动窗口策略：别把一天的额度一早烧光
- **来源**: [Ruben Hassid](https://x.com/rubenhassid/article/2043177416164815308) on X | 🔥 热门长文
- **摘要**: Ruben Hassid 揭示了 Claude 使用限额的一个关键机制：限额基于**滚动 5 小时窗口**而非每日固定重置。这意味着如果你早上一口气用完全部额度，你大部分工作时间都在等待。最优策略是将工作分成 2-3 个时段（早、中、晚），每个时段适度使用——当你回来时，之前的使用量已经从窗口中滚出。避免在一个长会话中无节制使用。
- **代码示例**:
```bash
# 使用限额优化策略

# ❌ 错误方式：一早上烧完全部额度
# 9:00-11:00  疯狂使用 ████████████ 100%
# 11:00-17:00 等待恢复... ░░░░░░░░░░░

# ✅ 正确方式：分时段使用
# 9:00-10:30  适度使用 ████░░ 40%
# 10:30-12:00 自然恢复 → 额度回滚
# 13:00-14:30 适度使用 ████░░ 40%
# 14:30-16:00 自然恢复 → 额度回滚
# 16:00-17:30 适度使用 ████░░ 40%

# 实用技巧：
/cost           # 检查当前会话花费
/tokens         # 查看 token 使用量

# 配合上下文管理减少不必要消耗：
/compact        # 压缩上下文（减少后续 token 消耗）
/clear          # 切换任务时清空（避免携带旧上下文）
```

## 8. 自定义 Slash Command：打造团队标准工作流
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 6k stars
- **摘要**: 该项目展示了如何通过自定义 Slash Command 将团队常用操作标准化。例如 `/onboard` 自动分析代码库并生成新成员入门指南，`/ticket` 对接 JIRA 自动拉取需求上下文，`/pr-review` 执行标准化代码审查流程，`/docs-sync` 同步文档与代码变更。这些命令配合 MCP Server（JIRA、Slack、数据库）使 Claude Code 成为团队协作的中枢。
- **代码示例**:
```markdown
<!-- .claude/commands/onboard.md -->
分析当前代码库并生成入门文档：
1. 识别技术栈和框架版本
2. 绘制目录结构和模块依赖图
3. 列出关键配置文件及其作用
4. 总结编码规范和提交约定
5. 输出到 docs/onboarding.md

<!-- .claude/commands/pr-review.md -->
对当前分支执行标准化代码审查：
1. 运行 `git diff main...HEAD`
2. 按维度检查：类型安全、错误处理、测试覆盖
3. 检查是否有遗漏的 mutation 副作用
4. 输出结构化审查报告

<!-- 使用方式 -->
<!-- 在 Claude Code 中直接输入: -->
<!-- /onboard -->
<!-- /pr-review -->
<!-- /ticket PROJ-1234 -->
```
