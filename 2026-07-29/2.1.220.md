# Claude Code 2.1.220 社区实用技巧 - 2026-07-29

## 1. PreToolUse Hook 守护主分支：从源头阻止误操作
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 6k stars
- **摘要**: 在 `settings.json` 中配置 PreToolUse 钩子，当 Claude 尝试编辑文件时自动检查当前 Git 分支。如果在 main/master 上，钩子返回 exit code 2 直接阻断操作，比口头提醒 "不要在主分支上改代码" 可靠得多。这是确定性守护，不依赖模型理解指令。
- **代码示例**:
```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "command": "branch=$(git branch --show-current 2>/dev/null); if [ \"$branch\" = \"main\" ] || [ \"$branch\" = \"master\" ]; then echo 'ERROR: Cannot edit files on main branch. Create a feature branch first.' >&2; exit 2; fi"
      }
    ]
  }
}
```

## 2. 上下文 40% 警戒线：主动 /compact 防止质量衰减
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 63.8k stars
- **摘要**: 社区经验表明，当上下文使用量超过 40% 时，Claude 的输出质量开始明显下降。最佳实践是在接近 40% 时主动执行 `/compact`，并附带提示语（hint）告诉 Claude 压缩时应保留哪些关键信息，而不是等系统自动压缩导致重要上下文丢失（"上下文腐烂"）。
- **代码示例**:
```
# 查看当前上下文使用量（状态栏或输入框旁会显示百分比）
# 当接近 40% 时，主动执行带 hint 的压缩：

/compact 保留：当前任务目标是重构 auth 模块，已完成 JWT 验证部分，
待处理 OAuth 回调和 rate limiting。关键文件：src/auth/jwt.ts 和 src/auth/oauth.ts

# 错误做法：等自动压缩，或不带 hint 直接 /compact
```

## 3. PostToolUse 自动质量门：每次编辑自动格式化+测试
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 6k stars
- **摘要**: 配置 PostToolUse 钩子，在每次文件编辑后自动运行 Prettier 格式化和相关测试。这让代码风格和测试验证成为自动化流水线的一部分，而不是依赖 Claude 记得去做。搭配 PreToolUse 的分支守护，形成完整的"编辑安全网"。
- **代码示例**:
```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "command": "npx prettier --write \"$CLAUDE_FILE_PATH\" 2>/dev/null; npm test -- --findRelatedTests \"$CLAUDE_FILE_PATH\" --passWithNoTests 2>/dev/null || true"
      }
    ]
  }
}
```

## 4. 挑战式开发：让 Claude 自证代码正确性
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 63.8k stars
- **摘要**: 不要被动接受 Claude 的实现——要求它"证明这段代码有效"。具体方法是让 Claude 执行 `git diff main` 对比变更，然后逐一验证每个改动的正确性。这种"挑战驱动开发"模式把 Claude 从执行者变成了需要自证的开发者，显著减少"看着合理但实际有 bug"的代码。
- **代码示例**:
```
# 实现功能后，不要直接说"looks good"
# 而是要求 Claude 自证：

"Now prove this works:
1. Run git diff main to show all changes
2. For each changed file, explain why the change is correct
3. Identify any edge cases that aren't handled
4. Write and run a test that exercises the critical path"

# 更进一步：让第二个 Claude 实例做独立审查
# （参见前天的双 Agent 对审模式）
```

## 5. DX 插件：一键安装社区最佳实践技能包
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 9.5k stars
- **摘要**: ykdojo 推出的 DX（Developer Experience）插件将社区高频使用的技能打包：`/dx:gha` 自动分析 GitHub Actions 失败原因、`/dx:handoff` 生成交接文档、`/dx:context` 减少上下文消耗、`/dx:reddit` 从 Reddit 获取相关讨论。两条命令完成安装，立即可用。
- **代码示例**:
```bash
# 安装 DX 插件
cd your-project
claude "/install-plugin ykdojo/dx"

# 使用示例
/dx:gha          # CI 失败了？自动分析日志定位问题
/dx:handoff      # 生成任务交接文档，方便同事接手
/dx:context      # 分析并减少不必要的上下文消耗
```

## 6. CLAUDE.md 瘦身术：200 行以内 + rules 目录拆分
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 63.8k stars
- **摘要**: 社区共识是 CLAUDE.md 应控制在 200 行以内。超过这个长度说明你把领域知识塞进了全局指令——正确做法是用 `.claude/rules/` 目录按领域拆分。同时使用 `<important if="...">` 条件标签防止指令在文件增长后被"稀释"——只在特定条件下才加载特定指令段。
- **代码示例**:
```
# 项目结构示例
CLAUDE.md                          # ≤200 行：项目概览、关键命令、代码规范
.claude/rules/
├── frontend.md                    # React/组件相关规则
├── api.md                         # API 设计和端点规范
├── database.md                    # 数据库迁移和查询规范
└── testing.md                     # 测试策略和覆盖率要求

# CLAUDE.md 中使用条件标签
<important if="editing files in src/auth/">
认证模块使用 JWT + refresh token 双 token 机制，
修改时必须同时更新 token 验证和刷新逻辑。
</important>
```

## 7. Skill 目录映射：基于文件路径自动推荐技能
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 6k stars
- **摘要**: 通过配置文件路径到技能（Skill）的映射关系，当你编辑特定目录的文件时，系统自动推荐最相关的技能。配合关键词匹配和意图识别的置信度评分（keyword=2分, directoryMatch=5分, intentPattern=4分），实现"编辑什么文件就自动加载什么领域知识"的智能体验。
- **代码示例**:
```json
{
  "skillMapping": {
    "src/components/core": "core-components",
    "src/graphql": "graphql-schema",
    "src/forms": "formik-patterns",
    ".github/workflows": "github-actions",
    "src/__tests__": "testing-patterns"
  }
}
```
```
# 当你在 src/graphql/ 下编辑文件时，
# 系统自动推荐 graphql-schema skill（置信度 5 分）
# 无需手动 /skill graphql-schema

# 置信度计算示例：
# 编辑 src/graphql/schema.ts + 提问 "add mutation"
# directoryMatch: 5 + keyword("mutation"): 2 + intentPattern("add"): 4 = 11 分
# → 高置信度，自动加载 graphql-schema skill
```
