## 1. 动态 Workflows：让 Claude 自动编排多阶段任务
- **来源**: [cat (catwu)](https://x.com/_catwu/status/2060054180379689074) on X | 🔥 Claude Code 团队成员发布，高互动帖
- **摘要**: 在 prompt 中提到 "workflow" 关键词，Claude 会动态生成一个编排计划并严格按顺序执行。每个阶段按正确顺序完成，无需手动拆分任务。适合多文件迁移、跨模块重构、分阶段审查等场景。这是自 skills 和 subagents 以来最大的能力升级。
- **代码示例**:
```bash
# 在 prompt 中使用 "workflow" 触发动态编排
> Create a workflow to refactor the payment module:
  1. Audit all payment-related files
  2. Extract shared types into a common module
  3. Update each service to use the new types
  4. Run tests after each change
  5. Generate a summary of all modifications
```

## 2. Workflows 最佳实践：非技术任务也能编排
- **来源**: [Thariq](https://x.com/trq212/status/2061907538741006796) on X | 🔥 高互动深度分析帖
- **摘要**: Workflows 不仅适用于代码任务，还能用于非技术性工作——比如生成市场调研报告、整理竞品分析、批量处理文档等。关键是把任务拆成明确的阶段，每个阶段有清晰的输入输出。Thariq 与 @sidbid 深入研究了 workflows 的最佳实践，发现 pipeline 模式（无屏障）比 parallel+barrier 模式在大多数场景下更高效。
- **代码示例**:
```bash
# 非技术任务的 workflow 示例
> Create a workflow for competitive analysis:
  1. Search for top 5 competitors in the AI coding space
  2. For each competitor, analyze pricing, features, and reviews
  3. Create a comparison matrix
  4. Generate a strategic recommendations document

# pipeline 模式 vs barrier 模式
# pipeline: 每个 item 独立流过所有阶段，无等待
# barrier (parallel): 等所有 item 完成后再进入下一阶段
# 默认选择 pipeline，仅在需要跨 item 去重时使用 barrier
```

## 3. 并行 Worktrees：同时运行 3-5 个 Claude 会话
- **来源**: [Shruti](https://x.com/heyshrutimishra/status/2018368588432978151) on X | 🔥 高互动帖，引用 Boris (Claude Code 创建者) 的建议
- **摘要**: Claude Code 创建者 Boris 分享的第一条高级技巧：用 git worktree 创建 3-5 个独立的工作目录，每个目录运行一个 Claude 会话，实现真正的并行开发。每个 worktree 有自己的文件状态，不会互相干扰。这是单人开发者最大的生产力提升——相当于同时有多个"你"在并行工作。
- **代码示例**:
```bash
# 创建多个 git worktree 并行工作
git worktree add ../project-auth feature/auth
git worktree add ../project-api feature/api
git worktree add ../project-ui feature/ui

# 在每个 worktree 中启动独立的 Claude 会话
cd ../project-auth && claude
cd ../project-api && claude
cd ../project-ui && claude

# 完成后清理 worktree
git worktree remove ../project-auth
git worktree remove ../project-api
git worktree remove ../project-ui
```

## 4. 50 条 Claude Code 速查技巧：隐藏功能与 Prompt 模式
- **来源**: [Miles Deutscher](https://x.com/milesdeutscher/status/2014027971254952332) on X | 🔥 百万粉丝级博主，高互动帖
- **摘要**: 使用 Claude Code 一年后总结的 50 条常用技巧，采用速射风格方便快速阅读。核心要点包括：(1) 用 `/compact` 加提示词比自动压缩效果更好；(2) 挑战式 prompt "grill me on these changes" 可以防止提交半成品代码；(3) 功能特定的 subagent 比通用 "QA engineer" agent 效果更好；(4) 用 `/rewind` 回退失败的尝试而不是在上下文中留下修正痕迹。
- **代码示例**:
```bash
# 带提示词的 compact，比自动压缩更精准
> /compact focus on the authentication refactoring decisions

# 挑战式 prompt，提交前自审
> Grill me on these changes. What edge cases am I missing?
  What could break in production? Be harsh.

# 用 /rewind 代替在上下文中修正
# 错误做法：在失败的上下文中继续修复
# 正确做法：
> /rewind
# 然后用新的方法重新开始
```

## 5. CLAUDE.md 模板集合：按技术栈定制配置
- **来源**: [abhishekray07](https://github.com/abhishekray07/claude-md-templates) on GitHub | ⭐ 社区模板项目
- **摘要**: 提供按技术栈分类的 CLAUDE.md 模板——Next.js、FastAPI、通用项目各有专属模板。核心理念：与其从零开始写 CLAUDE.md，不如从一个匹配你技术栈的模板开始，然后根据项目特性定制。每个模板都控制在合理行数内（避免超过 80 行导致 Claude 忽略部分内容），且包含该技术栈最常见的约定和最佳实践。
- **代码示例**:
```markdown
<!-- Next.js CLAUDE.md 模板核心结构 -->
# Project: [Name]

## Stack
- Next.js 15 with App Router
- TypeScript strict mode
- Tailwind CSS + shadcn/ui

## Commands
- `npm run dev` - development server
- `npm run build` - production build
- `npm test` - run tests

## Rules
- Use server components by default
- Client components only for interactivity
- All API routes in app/api/
- Zod for all input validation
```

## 6. 记忆银行系统：跨会话持久化 Claude 的学习成果
- **来源**: [centminmod](https://github.com/centminmod/my-claude-code-setup) on GitHub | ⭐ 2,500 stars, 238 forks
- **摘要**: 一个双层记忆架构——Git 共享的 CLAUDE-*.md 文件 + 机器本地的自动记忆，确保跨会话知识持续积累。使用渐进式披露（progressive disclosure），记忆文件按需加载而非全部自动加载，避免浪费上下文窗口。还包含一个 shell 函数快速创建隔离的 git worktree，以及安装 ripgrep、fd、jq 等命令行工具来加速文件操作的建议。
- **代码示例**:
```bash
# 安装推荐的命令行工具加速 Claude 操作
brew install ripgrep fd jq  # macOS
apt install ripgrep fd-find jq  # Ubuntu/Debian

# 初始化记忆银行
> /init
# Claude 会分析你的代码库并填充记忆文件

# 记忆文件结构
# CLAUDE.md          - 核心项目指令（Git 共享）
# CLAUDE.local.md    - 个人偏好（本地不提交）
# .claude/rules/     - 拆分的行为规则
# memory-bank/       - 持久化的模式和决策
```

## 7. Claude Code 创建者的完整工作流解析
- **来源**: [josh](https://x.com/joshycodes/status/2008019582150426799) on X | 🔥 高互动帖
- **摘要**: 深入分析了 Claude Code 创建者的日常工作流程。核心发现：(1) 每个项目保持一个精简的 CLAUDE.md，不超过 60 行；(2) 大量使用自定义 slash commands 把重复操作变成一键命令；(3) 用 plan mode 先规划再执行，避免 Claude 过早动手；(4) 保持短会话——宁可多开几个新会话，也不要让单个会话的上下文膨胀到影响质量。
- **代码示例**:
```bash
# Plan mode 先规划再执行
> /plan Redesign the notification system to support
  real-time push, email digest, and in-app alerts.
# Claude 会输出详细计划而不直接改代码
# 确认计划后再执行

# 创建自定义 slash command
# .claude/commands/deploy-check.md:
# Run the full deployment checklist:
# 1. Run all tests
# 2. Check for uncommitted changes
# 3. Verify environment variables
# 4. Build the project
# 5. Report any issues found

# 然后直接使用
> /deploy-check
```
