# Claude Code 2.1.322 社区实用技巧 - 2026-11-10

## 1. 任务间及时清理上下文，大幅节省 Token
- **来源**: [0xKense1](https://x.com/0xKense1/article/2111105138290987198) on X | 🔥 945 次实测验证
- **摘要**: 在不相关任务之间使用 `/clear` 是测试中节省 Token 最多的操作。如果需要保留部分上下文，用 `/compact` 压缩当前对话。这个习惯能显著降低每日用量。
- **代码示例**:
```bash
# 完成一个任务后，开始新任务前
/clear

# 或者保留关键上下文但压缩对话
/compact
```

## 2. 用 Esc+Esc 回退检查点，放心让 Agent 尝试高风险操作
- **来源**: [Santiago (@svpino)](https://x.com/svpino/status/2050563493708112190) on X | 🔥 大量转发的 20 条技巧合集
- **摘要**: 双击 Esc 键可以回退到之前的检查点（rewind），相当于免费的撤销功能。有了这个安全网，你可以放心让 Claude 尝试有风险的代码变更，不满意随时回退。
- **代码示例**:
```bash
# 在 Claude Code 中按两次 Esc 键
# 或使用命令
/rewind
```

## 3. 用 Git Worktree 实现多任务并行开发
- **来源**: [mvanhorn](https://x.com/mvanhorn/article/2035857346602340637) on X | 🔥 系列文章持续更新至 2026年10月
- **摘要**: 使用 `claude --worktree` 启动隔离的工作树会话，多个 Claude Code 实例可以同时处理不同任务而互不干扰。适合同时修复多个 bug 或并行开发多个功能。
- **代码示例**:
```bash
# 在隔离的 worktree 中启动 Claude Code
claude --worktree

# 每个 worktree 有独立的文件副本，不会冲突
```

## 4. 将长规则移入 Skills，保持 CLAUDE.md 精简
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 社区最佳实践仓库
- **摘要**: CLAUDE.md 控制在 200 行以内，把详细的规则和流程移到 Skills 文件中。Skills 只在相关时加载，不会浪费基础上下文窗口。测试表明，把长规则放在 CLAUDE.md 比用 Skill 引用每次多消耗明显更多 Token。
- **代码示例**:
```markdown
<!-- CLAUDE.md 中只放一行引用 -->
For deployment rules, see @.claude/skills/deploy.md

<!-- .claude/skills/deploy.md 中放详细规则 -->
# Deploy Skill
When deploying, run tests first...
```

## 5. 用 @ 直接引用文件，跳过搜索步骤
- **来源**: [Santiago (@svpino)](https://x.com/svpino/status/2029645889980305777) on X | 🔥 18 条技巧演讲总结
- **摘要**: 使用 `@filename.py` 或 `@src/classes/` 直接引用文件和目录，让 Claude 跳过搜索步骤直接定位到目标。文件会自动加入上下文，后续对话中无需重复指定。
- **代码示例**:
```bash
# 在提示中直接引用文件
"请检查 @src/auth/login.ts 中的安全问题"

# 引用整个目录
"重构 @src/components/ 下所有组件的状态管理"
```

## 6. 修复 Claude Code "偷懒"行为：系统提示的不平衡问题
- **来源**: [Elie Steinbock (@elie2222)](https://x.com/elie2222/status/2041477770245451885) on X | 🔥 社区广泛讨论
- **摘要**: Claude Code 的系统提示中有约 20 处指示"保持精简"，但只有 4 处指示"保持详尽"，比例为 5:1 倾向于简化输出。可以通过在 CLAUDE.md 中添加明确的详尽指令来纠正这个偏差。
- **代码示例**:
```markdown
<!-- 在 CLAUDE.md 中添加 -->
When implementing features, write complete implementations.
Do not leave placeholder comments like "// TODO" or "// implement here".
Write all necessary code including error handling and edge cases.
```

## 7. 给 Claude 一个自我检查的反馈循环
- **来源**: [CodevolutionWeb (@Vishwas)](https://x.com/CodevolutionWeb/status/2034683638382506063) on X | 🔥 50 条最佳实践合集
- **摘要**: 在提示中包含测试命令、Linter 检查或预期输出，让 Claude 能自行验证结果并修复错误。对 UI 工作可以添加 Playwright MCP 服务器进行可视化验证。
- **代码示例**:
```markdown
<!-- 在 CLAUDE.md 中配置 -->
After making changes, always run:
- `npm run test` to verify tests pass
- `npm run lint` to check code style
- `npm run typecheck` to verify types

Fix any failures before reporting completion.
```

## 8. 注意安全：警惕权限配置中的密钥泄露风险
- **来源**: [X 热门话题](https://x.com/i/trending/2119093916985180458) on X | 🔥 2026年11月安全研究热议
- **摘要**: 安全研究发现约 10 万个公开文件中泄露了 1,122 到 2,539 个密钥，源于 Claude Code 的"不再询问"权限设置会将包含数据库密码和 AWS Key 的命令以明文保存在配置文件中。务必配置严格的 `.gitignore` 并定期扫描。
- **代码示例**:
```bash
# .gitignore 中确保包含
.claude/settings.local.json
.claude/statsig/

# 定期扫描敏感信息
git secrets --scan
# 或使用 trufflehog
trufflehog filesystem .
```

## 9. 定期审计已安装的 Skills，清理冗余
- **来源**: [Prajwal Tomar (@PrajwalTomar_)](https://x.com/PrajwalTomar_/status/2074787074641899896) on X | 🔥 实用清理建议
- **摘要**: 将技巧文章粘贴到 Claude Code 会话中，让它对比你当前安装的所有 Skills，自动卸载重叠、从未触发或功能较弱的 Skill。保持精简的 Skill 列表能提升响应速度和准确性。
- **代码示例**:
```bash
# 在 Claude Code 中执行
"列出我当前安装的所有 skills，对比这篇文章，
卸载任何重叠、从未触发或有更好替代的 skill"
```
