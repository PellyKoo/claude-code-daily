# Claude Code 2.1.200 社区实用技巧 - 2026-07-02

## 1. 监控上下文窗口使用率，避免"上下文腐烂"
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 61.9k stars
- **摘要**: 当上下文使用率超过 40% 时，模型性能会明显下降。有经验的用户建议将使用率控制在 30% 以下，只有简单任务才推到 60%。使用 `/compact` 手动压缩比自动压缩效果更好，因为你可以附加提示词引导压缩方向。
- **代码示例**:
```bash
# 手动压缩并附加提示
/compact 保留所有关于认证模块的上下文

# 在每个 Claude 回合后评估：继续、/rewind、/clear、/compact 或派生子代理
```

## 2. 用 /rewind 回退而不是用更多提示纠正错误
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 61.9k stars
- **摘要**: 当 Claude 走错方向时，不要用新提示去纠正（这会污染上下文），而是按两次 `Esc` 或使用 `/rewind` 回退到错误之前的状态，然后带着教训重新提示。还可以在回退前用"summarize from here"生成过渡笔记，相当于未来的 Claude 给过去的自己传话。
- **代码示例**:
```bash
# 双击 Esc 回退到上一个检查点
Esc + Esc

# 或使用命令
/rewind
```

## 3. CLAUDE.md 保持精简：60 行理想，不超过 200 行
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 61.9k stars
- **摘要**: 过长的 CLAUDE.md 会导致 Claude 忽略关键指令。对每一行自问：删掉它会不会导致 Claude 犯错？如果不会就删掉。对于只在特定场景需要的领域知识，使用 `.claude/rules/*.md` 按文件模式懒加载，避免每次会话都加载全部指令。
- **代码示例**:
```markdown
# .claude/rules/react-components.md
---
paths:
  - "src/components/**/*.tsx"
---
使用函数组件和 hooks，不使用 class 组件。
所有组件必须有 TypeScript Props 接口定义。
```

## 4. 使用 Thinking 关键词控制推理深度
- **来源**: [zebbern](https://github.com/zebbern/claude-code-guide) on GitHub | ⭐ 4.4k stars
- **摘要**: 在提示词中加入特定关键词可以让 Claude 进行更深层次的规划思考，按 token 消耗从低到高排列。对于复杂架构决策使用 `ultrathink`，对于日常任务用默认即可，选择能解决问题的最低级别以减少延迟和成本。
- **代码示例**:
```bash
# 从低到高的思考深度
"think"        # 基础思考
"think hard"   # 更深入
"think harder" # 深度分析
"ultrathink"   # 最大深度

# 示例
"Ultrathink. 设计一个方案来修复不稳定的测试用例。"
```

## 5. 用 Git Worktree 隔离实现安全的并行开发
- **来源**: [zebbern](https://github.com/zebbern/claude-code-guide) on GitHub | ⭐ 4.4k stars
- **摘要**: 使用 `claude -w` 在隔离的 git worktree 中启动 Claude，所有更改都在隔离环境中提交，工作目录保持干净。可以配置基准引用为 `fresh`（从远程默认分支创建）或 `head`（从本地 HEAD 创建）。
- **代码示例**:
```bash
# 在隔离的 worktree 中实现功能
claude -w "实现用户认证功能"

# 配置基准引用
claude config set worktree.baseRef "fresh"  # 从 origin/default 分支
claude config set worktree.baseRef "head"   # 从本地 HEAD 分支
```

## 6. 定义专用子代理限制工具集
- **来源**: [zebbern](https://github.com/zebbern/claude-code-guide) on GitHub | ⭐ 4.4k stars
- **摘要**: 在 `.claude/agents/` 目录下创建专用代理，限制其可用工具和提示词范围。每个代理拥有独立的上下文窗口，只继承指定的工具，产出更干净的输出和更精准的修改。适合代码审查、安全检查等专项任务。
- **代码示例**:
```markdown
# .claude/agents/code-reviewer.md
---
name: code-reviewer
tools: Read, Glob, Grep
disallowedTools: Write, Edit
---
审查代码质量和安全性，检查潜在的性能问题。
```

## 7. Ctrl+B 将长时间任务移至后台
- **来源**: [zebbern](https://github.com/zebbern/claude-code-guide) on GitHub | ⭐ 4.4k stars
- **摘要**: 运行测试套件或大规模重构时，使用 `Ctrl+B` 将当前操作移到后台继续执行，你可以在前台继续其他工作。也可以直接用 `claude --bg` 启动后台会话，用 `/tasks` 管理所有后台任务。
- **代码示例**:
```bash
# 将当前运行中的命令移到后台
Ctrl+B

# 直接启动后台会话
claude --bg "npm test"

# 查看和管理后台任务
/tasks
```

## 8. 用 /insights 生成个人使用习惯报告
- **来源**: [zebbern](https://github.com/zebbern/claude-code-guide) on GitHub | ⭐ 4.4k stars
- **摘要**: `/insights` 命令会生成一份交互式的使用分析报告，包括工具使用频率、编程语言分布、常见摩擦点，以及针对你的 CLAUDE.md 的个性化改进建议。帮助你了解自己的使用模式并持续优化工作流。
- **代码示例**:
```bash
# 生成使用洞察报告
/insights
# 报告位置: ~/.claude/usage-data/report.html
```
