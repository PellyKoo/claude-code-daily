## 1. 20 条 Claude Code 实战技巧速查表
- **来源**: [Santiago](https://x.com/svpino/status/2050563493708112190) on X | 🔥 高互动推文
- **摘要**: 开发者 Santiago 整理了 20 条精炼的 Claude Code 日常技巧。社区反响最大的几条：`Esc+Esc` 可以回退到任意检查点，相当于免费的撤销操作，适合让 Agent 放手尝试高风险修改；`Ctrl+V` 直接粘贴截图进终端（比描述 UI bug 快 10 倍）；`Ctrl+G` 打开编辑器写长提示词（告别终端里反复按退格键的痛苦）；`/rewind → "Summarize from here"` 可以在回退后让 Claude 总结之前的探索结果，避免重复劳动。
- **代码示例**:
```bash
# 常用快捷键速查
Esc+Esc    # 回退到检查点（免费撤销）
Ctrl+V     # 粘贴截图
Ctrl+G     # 打开编辑器写长提示词
Ctrl+R     # 搜索历史提示词
/rewind    # 回退并重试

# 回退后保留探索成果
/rewind
> Summarize from here
# Claude 会总结之前的尝试，然后你可以给更精确的指令
```

- **摘要**: Claude Code 推出了"动态工作流"功能，在提示中提到 "workflow" 或开启 "ultracode" 模式后，Claude 会自动拆分任务并启动数百个并行 Agent，彼此交叉验证工作成果。这把单次能交付的工作单位从"一个文件"提升到了"一整个功能模块"。社区开发者反馈：对于大型重构、代码审查和跨文件迁移等场景，效率提升显著。
- **代码示例**:
```bash

"create a workflow to refactor the auth module across all services"

# 方式 2：通过 effort menu 开启 ultracode 模式
# 开启后所有复杂任务自动使用动态工作流

# 适用场景：
# - 大规模代码重构（跨 10+ 文件）
# - 全面代码审查（多维度并行检查）
# - 数据库 migration 生成与验证
# - 跨服务 API 接口对齐
```

## 5. CLAUDE.md 黄金法则：60-400 行最佳实践
- **来源**: [claude-code-ultimate-guide](https://github.com/FlorianBruniaux/claude-code-ultimate-guide) on GitHub | ⭐ 5.7k stars, 751 forks
- **摘要**: 拥有 5700+ Star 的社区指南项目总结了 CLAUDE.md 配置的核心原则：文件长度保持在 100-400 行之间，少于 100 行会缺失关键上下文，超过 400 行 Claude 会开始忽略部分内容（HumanLayer 团队的经验是控制在 60 行以内效果最好）。另一个关键发现：在上下文容量达到 70% 时精确度开始下降，85%+ 会显著增加幻觉，建议在 70% 时使用 `/compact`，90% 时强制 `/clear`。
- **代码示例**:
```markdown
# CLAUDE.md 配置层级（三级覆盖）
~/.claude/CLAUDE.md       # 全局：个人偏好（所有项目生效）
.claude/CLAUDE.md         # 项目级：团队共享（提交到 Git）
./CLAUDE.local.md         # 本地：个人覆盖（gitignore）

# 上下文健康管理
/compact    # 70% 上下文时压缩（精确度保护）
/clear      # 90% 上下文时清空（防止幻觉）

# CLAUDE.md 精简原则：
# ✅ 项目架构、技术栈、测试命令、编码规范
# ❌ 通用编程知识、显而易见的规则、冗长示例
```

## 7. 35+ Claude Code 技巧合集（2026 版）
- **来源**: [Suryanshti](https://x.com/Suryanshti777/status/2029200211093201017) on X | 🔥 热门技巧合集
- **摘要**: 开发者整理的 35+ 条 Claude Code 技巧，覆盖 2026 年新增的全部核心功能。社区特别推荐的实战技巧包括：使用 `/memory` 保存跨项目的个人偏好（如代码风格、常用框架配置）；通过 `.claudeignore` 文件排除不需要 Agent 读取或修改的路径（类似 .gitignore 语法）；以及利用 Hooks 机制让 Claude 在每次编辑后自动运行 lint 和类型检查，把错误消灭在提交之前。
- **代码示例**:
```bash
# /memory：保存持久化偏好
/memory
> 我偏好使用 TypeScript strict 模式
> 测试框架统一使用 Vitest
> 组件命名使用 PascalCase

# .claudeignore：排除不相关路径
echo "node_modules/
dist/
*.log
.env*
coverage/" > .claudeignore

# Hooks：编辑后自动校验
# 在 .claude/settings.json 中配置：
{
  "hooks": {
    "post-edit": "npm run lint && npm run typecheck"
  }
}
```

## 8. 上下文工程：给 Claude 建立"工作记忆"
- **来源**: [Coffee with One](https://x.com/coffeewithone/status/2007466193473745043) on X | 🔥 最佳实践讨论
- **摘要**: 开发者强调直接阅读 Claude Code 创始人 Boris 的工作流建议可以节省 10 倍工程时间。核心洞察：给 Claude 提供验证自身工作的手段（测试、浏览器自动化、Hooks）比给它更详细的需求描述更重要，因为自我纠错循环可以将输出质量提升 2-3 倍。另一个关键实践：利用 CLAUDE.md 的三级层级（全局/项目/本地）建立持久的"工作记忆"，避免每次新会话都从零开始解释项目背景。
- **代码示例**:
```bash
# 自我验证循环示例
"添加用户注册 API endpoint。
验证方式：
1. 运行 npm test -- --grep 'register'
2. 用 curl 测试 API 端点
3. 检查数据库是否正确写入

每步失败就修复后重试，全部通过后告诉我。"

# CLAUDE.md 建立工作记忆
# ~/.claude/CLAUDE.md（全局偏好）
## 个人编码规范
- 变量命名：camelCase
- 错误处理：始终使用 try-catch + 自定义 Error 类
- 提交信息：Conventional Commits 格式
```
