## 1. 小任务 + /clear 策略：降低 Token 消耗，提升输出质量
- **来源**: [Julio César Fernández (@jcfmunoz)](https://x.com/jcfmunoz/status/2038288124577562714) on X | 🔥 高互动推文
- **摘要**: 长会话会不断拖拽旧上下文（文件读取、日志、工具输出），导致 Token 消耗增加、噪音变多、Claude 注意力下降。最佳工作流是：每次只做一个明确的小任务，完成后立即 `/clear` 清空上下文再开始下一个。Julio 实测中 Claude 在会话末尾主动提示 "new task? /clear to save 412K tokens"，证明上下文越多，响应质量越差。小任务 = 更干净的上下文 = 更低的 Token 费用 = 更好的结果。
- **代码示例**:
```bash
# 推荐工作流
> 修复 auth 模块的登录 bug
# Claude 完成修复
/clear
> 给 user 模块添加分页功能
# Claude 完成功能
/clear
> 写 auth 模块的单元测试

# 避免：在一个超长会话里混杂不相关任务
```

## 2. Dynamic Workflows：用 "ultracode" 触发多 Agent 并行协作

## 3. CLAUDE.md 错误自纠：让 Claude 自己写规则防止重复犯错
- **来源**: [mvanhorn](https://x.com/mvanhorn/article/2035857346602340637) on X | 🔥 热门 Claude Code 技巧合集
- **摘要**: 当 Claude 犯了一个错误（比如误删文件、用错 API），不要只是纠正它——让它把教训写进 CLAUDE.md。下次会话启动时，Claude 会自动读取并遵循这条规则，从根本上避免同类错误重复发生。这种"自我纠错循环"是社区公认的高级用法，让 CLAUDE.md 成为一份不断进化的团队知识库。
- **代码示例**:
```bash
# Claude 犯错后
> 你刚才不应该直接修改 generated/ 目录下的文件。
> 请把这个教训添加到 CLAUDE.md 中，确保以后不再犯。

# Claude 会自动在 CLAUDE.md 中添加：
# ## 注意事项
# - 永远不要直接编辑 generated/ 目录下的文件，它们由代码生成器维护
```

## 5. .claude/rules/ 分文件管理：用路径匹配实现按需加载
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | 🔥 热门最佳实践仓库
- **摘要**: 当 CLAUDE.md 越来越长时，将规则拆分到 `.claude/rules/` 目录下的独立文件中。每个规则文件可以用 YAML frontmatter 中的 `paths:` 指定生效的文件路径 glob 模式——只有当 Claude 操作匹配路径的文件时，对应规则才会被加载。这样既保持了全局 CLAUDE.md 的精简，又确保了领域规则在需要时精准注入。
- **代码示例**:
```markdown
# .claude/rules/api-conventions.md
---
paths:
  - "src/api/**"
  - "src/routes/**"
---
- 所有 API 端点必须返回标准格式 { data, error, message }
- 错误处理使用自定义 AppError 类
- 路由参数必须做类型校验

# .claude/rules/testing.md
---
paths:
  - "**/*.test.*"
  - "**/*.spec.*"
---
- 使用 describe/it 结构组织测试
- Mock 外部依赖，不要 mock 内部模块
- 每个测试用例只验证一个行为
```

## 8. PreToolUse Hook：用安全钩子阻止危险操作
- **来源**: [mvanhorn](https://x.com/mvanhorn/article/2035857346602340637) on X | 🔥 热门 Claude Code 技巧合集
- **摘要**: 通过配置 PreToolUse Hook，可以在 Claude 执行任何工具操作前进行安全检查。例如可以拦截所有包含 `rm -rf`、`DROP TABLE` 等危险命令的 Bash 调用，或阻止对特定目录的写入操作。这比依赖 Claude 自己的判断力更可靠，因为 Hook 是在系统层面强制执行的安全边界，Claude 无法绕过。
- **代码示例**:
```jsonc
// .claude/settings.json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hooks": [
          {
            "type": "command",
            "command": "if echo \"$CLAUDE_TOOL_INPUT\" | grep -qE 'rm -rf|DROP TABLE|truncate'; then echo 'BLOCK: 危险命令被拦截' >&2; exit 1; fi"
          }
        ]
      }
    ]
  }
}
```
