## 1. Opus 5.5 编写计划脚本，廉价模型执行 — 大幅降低 Token 消耗
- **来源**: [delost](https://x.com/thedelost/status/2110472847084650726) on X | 🔥 高互动讨论帖
- **摘要**: 让 Opus 5.5 把实现计划写成 workflow 脚本，然后用一群更便宜的 agent 并行执行。Opus 只在规划阶段参与，脚本本身承载了完整的计划，执行阶段不再消耗 Opus token。适合大型任务的成本优化。
- **代码示例**:
```
# 在 Claude Code 中使用 workflow 脚本模式
# 1. 让 Opus 生成 workflow 脚本
# 2. 脚本中用 agent() 分发子任务给更便宜的模型
export const meta = {
  name: 'my-task',
  description: 'Plan with Opus, execute with cheaper agents',
}
const results = await parallel(
  tasks.map(t => () => agent(t.prompt, {label: t.name}))
)
return { results }
```

## 2. 20 个 Claude Code 快捷键和技巧速查
- **来源**: [Santiago (@svpino)](https://x.com/svpino/status/2050563493708112190) on X | 🔥 高赞推文
- **摘要**: 精选 20 个实用快捷键，包括：`Esc+Esc` 回退到任意检查点（相当于免费撤销）、`Ctrl+V` 直接粘贴截图、`Ctrl+G` 打开编辑器编写长提示词、`Shift+Tab` 两次进入计划模式。把 Claude Code 当成有免费 undo 的实验环境，大胆让它尝试高风险变更。
- **代码示例**:
```
# 常用快捷键速查
Esc+Esc    → 回退到之前的检查点（免费撤销）
Ctrl+V     → 粘贴截图直接进上下文
Ctrl+G     → 打开外部编辑器写长提示
Shift+Tab×2 → 进入计划模式（先规划再编码）
/clear     → 清除上下文，重新开始
```

## 3. CLAUDE.md 保持 200 行以内，用 .claude/rules/ 拆分规则
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 社区最佳实践仓库
- **摘要**: CLAUDE.md 文件过长会降低 Claude 的遵守率。建议主文件控制在 200 行以内，只放架构概览、构建/测试命令和核心约定。领域特定规则拆到 `.claude/rules/` 目录下，每个文件一个主题，按需懒加载。还可以用 `CLAUDE.local.md` 存放个人私有配置（自动 gitignore）。
- **代码示例**:
```
# 推荐的文件结构
~/.claude/CLAUDE.md          # 全局配置（个人偏好）
项目根目录/CLAUDE.md          # 团队共享配置
项目根目录/CLAUDE.local.md    # 个人私有配置（自动 gitignore）
项目根目录/.claude/rules/     # 按主题拆分的规则文件
  ├── testing.md
  ├── code-style.md
  └── security.md
```

## 4. 用 Hooks 替代 CLAUDE.md 中的硬性规则 — 自动化不可违反的约束
- **来源**: [dduzgun-security/claude-code](https://github.com/dduzgun-security/claude-code) on GitHub | ⭐ 安全工程师的 Claude Code 配置
- **摘要**: CLAUDE.md 中写"永远不要用 rm -rf"这类指令，在上下文压力下可能被遗忘。改用 PreToolUse hook，每次工具调用前自动检查并拦截危险操作。Hook 是代码级别的强制执行，比提示词指令可靠得多。同理，编辑后自动运行 formatter 也应该用 hook 实现。
- **代码示例**:
```json
// .claude/settings.json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "hook": "bash -c 'if echo \"$TOOL_INPUT\" | grep -q \"rm -rf\"; then echo \"BLOCKED: rm -rf is not allowed\" >&2; exit 1; fi'"
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Edit",
        "hook": "npx prettier --write $FILE_PATH"
      }
    ]
  }
}
```

## 5. 并行 Git Worktree 多任务 — 同时运行 3-5 个 Claude 会话
- **来源**: [Matt Van Horn (@mvanhorn)](https://x.com/mvanhorn/article/2035857346602340637) on X | 🔥 高互动长文
- **摘要**: 为每个任务创建独立的 git worktree，在每个 worktree 中启动独立的 Claude Code 会话。这样可以同时处理 3-5 个不同的功能开发或 bug 修复，互不干扰。每个会话有独立的上下文和文件状态，完成后合并回主分支。
- **代码示例**:
```bash
# 创建多个 worktree 并行工作
git worktree add ../feature-auth feature/auth
git worktree add ../fix-perf fix/performance
git worktree add ../refactor-api refactor/api

# 在每个 worktree 中启动 Claude Code
cd ../feature-auth && claude &
cd ../fix-perf && claude &
cd ../refactor-api && claude &

# 完成后清理
git worktree remove ../feature-auth
```

## 7. 上下文管理：保持在 40% 以下，超过 60% 就该收尾
- **来源**: [marmelab.com](https://marmelab.com/blog/2026/04/24/claude-code-tips-i-wish-id-had-from-day-one.html) | 🔥 开发者博客热文
- **摘要**: 上下文使用率是影响 Claude Code 输出质量的关键因素。建议用 `/statusline` 实时监控上下文占用。日常开发保持在 40% 以下最佳；接近 60% 时考虑收尾当前任务；用 `/clear` 清除后写一个聚焦的起始提示词重新开始。对于大型任务，用子 agent 处理子任务，只把最终结果返回主上下文。
- **代码示例**:
```
# 上下文管理最佳实践
/statusline          # 开启状态栏，实时查看上下文占用
/clear               # 上下文过大时清除重来
# 或者用子 agent 隔离上下文
"帮我用一个子 agent 分析 src/auth/ 目录下所有文件的安全问题，
 只返回最终的问题清单，不要把文件内容带回主上下文"
```

## 8. Claude Code 创始人 Boris Cherny 的核心建议：让 Claude 自查
- **来源**: [Boris Cherny (@bcherny)](https://x.com/bcherny/status/2017742741636321619) on X | 🔥 Claude Code 创始人亲自分享
- **摘要**: Boris Cherny（Claude Code 创建者）分享的首要建议：给 Claude 提供验证自身工作的方式（测试命令、lint 检查等），这一项就能带来 2-3 倍的质量提升。同时建议让 Claude 在犯错后更新 CLAUDE.md，这样错误教训会自动传递到后续会话。
- **代码示例**:
```markdown
# 在 CLAUDE.md 中配置自查命令
## Verification
- 每次修改后运行: `npm test -- --related`
- 提交前运行: `npm run lint && npm run typecheck`
- 如果测试失败，先分析原因再修复，不要直接跳过

## Learning
- 如果你犯了一个错误，请在本文件的 ## Lessons 部分记录下来
## Lessons
- （Claude 会自动在这里追加经验教训）
```
