# Claude Code 2.1.160 社区实用技巧 - 2026-06-01

## 1. 上下文控制：保持在 40% 以下
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 56.1k stars
- **摘要**: 经验丰富的开发者建议将上下文使用量控制在 40% 以下，最好低于 30%。超过这个阈值，Claude 的"智力"会明显下降，回答质量降低。当上下文接近阈值时，应使用 `/compact` 压缩或开启新会话。
- **要点**: 每次对话轮次结束后评估：继续、`/rewind`、`/clear`、`/compact`、还是委派给子代理。

## 2. 双击 Esc 回退：比纠错更高效
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 56.1k stars
- **摘要**: 当 Claude 的尝试失败时，不要在当前上下文中反复纠正（会污染上下文），而是双击 Esc 键回退到失败前的状态重新开始。这种"回退策略"比在错误基础上修修补补更高效，能保持上下文的干净。

## 3. Pre-Tool-Use Hook 保护主分支
- **来源**: [ChrisWiles](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 5.9k stars
- **摘要**: 通过配置 pre-tool-use hook，自动阻止 Claude 在 main 分支上进行文件编辑操作，防止误操作直接修改主分支代码。
- **代码示例**:
```json
{
  "matcher": "Edit|Write",
  "command": "[ \"$(git branch --show-current)\" != \"main\" ] || exit 2"
}
```

## 4. 子代理上下文卫生：只返回结论
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 56.1k stars
- **摘要**: 将中间性工作（文件读取、grep 搜索、死胡同探索）交给子代理处理，只将最终结论返回父上下文。这样可以保持主会话上下文的整洁，避免无关信息占用宝贵的上下文空间。采用"垂直切片"而非"水平分层"的工作方式，同时推进 DB→API→UI 各层。

## 5. Rules 懒加载：按文件路径条件加载
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 56.1k stars
- **摘要**: 将规则文件放在 `.claude/rules/` 目录下，使用 YAML frontmatter 的 `paths:` 字段按文件模式条件加载，避免每次会话都加载所有规则。只在 Claude 接触到相关文件时才加载对应规则，减少上下文浪费。
- **代码示例**:
```markdown
---
paths:
  - "src/components/**/*.tsx"
  - "src/hooks/**/*.ts"
---
# React 组件规范
- 使用函数式组件
- Props 必须定义 TypeScript 接口
```

## 6. Headless 模式集成 CI/CD 流水线
- **来源**: [luongnv89](https://github.com/luongnv89/claude-howto) on GitHub | ⭐ 34.8k stars
- **摘要**: 使用 `claude -p` 命令以非交互模式运行 Claude Code，可直接集成到 CI/CD 部署流水线中，实现自动化代码审查、测试报告生成等任务，无需人工交互。
- **代码示例**:
```bash
claude -p "Run tests and generate report"
claude -p "Review the last commit for security issues"
```

## 7. Skill 自动评估 Hook：智能推荐技能
- **来源**: [ChrisWiles](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 5.9k stars
- **摘要**: 配置技能评估 hook，根据用户输入的 prompt 自动分析关键词、文件路径和意图，使用置信度评分来推荐最相关的 skill。例如检测到测试相关关键词时自动建议使用测试技能。
- **代码示例**:
```json
{
  "keywords": ["test", "jest", "spec", "tdd", "mock"],
  "pathPatterns": ["**/**.test.ts", "**/**.test.tsx"]
}
```

## 8. 用 settings.json 替代 CLAUDE.md 中的行为指令
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 56.1k stars
- **摘要**: 对于确定性行为规则（如提交信息格式、代码风格等），优先使用 `.claude/settings.json` 进行配置，而不是在 CLAUDE.md 中用自然语言描述。settings.json 提供确定性的行为控制，不会因为 Claude 的"理解偏差"而被忽略。CLAUDE.md 应保持精简，只放那些"删掉会导致 Claude 犯错"的内容。
