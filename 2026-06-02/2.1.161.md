## 2. Dynamic Workflows：百倍并行子代理
- **来源**: [Min Choi](https://x.com/minchoi/status/2060226858994565563) on X | 🔥 高互动
- **摘要**: Claude Code 的全新 Dynamic Workflow 功能：将模型设为 Opus 4.8，effort 设为 "ultracode"，然后在 prompt 中使用"workflow"关键词。Claude 会自动编写编排脚本，生成大量并行子代理群，验证结果后汇报。适合处理大规模重构、跨文件修改等复杂任务。
- **代码示例**:
```
/model opus 4.8
/effort ultracode
> Create a workflow to refactor all API endpoints to use the new auth middleware
```

## 3. Git Worktree 并行开发：3-5 个会话同时跑
- **来源**: [Shruti Mishra](https://x.com/heyshrutimishra/status/2018368588432978151) on X | 🔥 高互动
- **摘要**: Boris 的十大高级技巧中排名第一：利用 git worktree 创建 3-5 个独立工作目录，每个目录运行一个 Claude Code 会话，实现真正的并行开发。每个 worktree 有独立的文件系统和分支，互不干扰，是"大多数人忽略的生产力作弊码"。
- **代码示例**:
```bash
# 创建多个 worktree 并行工作
git worktree add ../project-feat-auth feat/auth
git worktree add ../project-feat-ui feat/ui
git worktree add ../project-fix-perf fix/perf
# 在每个目录中分别启动 claude code 会话
```

## 4. /last 30 days 技能：替代整个研究流程
- **来源**: [Startup Ideas Podcast](https://x.com/startupideaspod/status/2036896888507818099) on X | 🔥 高互动
- **摘要**: 自定义 Skill `/last 30 days` 可以替代整个研究工作流。输入任意主题，它会自动拉取过去 30 天内的 Reddit 帖子、X 推文和网页搜索结果，综合为一份专家级分析报告。适合快速了解某个技术方向的最新动态和社区讨论。

## 5. "质疑我的改动"：合并前的自我审查
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 56.2k stars
- **摘要**: 在合并代码前，让 Claude 反过来质疑你的方案——输入"grill me on these changes"。Claude 会扮演严格的代码审查者，指出潜在问题、边界情况和设计缺陷。这种"对抗式验证"能在 PR 提交前发现大多数问题，比单纯让 Claude 生成代码更能保证质量。
- **代码示例**:
```
> grill me on these changes — 找出所有可能的问题
> 这个方案有什么隐患？请像资深架构师一样审查
```

## 6. CLAUDE.md 黄金法则：不超过 200 行
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 56.2k stars
- **摘要**: CLAUDE.md 应严格控制在 200 行以内。臃肿的 CLAUDE.md 会导致 Claude 忽略你的实际指令。对每一行自问："删掉这行会让 Claude 犯错吗？"如果不会，就删掉。超出的领域特定规则应放到 `.claude/rules/` 目录下按路径懒加载，单仓库（monorepo）可利用祖先/后代 CLAUDE.md 层级加载机制。

## 7. 快速原型法：多版本试错优于详细规格
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 56.2k stars
- **摘要**: 不要花大量时间写详细的技术规格说明书，而是让 Claude 快速生成多个原型版本进行对比。AI 时代的开发范式已变——快速迭代、实际验证比纸上设计更高效。先用 Plan 模式确定方向，然后快速实现，用测试和浏览器验证结果。

## 8. 渐进式技能披露：按需加载专业知识
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 56.2k stars
- **摘要**: 为特定功能创建独立的子代理，配合"渐进式披露"技能（progressive-disclosure skills），而不是使用一个万能通用代理。每个子代理只加载它需要的领域知识，避免上下文被无关信息稀释。比如数据库迁移用专门的迁移子代理，UI 组件用 React 专用子代理。
