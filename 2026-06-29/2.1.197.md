## 1. 五个改变工作方式的斜杠命令
- **来源**: [Vaibhav Sisinty](https://x.com/VaibhavSisinty/status/2067234559721361699) on X | 🔥 高互动推文
- **摘要**: 大多数人从未输入过这些命令。`/compact` 在上下文膨胀时压缩摘要，防止 Claude 丢失主线；`/loop` 按设定间隔重复执行提示，不用手动反复运行；`/schedule` 创建云端定时任务，即使笔记本关机也能按时执行；`/deep-research` 执行多源交叉验证的深度研究。这五个命令是从"会用"到"高效"的关键跨越。
- **代码示例**:
```bash
# 上下文膨胀时压缩
> /compact

# 每 5 分钟自动运行一次检查
> /loop 5m check deployment status

# 创建云端定时任务（关机也能运行）
> /schedule "every morning at 9am" run test suite and report failures
```

## 2. 工作流用于非技术任务：超越代码的编排能力
- **来源**: [Thariq](https://x.com/trq212/status/2061907538741006796) on X | 🔥 高互动推文
- **摘要**: 工作流（Workflows）是继 skills 和 subagents 之后 Claude Code 最大的能力升级。关键洞察：工作流不仅能编排代码任务，还能处理非技术工作——如撰写文档、整理研究资料、执行跨团队审核流程。通过 `export const meta` 定义阶段，配合 `pipeline()` 和 `parallel()` 实现复杂编排。
- **代码示例**:
```javascript
// .claude/workflows/content-review.js
export const meta = {
  name: 'content-review',
  description: 'Multi-reviewer content pipeline',
  phases: [
    { title: 'Draft', detail: 'Generate initial drafts' },
    { title: 'Review', detail: 'Parallel review from 3 perspectives' },
  ],
}

phase('Draft')
const draft = await agent('Write a blog post about our new feature')

phase('Review')
const reviews = await parallel([
  () => agent('Review for technical accuracy: ' + draft),
  () => agent('Review for clarity and readability: ' + draft),
  () => agent('Review for SEO optimization: ' + draft),
])
```

## 3. Karpathy 的 Agent 编码工作流：80% Agent + 20% 手动
- **来源**: [Andrej Karpathy](https://x.com/karpathy/status/2015883857489522876) on X | 🔥 高互动推文
- **摘要**: Karpathy 分享了最近几周的编码方式转变：从 80% 手动编码 + 20% Agent 迅速转向 80% Agent 编码 + 20% 手动微调。关键技巧是让 Agent 处理大块实现工作，自己只负责架构决策和最终修饰。他建议保持提示简洁直接，避免过度解释，让 Agent 自行探索代码库找到上下文。
- **代码示例**:
```bash
# Karpathy 推荐的工作模式

# 1. 高层指令，不要过度约束
> add websocket support for real-time notifications

# 2. 让 Claude 自己探索代码库
# （不需要手动列出所有相关文件）

# 3. 审查 Agent 的更改，只做精确修饰
> the error handling in ws-handler.ts line 45
  should retry 3 times before disconnecting
```

## 4. 并行 Worktrees：同时运行 3-5 个 Claude 会话
- **来源**: [Shruti](https://x.com/heyshrutimishra/status/2018368588432978151) on X | 🔥 高互动推文（引用 Boris / Claude Code 创始人的技巧）
- **摘要**: Claude Code 创始人 Boris 分享的第一个也是最重要的技巧：用 git worktree 创建 3-5 个并行工作目录，每个运行独立的 Claude 会话。每个 worktree 拥有独立的分支和上下文，互不干扰。这是"大多数人忽略的生产力作弊码"——一个人可以同时推进前端、后端和测试三条线。
- **代码示例**:
```bash
# 创建并行 worktrees
git worktree add ../project-frontend feature/ui-redesign
git worktree add ../project-backend feature/api-v2
git worktree add ../project-tests feature/e2e-tests

# 在三个终端中分别启动 Claude Code
cd ../project-frontend && claude
cd ../project-backend && claude
cd ../project-tests && claude

# 完成后清理
git worktree remove ../project-frontend
```

## 7. 上下文管理的"复制粘贴重置"技巧
- **来源**: [Aakash Gupta](https://x.com/aakashgupta/status/2035933202750361665) on X | 🔥 高互动推文
- **摘要**: 当上下文变得臃肿时的急救技巧：先复制终端中所有重要内容，运行 `/compact` 获取摘要，然后 `/clear` 完全清除上下文，最后只粘贴回真正重要的信息。这比单纯的 `/compact` 更彻底——相当于手动筛选后的"硬重置"。配合验证机制（让 Claude 检查自己的输出）使用效果最佳。
- **代码示例**:
```bash
# "复制粘贴重置" 流程

# 1. 复制当前关键上下文到剪贴板
# （手动选择终端中的重要输出）

# 2. 压缩并清除
> /compact
> /clear

# 3. 粘贴回关键信息，重新开始
> Here's where we left off:
  - Working on: user auth refactor
  - Key files: src/auth/*.ts
  - Current issue: JWT validation fails on refresh
  Continue from here.
```
