## 1. CLAUDE.md 黄金法则：60 行以内，按需加载
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 63.9k stars, 6.4k forks
- **摘要**: 社区最高星的 Claude Code 最佳实践仓库总结：CLAUDE.md 超过 80 行后 Claude 会开始忽略部分内容，60 行以内是最佳基准。领域特定规则应放到 `.claude/rules/*.md` 中用 YAML frontmatter 的 `paths:` 字段按文件 glob 懒加载，而非全部塞进主文件。用 `<important if="...">` 标签包裹关键规则防止被忽略。
- **代码示例**:
```yaml
# .claude/rules/api-conventions.md
---
paths:
  - "src/api/**"
  - "src/routes/**"
---
- 所有 API 端点使用 snake_case 命名
- 必须包含请求验证中间件
- 错误响应统一使用 RFC 7807 格式
```

## 2. 上下文退化预警：300k tokens 是悬崖
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 63.9k stars
- **摘要**: 该仓库基于 Boris Cherny（Claude Code 创建者）的 37+ 条技巧整理，指出上下文在 300-400k tokens 时开始退化，可理解性在约 40% 容量时就会下降。核心建议：优先使用 "Rewind > correct" 策略——按 `Esc+Esc` 或 `/rewind` 回退到失败前的检查点，而不是在污染的上下文中继续纠错。手动 `/compact` 并附带提示语优于自动压缩。
- **代码示例**:
```bash
# 上下文退化应对策略

# 1. 失败时回退，不要在错误上下文中纠正
# 按 Esc+Esc 选择检查点回退
# 然后重新给出更明确的指令

# 2. 手动压缩优于自动压缩（附带聚焦提示）
/compact "keep only the database migration logic and test failures"

# 3. 验证上下文健康度的快速检查
# 如果 Claude 开始重复之前的错误或忘记已讨论的内容
# 这就是上下文退化的信号，立即 /compact 或 /clear
```

## 3. "btw" 侧问技巧：不中断当前工作流的快速提问
- **来源**: [Davey (@dvyio)](https://x.com/dvyio/status/2002399923619156039) on X | 🔥 社区热传
- **摘要**: 一个被广泛分享的隐藏技巧——在 Claude Code 中以 "btw" 开头提问，可以问一个快速的旁支问题而不中断 Claude 当前的工作流。适用于开发过程中突然想确认某个 API 用法、某个函数签名等场景，Claude 会简短回答后继续之前的任务。
- **代码示例**:
```bash
# 正在让 Claude 重构一个模块时，突然想确认某个用法

# 输入:
btw Express 的 router.param() 中间件是在路由匹配前还是匹配后执行？

# Claude 会简短回答问题，然后继续之前的重构任务
# 不会丢失当前工作的上下文
```

## 4. UserPromptSubmit Hook 实现智能 Skill 推荐
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 6k stars, 565 forks
- **摘要**: 该仓库展示了一个高级 hook 模式：在 `UserPromptSubmit` 事件中运行置信度评分系统，分析用户输入的关键词（2分）、正则模式（3分）、文件路径（可变分）、意图模式（4分）、目录映射（5分），自动推荐最匹配的 skill。超过阈值时显示排序后的推荐列表和推荐理由。
- **代码示例**:
```jsonc
// .claude/settings.json
{
  "hooks": {
    "UserPromptSubmit": [
      {
        "matcher": "",
        "command": "node .claude/hooks/skill-recommender.js \"$PROMPT\""
      }
    ]
  }
}

// skill-recommender.js 核心逻辑：
// 1. 解析用户 prompt 中的关键词和意图
// 2. 对每个已安装 skill 计算匹配分数
// 3. 超过阈值时输出推荐（附推荐理由）
// 4. 用户可选择采纳或忽略
```

## 5. 垂直切片开发法：用 Tracer Bullet 替代水平分层
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 63.9k stars
- **摘要**: 仓库推荐的规划哲学——将 PRD 拆分为垂直切片（tracer bullets），每个切片贯穿所有层（前端→API→数据库），而非按水平层分阶段。这与 Claude Code 的工作方式高度契合：每个垂直切片可以作为一个独立的 Claude 会话任务，有明确的输入输出和验证标准。配合 "Prototype > PRD" 理念，直接构建 20-30 个原型版本比写冗长规格文档更高效。
- **代码示例**:
```bash
# 垂直切片示例：用户认证功能

# ❌ 水平分层（不推荐）
# Phase 1: 所有数据库 schema
# Phase 2: 所有 API 端点
# Phase 3: 所有前端页面

# ✅ 垂直切片（推荐）
# Slice 1: 用户注册 (DB schema + API + 前端表单)
claude "Implement user registration: create users table migration,
POST /api/auth/register endpoint with validation, and a
React registration form. Include tests for each layer."

# Slice 2: 用户登录 (JWT + API + 前端)
claude "Implement login flow: JWT token generation in auth service,
POST /api/auth/login endpoint, and React login form with
token storage. Build on the users table from slice 1."
```

## 6. 并行 Git Worktree 多代理开发：最大生产力解锁
- **来源**: [Boris Cherny (@bcherny)](https://x.com/bcherny/status/2017742741636321619) on X | 🔥 Claude Code 创建者官方推荐
- **摘要**: Boris Cherny（Claude Code 创建者）分享的核心技巧：同时创建 3-5 个 git worktree，每个运行独立的 Claude 会话处理不同任务，被描述为"最大的生产力解锁"。每个 worktree 有独立的文件系统和上下文窗口，互不干扰。适合同时处理多个独立功能、bug 修复或代码审查。
- **代码示例**:
```bash
# 创建多个 worktree 并行开发

# 1. 为不同任务创建独立 worktree
git worktree add ../project-auth feat/auth
git worktree add ../project-perf fix/performance
git worktree add ../project-tests chore/test-coverage

# 2. 在每个 worktree 中启动独立 Claude 会话
# 终端 1:
cd ../project-auth && claude

# 终端 2:
cd ../project-perf && claude

# 终端 3:
cd ../project-tests && claude

# 3. 每个会话互不干扰，各自有独立的上下文
# 完成后合并回主分支
git worktree remove ../project-auth
```

## 7. Skill 的 PRO 用法：对比审计已安装 Skills
- **来源**: [Prajwal Tomar (@PrajwalTomar_)](https://x.com/PrajwalTomar_/status/2074787074641899896) on X | 🔥 高互动
- **摘要**: 一个高效的 skill 管理技巧——将最佳实践文章或 skill 推荐列表整段粘贴到 Claude Code 会话中，让 Claude 自动对比当前已安装的 skills，识别重叠、从未触发、或过时的 skill 并卸载，同时发现缺失的高价值 skill。这比手动逐个审查高效得多。
- **代码示例**:
```bash
# Skill 审计工作流

# 1. 将最佳实践文章内容粘贴到 Claude 会话中
# 2. 输入以下指令：
"Read this article end to end. Then list every skill I currently
have installed, and compare it against this list. Uninstall
anything that overlaps, never triggers, or is outdated.
Recommend new skills I'm missing."

# Claude 会：
# - 列出所有已安装的 .claude/skills/
# - 逐一对比文章推荐
# - 标记冗余和过时的 skill
# - 推荐缺失的高价值 skill
```

## 8. 确定性行为强制：用 settings.json 替代 CLAUDE.md 散文
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 63.9k stars
- **摘要**: 一个容易被忽视的配置最佳实践——需要确定性执行的规则（如归因信息、权限控制、模型选择）应通过 `settings.json` 强制执行，而非写在 CLAUDE.md 中靠 Claude "理解"。CLAUDE.md 中的散文指令是概率性的（Claude 可能遵守也可能忽略），而 settings.json 中的 hooks 和配置是确定性的（系统级别强制执行）。
- **代码示例**:
```jsonc
// .claude/settings.json - 确定性规则配置

{
  // ❌ 不要在 CLAUDE.md 中写 "每次提交前运行测试"
  // ✅ 用 hook 强制执行
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "command": "node .claude/hooks/block-main-branch-edits.js"
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "command": "npx prettier --write $FILEPATH"
      }
    ]
  },

  // 权限控制也走 settings.json
  "permissions": {
    "allow": ["Bash(npm test)", "Bash(npm run lint)"],
    "deny": ["Bash(rm -rf)"]
  }
}
```
