## 1. 多会话并行开发：用 Git Worktree 隔离工作区
- **来源**: [Boris Cherny (Claude Code创作者)](https://www.xda-developers.com/claude-codes-creator-keeps-sharing-tips-and-they-all-made-my-experience-better/) on XDA/Twitter | 🔥 高热度讨论
- **摘要**: Claude Code 创作者 Boris Cherny 分享其日常工作流：同时运行 10-15 个 Claude 会话（5个终端标签页、5-10个网页端、加上手机端）。每个会话使用独立的 git worktree，确保多个会话的代码修改互不冲突。这种并行模式让复杂项目的开发效率成倍提升。
- **代码示例**:
```bash
# 为每个 Claude 会话创建独立 worktree
git worktree add ../feature-auth feature/auth
git worktree add ../feature-api feature/api
git worktree add ../bugfix-login bugfix/login

# 列出所有 worktree
git worktree list

# 完成后清理
git worktree remove ../feature-auth
```

## 2. /btw 命令：不打断任务的快速提问
- **来源**: [社区讨论](https://agenticcoding.substack.com/p/32-claude-code-tips-from-basics-to) on Substack/Reddit | 🔥 广泛传播
- **摘要**: 2026年3月引入的 /btw 命令允许在 Claude 执行任务期间提出快速侧问题，答案以浮层形式弹出，不会中断当前工作流也不会污染对话历史。非常适合临时查询 API 用法、确认语法等场景。
- **代码示例**:
```
# Claude 正在实现一个复杂功能时...
/btw TypeScript 中 Record<string, never> 和空对象类型有什么区别？

# 答案弹出后，Claude 继续原来的任务不受影响
```

## 3. 自定义 Slash Commands 加速内循环
- **来源**: [marmelab](https://marmelab.com/blog/2026/04/24/claude-code-tips-i-wish-id-had-from-day-one.html) on Blog | 🔥 Reddit/HN 热议
- **摘要**: 将每天重复多次的"内循环"操作封装为 slash commands，存放在 `.claude/commands/` 目录并提交到 git。团队成员共享统一的工作流命令，减少重复提示输入，保持一致的代码质量标准。
- **代码示例**:
```markdown
<!-- .claude/commands/review.md -->
Review the current git diff for:
1. Security vulnerabilities (injection, XSS, SSRF)
2. Performance regressions
3. Missing error handling
4. Breaking API changes

Output a table: | File | Issue | Severity | Suggestion |
```

## 4. Subagent 隔离模式：专家代理分而治之
- **来源**: [shinpr/claude-code-workflows](https://github.com/shinpr/claude-code-workflows) on GitHub | ⭐ 1.2k stars
- **摘要**: 在 `.claude/agents/` 中定义子代理（subagent），每个代理有独立的角色、工具权限和模型选择。关键优势是上下文隔离——子代理在自己的上下文窗口中探索，完成后向主会话返回压缩摘要，避免主上下文被大量探索性内容淹没。
- **代码示例**:
```yaml
# .claude/agents/security-auditor.yml
name: security-auditor
model: claude-opus-4-6
role: |
  You are a security specialist. Review code for OWASP Top 10
  vulnerabilities. Report findings with severity ratings.
tools:
  - Read
  - Bash
  - WebSearch
max_tokens: 4096
```

## 5. Context7 插件替代在线文档搜索
- **来源**: [社区推荐](https://www.geeky-gadgets.com/claude-code-hacks-guide/) on Geeky Gadgets | 🔥 多平台热议
- **摘要**: 不要让 Claude 自己搜索和解析在线文档——使用 Context7 插件，它会索引指定版本的库文档，直接向 Claude 提供精确匹配的文档页面。大幅减少 token 消耗，提高文档引用的准确性，避免因版本不匹配导致的错误建议。
- **代码示例**:
```json
// .claude/settings.json
{
  "mcpServers": {
    "context7": {
      "command": "npx",
      "args": ["-y", "@context7/mcp-server"],
      "env": {}
    }
  }
}
```

## 6. Plan Mode 先行：复杂任务先规划再实现
- **来源**: [marmelab](https://marmelab.com/blog/2026/04/24/claude-code-tips-i-wish-id-had-from-day-one.html) on Blog | 🔥 Reddit 多次引用
- **摘要**: 对复杂任务使用 Shift+Tab 两次进入 Plan Mode，让 Claude 先输出完整方案再动手。这样能强制端到端思考，暴露错误假设，纠正方案比回滚半成品代码容易得多。轻量任务则用 Shift+Tab 一次直接进入实现模式。
- **代码示例**:
```
工作流:
1. Shift+Tab × 2 → 进入 Plan Mode
2. 描述需求 → Claude 输出分步方案
3. 审核方案 → 修正假设或遗漏
4. Shift+Tab × 1 → 切换到 Act Mode 执行
5. Claude 按已确认的方案实现代码
```

## 7. CLAUDE.md 精简原则：每行问"删了会出错吗？"
- **来源**: [centminmod/my-claude-code-setup](https://github.com/centminmod/my-claude-code-setup) on GitHub | ⭐ 活跃维护
- **摘要**: 社区共识是 CLAUDE.md 应尽可能精简。每行内容都问自己"删除这行后 Claude 会犯错吗？"——如果不会，就删掉。过长的 CLAUDE.md 会导致 Claude 忽略实际指令，规则被淹没在噪声中。领域知识和偶尔使用的工作流应放入 skills 按需加载。
- **代码示例**:
```markdown
<!-- ✅ 好的 CLAUDE.md - 简洁有力 -->
# 项目规范
- 使用 pnpm, 不用 npm/yarn
- 测试命令: pnpm test -- --filter={file}
- 提交前必须通过 pnpm lint

# 架构约束
- API 路由在 src/routes/, 业务逻辑在 src/services/
- 数据库操作只通过 Drizzle ORM, 不写裸 SQL

<!-- ❌ 坏的 CLAUDE.md - 解释性废话 -->
# 关于本项目
本项目是一个使用 TypeScript 构建的...（省略200字背景介绍）
```

## 8. /install-github-app：自动化 PR 审查
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 8k stars
- **摘要**: 运行 `/install-github-app` 后，Claude 会自动审查团队的 Pull Request。结合自定义审查规则，可以在 PR 提交时自动检查安全问题、代码风格和架构一致性，减少人工审查负担。
- **代码示例**:
```bash
# 在 Claude Code 中运行
/install-github-app

# 安装后 Claude 会自动:
# - 审查新的 PR
# - 检查代码风格一致性
# - 标记潜在安全问题
# - 验证测试覆盖率
```
