## 3. 70% 上下文用量是黄金分割线——超过即压缩
- **来源**: [FlorianBruniaux](https://github.com/FlorianBruniaux/claude-code-ultimate-guide) on GitHub | ⭐ 4.1k stars
- **摘要**: 社区测试发现，当上下文使用率达到 70% 时 Claude 精度开始下降，85% 时幻觉显著增加。建议在 70% 时主动执行 `/compact`，90% 以上则强制 `/clear` 重新开始。这比之前 shanraisshan 仓库建议的 300-400k token 阈值提供了更精确的操作指标。
- **代码示例**:
```
# 在会话中随时检查上下文用量
/context

# 70% 时主动压缩，附带关键信息提示
/compact 保留当前架构设计决策和未完成的迁移步骤

# 90%+ 时果断清空重来
/clear
```

## 4. Git Worktree + tmux 实现多代理并行开发
- **来源**: [centminmod](https://github.com/centminmod/my-claude-code-setup) on GitHub | ⭐ 2.3k stars
- **摘要**: 通过 shell 函数（clx/zaix/cx）将 git worktree 与 tmux 结合，实现多个 Claude Code 实例在完全隔离的文件状态下并行工作，同时共享 Git 历史。每个 worktree 是独立分支，互不干扰。搭配自定义状态栏实时显示上下文用量、token 消耗速率和成本。
- **代码示例**:
```bash
# 创建隔离的 worktree 并启动 Claude Code
git worktree add ../feature-auth feature/auth
cd ../feature-auth && tmux new -s auth-agent 'claude'

# 同时在另一个 worktree 上工作
git worktree add ../feature-api feature/api
cd ../feature-api && tmux new -s api-agent 'claude'

# 状态栏显示实时指标: 上下文 42% | 🌳 feature-auth | $0.35
```

## 5. Skill 触发器写法：用"何时启动"代替"功能描述"
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 50.9k stars
- **摘要**: SKILL.md 的 description 字段不应该写"这个技能做什么"，而应该写"什么情况下应该触发这个技能"。同时在 SKILL.md 中嵌入 `!command` 实现动态 shell 注入，让技能在被调用时自动执行脚本获取实时信息。
- **代码示例**:
```markdown
# .claude/skills/db-migration/SKILL.md
---
description: "当用户提到数据库迁移、schema 变更、或添加新表/字段时触发"
---

## 当前数据库状态
!npx prisma migrate status

## 迁移规范
- 始终先创建可逆迁移
- 大表变更必须分阶段执行
```

## 6. GitHub Actions 自动化：$10-50/月实现 PR 审查 + 文档同步 + 依赖审计
- **来源**: [ChrisWiles](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 5.9k stars
- **摘要**: 四套 GitHub Actions 工作流实现全自动化工程管理：PR 提交时自动代码审查、每月文档与代码同步检查、每周随机目录质量扫描修复、双周依赖安全审计。月成本仅 $10-50，取决于 PR 量。
- **代码示例**:
```yaml
# .github/workflows/pr-review.yml
name: Claude PR Review
on:
  pull_request:
    types: [opened, synchronize]
  issue_comment:
    types: [created]

jobs:
  review:
    if: contains(github.event.comment.body, '@claude')
    runs-on: ubuntu-latest
    steps:
      - uses: anthropic/claude-code-action@v1
        with:
          model: claude-sonnet-4-6
          prompt: "Review this PR for bugs, security issues, and style"
```

## 7. 双重记忆架构：Git 共享记忆 + 本地机器记忆
- **来源**: [centminmod](https://github.com/centminmod/my-claude-code-setup) on GitHub | ⭐ 2.3k stars
- **摘要**: 采用双层记忆设计——团队共享的 CLAUDE.md 系列文件通过 Git 跟踪版本，同时每台开发机保留本地 auto-memory 用于个人偏好和环境特定配置。支持 CLAUDE-patterns.md（架构模式）、CLAUDE-decisions.md（架构决策记录）、CLAUDE-troubleshooting.md（已知问题）等专用记忆文件。
- **代码示例**:
```
# Git 跟踪的团队共享记忆
CLAUDE.md                    # 主配置（200行以内）
CLAUDE-patterns.md           # 团队架构模式
CLAUDE-decisions.md          # ADR 架构决策记录
CLAUDE-troubleshooting.md    # 已知问题和解决方案

# .gitignore 中排除的本地记忆
.claude/auto-memory.md       # 个人偏好、本地路径等
```

## 9. MCP 安全审计：28 个 CVE 漏洞和 655 个恶意技能的警示
- **来源**: [FlorianBruniaux](https://github.com/FlorianBruniaux/claude-code-ultimate-guide) on GitHub | ⭐ 4.1k stars
- **摘要**: MCP 生态系统已被发现 28 个 CVE 级别漏洞和 655 个恶意技能。在启用任何第三方 MCP 服务器前，务必执行 5 分钟安全审计清单：检查源码来源、审查权限请求、验证环境变量暴露范围、确认是否有已知漏洞。不要盲目信任社区推荐的 MCP 服务器。
- **代码示例**:
```bash
# MCP 服务器安全审计清单
# 1. 检查 npm 包来源和维护状态
npm info @some-mcp/server

# 2. 审查 .mcp.json 中的环境变量暴露
cat .mcp.json | jq '.mcpServers[].env'

# 3. 检查是否有已知漏洞
npm audit --registry https://registry.npmjs.org @some-mcp/server
```

## 10. Command → Agent → Skill 三层编排模式
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 50.9k stars
- **摘要**: 社区沉淀出的成熟架构模式：Command 定义意图（用户触发入口）、Agent 管理编排（分配和协调任务）、Skill 封装可复用逻辑（带渐进式披露）。三层分离使得每个组件职责清晰，Skill 用 `context: fork` 在隔离子代理中运行，只将最终结果返回给父代理。
- **代码示例**:
```
# 用户执行命令
/deploy-feature

# Command (.claude/commands/deploy-feature.md) 触发 Agent
→ 启动 deployment-agent

# Agent (.claude/agents/deployment-agent.md) 编排 Skills
→ 调用 testing-patterns skill (context: fork)
→ 调用 security-scan skill (context: fork)
→ 调用 deploy skill

# 每个 Skill 在隔离上下文中运行，只返回结论
```
