## 1. 使用 "ultrathink" 关键词触发深度思考
- **来源**: [Santiago (@svpino)](https://x.com/svpino/status/2029913404987822250) on X | 🔥 高互动推文
- **摘要**: 在提示词中任意位置加入 "ultrathink" 一词，可以将模型的思考努力等级设为 HIGH，让模型花更多时间推理，通常能获得更好的结果。代价是速度更慢、消耗更多 token，建议仅在复杂任务中使用。
- **代码示例**:
```
ultrathink - 请帮我重构这个模块，确保所有边界情况都被处理
```

## 2. 上下文利用率保持在 30% 以下
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 52.6k stars
- **摘要**: Anthropic 工程师 Thariq 分享：当上下文利用率超过 40% 时，模型进入"笨区"（dumb zone），输出质量明显下降。高手用户会将上下文保持在 30% 以下，通过频繁开新会话和使用 `/compact` 来控制。
- **代码示例**:
```bash
# 在任务切换时主动压缩上下文
/compact 保留当前文件结构和修改记录

# 或者直接开新会话处理新任务
claude --resume  # 恢复之前的会话（如需要）
```

## 3. Git Worktree 实现多会话并行开发
- **来源**: [Boris Cherny (Claude Code 创始人)](https://x.com/minchoi/status/2051837741541863762) on X | 🔥 高互动推文
- **摘要**: 使用 git worktree 创建隔离的工作目录，在每个目录中启动独立的 Claude Code 会话。Boris Cherny 本人同时运行 10-15 个并行会话，大多数开发者 4 个为可持续上限。每个会话有独立的文件状态，互不干扰。
- **代码示例**:
```bash
# 创建隔离工作目录
git worktree add ../feature-auth feature/auth
git worktree add ../feature-api feature/api

# 在各自目录中启动独立 Claude Code 会话
cd ../feature-auth && claude
cd ../feature-api && claude

# 完成后清理
git worktree remove ../feature-auth
```

## 4. DX 插件：一键安装多工具套件
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 8.2k stars
- **摘要**: DX 插件将多个实用工具打包为一个安装，包括 GitHub Actions 失败分析、上下文交接文档、会话分支克隆等功能。一次安装即可获得完整的开发体验增强工具链。
- **代码示例**:
```bash
# 安装 DX 插件后可用的命令
/dx:gha      # GitHub Actions 失败分析
/dx:handoff  # 生成上下文交接文档，方便会话间传递
/dx:clone    # 会话分支克隆
/dx:half-clone  # 部分上下文克隆
```

## 5. Rules 系统：基于路径的延迟加载规则
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 52.6k stars
- **摘要**: 在 `.claude/rules/` 目录下用带 YAML frontmatter 的 Markdown 文件定义规则，通过 path glob 匹配实现按需加载。只有当 Claude 访问匹配路径的文件时才加载对应规则，避免上下文浪费。
- **代码示例**:
```markdown
<!-- .claude/rules/react-components.md -->
---
path: "src/components/**/*.tsx"
---
- 所有组件使用函数式写法
- Props 必须定义 TypeScript 接口
- 禁止在组件内使用 any 类型
```

## 6. cc-safe：命令安全审计工具
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 8.2k stars
- **摘要**: cc-safe 工具会扫描项目中已批准的命令列表，检测潜在危险模式（如 `rm -rf`、`git push --force` 等）。帮助开发者发现无意中授予 Claude Code 的高风险权限，防止误操作。
- **代码示例**:
```bash
# 运行安全审计
npx cc-safe

# 输出示例：
# ⚠️  Found risky pattern: rm -rf in .claude/settings.json
# ⚠️  Found risky pattern: git push --force in allowedCommands
```

## 7. Subagent 隔离策略：用 context:fork 保护主上下文
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 52.6k stars
- **摘要**: 使用 `context: fork` 将技能执行隔离在子代理中，主上下文只接收最终结果。这样可以让子代理读取大量文件或执行复杂搜索，而不会污染主会话的上下文窗口。功能型子代理配合专属技能比通用代理表现更好。
- **代码示例**:
```markdown
<!-- .claude/agents/researcher.md -->
---
context: fork
tools: [Read, Bash, WebSearch]
---
你是一个代码研究助手。搜索相关文件并总结发现，
只返回关键结论给主会话。
```

## 8. Plan Mode + 垂直切片工作流
- **来源**: [Boris Cherny](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 52.6k stars
- **摘要**: Claude Code 创始人 Boris Cherny 推荐：永远从 Plan Mode 开始，将 PRD 拆分为跨所有层的"垂直切片"。每个切片是一个独立可交付的功能片段（包含 UI、逻辑、API、数据库），而非按层水平切分。这样每次提交都是可运行的增量。
- **代码示例**:
```
# 使用 Shift+Tab 切换到 Plan Mode
# 示例提示词：
请将这个用户故事拆分为垂直切片，每个切片包含：
1. 数据库 migration
2. API endpoint
3. 前端组件
4. 测试用例
确保每个切片独立可部署。
```
