## 1. 每个复杂任务先进入 Plan 模式再动手
- **来源**: [@bcherny](https://x.com/bcherny/status/2017742741636321619) on X | 🔥 Claude Code 创始人分享，高互动量
- **摘要**: Claude Code 创始人 Boris Cherny 分享了团队内部的使用技巧。核心建议：每个复杂任务都应该先进入 plan 模式（Shift+Tab 切换），让 Claude 先思考方案再写代码。团队发现这样可以显著减少返工次数，尤其是在涉及多文件修改的场景下。不要急着让 Claude 动手，先让它把方案想清楚。
- **代码示例**:
```bash
# 按 Shift+Tab 进入 plan 模式
# 或在提示中明确要求：
请先分析这个任务的实现方案，列出需要修改的文件和步骤，不要直接写代码

# plan 模式下 Claude 会：
# 1. 分析任务范围
# 2. 列出需要修改的文件
# 3. 规划实现步骤
# 4. 确认后再执行
```

## 2. 任务间用 /clear 清空上下文：经 945 次运行验证的最大优化
- **来源**: [Stop Hitting Claude Code Limits](https://x.com/i/article/2111105138290987198) on X | 🔥 热门长文，数据驱动分析
- **摘要**: 一位开发者基于 945 次 Claude Code 运行的数据分析得出结论：在不相关任务之间使用 /clear 命令清空上下文是所有优化中收益最大的一项。长会话中累积的无关上下文会导致 Claude 表现下降、token 浪费增加。每完成一个独立任务后及时清理，比任何 CLAUDE.md 优化都更有效。
- **代码示例**:
```bash
# 完成任务 A 后
/clear

# 然后开始任务 B
# 上下文干净，Claude 不会被之前的讨论干扰

# 其他上下文管理技巧：
/compact          # 压缩当前上下文（保留关键信息）
# 长对话中定期 compact，避免上下文膨胀
```

## 3. 把重复操作变成 Skill 或自定义命令
- **来源**: [@bcherny](https://x.com/bcherny/status/2017742741636321619) on X | 🔥 Claude Code 团队内部实践
- **摘要**: Claude Code 团队的另一个核心实践：任何一天内重复超过一次的操作，都应该封装成 skill 或自定义斜杠命令。这不仅节省时间，还能确保操作的一致性。比如代码审查流程、部署步骤、测试运行等重复性高的任务，都适合做成可复用的命令。
- **代码示例**:
```bash
# 创建自定义命令：在 .claude/commands/ 目录下创建 markdown 文件
# 文件：.claude/commands/deploy.md
# 内容：
# 1. 运行测试确保通过
# 2. 构建生产版本
# 3. 部署到 staging 环境
# 4. 运行 smoke test
# 5. 确认后部署到 production

# 使用时直接输入：
/deploy
```

## 4. CLAUDE.md 中加入"禁止事项"章节：被低估的高价值配置
- **来源**: [CLAUDE.md Setup Guide 2026](https://baeseokjae.github.io/posts/claude-md-setup-guide-2026/) on Blog | 🔥 高流量技术博客
- **摘要**: 多个社区指南不约而同地指出，CLAUDE.md 中最被低估但价值最高的部分是"禁止事项"（What NOT to do）章节。明确告诉 Claude 不要做什么，比告诉它要做什么更有效。比如"不要删除现有测试"、"不要修改数据库迁移文件"、"不要添加新依赖"等负面约束，可以避免 Claude 做出意外的破坏性操作。
- **代码示例**:
```markdown
# CLAUDE.md 中的禁止事项示例

## 禁止事项
- 绝对不要删除或跳过现有测试
- 不要修改 db/migrations/ 目录下的已有文件
- 不要在没有明确要求时添加新的 npm 依赖
- 不要修改 .env 或任何包含密钥的文件
- 不要使用 any 类型（TypeScript 项目）
- 不要在 PR 中包含 console.log 调试语句
```

## 5. 用 Git Worktree 跑多个并行 Claude 会话
- **来源**: [@mvanhorn](https://x.com/mvanhorn/article/2107139054907388097) on X | 🔥 Agentic Engineering 系列热门文章
- **摘要**: 资深开发者 mvanhorn 在其广受欢迎的 "Every Agentic Engineering Hack I Know" 系列文章中推荐：使用 git worktree 创建多个工作目录，每个目录运行独立的 Claude Code 会话。这样可以同时处理 3-5 个不相关的任务而互不干扰。每个 worktree 有自己的分支和文件状态，完成后合并回主分支即可。
- **代码示例**:
```bash
# 创建 worktree 用于并行任务
git worktree add ../feature-auth feature/auth
git worktree add ../feature-api feature/api
git worktree add ../bugfix-login bugfix/login

# 在每个 worktree 目录中启动独立的 Claude Code 会话
cd ../feature-auth && claude
cd ../feature-api && claude
cd ../bugfix-login && claude

# 完成后清理 worktree
git worktree remove ../feature-auth
```

## 6. 用 .claude/rules/ 分路径加载规则：大型项目的配置利器
- **来源**: [claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 600+ Stars
- **摘要**: 对于大型项目或 monorepo，社区推荐使用 .claude/rules/ 目录存放分模块的规则文件，通过 frontmatter 中的路径匹配条件按需加载。这样前端代码只加载前端规则，后端代码只加载后端规则，避免不相关的上下文干扰 Claude 的判断。比一个巨大的 CLAUDE.md 文件更高效、更可维护。
- **代码示例**:
```markdown
<!-- .claude/rules/frontend.md -->
---
paths:
  - "src/components/**"
  - "src/pages/**"
  - "*.tsx"
---
- 使用 React 函数组件和 hooks
- 样式使用 Tailwind CSS
- 组件必须导出 TypeScript 接口定义 props

<!-- .claude/rules/api.md -->
---
paths:
  - "src/api/**"
  - "src/services/**"
---
- 所有 API 端点必须有输入验证
- 使用统一的错误处理中间件
- 必须编写集成测试
```

## 7. Dynamic Workflows 的进阶用法：多路径尝试 + 评判代理
- **来源**: [@trq212](https://x.com/trq212/status/2061907337154367865) on X | 🔥 Anthropic 工程师分享
- **摘要**: Anthropic 工程师 Thariq 分享了 dynamic workflows 的高级用法：让多个代理用不同策略尝试同一个任务，然后由一个"评判代理"比较各方案，选出最优解。这种模式特别适合开放性问题（如架构设计、性能优化），因为不同的解决路径可能产生截然不同的结果。通过竞争和评判，获得比单一代理更高质量的输出。
- **代码示例**:
```javascript
// workflow 脚本示例：多路径竞争 + 评判
export const meta = {
  name: 'compete-and-judge',
  description: '多策略竞争，评判代理选最优',
  phases: [{ title: 'Attempt' }, { title: 'Judge' }]
}

const strategies = [
  { key: 'conservative', prompt: '用最小改动修复这个性能问题' },
  { key: 'aggressive', prompt: '重构这个模块以获得最佳性能' },
  { key: 'creative', prompt: '用完全不同的算法思路解决这个问题' }
]

const attempts = await parallel(
  strategies.map(s => () =>
    agent(s.prompt, { label: s.key, phase: 'Attempt' })
  )
)

const best = await agent(
  `比较这些方案并选出最优解: ${JSON.stringify(attempts)}`,
  { label: 'judge', phase: 'Judge' }
)
return best
```

## 8. 把安全约束放进 Hooks 而非 CLAUDE.md
- **来源**: [trailofbits/claude-code-config](https://github.com/trailofbits/claude-code-config) on GitHub | ⭐ 知名安全公司 Trail of Bits 开源
- **摘要**: Trail of Bits 安全团队强调：关键的安全约束不应该只写在 CLAUDE.md 中（因为 prompt 指令只是"大部分时候"会被遵守），而应该通过 hooks 机制强制执行。Hooks 是在特定事件（如代码提交前、文件修改后）触发的脚本，Claude 无法绕过。比如禁止提交含密钥的文件、强制运行 linter、阻止删除测试文件等安全策略，都应该用 hooks 实现。
- **代码示例**:
```json
// .claude/settings.json 中的 hooks 配置
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "command": "python3 .claude/hooks/check_no_secrets.py \"$TOOL_INPUT\""
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "command": "npx eslint --fix $FILEPATH 2>/dev/null || true"
      }
    ]
  }
}
```
