## 1. 5 个改变工作方式的内置斜杠命令
- **来源**: [Vaibhav Sisinty](https://x.com/VaibhavSisinty/status/2067234559721361699) on X | 🔥 高互动热帖
- **摘要**: 大多数人从未输入过这些命令，但它们能彻底改变你的工作流程：`/compact` 在上下文即将溢出时手动总结对话；`/plan` 在多文件变更前先让 Claude 规划方案；`/loop` 按间隔重复执行任务；`/clear` 彻底重置上下文；以及自定义命令系统。
- **代码示例**:
```bash
# /compact - 手动压缩上下文（比自动压缩更精确）
> /compact 保留认证模块的重构方案和测试结果

# /loop - 自动定时执行任务
> /loop 5m /babysit    # 每5分钟自动处理PR评审
> /loop 30m check CI   # 每30分钟检查CI状态

# /plan - 复杂任务先规划
> /plan 重构整个支付模块的错误处理逻辑
```

## 2. "穴居人 Claude" token 节省神话的真相
- **来源**: [Hayrettin Tüzel](https://x.com/devneeddev/status/2040701876871157849) on X | 🔥 深度技术分析帖
- **摘要**: 社区流传让 Claude 用极简风格回复（如"工具完成"代替"我已执行了网络搜索工具"）可节省 75% token。但实际分析表明：在真实 agentic 工作流中，90%+ 的 token 开销来自工具调用、上下文窗口、系统提示词和 CLAUDE.md，而非文本输出。Claude Code 内部已自动优化输出长度，这个 hack 效果微乎其微。
- **代码示例**:
```markdown
# ❌ 不要在 CLAUDE.md 中加这类规则：
"Reply like a caveman. Use minimal words."

# ✅ 真正节省 token 的方法：
# 1. 保持 CLAUDE.md 精简（<200行）
# 2. 用 .claude/rules/*.md 按路径懒加载规则
# 3. 积极使用 /compact 控制上下文
# 4. 敏感任务保持上下文低于 30%
```

## 3. Skill-Eval 钩子系统：自动匹配项目技能
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 6,000+ stars
- **摘要**: 这个模板项目展示了一个自动技能评估系统——通过 hooks 分析你的提示词关键字、文件路径和意图，自动激活相关的 Skills（如 Jest 测试模式、React UI 模式、GraphQL 规范等），无需手动选择。配合 MCP 集成 JIRA/Linear，可实现从读取工单到创建 PR 的端到端自动化。
- **代码示例**:
```json
// .claude/settings.json - 钩子配置示例
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "command": "node .claude/hooks/skill-eval.js"
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Edit",
        "command": "npx prettier --write $CLAUDE_FILE_PATH"
      }
    ]
  }
}
```

## 4. 上下文窗口黄金法则：30% 是智力分界线
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 62.1k stars
- **摘要**: 这个拥有 62k+ star 的最佳实践仓库指出：Claude 的"智力衰退区"大约在上下文占用 40% 时开始。对于关键工作，应将上下文控制在 30% 以下。建议使用 `/compact` 时附带明确提示（告诉它保留什么），而非依赖自动压缩。在 monorepo 中使用 `.claude/rules/*.md` 配合 YAML frontmatter 实现按路径懒加载。
- **代码示例**:
```markdown
<!-- .claude/rules/auth.md -->
---
globs: ["src/auth/**", "src/middleware/auth*"]
---
# 认证模块规则
- 所有 token 操作必须使用 jose 库
- refresh token 有效期 7 天
- 错误一律抛出 AuthError 子类
```

## 5. 工作流编排：从文件级到模块级的跃迁
- **来源**: [Thariq](https://x.com/trq212/status/2061907538741006796) on X | 🔥 高互动（联合创作者深度解读）
- **摘要**: Workflows 被认为是自 Skills 和 Subagents 之后 Claude Code 最大的能力升级。通过 `export const meta` 定义多阶段工作流，可以将多个代理组织成 pipeline，实现发现→验证→综合的复杂任务。特别适合非技术任务（如研究、审计、文档生成），让 Claude Code 的适用范围超越纯编码。
- **代码示例**:
```javascript
// .claude/workflows/security-audit.js
export const meta = {
  name: 'security-audit',
  description: 'Multi-agent security audit with verification',
  phases: [
    { title: 'Scan', detail: 'Find potential vulnerabilities' },
    { title: 'Verify', detail: 'Adversarially verify each finding' },
  ],
}

phase('Scan')
const findings = await parallel(
  DIMENSIONS.map(d => () => agent(d.prompt, {
    schema: FINDING_SCHEMA,
    phase: 'Scan'
  }))
)

phase('Verify')
const verified = await pipeline(
  findings.filter(Boolean).flatMap(r => r.issues),
  f => agent(`Try to refute: ${f.desc}`, { schema: VERDICT })
)
```

## 6. 自定义命令实现端到端工单自动化
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 6,000+ stars
- **摘要**: 通过在 `.claude/commands/` 目录下创建 Markdown 模板，可以定义可复用的工作流命令。最强大的例子是 `/ticket` 命令：自动从 JIRA/Linear 读取工单详情、分析需求、创建分支、实现功能、运行测试、最终创建 PR——全程无需手动干预。
- **代码示例**:
```markdown
<!-- .claude/commands/ticket.md -->
# /ticket 命令

读取工单 $ARGUMENTS 的详细信息，然后：

1. 分析需求和验收标准
2. 创建功能分支 `feat/{ticket-id}-{short-desc}`
3. 实现所有需求
4. 确保所有测试通过
5. 创建 PR 并关联工单

使用 MCP 工具与项目管理系统交互。
```

## 7. CLAUDE.md 精简原则：200 行封顶，60 行最优
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 62.1k stars
- **摘要**: 社区实践表明，CLAUDE.md 的有效性随长度增加而递减。目标是每个文件不超过 200 行，成功案例中最精简的仅 60 行。核心策略：将领域特定规则包裹在 `<important if="...">` 标签中防止被忽略；利用祖先/后代加载机制实现 monorepo 结构；用 `.claude/rules/*.md` 分片管理替代单一巨型文件。
- **代码示例**:
```markdown
<!-- CLAUDE.md - 精简示例（~60行） -->
# 项目：电商后端 API

## 技术栈
Node.js 22, TypeScript 5.7, Fastify, Prisma, PostgreSQL

## 关键约定
- 路由文件放在 src/routes/，命名 {resource}.route.ts
- 业务逻辑放在 src/services/
- 所有数据库操作通过 Prisma，禁止原始 SQL
- 错误处理用 AppError 类层次结构

## 测试
- 运行: `pnpm test`
- 集成测试用 testcontainers 起 PostgreSQL
- 覆盖率目标 80%+

## 禁止事项
<important>
- 绝不在路由层直接操作数据库
- 绝不 commit .env 文件
- 绝不使用 any 类型
</important>
```
