## 1. 禁用自动记忆功能以提升输出质量
- **来源**: [@kunchenguid](https://x.com/kunchenguid/status/2067728608584675465) on X | 🔥 高互动讨论帖
- **摘要**: 输入 `/memory` 可以关闭 Claude Code 的自动记忆功能。自动记忆有时会存储不相关或低质量的上下文，关闭后反而能让 Claude 更专注于当前任务，提高代码生成质量。
- **代码示例**:
```
# 在 Claude Code 会话中输入
/memory
# 然后选择禁用自动记忆
```

## 3. 五个改变工作方式的斜杠命令
- **来源**: [@VaibhavSisinty](https://x.com/VaibhavSisinty/status/2067234559721361699) on X | 🔥 高互动讨论帖
- **摘要**: 五个最实用的内置命令：`/compact` 压缩上下文防止 Claude 丢失主线；`/loop` 按设定间隔自动重复执行提示，无需手动重复；`/schedule` 在 Anthropic 云端创建定时任务，即使关闭笔记本也能运行；`/deep-research` 进行多源交叉验证的深度研究并返回带引用的报告。
- **代码示例**:
```
/loop 5m /code-review    # 每5分钟自动执行代码审查
/schedule "0 9 * * *"    # 每天早上9点执行任务
/deep-research "对比 React 和 Vue 在 2026 年的生态差异"
```

## 4. CLAUDE.md 写作黄金法则：控制在 60 行以内
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 59.3k stars
- **摘要**: 当 CLAUDE.md 超过 80 行时，Claude 会开始忽略部分指令。社区最佳实践建议控制在 60 行以内。对于大型项目，使用 `.claude/rules/*.md` 配合 YAML frontmatter 按文件模式懒加载规则，而非把所有内容塞进一个文件。
- **代码示例**:
```yaml
# .claude/rules/frontend.md
---
globs: ["src/components/**/*.tsx", "src/pages/**/*.tsx"]
---
- 使用 React Server Components
- 样式统一使用 Tailwind CSS
- 组件命名使用 PascalCase
```

## 5. 用 /rewind 代替纠正——回到错误之前重新开始
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 59.3k stars
- **摘要**: 当 Claude 走错方向时，不要试图在当前上下文中纠正它。使用 `/rewind` 回退到失败尝试之前的节点，带着已学到的教训重新提示。这比在错误基础上修补更高效，因为被污染的上下文会持续影响后续输出。

## 6. 上下文管理：避免进入"愚钝区"
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 59.3k stars
- **摘要**: 当会话超过 300-400k tokens 时，Claude 的表现会明显下降，大约在上下文利用率达到 40% 时就开始进入"愚钝区"。最佳实践是：新任务开新会话、用 subagents 分流探索性工作、将每个 turn 视为决策点（继续/回退/清除/压缩/委派）。

## 7. 并行 Worktrees：同时运行 3-5 个 Claude 会话
- **来源**: [@heyshrutimishra](https://x.com/heyshrutimishra/status/2018368588432978151) on X（转述 Boris 的建议）| 🔥 高互动讨论帖
- **摘要**: Claude Code 创始人 Boris 的核心生产力技巧：使用 git worktrees 创建多个工作目录，每个目录运行独立的 Claude 会话，实现真正的并行开发。这是大多数人忽略的"生产力作弊码"。
- **代码示例**:
```bash
# 创建多个 worktree 并行开发
git worktree add ../feature-auth feature/auth
git worktree add ../feature-api feature/api
git worktree add ../bugfix-login bugfix/login

# 在每个 worktree 中启动独立的 Claude Code 会话
cd ../feature-auth && claude
cd ../feature-api && claude
cd ../bugfix-login && claude
```

## 8. CLAUDE.md 中的提示策略：先规划再执行
- **来源**: [@svpino](https://x.com/svpino/status/2018682144361734368) on X | 🔥 高互动讨论帖
- **摘要**: 在 CLAUDE.md 中添加规划指令，强制 Claude 在写代码前先描述方案并等待批准。对于需要修改多文件的任务，要求 Claude 先列出影响范围。这种方式能显著减少返工次数。
- **代码示例**:
```markdown
<!-- 在 CLAUDE.md 中添加 -->
- Before writing any code, describe your approach and wait for approval.
- Always ask clarifying questions before writing any code if requirements are ambiguous.
- If a task requires changes to more than 3 files, list all affected files first.
```
