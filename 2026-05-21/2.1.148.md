## 1. 并行会话 + Git Worktree——10 倍生产力秘诀
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 54.4k stars
- **摘要**: 社区高手同时运行 10-15 个 Claude Code 会话——终端标签页 5 个、网页版 5-10 个、手机端若干。关键是每个会话分配独立的 git worktree，避免文件冲突。这是目前社区公认的第一生产力技巧，让多个功能、Bug 修复、重构任务真正并行推进。
- **代码示例**:
```bash
# 为并行会话创建独立 worktree
git worktree add ../feature-auth feature/auth
git worktree add ../fix-perf fix/performance
git worktree add ../refactor-db refactor/database

# 每个 worktree 中启动独立 Claude Code 会话
cd ../feature-auth && claude
cd ../fix-perf && claude
cd ../refactor-db && claude

# centminmod 提供的快捷函数（2.3k stars）
# clx / cx 命令可自动管理 worktree 生命周期
```

## 2. 自我改进规则——让 Claude 从错误中学习
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 54.4k stars
- **摘要**: 每次 Claude 犯错并被纠正后，立即让它把教训写入 `lessons.md` 文件。随着时间推移，Claude 会针对你的具体项目"自我进化"，同样的错误不会再犯。这是一种低成本、高回报的持续改进机制。
- **代码示例**:
```bash
# 当 Claude 犯错后，说：
"把这次错误的原因和正确做法写入 lessons.md，
下次遇到类似情况要先检查这个文件"

# lessons.md 示例内容：
# - 修改 API 路由时，必须同步更新 OpenAPI spec
# - 本项目使用 pnpm，不要用 npm install
# - 数据库迁移必须可回滚，不能用 DROP COLUMN
```

## 3. Hook 自动化——在错误落盘前拦截
- **来源**: [ChrisWiles](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 5.9k stars
- **摘要**: 通过 `settings.json` 配置四种 Hook 事件（PreToolUse、PostToolUse、UserPromptSubmit、Stop），实现自动化质量把关。例如：在保存文件后自动跑 lint 和格式化，在提交前自动运行测试，在受保护分支上阻止直接编辑。这比事后修复效率高得多。
- **代码示例**:
```json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "command": "npx prettier --write $CLAUDE_FILE_PATH && npx eslint --fix $CLAUDE_FILE_PATH"
      }
    ],
    "PreToolUse": [
      {
        "matcher": "Edit",
        "command": "if git branch --show-current | grep -q 'main\\|master'; then echo 'BLOCK: 不要直接编辑主分支'; exit 1; fi"
      }
    ]
  }
}
```

## 4. Skill 智能评估——让 Claude 自动匹配领域知识
- **来源**: [ChrisWiles](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 5.9k stars
- **摘要**: 在 `.claude/skills/` 目录下为项目的不同领域创建 SKILL.md 文件，配合 `skill-eval.js` 和 `skill-rules.json` 构建智能匹配系统。Claude 会根据用户提示中的关键词、文件路径和意图模式，自动选择最相关的技能上下文。使用 `context: fork` 隔离 Skill 执行，让主上下文只看到结果。
- **代码示例**:
```markdown
<!-- .claude/skills/testing-patterns/SKILL.md -->
---
name: testing-patterns
description: Jest patterns for this project.
context: fork
---

## 测试规范
- 使用 describe/it 嵌套结构
- Mock 外部依赖，不 mock 内部模块
- 每个测试文件对应一个源文件
```

## 5. CLAUDE.md 黄金法则——200 行封顶，60 行最佳
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 54.4k stars
- **摘要**: 社区实测发现，CLAUDE.md 超过 200 行后，Claude 会开始降低对后面内容的优先级。复杂领域建议控制在 60 行以内，把核心约束用 `<important if="...">` 标签包裹以防被忽略。超出的内容应拆分到子目录的 CLAUDE.md 或 Skill 文件中，利用 Claude 的分层加载机制按需读取。
- **代码示例**:
```markdown
<!-- 根目录 CLAUDE.md（控制在 60 行内） -->
# 项目概要
TypeScript + React + PostgreSQL 全栈应用

# 关键命令
- `pnpm dev` 启动开发服务器
- `pnpm test` 运行测试
- `pnpm lint` 代码检查

<important if="editing database files">
所有数据库迁移必须可回滚，禁止 destructive 操作
</important>

# 详细规范见各子目录 CLAUDE.md
```

## 6. 重复任务一键 Slash Command 化
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 54.4k stars
- **摘要**: 如果你每天重复做某件事超过一次，就应该把它转成 `.claude/commands/` 下的 Slash Command。相比每次手动输入提示词，Command 可以版本控制、团队共享、保持一致性，还能作为 Skill 的入口点，大幅减少重复提示开销。
- **代码示例**:
```markdown
<!-- .claude/commands/pr-review.md -->
Review the current PR changes:
1. Check for security vulnerabilities
2. Verify error handling completeness
3. Ensure test coverage for new code paths
4. Flag any breaking API changes
Output a structured review with severity levels.
```
```bash
# 使用方式：在 Claude Code 中直接输入
/pr-review
```

## 7. 双重记忆架构——Git 共享 + 本地私有
- **来源**: [centminmod](https://github.com/centminmod/my-claude-code-setup) on GitHub | ⭐ 2.3k stars
- **摘要**: 采用双层记忆系统：`CLAUDE-*.md` 文件提交到 Git 供团队共享，同时使用机器本地的 auto-memory 存储个人偏好和环境特定配置。这样既保证团队一致性，又能适配每个开发者的个性化需求，防止跨会话的上下文丢失。
- **代码示例**:
```bash
# Git 共享层（团队统一）
CLAUDE.md              # 项目核心规则
CLAUDE-testing.md      # 测试标准
CLAUDE-api.md          # API 设计规范

# 本地私有层（个人偏好，不提交到 Git）
# Claude 自动管理的 memory 文件
# 存储如：个人常用命令、本地环境路径、偏好的代码风格等
```

## 8. GitHub Actions 自动化——低成本持续质量保障
- **来源**: [ChrisWiles](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 5.9k stars
- **摘要**: 用 Claude Code 的 GitHub Actions 集成实现低成本自动化：PR 自动审查（每次 $0.05-$0.50）、每周代码质量扫描（$1-$5/周）、月度文档同步（$0.50-$2/月）、双周依赖审计（$0.20-$1）。把重复性的质量保障工作交给 AI，开发者专注创造性工作。
- **代码示例**:
```yaml
# .github/workflows/claude-pr-review.yml
name: Claude PR Review
on:
  pull_request:
    types: [opened, synchronize]

jobs:
  review:
    runs-on: ubuntu-latest
    steps:
      - uses: anthropics/claude-code-action@v1
        with:
          prompt: |
            Review this PR for:
            - Security vulnerabilities
            - Performance regressions
            - Test coverage gaps
            Flag issues with severity levels.
```
