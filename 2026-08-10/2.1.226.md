# Claude Code 2.1.226 社区实用技巧 - 2026-08-10

## 1. Plan-First 工作流：先规划再动手
- **来源**: [Claude Code Hacks 2026](https://youmind.com/landing/x-viral-articles/claude-code-hacks-2026-workflow) on YouMind | 🔥 高互动热文
- **摘要**: 社区公认的最重要习惯：每次有新想法时先用计划模式（`Shift+Tab×2` 或 `claude --permission-mode plan`）让 Claude 只读分析、生成方案，审核通过后再执行。计划模式下 Claude 无法修改任何文件，避免了"还没想清楚就动手"导致的返工。
- **代码示例**:
```bash
# 以只读计划模式启动会话
claude --permission-mode plan

# 或在会话中切换到计划模式
# 按两次 Shift+Tab 进入 Plan 模式
```

## 2. 验证优先：给 Claude 自查能力
- **来源**: [Claude Code Workflow Best Practices](https://dev.to/galian/claude-code-workflow-best-practices-that-ship-code-na) on DEV Community | 🔥 广泛引用
- **摘要**: 社区投票选出的"如果只能采纳一个技巧"的冠军：始终给 Claude 一种验证自身输出的方式。在 CLAUDE.md 中明确写出验证命令（如 `npm test`、`pytest`、`cargo check`），Claude 会在每次修改后自动运行验证，大幅减少"看起来对但实际有 bug"的情况。
- **代码示例**:
```markdown
# CLAUDE.md
## 验证命令
- 每次修改代码后运行: npm run typecheck && npm test
- 提交前运行: npm run lint -- --fix
```

## 3. MCP + Skills 组合拳：1+1 > 2
- **来源**: [Claude Code Workflows 2026](https://smart-webtech.com/blog/claude-code-workflows-and-best-practices/) on SmartWebTech | 🔥 社区热议
- **摘要**: 单独使用 MCP 连接外部工具（数据库、API）效果有限，单独写 Skill 也缺乏实际数据源。社区发现将 MCP 连接与对应的 Skill 配对使用（例如 MCP 连接 PostgreSQL + 编写一个教 Claude 如何查询该数据库的 Skill），效果远超单独使用任何一个。
- **代码示例**:
```json
// .claude/settings.json - MCP 连接
{
  "mcpServers": {
    "postgres": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-postgres", "postgresql://localhost/mydb"]
    }
  }
}
```
```markdown
<!-- .claude/skills/db-query.md -->
# 数据库查询技巧
- 查询前先用 list_tables 了解表结构
- 大表查询必须加 LIMIT，默认 100 行
- 生产环境只允许 SELECT，禁止 UPDATE/DELETE
```

## 4. 分步执行模式："做完第一步就停"
- **来源**: [Claude Code Workflow Best Practices](https://dev.to/galian/claude-code-workflow-best-practices-that-ship-code-na) on DEV Community | 🔥 高互动
- **摘要**: 对于大型功能开发，社区推荐使用"分步执行"模式：在提示词中明确要求"Do step one, then stop and show me"。每一步完成后 Claude 暂停等待你审核，确认后再输入"continue"继续下一步。虽然感觉更慢，但能在错误方向上及时纠正，总体反而更快。
- **代码示例**:
```
# 提示词模板
请按以下步骤实现用户认证功能：
1. 创建数据库 migration
2. 实现注册 API
3. 实现登录 API
4. 添加 JWT 中间件

请先完成第一步，然后停下来展示给我看。
```

## 5. CLAUDE.md 的隐藏上限：150 条指令
- **来源**: [CLAUDE.md Setup Guide 2026](https://baeseokjae.github.io/posts/claude-md-setup-guide-2026/) on RockB | 🔥 深度分析
- **摘要**: Claude Code 的系统提示已包含约 50 条内置指令，而前沿模型能可靠遵循的指令上限约为 150-200 条。这意味着你的 CLAUDE.md 实际只有约 100-150 条指令的空间。社区建议将 CLAUDE.md 控制在 100-400 行之间：低于 100 行说明缺少关键上下文，超过 400 行则应拆分到子目录的 CLAUDE.md 中。
- **代码示例**:
```
# 推荐的 CLAUDE.md 结构（控制在 200 行内）
1. 项目简介（5 行）
2. 技术栈和架构（10 行）
3. 构建/测试命令（10 行）
4. 编码规范（20 行）
5. 常见陷阱和注意事项（15 行）
# 总计约 60 行核心指令，留出充足空间
```

## 8. 截图驱动开发：粘贴图片即可编程
- **来源**: [Claude Code Hacks 2026](https://youmind.com/landing/x-viral-articles/claude-code-hacks-2026-workflow) on YouMind | 🔥 病毒式传播
- **摘要**: Claude Code 支持直接粘贴图片（`Ctrl+V`），社区发现这在多种场景下极其高效：粘贴 bug 截图让 Claude 定位问题、粘贴设计稿让 Claude 实现 UI、粘贴 Slack 对话让 Claude 理解需求、甚至粘贴手绘草图生成代码。这种"截图驱动开发"模式正在成为社区新宠。
