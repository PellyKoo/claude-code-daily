# Claude Code 2.1.226 社区实用技巧 - 2026-08-09

## 1. 上下文管理：保持在 30% 以下
- **来源**: [Dex / MLOps Community](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 64.3k stars
- **摘要**: 当上下文窗口使用率超过约 40% 时，Claude Code 会进入"笨拙区"，输出质量明显下降。社区建议将上下文使用率控制在 30% 以下，尤其在处理复杂任务时。超过阈值后应使用 `/rewind` 或开启新会话。
- **代码示例**:
```
# 在 CLAUDE.md 中添加提醒
- 复杂任务请保持上下文在 30% 以下
- 使用 "summarize from here" 压缩历史上下文
```

## 2. 使用 "summarize from here" 生成交接笔记
- **来源**: [Thariq (@trq212)](https://x.com/trq212/status/2061907538741006796) on X | 🔥 高互动
- **摘要**: 在 `/rewind` 之前，先让 Claude "summarize from here"，它会自动生成一份交接笔记，记录当前进度、已完成的工作和待办事项。这相当于让模型为自己写工作日志，下次会话可以无缝衔接。

## 3. 并行多会话 + Git Worktree 提速
- **来源**: [社区最佳实践](https://www.marktechpost.com/2026/06/14/claude-code-guide-2026-25-features-with-examples-demo/) on MarkTechPost | 🔥 广泛讨论
- **摘要**: 同时运行 3-5 个 Claude Code 会话，每个在独立的 git worktree 中工作，是目前社区公认的最大生产力提升方式。Claude Code 内置 worktree 支持，使用 `claude --worktree` 即可启动隔离会话，各会话互不干扰。
- **代码示例**:
```bash
# 启动隔离的 worktree 会话
claude --worktree

# 或手动创建 worktree 后在其中运行
git worktree add ../feature-auth
cd ../feature-auth && claude
```

## 4. 用 Hooks 替代 CLAUDE.md 实现关键规则
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 64.3k stars
- **摘要**: CLAUDE.md 中的指令遵循率约 70%——对代码风格偏好来说够用，但对于"不要推送到 main"或"不要删除生产数据"这类关键规则，70% 的遵循率意味着灾难。Hooks 通过在 Claude 工作流的特定节点运行脚本，将遵循率提升到 100%。
- **代码示例**:
```json
// .claude/settings.json
{
  "hooks": {
    "PreToolUse": [{
      "matcher": "Bash",
      "command": "echo \"$CLAUDE_TOOL_INPUT\" | grep -q 'git push.*main' && echo 'BLOCK: 禁止直接推送到 main' && exit 1 || exit 0"
    }]
  }
}
```

## 5. 功能级子代理优于角色级子代理
- **来源**: [Boris Cherny (Claude Code 创建者)](https://github.com/shanraisshan/claude-code-best-practice) via GitHub | ⭐ 64.3k stars
- **摘要**: 不要创建"QA 工程师"或"后端工程师"这样的通用角色代理，而应该创建功能特定的子代理配合 Skills 实现渐进式信息披露。例如用一个专门处理"表单验证"的 Skill，而不是一个泛泛的"前端代理"。这样上下文更聚焦，输出质量更高。

## 6. CLAUDE.md 支持 @filename 引用注入
- **来源**: [社区技巧汇总](https://www.marktechpost.com/2026/06/14/claude-code-guide-2026-25-features-with-examples-demo/) on MarkTechPost | 🔥 广泛引用
- **摘要**: 在 CLAUDE.md 中使用 `@filename` 语法可以引用项目中的其他文件（如数据库 schema、API 类型定义），这些文件会在会话启动时自动注入上下文。避免了每次手动粘贴关键文件的麻烦。
- **代码示例**:
```markdown
# CLAUDE.md
## 项目上下文
@prisma/schema.prisma
@src/types/api.ts
@docs/architecture.md
```

## 7. /loop 命令实现自动化重构循环
- **来源**: [社区实践](https://support.claude.com/en/articles/14554000-claude-code-power-user-tips) | 🔥 高频讨论
- **摘要**: `/loop` 命令让 Claude 在自动循环中运行单元测试并重构代码，直到所有测试通过，无需人工逐步确认。特别适合大规模重构或复杂系统迁移场景，可持续运行最多 3 天。
- **代码示例**:
```bash
# 在 Claude Code 中输入
/loop 5m run tests and fix failures

# Claude 会每 5 分钟自动运行测试、修复失败，直到全绿
```

## 8. 用 .claude/rules/*.md 替代臃肿的 CLAUDE.md
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 6k+ stars
- **摘要**: 将 CLAUDE.md 保持在 200 行以内，把具体规则拆分到 `.claude/rules/*.md` 文件中，利用 YAML frontmatter 的 path 字段实现按需加载——只有修改相关文件时才注入对应规则，避免上下文污染。
- **代码示例**:
```markdown
<!-- .claude/rules/react-components.md -->
---
path: "src/components/**/*.tsx"
---
- 使用函数式组件，不用 class 组件
- 所有 props 必须有 TypeScript 类型定义
- 使用 React.memo 包裹纯展示组件
```
