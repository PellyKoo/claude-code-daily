## 1. 垂直切片规划（Tracer Bullets）替代逐层开发
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 57.9k stars
- **摘要**: Claude 默认倾向于按水平层（先数据库、再服务层、最后 UI）依次生成代码，这会推迟端到端验证。社区推荐采用 Matt Pocock 提出的"垂直切片"策略：每次让 Claude 完成一个跨所有层的完整功能切片，确保尽早获得可运行的端到端反馈。
- **代码示例**:
```
# 反模式 ❌
"先帮我设计所有数据库表，然后实现所有 API 接口，最后做前端页面"

# 推荐做法 ✅
"实现用户注册功能的完整切片：数据库表 → API 接口 → 前端表单，确保可以端到端运行"
```

## 2. CLAUDE.md 控制在 200 行以内，用域标签按需加载
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 57.9k stars
- **摘要**: CLAUDE.md 过长会导致指令被忽略。社区实践建议核心文件控制在 200 行以内，使用 `<important if="...">` 标签将不同领域的规则分区，并利用 `.claude/rules/` 目录配合 glob 匹配实现懒加载，只在相关文件被操作时才加载对应规则。
- **代码示例**:
```markdown
<!-- .claude/rules/api-*.md 只在操作 API 文件时加载 -->
<!-- CLAUDE.md 主文件保持精简 -->
# 项目规范
- TypeScript strict mode
- 测试覆盖率 > 80%

<important if="editing database migrations">
使用 knex 迁移，禁止手写 SQL DDL
所有新表必须包含 created_at 和 updated_at 字段
</important>
```

## 3. MCP Server 集成实现 Jira 全自动工作流
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 6k stars
- **摘要**: 通过配置 MCP Server 将 Jira 等外部系统直接接入 Claude Code，实现"读 Ticket → 实现功能 → 更新状态 → 创建 PR"的全自动闭环工作流，无需在多个工具之间切换。
- **代码示例**:
```jsonc
// .claude/settings.json
{
  "mcpServers": {
    "jira": {
      "type": "stdio",
      "command": "npx",
      "args": ["-y", "@anthropic/mcp-jira"],
      "env": {
        "JIRA_HOST": "${JIRA_HOST}",
        "JIRA_EMAIL": "${JIRA_EMAIL}",
        "JIRA_API_TOKEN": "${JIRA_API_TOKEN}"
      }
    }
  }
}
```

## 4. 自定义 /ticket 命令编排复杂工作流
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 6k stars
- **摘要**: 利用自定义斜杠命令（Slash Commands）将多步骤操作封装为一键触发的工作流。例如 `/ticket` 命令可以自动读取需求文档、实现代码变更、运行测试并更新外部任务管理系统，大幅减少手动操作步骤。
- **代码示例**:
```markdown
<!-- .claude/commands/ticket.md -->
读取 Jira ticket $ARGUMENTS 的需求描述，然后：
1. 创建功能分支 feature/$ARGUMENTS
2. 根据需求实现代码变更
3. 编写并运行相关测试
4. 提交代码并创建 PR，标题引用 ticket 编号
5. 将 Jira ticket 状态更新为 "In Review"
```

## 5. 定时 GitHub Actions 实现无人值守代码质量巡检
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 6k stars
- **摘要**: 利用 GitHub Actions 定时触发 Claude Code 执行自动化代码质量巡检：每周代码扫描、每月文档对齐检查、每两周依赖更新审计。估算月成本仅 $10-$50，实现低成本的持续代码维护。
- **代码示例**:
```yaml
# .github/workflows/weekly-quality.yml
name: Weekly Quality Sweep
on:
  schedule:
    - cron: '0 9 * * 1'  # 每周一上午 9 点
jobs:
  quality-sweep:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Run Claude Code quality sweep
        run: claude -p "审查 src/ 目录下的代码质量问题，包括未使用的导入、过时的 API 调用和潜在的性能问题，生成报告"
```

## 6. Skill 触发引擎：基于置信度的智能技能匹配
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 6k stars
- **摘要**: 通过 `skill-rules.json` 配置关键词匹配、文件路径分析和意图检测，构建一个带有置信度评分的技能自动匹配引擎。当 Claude 检测到你正在操作测试文件时，自动加载测试相关的最佳实践；操作数据库迁移时，自动加载数据库规范。
- **代码示例**:
```jsonc
// .claude/skill-rules.json
{
  "rules": [
    {
      "skill": "testing",
      "triggers": ["test", "jest", "spec", "tdd", "mock"],
      "filePatterns": ["**/*.test.ts", "**/*.spec.ts"],
      "confidence": 0.85
    },
    {
      "skill": "database",
      "triggers": ["migration", "schema", "knex", "prisma"],
      "filePatterns": ["**/migrations/**", "**/prisma/**"],
      "confidence": 0.90
    }
  ]
}
```

## 7. clx() 函数：一键创建隔离工作树并进入规划模式
- **来源**: [centminmod/my-claude-code-setup](https://github.com/centminmod/my-claude-code-setup) on GitHub | ⭐ 2.4k stars
- **摘要**: 社区分享了一个实用的 Shell 函数，一条命令即可创建带时间戳的 Git Worktree、切换到新目录并以规划模式启动 Claude Code。特别适合需要在不影响主分支的前提下快速启动探索性开发或原型验证的场景。
- **代码示例**:
```bash
# 添加到 ~/.bashrc 或 ~/.zshrc
clx() {
    local branch_name="${1:-worktree-$(date +%Y%m%d-%H%M%S)}"
    git worktree add "../$branch_name" -b "$branch_name" && \
    cd "../$branch_name" || return 1
    claude --model opusplan --permission-mode plan
}

# 使用方式
clx feature-new-auth   # 指定分支名
clx                     # 自动生成带时间戳的分支名
```
