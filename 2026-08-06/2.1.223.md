## 1. CTRL+V 直接粘贴截图：视觉驱动开发
- **来源**: [Santiago (@svpino)](https://x.com/svpino/status/2050563493708112190) on X | 🔥 20条技巧合集，数千互动
- **摘要**: 在终端中按 CTRL+V 可以直接把截图粘贴给 Claude Code——不需要保存文件、不需要写路径。这意味着你可以截一张 bug 界面、设计稿、Slack 对话、甚至手绘草图，直接喂给 Claude 让它理解并行动。社区反馈：这个功能让"看到什么就修什么"的工作流成为可能，特别适合前端调试和 UI 还原。
- **代码示例**:
```bash
# 使用场景 1: Bug 修复
# 截图浏览器中的 bug → CTRL+V 粘贴到 Claude Code
"这个按钮在移动端溢出了，帮我修复这个 CSS 问题"

# 使用场景 2: UI 还原
# 截图设计稿 → CTRL+V
"按照这个设计稿实现这个卡片组件"

# 使用场景 3: 错误信息
# 截图终端报错 → CTRL+V
"这个错误怎么解决？"
```

## 2. CTRL+G 编辑器模式：告别终端里写长 Prompt
- **来源**: [Santiago (@svpino)](https://x.com/svpino/status/2050563493708112190) on X | 🔥 高互动技巧帖
- **摘要**: 按 CTRL+G 会打开你默认的代码编辑器（VS Code、Vim 等），让你在编辑器里编写复杂的 prompt，保存关闭后自动发送给 Claude。终端里写多行 prompt 既痛苦又容易出错，这个功能彻底解决了这个问题。社区用法：提前在编辑器里维护一个 prompt 模板库，需要时复制粘贴到编辑器窗口中修改后发送。
- **代码示例**:
```bash
# 按 CTRL+G 后，编辑器会打开一个临时文件
# 你可以在里面写多行、结构化的 prompt：

# ── 编辑器内容示例 ──
# 请帮我重构 src/auth/ 目录下的认证模块：
#
# 目标：
# 1. 将 JWT 和 OAuth 逻辑分离到独立的 strategy 文件
# 2. 添加 refresh token 轮换机制
# 3. 所有错误使用统一的 AuthError 类
#
# 约束：
# - 不要改动现有的 API 接口签名
# - 保持向后兼容
# - 每完成一个文件后运行 npm test
# ── 保存并关闭，自动发送 ──

# 设置默认编辑器
export EDITOR=code  # VS Code
export EDITOR=vim   # Vim
```

## 3. /insights 使用报告：用数据优化你的工作流
- **来源**: [Santiago (@svpino)](https://x.com/svpino/status/2050563493708112190) on X | 🔥 社区热议功能
- **摘要**: `/insights` 命令生成你的 Claude Code 使用报告——包括 token 消耗、常用命令、会话时长、成功率等数据。Santiago 推荐的进阶用法：把 insights 报告附到一个新的 Claude 会话中，让 Claude 分析你的使用模式并给出优化建议。社区实测：通过这种方式发现自己 60% 的 token 浪费在重复的上下文加载上，改用 `/compact` 策略后成本降低了 40%。
- **代码示例**:
```bash
# 生成使用报告
/insights

# 进阶：让 Claude 分析你的使用模式
# 1. 先运行 /insights 获取报告
# 2. 开一个新会话，把报告粘贴进去
"分析这份 Claude Code 使用报告，找出：
1. 我最常犯的模式错误
2. token 消耗最高的操作类型
3. 可以通过自动化减少的重复操作
给我3个具体的改进建议。"
```

## 4. 并行会话 + tmux：一人多线程开发
- **来源**: [Claude Code Hacks 2026](https://youmind.com/landing/x-viral-articles/claude-code-hacks-2026-workflow) on YouMind | 🔥 病毒式传播文章
- **摘要**: 社区发现的高效模式：用 tmux 开多个终端窗格，每个窗格运行一个 Claude Code 会话，分别处理不同的任务。例如左边窗格让 Claude 写功能代码，右边窗格让另一个 Claude 写测试，第三个窗格做 code review。关键技巧：如果先 tmux 到远程机器（如 Mac Mini），所有会话都在远程运行，本地笔记本只是一个窗口，关掉笔记本也不影响运行。
- **代码示例**:
```bash
# 基础：tmux 多会话工作流
tmux new-session -s claude-dev

# 窗格 1: 功能开发
claude
"实现用户头像上传功能"

# CTRL+B % 分割窗格
# 窗格 2: 测试编写
claude
"为 src/upload/ 编写完整的单元测试"

# CTRL+B " 水平分割
# 窗格 3: 审查
claude --permission-mode plan
"审查 src/upload/ 的安全性"

# 远程开发：先连接远程机器
ssh mac-mini
tmux new-session -s remote-claude
# 现在所有 Claude 会话都在 Mac Mini 上运行
# 关闭笔记本也不会中断
```

## 5. # 号指令持久化：一条消息变永久规则
- **来源**: [Santiago (@svpino)](https://x.com/svpino/status/2050563493708112190) on X & [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 40+ tips 合集
- **摘要**: 在消息前加 `#` 号，Claude Code 会把这条消息保存为持久化指令（写入 CLAUDE.md 或 memory）。不需要手动编辑配置文件，一条命令就能建立长期规则。社区推荐的用法：每当你纠正 Claude 的一个错误行为时，加上 # 号让它"记住"。例如 `# 这个项目用 pnpm，不要用 npm`，之后每次会话都会遵循这个规则。
- **代码示例**:
```bash
# 保存项目级别的规则
# 这个项目使用 pnpm 作为包管理器，永远不要用 npm

# 保存编码风格偏好
# 所有 React 组件使用函数式组件 + TypeScript，不要用 class 组件

# 保存测试规则
# 测试文件放在 __tests__ 目录下，使用 .test.ts 后缀

# 保存个人偏好（跨项目生效）
/memory
# 我偏好简洁的代码风格，变量名使用 camelCase
# 回答用中文，代码注释用英文
```

## 6. opusplan 混合模型策略：性价比最优解
- **来源**: [Claude Code Best Practices](https://www.the-ai-corner.com/p/claude-best-practices-power-user-guide-2026) on The AI Corner & 社区多个讨论帖 | 🔥 成本优化热门话题
- **摘要**: 社区总结出的模型选择最佳实践：使用 `opusplan` 模式——规划阶段用 Opus（推理能力强），执行阶段用 Sonnet（速度快、成本低）。这是一个被社区广泛验证的"甜蜜点"。具体数据：纯 Opus 模式每小时约 $3-5，opusplan 降到约 $1-2，而代码质量差异小于 5%。社区共识：除非是极其复杂的架构决策，否则 opusplan 足够应付 95% 的日常开发。
- **代码示例**:
```bash
# 设置 opusplan 模式
# 规划阶段自动使用 Opus，执行阶段使用 Sonnet

# 不同场景的模型建议（社区经验）：
# 日常开发 → opusplan（性价比最优）
# 复杂架构 → opus（需要最强推理）
# 简单修复 → sonnet（速度快，成本低）
# 代码审查 → sonnet（够用且便宜）
# 大规模重构 → opus + workflow（需要最强规划 + 并行执行）

# 在 /config 中调整模型策略
/config
# → Model: opusplan
```

## 8. dx 插件：日常开发工作流技能包
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 社区推荐的实用插件
- **摘要**: ykdojo 发布的 `dx` 插件为 Claude Code 添加了一系列日常开发技能（skills），覆盖了代码审查、PR 管理、测试生成、文档更新等常见场景。安装后通过 `/dx:review`、`/dx:test` 等斜杠命令调用。社区评价：它把散落在各处的最佳实践打包成了开箱即用的命令，特别适合团队统一开发流程。
- **代码示例**:
```bash
# 安装 dx 插件
/install-plugin ykdojo/claude-code-tips/dx

# 使用 dx 技能
/dx:review     # 代码审查，按维度拆分检查
/dx:test       # 为当前修改生成测试
/dx:refactor   # 智能重构建议
/dx:doc        # 自动更新文档

# 查看所有可用的 dx 技能
/dx:help
```
