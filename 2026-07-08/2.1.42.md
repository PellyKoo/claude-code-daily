## 1. 上下文管理黄金法则：避免"笨区"陷阱
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 62.3k stars
- **摘要**: 社区测试发现 Claude Code 存在"上下文劣化"现象：当上下文利用率超过 40% 时进入"笨区"（Dumb Zone），输出质量显著下降；到 300-400k token 时发生"上下文腐烂"（Context Rot）。最佳实践：保持上下文利用率低于 30%；新任务开新会话；用 `/rewind` 回退失败尝试而不是在上下文中堆积修正；CLAUDE.md 控制在 200 行以内，超出部分拆分到 `.claude/rules/*.md` 按需懒加载。
- **代码示例**:
```
上下文健康指标：
  < 30% 利用率  → ✅ 最佳质量区
  30-40% 利用率 → ⚠️ 开始注意，准备新会话
  > 40% 利用率  → 🔴 "笨区"，输出质量下降
  300k+ tokens  → 💀 上下文腐烂，必须开新会话

# 拆分 CLAUDE.md 到规则文件（按需加载）
.claude/rules/
  react-patterns.md    # 仅编辑 .tsx 时加载
  api-conventions.md   # 仅编辑 routes/ 时加载
  testing-rules.md     # 仅编辑 *.test.* 时加载
```

## 2. Ultracode 模式：让数百个并行代理互相校验

- **摘要**: Claude Code 的 Dynamic Workflows 配合 Ultracode 模式，能让数百个并行代理同时工作并互相检查。只需在提示中提及"workflow"或在 effort 菜单开启 ultracode，Claude 就会自动生成编排方案。关键突破：工作交付单位从"一个文件"跳升到"一整个功能模块"——可以放心把大块任务丢给它，代理们会自动分工、审查、汇总。适合大规模代码迁移、全面审计、多维度代码审查等场景。

# Claude 会自动：
# 1. 扫描所有路由文件（并行 agents）
# 2. 逐文件迁移（pipeline 模式）
# 3. 交叉审查迁移结果（对抗性验证）
# 4. 运行测试并修复失败用例

## 6. 多账号快速切换：工作与个人项目无缝衔接
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) (Tip 45) on GitHub | ⭐ 9.1k stars
- **摘要**: 使用环境变量和 Keychain 存储实现多个 Claude 账号的快速切换，无需反复登录。适合同时管理工作项目和个人项目的开发者，或在不同组织间切换的自由职业者。通过 shell 函数一键切换，保持各账号的配额和计费独立。
- **代码示例**:
```bash
# 在 .zshrc / .bashrc 中添加切换函数
clw() {
  export CLAUDE_ACCOUNT="work"
  export CLAUDE_API_KEY=$(security find-generic-password \
    -s "claude-work" -w)
  echo "已切换到工作账号 ✓"
}

clp() {
  export CLAUDE_ACCOUNT="personal"
  export CLAUDE_API_KEY=$(security find-generic-password \
    -s "claude-personal" -w)
  echo "已切换到个人账号 ✓"
}

# 使用：直接调用函数即可
$ clw   # 切换到工作账号
$ clp   # 切换到个人账号
```

## 7. 垂直切片开发法：告别水平分层的低效迭代
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 62.3k stars
- **摘要**: Claude Code 创始人 Boris Cherny 反复强调的开发方法论：将 PRD 拆分为垂直切片（Tracer Bullets）而非水平分层。每个切片贯穿所有层（UI → API → DB → 测试），而不是先做完所有 UI 再做 API。这样每完成一个切片就有一个可验证的端到端功能。配合 Claude Code 的子代理模式，每个切片可以分配一个 feature-specific subagent，用 `context: fork` 隔离执行，主上下文只接收最终结果。
- **代码示例**:
```
# ❌ 水平分层（低效）
Phase 1: 所有 UI 组件
Phase 2: 所有 API 路由
Phase 3: 所有数据库模型
Phase 4: 所有测试
→ 直到 Phase 4 才能验证任何功能

# ✅ 垂直切片（推荐）
Slice 1: 用户注册（UI + API + DB + 测试）→ 可验证 ✓
Slice 2: 登录认证（UI + API + DB + 测试）→ 可验证 ✓
Slice 3: 个人资料（UI + API + DB + 测试）→ 可验证 ✓

# Claude Code 中的实践
> 用垂直切片方式实现用户注册功能：
  1. 创建注册表单组件
  2. 实现 /api/auth/register 端点
  3. 添加 users 表迁移
  4. 编写端到端测试
  每完成一步就运行测试确认
```
