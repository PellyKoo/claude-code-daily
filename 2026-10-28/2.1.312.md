## 3. CLAUDE.md 记忆银行系统：让 Claude 在会话间保持记忆
- **来源**: [centminmod](https://github.com/centminmod/my-claude-code-setup) on GitHub | ⭐ 高星模板仓库
- **摘要**: 一个精心设计的 CLAUDE.md 模板系统，核心创新是"记忆银行"模式：将项目上下文结构化为 projectbrief.md、techContext.md、activeContext.md 等文件，Claude Code 在每次会话开始时自动读取这些文件恢复上下文。这样即使 `/clear` 或开新会话，Claude 也能快速理解项目状态。适合长期项目，避免每次都从头解释项目背景。
- **代码示例**:
```bash
# 记忆银行文件结构
# memory-bank/
#   projectbrief.md     # 项目愿景和核心需求
#   techContext.md       # 技术栈和架构决策
#   activeContext.md     # 当前工作状态和待办
#   systemPatterns.md   # 代码模式和约定
#   progress.md          # 已完成和进行中的工作

# 在 CLAUDE.md 中引用：
# @memory-bank/activeContext.md
# @memory-bank/techContext.md
# 这样每次新会话都能恢复完整上下文
```

## 4. 给 Claude 建立验证反馈循环：质量翻倍的关键
- **来源**: [Boris Cherny (@bcherny)](https://x.com/bcherny/status/2007179861115511237) on X | 🔥 高赞深度建议
- **摘要**: Boris Cherny（TypeScript 专家）分享了他认为最重要的一条 Claude Code 使用原则：给 Claude 一个验证自己工作的方式。无论是写测试、运行类型检查、还是用浏览器预览——只要 Claude 能看到自己的输出结果，代码质量就能提升 2-3 倍。核心思路是把工作流从"生成代码 → 人工检查"变成"生成代码 → 自动验证 → 迭代修复 → 人工确认"。
- **代码示例**:
```bash
# 在 CLAUDE.md 中配置验证循环
# ## 验证规则
# - 每次修改后运行 `npm test` 验证
# - 修改 UI 组件后启动 dev server 并截图确认
# - 修改 API 后用 curl 测试端点
# - 修改类型后运行 `tsc --noEmit`

# PostToolUse hook 自动触发类型检查
# settings.json:
# "PostToolUse": [{
#   "matcher": "Edit",
#   "command": "tsc --noEmit --pretty 2>&1 | tail -20"
# }]
```

## 7. 路径作用域规则：让不同目录加载不同 AI 规则
- **来源**: [AlexandrG539](https://github.com/AlexandrG539/claude-code-setup-guide) on GitHub | ⭐ 2026 年 10 月更新的配置指南
- **摘要**: 这份 10 月新更新的指南详细介绍了 `.claude/rules/` 目录的高级用法：通过 YAML frontmatter 中的 `paths:` 字段，让规则只在 Claude 操作特定文件时才加载。前端规则只在碰到 React 组件时触发，后端规则只在碰到 API 路由时触发。这样既减少了上下文消耗，又提高了规则的针对性。配合 `@import` 语法还可以跨文件引用共享规则。
- **代码示例**:
```markdown
<!-- .claude/rules/frontend.md -->
---
paths:
  - "src/components/**"
  - "src/pages/**"
  - "*.tsx"
---
- 使用 React Server Components 优先
- 样式使用 Tailwind CSS
- 组件遵循 src/components/ui/ 中的设计系统

<!-- .claude/rules/api.md -->
---
paths:
  - "src/api/**"
  - "src/routes/**"
---
- 所有端点必须有输入验证（用 zod）
- 错误返回标准 JSON 格式
- 修改后运行 `pnpm test:api`
```

## 8. Greg Isenberg 解读 Dynamic Workflow：一键启动百 Agent 并行
- **来源**: [Greg Isenberg (@gregisenberg)](https://x.com/gregisenberg/status/2060072130339873093) on X | 🔥 高曝光功能介绍
- **摘要**: Greg Isenberg 对 Claude Code 的 "dynamic workflows" 功能做了通俗解读：输入 "create a workflow" 或在 effort 菜单中开启 "ultracode"，Claude 就会自动生成编排脚本、启动大量并行 Agent，每个 Agent 检查其他人的工作。这把你能一次交出去的工作单位从"一个文件"提升到"一整个功能"。关键在于 Agent 之间会互相校验，减少单点错误。社区反馈：token 消耗很高，但对大规模重构和全面代码审查效果惊人。
- **代码示例**:
```bash
# 方法一：在提示中使用关键字触发
> "create a workflow 来审查这次重构的所有文件"

# 方法二：在 effort 菜单中开启 ultracode
# Claude 自动：
# 1. 分析任务，识别可并行的子任务
# 2. 生成 workflow 编排脚本
# 3. 启动多个子 Agent 并行执行
# 4. 子 Agent 互相校验结果
# 5. 汇总最终报告

# 适用场景：大规模代码审查、跨仓库重构、全面测试覆盖
# 注意：token 消耗约为普通会话的 5-10 倍
```
