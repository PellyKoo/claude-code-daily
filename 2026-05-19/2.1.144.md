## 1. 六文档上下文管理法——跨会话记忆不丢失
- **来源**: [Cathryn Lavery](https://x.com/cathrynlavery/status/1950010270530585042) on X | 🔥 高互动热帖
- **摘要**: 在每次 Claude Code 会话开始和结束时，让 Claude 自动创建或更新六个 Markdown 文档，形成持久化的项目记忆系统。新会话启动时优先读取这些文档，即可无缝续接上次工作进度，彻底解决跨会话上下文丢失问题。
- **代码示例**:
```
项目根目录/
├── CONTEXT.md    # 当前项目状态与架构概览
├── PROGRESS.md   # 已完成的工作记录
├── TODO.md       # 下一步优先级任务
├── DECISIONS.md  # 技术决策及其理由
├── ISSUES.md     # 已知阻塞问题
└── SETUP.md      # 项目运行方式说明
```

## 2. 双阶段 Agent 工作流——长任务不失控
- **来源**: [HackerRank](https://x.com/hackerrank/status/2016398850265935929) on X | 🔥 高互动热帖
- **摘要**: 将长时间运行的任务拆分为两个独立 Agent 阶段。Initializer Agent 负责项目搭建、功能列表、Git 初始化和进度追踪；Coding Agent 负责读取、构建、测试、提交和更新。这样避免单个超长会话导致上下文饱和和质量下降。
- **代码示例**:
```bash
# 阶段一：初始化 Agent（Plan 模式）
claude --permission-mode plan "搭建项目结构、定义功能列表、初始化 Git"

# 阶段二：编码 Agent（执行模式）
claude "读取 TODO.md，逐项实现功能，每完成一项自动提交并更新进度"
```

## 3. tmux + 远程机器——飞机 WiFi 也不断连
- **来源**: [Boris Cherny](https://x.com/bcherny/status/2007179832300581177) on X | 🔥 Claude Code 创始人分享
- **摘要**: 先通过 SSH 连接到远程 Mac Mini 或服务器，在 tmux 会话中运行 Claude Code。这样即使本地网络断开（如飞机上），Claude Code 会话仍在远程机器上持续运行，重新连接后恢复即可。特别适合不稳定网络环境下的长时间任务。
- **代码示例**:
```bash
# 远程机器上创建 tmux 会话
ssh remote-server
tmux new -s claude-session
claude

# 断开后重新连接
ssh remote-server
tmux attach -t claude-session
```

## 4. `/compact` 带自定义提示——精准保留关键上下文
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 54k stars
- **摘要**: 不要依赖自动压缩（auto-compact），而是手动使用 `/compact` 并附带提示词，明确告诉 Claude 哪些上下文必须保留。自动压缩会在上下文满时触发，可能丢弃关键信息；手动带提示的压缩能精准控制保留内容，维持输出质量。
- **代码示例**:
```
/compact 保留：当前正在修改的 API 端点列表、数据库 schema 变更、
以及 auth 模块的错误处理逻辑。可以丢弃之前的调试过程。
```

## 5. 一键生成 CLAUDE.md——新项目快速启动
- **来源**: [MuhammadUsmanGM](https://github.com/MuhammadUsmanGM/claude-code-best-practices) on GitHub | ⭐ GitHub 热门仓库
- **摘要**: 使用脚本自动扫描现有代码库并生成 CLAUDE.md 文件，包含项目结构、技术栈、构建命令、代码风格等信息。避免手写 CLAUDE.md 时遗漏关键配置，也可以直接让 Claude 分析代码库后自动生成。
- **代码示例**:
```bash
# 方式一：使用生成脚本
bash tools/generate-claude-md.sh

# 方式二：让 Claude 自动生成（在项目根目录运行）
claude "分析这个代码库，生成一个 CLAUDE.md 文件，
包含构建命令、测试命令、代码风格规范、关键目录说明"
```

## 6. 双重记忆架构——团队共享 + 本地自动
- **来源**: [centminmod](https://github.com/centminmod/my-claude-code-setup) on GitHub | ⭐ 2.3k stars
- **摘要**: 采用 Git 共享的 `CLAUDE-*.md` 文件实现团队级记忆（架构决策、编码规范），同时利用机器本地的自动记忆存储个人偏好和环境配置。两层记忆互为冗余，即使一层失效也不会丢失关键上下文。
- **代码示例**:
```
# 团队共享层（提交到 Git）
CLAUDE.md            # 项目级规范
CLAUDE-ARCHITECTURE.md  # 架构决策记录
CLAUDE-PATTERNS.md   # 代码模式参考

# 本地自动层（不提交）
~/.claude/memory/    # 个人偏好和历史记忆
.claude/settings.local.json  # 本地环境配置
```

## 7. Git Worktree 快捷启动函数——秒开并行会话
- **来源**: [centminmod](https://github.com/centminmod/my-claude-code-setup) on GitHub | ⭐ 2.3k stars
- **摘要**: 将 git worktree 创建 + 分支切换 + Claude 启动封装为一个 Shell 函数，一条命令即可创建隔离的工作副本并启动 Claude Code 会话，实现真正的一键并行开发。
- **代码示例**:
```bash
# 添加到 .bashrc 或 .zshrc
clx() {
    local branch_name="${1:-worktree-$(date +%Y%m%d-%H%M%S)}"
    git worktree add "../$branch_name" -b "$branch_name"
    cd "../$branch_name" || return 1
    claude --model opusplan --permission-mode plan
}

# 使用：一键创建独立工作区并启动 Claude
clx feature-login
```
