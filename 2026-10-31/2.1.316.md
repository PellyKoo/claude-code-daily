## 1. Plan Mode：编辑前先审查计划
- **来源**: [marmelab](https://marmelab.com/blog/2026/04/24/claude-code-tips-i-wish-id-had-from-day-one.html) on Blog | 🔥 高引用社区博文
- **摘要**: 多个社区指南一致推荐在让 Claude 修改代码前先进入 Plan Mode（按 Shift+Tab 或输入 /plan）。Plan Mode 下 Claude 只分析和规划，不动文件。你可以审查它的方案、调整方向，确认后再让它执行。这避免了 Claude 一上来就大刀阔斧改代码、结果方向错误需要回滚的常见问题。尤其适合复杂重构和不熟悉的代码库。
- **代码示例**:
```bash
# 方法一：快捷键切换
# 在 Claude Code 中按 Shift+Tab 切换到 Plan Mode

# 方法二：slash 命令
/plan 重构这个模块的认证逻辑

# Plan Mode 下 Claude 会：
# ✅ 分析代码结构和依赖关系
# ✅ 列出需要修改的文件
# ✅ 说明修改策略和风险
# ❌ 不会实际修改任何文件
# 确认方案后再按 Shift+Tab 切回 Act Mode 执行
```

## 2. Hooks 替代 CLAUDE.md 中的强制规则
- **来源**: [collabnix](https://collabnix.com/claude-code-best-practices-10-workflow-tips-that-senior-engineers-swear-by-in-2026/) on Blog + [Reddit r/ClaudeAI 社区讨论](https://www.morphllm.com/claude-code-reddit) | 🔥 多源共识
- **摘要**: 社区实践证明，CLAUDE.md 中的指令在长上下文中遵守率会下降。真正必须执行的规则（如代码格式化、测试运行、安全检查）应该用 Hooks 实现，而非靠 CLAUDE.md 描述。Hooks 是确定性的——每次工具调用前后都会执行，不受上下文长度影响。CLAUDE.md 适合放偏好和指导性规则，Hooks 适合放"零容忍"的强制行为。
- **代码示例**:
```json
// .claude/settings.json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "command": "npx prettier --write $CLAUDE_FILE_PATH"
      }
    ],
    "PreCommit": [
      {
        "command": "npm run lint && npm test"
      }
    ]
  }
}
```
```markdown
# CLAUDE.md 中只保留指导性规则：
# ✅ "优先使用组合而非继承"
# ✅ "API 错误响应使用 RFC 7807 格式"
# ❌ 不要写 "提交前运行测试" → 这应该是 Hook
```

## 3. 自主工作前先 Checkpoint：错了就回滚
- **来源**: [Reddit r/ClaudeAI 社区讨论](https://www.morphllm.com/claude-code-reddit) | 🔥 社区高赞实践
- **摘要**: Reddit 社区广泛推荐的安全工作模式：在让 Claude 进行自主编码（autonomous mode）前，先手动 commit 一个 checkpoint。如果结果不理想，直接 `git reset --hard` 回到 checkpoint，而不是让 Claude "修复"它自己犯的错。社区经验是，让 AI 修复自己的错误往往越改越乱，不如干净回滚重来。这个习惯可以大胆让 Claude 尝试激进方案，因为回退成本极低。
- **代码示例**:
```bash
# 安全的自主工作流程：

# 1. 创建 checkpoint
git add -A && git commit -m "checkpoint: before claude refactor"

# 2. 让 Claude 自主工作
claude "重构整个认证模块，使用 OAuth 2.0"

# 3a. 结果满意 → 保留
git add -A && git commit -m "feat: refactor auth to OAuth 2.0"

# 3b. 结果不满意 → 干净回滚
git reset --hard HEAD~1
# 调整提示词后重新尝试
```

## 4. 非交互式脚本化：用 --allowedTools 和 --max-turns 控制范围
- **来源**: [ayautomate](https://www.ayautomate.com/blog/best-claude-code-workflows) on Blog | 🔥 DevOps 社区推荐
- **摘要**: Claude Code 可以完全非交互运行，适合集成到 CI/CD 管道或自动化脚本。关键参数：`-p` 进入非交互模式传递提示词，`--allowedTools` 限制可用工具（安全白名单），`--max-turns` 限制最大对话轮次（控制成本）。搭配 `--output-format json` 还能让输出结构化，方便下游脚本解析。社区已有人将其集成到 GitHub Actions 中做自动 PR 审查。
- **代码示例**:
```bash
# 基础非交互运行
claude -p "检查这个文件是否有安全漏洞" --max-turns 3

# 限制工具范围（只读分析，不许修改）
claude -p "分析代码质量" \
  --allowedTools "Read,Grep,Glob" \
  --max-turns 5

# CI/CD 集成示例
claude -p "审查最近的 git diff" \
  --allowedTools "Read,Grep,Glob,Bash(git diff)" \
  --output-format json \
  --max-turns 10 > review-result.json

# 在 GitHub Actions 中使用
# - name: Auto Review
#   run: claude -p "Review PR changes" --max-turns 5
```

## 5. --resume 恢复上次会话：不必重新建立上下文
- **来源**: [Reddit r/ClaudeAI 社区讨论](https://www.morphllm.com/claude-code-reddit) | 🔥 省 token 技巧
- **摘要**: 很多开发者不知道 `claude --resume` 可以恢复上一个会话的完整上下文。当你中断了一个长任务（比如吃饭、开会），回来时不需要重新描述背景，直接 resume 即可继续。这不仅节省了重复输入的时间，更重要的是节省了重新建立上下文消耗的 token。社区建议：与其频繁 /clear 开新会话，不如在同一会话中持续工作，利用 /compact 管理上下文长度。
- **代码示例**:
```bash
# 恢复最近的会话
claude --resume

# 恢复特定会话（通过会话 ID）
claude --resume <session-id>

# 会话管理最佳实践：
# 1. 一个功能 = 一个会话，保持专注
# 2. 中断后用 --resume 恢复，而非开新会话
# 3. 上下文太长时用 /compact 压缩，而非 /clear 清除
# 4. /clear 只在完全切换任务时使用
```

## 6. 个人偏好文件 ~/.claude/CLAUDE.md：跨项目生效
- **来源**: [towardsai](https://pub.towardsai.net/claude-md-best-practices-13cfe020050d) on Medium + [datacamp](https://www.datacamp.com/tutorial/writing-the-best-claude-md) | 🔥 多平台推荐
- **摘要**: 社区推荐的三层 CLAUDE.md 配置体系：全局个人偏好放 `~/.claude/CLAUDE.md`（如代码风格、语言偏好），项目规则放项目根目录 `CLAUDE.md`（团队共享，提交到 git），目录专属规则放子目录 `CLAUDE.md`（如 `src/api/CLAUDE.md`）。这样个人偏好跨所有项目生效，项目规则团队统一，模块规则按需加载不浪费上下文。
- **代码示例**:
```bash
# 层级结构：
# ~/.claude/CLAUDE.md          → 个人偏好（不提交 git）
# ~/project/CLAUDE.md          → 项目规则（提交 git，团队共享）
# ~/project/src/api/CLAUDE.md  → 模块规则（按路径自动加载）

# ~/.claude/CLAUDE.md 示例内容：
cat << 'EOF' > ~/.claude/CLAUDE.md
- 用中文回复所有问题
- 代码注释用英文
- 优先使用函数式编程风格
- commit message 用 conventional commits 格式
EOF
```

## 7. 限制 MCP 服务器数量 + 启用 Tool Search 省 token
- **来源**: [Reddit r/ClaudeAI 社区讨论](https://www.morphllm.com/claude-code-reddit) | 🔥 成本优化热帖
- **摘要**: 社区发现 MCP 服务器是隐形的 token 消耗大户——每个活跃的 MCP 服务器的工具定义都会占据上下文窗口。Reddit 用户分享的优化策略：只保留当前任务必需的 MCP 服务器；启用 Tool Search（延迟加载），让工具定义仅在需要时才加载进上下文；对于偶尔使用的工具，宁可手动 ToolSearch 调用，也不要让它常驻上下文。有用户报告这样做 token 消耗降低了 20-30%。
- **代码示例**:
```json
// .claude/settings.json - MCP 精简配置
{
  "mcpServers": {
    // ✅ 只保留每天都用的服务器
    "github": { "command": "mcp-server-github" },

    // ❌ 不要同时加载所有可能用到的服务器
    // "slack": { ... },
    // "jira": { ... },
    // "confluence": { ... },
    // "linear": { ... }
  }
}
```
```bash
# 在会话中按需加载工具，而非全部预加载
# Claude 会自动通过 Tool Search 找到延迟加载的工具
# 你也可以手动触发：
# "请搜索并加载 Slack 相关的 MCP 工具"
```

## 8. --bare 模式：脚本和自动化场景的快速启动
- **来源**: [productbuilder](https://www.productbuilder.net/learn/claude-code-tips) on Blog + [Claude Code Power User Tips](https://support.claude.com/en/articles/14554000-claude-code-power-user-tips) | 🔥 高级用户技巧
- **摘要**: 使用 `--bare` 标志启动 Claude Code 会跳过 CLAUDE.md 的加载和环境初始化，实现最快速度启动。适合在自动化脚本中使用，特别是当你通过 `--system-prompt` 传递自定义系统提示词时，不需要项目的 CLAUDE.md 干扰。配合 `-p` 非交互模式，可以打造极简的自动化管道。社区在批量处理场景（如同时处理多个仓库）中大量使用这个模式。
- **代码示例**:
```bash
# 标准启动（加载 CLAUDE.md + 环境初始化）
claude -p "分析代码"  # 较慢

# bare 模式（跳过初始化）
claude --bare -p "分析代码" --system-prompt "你是代码审查专家"  # 更快

# 批量处理多个仓库示例
for repo in ~/projects/*/; do
  claude --bare -p "检查 $repo 中的安全漏洞" \
    --allowedTools "Read,Grep,Glob" \
    --max-turns 5 \
    --output-format json > "/tmp/review-$(basename $repo).json" &
done
wait  # 等待所有并行任务完成
```
