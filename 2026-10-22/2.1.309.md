# Claude Code 2.1.309 社区实用技巧 - 2026-10-22

## 1. 会话卫生：小任务 + /clear = 最佳效率
- **来源**: [Julio César Fernández (@jcfmunoz)](https://x.com/jcfmunoz/status/2038288124577562714) on X | 🔥 高互动实战分享
- **摘要**: 资深开发者的核心建议——把工作拆成尽可能小的独立任务。长会话会不断拖着旧的上下文、文件读取记录和工具输出，导致 token 消耗增加、噪声变多、Claude 的注意力下降。正确工作流：一个清晰任务 → 完成 → `/clear` → 下一个任务。作者实测中 Claude 自己都提示"新任务？/clear 可节省 412K tokens"。上下文越多，响应质量越差。
- **代码示例**:
```bash
# 正确的工作流节奏
# 1. 给出一个明确任务
> 修复 auth 模块的 token 刷新 bug

# 2. 完成后立即清除上下文
/clear

# 3. 开始下一个不相关的任务
> 给 user profile 页面添加头像上传功能

# 避免在同一个会话里混合多个不相关任务
# 每次 /clear 都能省下大量 token，同时提升响应质量
```

## 2. 把 Claude Code 连接到你的知识源
- **来源**: [Aakash Gupta (@aakashgupta)](https://x.com/aakashgupta/status/2018798638647202147) on X | 🔥 高热度工作流帖
- **摘要**: 大多数人打开 Claude Code 只是输入提示、获取回复——这只用到了 10% 的能力。关键突破：通过 MCP 把 Claude Code 连接到你的知识库（内部文档、设计稿、产品规格书、数据库 schema）。当 Claude 能直接访问你的上下文，它的输出质量会质变。另外，用 `/init` 生成 CLAUDE.md 作为项目专属记忆，比每次重复解释项目结构高效得多。
- **代码示例**:
```bash
# 用 /init 自动生成项目专属 CLAUDE.md
/init

# 通过 MCP 连接 Notion 知识库
# .claude/settings.json
{
  "mcpServers": {
    "notion": {
      "command": "npx",
      "args": ["-y", "@notionhq/mcp-server"],
      "env": {
        "NOTION_API_KEY": "${NOTION_TOKEN}"
      }
    }
  }
}

# Claude 现在可以直接查询你的 Notion 文档
> 根据 Notion 里的产品规格书，实现用户通知功能
```

## 3. 技能审计：定期清理无用 Skills
- **来源**: [Prajwal Tomar (@PrajwalTomar_)](https://x.com/PrajwalTomar_/status/2074787074641899896) on X | 🔥 PRO 级技巧
- **摘要**: 随着 Claude Code 技能生态的扩展，很多开发者安装了大量 skills 但从不清理。PRO 做法：把参考文章直接粘贴到会话里，让 Claude 列出所有已安装的技能，对比文章推荐的技能列表，然后卸载重叠的、从不触发的、过时的技能。定期审计可以减少上下文膨胀，让真正有用的技能获得更多注意力。
- **代码示例**:
```bash
# 查看当前安装的所有技能
/skills

# 在会话中直接让 Claude 审计
> 列出我当前所有已安装的 skills，
> 标记哪些功能重叠、哪些从未被触发过，
> 给出精简建议

# 卸载不需要的技能
# 在 .claude/settings.json 中移除对应配置
# 或通过 Skills 管理界面操作
```

## 4. CLAUDE.md Memory Bank 系统
- **来源**: [centminmod/my-claude-code-setup](https://github.com/centminmod/my-claude-code-setup) on GitHub | ⭐ 实用模板仓库
- **摘要**: 一套完整的 CLAUDE.md "记忆银行"系统。核心理念：用结构化的 CLAUDE.md 模板作为项目的持久记忆层，包含项目架构、开发规范、常用命令、已知问题和决策记录。关键技巧是分层组织——全局配置放 `~/.claude/CLAUDE.md`，项目级放根目录，模块级放子目录。每层只包含该层面的信息，避免重复。
- **代码示例**:
```markdown
# 分层 CLAUDE.md 结构

# ~/.claude/CLAUDE.md (全局级)
## 个人偏好
- 使用中文注释
- 优先使用 TypeScript
- commit message 用英文

# /project/CLAUDE.md (项目级)
## 项目架构
- Monorepo: pnpm workspaces
- Frontend: Next.js 15 in apps/web
- Backend: Hono in apps/api

## 命令
- `pnpm dev` - 启动所有服务
- `pnpm test` - 运行测试
- `pnpm db:migrate` - 数据库迁移

# /project/apps/api/CLAUDE.md (模块级)
## API 规范
- 所有端点必须有 Zod schema 验证
- 错误响应遵循 RFC 7807
```

## 6. Claude Code 实战指南与技巧精华集
- **来源**: [jacques-visser](https://gist.github.com/jacques-visser/2774b3df042d96482b7bb232ecb51a8f) on GitHub Gist | 🔥 高收藏技术 Gist
- **摘要**: 一位全栈开发者整理的 Claude Code 实战指南。亮点包括：(1) 用 `claude --resume` 恢复被意外关闭的会话；(2) 把常用的多步操作封装成自定义 slash command，一个命令完成"跑测试 → 修 lint → 提交"的完整流程；(3) 用环境变量控制 Claude 行为——`CLAUDE_CODE_MAX_TURNS` 限制自动执行轮次防止失控，`CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` 关闭遥测节省带宽。
- **代码示例**:
```bash
# 恢复上次会话
claude --resume

# 自定义 slash command 示例
# .claude/commands/ship.md
# ---
# 描述: 提交前的完整检查流程
# ---
# 1. 运行 `pnpm test --run`
# 2. 运行 `pnpm lint --fix`
# 3. 运行 `pnpm typecheck`
# 4. 如果全部通过，执行 `git add -A && git commit`
# 5. 列出变更摘要

# 环境变量控制
export CLAUDE_CODE_MAX_TURNS=25  # 限制自动轮次
```

## 7. Auto Mode 和 Manual Mode 的正确切换时机
- **来源**: [claude-world.com Aug-Oct 2026 Roundup](https://claude-world.com/articles/claude-code-august-october-2026-roundup/) 引用社区讨论 | 🔥 版本演进分析
- **摘要**: 从 2.1.302 版本开始，交互式会话默认进入 Auto Mode（自动批准安全操作），而 `claude -p` 和 Agent SDK 默认使用 Manual Mode。社区讨论的最佳实践：日常开发用 Auto Mode 提升流畅度，但在操作生产环境、修改 CI 配置、处理敏感数据时主动切回 Manual Mode。配合 `allowedTools` 白名单精细控制哪些操作可以自动执行。
- **代码示例**:
```json
// .claude/settings.json - 精细化权限控制
{
  "permissions": {
    "allow": [
      "Read",
      "Edit",
      "Write",
      "Glob",
      "Grep",
      "Bash(npm test*)",
      "Bash(npm run lint*)",
      "Bash(git status)",
      "Bash(git diff*)"
    ],
    "deny": [
      "Bash(rm -rf*)",
      "Bash(git push --force*)",
      "Bash(DROP TABLE*)"
    ]
  }
}
```
