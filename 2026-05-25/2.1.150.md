## 1. Opus 规划 + Sonnet 编码：混合模型策略
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 55k stars
- **摘要**: 在同一个会话中切换模型——用 Opus 进入 Plan Mode 做架构设计和任务拆解，切回 Sonnet 做具体编码实现。Opus 擅长战略性思考，Sonnet 执行速度更快且 token 成本更低，两者配合可以在不牺牲质量的前提下显著降低开销。
- **代码示例**:
```bash
# 会话中动态切换模型
# 1. 用 Opus 规划
/model opus
/plan 设计用户认证模块的完整架构

# 2. 规划完成后切回 Sonnet 编码
/model sonnet
# Claude 基于 Opus 的规划开始高效实现代码
```

## 2. 用 /rewind 回退而非在上下文中纠错
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 55k stars
- **摘要**: 当 Claude 走错方向时，不要在当前上下文中反复纠正（这会让失败尝试污染上下文），而是用双击 Escape 或 `/rewind` 回退到错误发生前的状态，然后用新学到的信息重新提示。这样上下文保持干净，后续输出质量更高。
- **代码示例**:
```bash
# 错误做法：在上下文中纠正
> "不对，不要用 class 组件，用函数组件重写"
# 此时上下文中保留了错误的 class 组件代码，占用空间且干扰后续生成

# 正确做法：回退后重新提示
# 按两次 Escape 或输入 /rewind
# 回到错误前的干净上下文
> "用 React 函数组件 + hooks 实现用户列表，不使用 class 组件"
```

## 3. /compact 加自定义提示词，效果远超自动压缩
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 55k stars
- **摘要**: 自动压缩（auto-compaction）不知道你在做什么，会丢弃关键信息。手动 `/compact` 时附带提示词告诉 Claude 应该保留什么，可以精准控制压缩方向。例如 `/compact 保留认证重构的所有决策，丢弃测试调试记录`，让压缩后的上下文聚焦于当前任务核心。
- **代码示例**:
```bash
# 低效：不带提示的压缩
/compact

# 高效：带提示的定向压缩
/compact 保留 API 接口设计决策和数据库 schema 变更，丢弃 lint 错误调试过程

# 更精准的场景示例
/compact focus on the auth refactor decisions and new middleware chain, drop test debugging
```

## 4. SKILL.md 中用 !command 动态注入 Shell 输出
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 55k stars
- **摘要**: 在 `SKILL.md` 文件中嵌入 `!command` 指令，Claude 在调用 Skill 时会先执行命令，只将输出注入提示词中，避免将原始命令的 stderr 等噪音污染上下文。适合在 Skill 启动时动态获取环境信息、git 状态或项目配置。
- **代码示例**:
```markdown
<!-- .claude/skills/deploy-check.md -->
---
description: "检查部署就绪状态（当用户提到部署、发布、上线时触发）"
---

当前分支状态：
!git status --short

最近提交：
!git log --oneline -5

未通过的测试：
!npm test 2>&1 | grep "FAIL" || echo "全部通过"

根据以上信息评估是否可以安全部署。
```

## 5. Skill 描述写成触发条件而非功能摘要
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 55k stars
- **摘要**: Claude 通过语义匹配 Skill 的 description 字段来决定何时自动触发。如果描述写成"数据库迁移工具"这样的功能摘要，触发率很低。应该写成触发条件："当用户提到数据库变更、schema 修改、迁移、添加表/列时触发"，让 Claude 更容易匹配用户意图。
- **代码示例**:
```markdown
<!-- .claude/skills/db-migrate.md -->
---
# 差：功能摘要式描述
# description: "数据库迁移管理工具"

# 好：触发条件式描述
description: "当用户提到数据库变更、修改 schema、添加/删除表或列、创建迁移文件、或讨论数据模型修改时触发"
---
```

## 6. Monorepo 的 CLAUDE.md 层级自动继承
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 55k stars
- **摘要**: 在 monorepo 中，Claude 会自动加载从根目录到当前工作目录路径上所有的 CLAUDE.md 文件，父级规则与子级规则自动合并。利用这个机制，把通用规则放根目录，团队规则放子目录，项目特定规则放最深层，实现规则的分层继承和按需覆盖。
- **代码示例**:
```
monorepo/
├── CLAUDE.md              # 通用规则：代码风格、commit 规范、CI 要求
├── packages/
│   ├── CLAUDE.md          # 共享包规则：版本管理、发布流程
│   ├── frontend/
│   │   └── CLAUDE.md      # 前端规则：React 规范、组件模式
│   └── backend/
│       └── CLAUDE.md      # 后端规则：API 设计、数据库约定
└── services/
    └── auth/
        └── CLAUDE.md      # 认证服务特定规则：安全要求、加密标准

# Claude 在 packages/frontend/ 工作时自动加载：
# monorepo/CLAUDE.md + packages/CLAUDE.md + packages/frontend/CLAUDE.md
```

## 7. MCP Server 安全审查五步流程

```bash

# Step 1: 来源验证
gh repo view <mcp-server-repo> --json stargazerCount,updatedAt

grep -r "fs\." node_modules/<mcp-server>/  # 文件系统访问
grep -r "net\.\|http\." node_modules/<mcp-server>/  # 网络访问

# Step 3: 权限白名单配置
# .claude/settings.json
# "mcpServers": { "server-name": { "allowedPaths": ["./src/**"] } }

# Step 4: Docker 沙箱测试
docker run --rm --network=none -v $(pwd):/app mcp-server-test

# Step 5: 会话监控
# 启用 hook 记录 MCP 调用日志
```
