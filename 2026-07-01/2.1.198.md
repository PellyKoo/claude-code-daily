## 1. Git Worktree 并行会话：同时运行多个 Claude 实例
- **来源**: [centminmod/my-claude-code-setup](https://github.com/centminmod/my-claude-code-setup) on GitHub | ⭐ 2.5k stars
- **摘要**: 使用 Git Worktree 创建独立的工作目录，让多个 Claude Code 实例同时运行互不干扰。每个会话拥有独立的文件状态，非常适合实验性功能开发或"YOLO 模式"测试。比起在同一目录切换分支，Worktree 方案彻底消除了文件冲突问题。
- **代码示例**:
```bash
# 创建独立的 worktree 用于并行开发
git worktree add ../my-project-experiment feature/new-auth
cd ../my-project-experiment

# 在新 worktree 中启动独立的 Claude Code 会话
claude

# 主项目和实验分支可以同时有 Claude 在工作
# 互不干扰，完成后清理
git worktree remove ../my-project-experiment
```

## 2. 规划优先纪律：80% 准确率的数学陷阱
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 61.8k stars
- **摘要**: 即使 Claude 在每个独立决策点上有 80% 的正确率，一个典型功能涉及 20 个决策点时，全部正确的概率只有 0.8^20 ≈ 1%。这就是为什么必须使用 Plan Mode（`/plan`）先确认意图再执行。始终以"先规划再编码"的方式开始会话，Review 每一步后再继续。
- **代码示例**:
```bash
# ✅ 正确：先进入 plan 模式
> /plan Implement OAuth2 login with Google provider

# Claude 输出计划后，逐步确认
> Do step 1, then stop and show me

# 确认无误后继续
> Looks good, proceed to step 2

# ❌ 错误：直接让 Claude 实现整个功能
> Implement full OAuth2 with Google, GitHub, Apple login,
  session management, and refresh tokens
```

## 3. CLAUDE.md 是建议（80%），Hooks 是法律（100%）
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 61.8k stars
- **摘要**: CLAUDE.md 中的指令大约 80% 的时间会被遵守，但 Hooks 是 100% 确定性执行的。对于必须每次都执行的操作（格式化、lint、安全检查），用 Hooks 而不是 CLAUDE.md。CLAUDE.md 适合放偏好和上下文，Hooks 适合放硬性规则。理解这个区别是从"偶尔出错"到"系统可靠"的关键跨越。
- **代码示例**:
```json
// .claude/settings.json - 用 Hook 强制执行硬性规则
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          {
            "type": "command",
            "command": "npx prettier --write \"$FILEPATH\" && npx eslint --fix \"$FILEPATH\""
          }
        ]
      }
    ]
  }
}
```
```markdown
<!-- CLAUDE.md - 放偏好和上下文指导 -->
## Code Style Preferences
- Prefer named exports over default exports
- Use early returns to reduce nesting
- Keep functions under 30 lines when possible
```

## 4. "贴上 bug，说 fix"：最小化 Prompt 策略
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 61.8k stars
- **摘要**: 社区经验表明，过度详细的指令反而降低修复质量。最有效的方式是直接粘贴错误信息，简单说"fix"。Claude 在大多数情况下能独立定位和解决问题。如果第一次修复不完美，与其追加微调指令，不如说"scrap this and implement the elegant solution"让 Claude 从零重来。
- **代码示例**:
```bash
# ✅ 最简 prompt（通常效果最好）
> TypeError: Cannot read properties of undefined (reading 'user')
  at AuthMiddleware.handle (src/middleware/auth.ts:42:18)
  fix

# ❌ 过度指导（限制了 Claude 的推理空间）
> There's a TypeError in auth.ts line 42. The user object
  is undefined. Please add a null check before accessing
  the user property. Make sure to also check the session
  object and add a try-catch block around it...

# 如果第一次修复不完美
> scrap this and implement the elegant solution
```

## 5. Skills 按需加载 vs CLAUDE.md 全局加载
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 6k stars
- **摘要**: CLAUDE.md 在每次会话开始时全部加载，放太多内容会浪费上下文并导致指令被忽略。领域知识和特定工作流应该写成 Skills（`.claude/skills/` 目录下的 markdown 文件），Claude 会按需加载。这是"胖 CLAUDE.md"和"瘦 CLAUDE.md + 丰富 Skills"之间的架构选择——后者显著更高效。
- **代码示例**:
```
.claude/
├── settings.json
└── skills/
    ├── testing-patterns.md      # Jest 测试约定和模式
    ├── api-design.md            # REST API 设计规范
    ├── formik-patterns.md       # 表单处理最佳实践
    └── deployment-checklist.md  # 部署前检查清单
```
```markdown
<!-- .claude/skills/testing-patterns.md -->
# Testing Patterns

## Conventions
- Use factory functions for test data
- Follow Arrange-Act-Assert pattern
- Mock external dependencies, not internal modules
- Name test files: `*.test.ts` next to source files
```

## 6. /loop 循环任务：自动化 PR 看护（最长 3 天）
- **来源**: [awesomeclaude.ai/code-cheatsheet](https://awesomeclaude.ai/code-cheatsheet) on Web | 🔥 社区热门 cheatsheet
- **摘要**: `/loop` 命令可以让 Claude Code 按固定间隔自动执行重复任务，最长持续 3 天。典型场景包括：自动回复 PR review 评论、持续 rebase 分支、监控 CI 状态并自动修复失败的测试。这让 Claude 变成了一个不知疲倦的 PR 看护人，你只需要在最后 approve 即可。
- **代码示例**:
```bash
# 每 10 分钟检查 PR 状态并处理评论
> /loop 10m Check PR #42 for new review comments,
  address them, and push fixes

# 每 5 分钟监控 CI 并自动修复
> /loop 5m Check CI status for current branch.
  If tests fail, analyze and fix the failures.

# 用 /loop 做持续的代码质量巡检
> /loop 30m Run linter and type checker.
  Fix any new issues introduced today.
```

## 7. 五层配置文件体系：理清 Claude Code 的记忆层级
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 6k stars
- **摘要**: Claude Code 的配置不是单一文件，而是五层体系，各司其职：`CLAUDE.md`（项目记忆和上下文）、`.claude/settings.json`（Hooks 和权限）、`.mcp.json`（外部集成如 JIRA/Slack）、`.claude/skills/`（领域知识）、`.claude/agents/`（专业化 AI 助手）。理解每一层的职责边界，才能构建出可维护、可协作的 Claude Code 项目配置。
- **代码示例**:
```
project-root/
├── CLAUDE.md                    # 🧠 项目记忆：技术栈、约定、关键命令
├── .mcp.json                    # 🔌 外部集成：JIRA, GitHub, Slack
└── .claude/
    ├── settings.json            # ⚙️ 行为控制：hooks, 权限, 环境变量
    ├── skills/                  # 📚 领域知识：按需加载的专业文档
    │   ├── code-review.md
    │   └── security-audit.md
    └── agents/                  # 🤖 专业助手：预配置的角色化代理
        ├── reviewer.md
        └── architect.md
```
