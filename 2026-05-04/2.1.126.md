## 3. 从 Vibe Coding 到 Agentic Engineering：Claude Code 最佳实践体系
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 5.5k+ stars
- **摘要**: 一套系统化的 Claude Code 使用方法论，核心理念是从"随意对话式编程"进化到"工程化代理协作"。强调三层 CLAUDE.md 架构：全局（~/.claude/CLAUDE.md）放跨项目通用规则、项目级（.claude/CLAUDE.md）放团队共享约定、本地级（CLAUDE.local.md）放个人偏好。搭配 hooks 机制确保关键操作（如测试、lint）确定性执行，而非依赖 LLM 自觉。
- **代码示例**:
```bash
# 三层 CLAUDE.md 架构
~/.claude/CLAUDE.md          # 全局：always run tests, prefer simple code
.claude/CLAUDE.md            # 项目：tech stack, conventions, commands
CLAUDE.local.md              # 个人：terminal quirks, personal MCP servers

# 用 hooks 替代 CLAUDE.md 中的"必须做"指令
# .claude/settings.json
{
  "hooks": {
    "preCommit": "npm run lint && npm run test"
  }
}
```

## 4. Context7 插件：让 Claude Code 精准读取库文档而非猜测
- **来源**: [社区多处讨论](https://www.openaitoolshub.org/en/blog/claude-code-workflow-examples) on 开发者社区 | 🔥 高频推荐
- **摘要**: Context7 是社区中被高频推荐的 MCP 插件，它能索引特定版本的第三方库文档，让 Claude Code 直接读取精确的 API 页面，而非依赖训练数据中可能过时的知识。相比让 Claude 上网搜索文档，Context7 更快更准确。社区建议只安装真正需要的插件——工具过多反而增加上下文负担。
- **代码示例**:
```json
// .claude/settings.json 中添加 Context7 MCP
{
  "mcpServers": {
    "context7": {
      "command": "npx",
      "args": ["-y", "@context7/mcp-server"]
    }
  }
}
```
```
# 使用时直接引用库文档
claude "参考 Context7 中 Next.js 15 的路由文档，重构 app/routes"
```

## 5. 多目录 CLAUDE.md 分层策略：大型代码库的上下文管理
- **来源**: [ArthurClune/claude-md-examples](https://github.com/ArthurClune/claude-md-examples) on GitHub | ⭐ 社区推荐仓库
- **摘要**: 针对大型项目的 CLAUDE.md 组织策略。在子目录中放置专门的 CLAUDE.md 文件（如 `src/auth/CLAUDE.md`、`src/api/CLAUDE.md`），Claude Code 会自动发现并拼接所有层级的指令。这样当 Claude 处理认证模块时自动获得认证相关的上下文，处理 API 时获得 API 相关的约定，避免根目录 CLAUDE.md 过于臃肿。
- **代码示例**:
```
project/
├── CLAUDE.md                    # 全局规则：代码风格、测试要求
├── src/
│   ├── auth/
│   │   └── CLAUDE.md            # 认证模块：JWT 规范、session 处理
│   ├── api/
│   │   └── CLAUDE.md            # API 层：RESTful 约定、错误码规范
│   └── database/
│       └── CLAUDE.md            # 数据库层：迁移规则、命名约定
```

## 6. RTK（Reduce Token Kit）：压缩命令输出节省上下文
- **来源**: [社区工具推荐](https://smart-webtech.com/blog/claude-code-workflows-and-best-practices/) on 技术博客 | 🔥 实用工具
- **摘要**: Claude Code 读取的每个文件、每条命令输出都消耗上下文窗口。RTK 是一个 CLI 工具，在命令输出到达 LLM 之前进行过滤和压缩。特别适合处理冗长的构建日志、测试输出或大型 JSON 响应。社区建议搭配 70% 上下文阈值策略使用——在上下文用量达到 70% 之前就主动管理，而非等到溢出。

## 7. Claude Code 终极指南：系统提示词的 150 条指令限制
- **来源**: [FlorianBruniaux/claude-code-ultimate-guide](https://github.com/FlorianBruniaux/claude-code-ultimate-guide) on GitHub | ⭐ 4.1k+ stars
- **摘要**: 这份与每个 Claude Code 版本同步更新的指南揭示了一个关键约束：Claude Code 系统提示词已包含约 50 条内置指令，而前沿模型能可靠遵循的指令上限约为 150-200 条。这意味着 CLAUDE.md 中只剩 100-150 条的"预算"。社区建议：每条规则都应明确、可执行、不重复，删掉模糊的指导性语句，只保留具体的行为指令。
- **代码示例**:
```markdown
# ❌ 模糊指令（浪费预算）
写干净的代码
注意代码质量

# ✅ 具体指令（可执行）
所有函数必须有类型注解
测试文件命名格式：{module}_test.py
commit message 使用 conventional commits 格式
```
