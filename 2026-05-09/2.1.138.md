## 3. 用 Hooks 解决 Skills 不自动触发的问题
- **来源**: [Aakash Gupta](https://x.com/aakashgupta/status/2040888715003019433) on X | 🔥 高互动推文
- **摘要**: Claude Code 的 Skills 经常不能按预期自动触发（即使写了"use when the user mentions slides"之类的触发条件）。解决方案是用 Hooks 替代——在 `settings.json` 中配置 `UserPromptSubmit` 钩子脚本，通过关键词匹配自动注入对应 Skill 的上下文。
- **代码示例**:
```json
{
  "hooks": {
    "UserPromptSubmit": [{
      "matcher": "",
      "hooks": [{
        "type": "command",
        "command": "python3 .claude/skill-evaluator.py \"$PROMPT\""
      }]
    }]
  }
}
```

## 5. 自我验证技巧：让 Claude 自查输出
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 8.2k stars
- **摘要**: 在提示词末尾加上"double check everything, every single claim in what you produced and at the end make a table of what you were able to verify"，让 Claude 对自己的输出做验证表格。这个简单的技巧能显著提升代码和内容的准确率。
- **代码示例**:
```
请完成以上任务，然后：
1. 逐条检查你产出的每个断言
2. 在末尾生成一个验证表格，标注每项是否可验证
```

## 6. /compact 带提示词压缩，而非自动压缩
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 52.1k stars
- **摘要**: Reddit 社区共识：不要依赖自动压缩（auto-compaction），而应手动使用 `/compact` 并附带提示词来指导压缩方向。自动压缩容易丢失关键上下文，导致"智商下降区"（约 40% 上下文占用时出现）。同时建议使用 `/rewind` 回退错误操作，而不是口头纠正。
- **代码示例**:
```
/compact 保留当前的数据库迁移方案和API接口设计，压缩之前的调试记录
```

## 7. Hooks 实现自动化质量门禁
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 5.9k stars
- **摘要**: 利用 Hooks 的四种事件（PreToolUse、PostToolUse、UserPromptSubmit、Stop）构建自动化质量门禁：提交前自动格式化、保存后自动跑测试和 lint、禁止在 main 分支直接编辑。每个 PR 审查成本仅约 $0.05-0.50。
- **代码示例**:
```json
{
  "hooks": {
    "PostToolUse": [{
      "matcher": "Edit|Write",
      "hooks": [{
        "type": "command",
        "command": "npx prettier --write $FILE_PATH && npx eslint --fix $FILE_PATH"
      }]
    }],
    "PreToolUse": [{
      "matcher": "Edit|Write",
      "hooks": [{
        "type": "command",
        "command": "bash .claude/block-main-edits.sh"
      }]
    }]
  }
}
```
