## 1. Opus 写计划 + 廉价模型群执行的 Workflow 模式
- **来源**: [@mvanhorn](https://x.com/mvanhorn/article/2107139054907388097) on X | 🔥 高互动系列文章（October 2026 edition）
- **摘要**: 在最新一期 "Every Agentic Engineering Hack I Know" 中，作者详细介绍了用 Opus 编写 workflow 脚本作为计划层，再由多个廉价模型代理并行执行的模式。关键在于让昂贵模型只负责"思考"，把"动手"交给便宜模型，从而在保持质量的同时大幅降低 token 成本。适合大规模重构和跨文件审查。
- **代码示例**:
```bash
# 在提示中使用 "ultracode" 关键词触发多代理工作流
ultracode 审查所有 API 端点的错误处理一致性

# 或者直接要求创建 workflow
"create a workflow to refactor all database queries"
```

## 2. 给 Claude 反馈循环：质量提升 2-3 倍
- **来源**: [@PrajwalTomar_](https://x.com/PrajwalTomar_/article/2063238968125333581) on X | 🔥 热门长文
- **摘要**: 在 Claude Code 的全面设置指南中，引用了 Boris Cherny 的经验：仅仅"给 Claude 一种验证自身工作的方式"就能带来 2-3 倍的质量提升。具体做法是在提示中包含测试命令、lint 检查或预期输出，让 Claude 在完成代码后自动运行验证，发现错误后自行修复，形成闭环。
- **代码示例**:
```markdown
# 在 CLAUDE.md 中添加验证命令
## 验证步骤
- 修改代码后运行 `npm test` 确认测试通过
- 运行 `npm run lint` 确认无 lint 错误
- 如果测试失败，分析错误并修复后重新验证
```

## 3. 用 /compact 管理上下文窗口，60% 时主动压缩
- **来源**: [@mvanhorn](https://x.com/mvanhorn/article/2107139054907388097) on X | 🔥 系列文章最佳实践
- **摘要**: 上下文窗口是 Claude Code 的核心资源。社区推荐在上下文使用达到约 60% 时运行 `/compact`，并告诉它需要保留哪些关键信息。切换完全不同的任务时使用 `/clear` 彻底清空。避免让上下文窗口自然溢出导致自动压缩，因为手动压缩可以指定保留重点。
- **代码示例**:
```bash
# 手动压缩并指定保留重点
/compact 保留当前正在修改的文件列表和测试结果

# 切换到全新任务时彻底清空
/clear
```

## 4. Git Worktree 并行开发：同时运行多个 Claude Code 会话
- **来源**: [@nateherk](https://x.com/nateherk/status/2048754250927272273) on X | 🔥 高转发实战技巧
- **摘要**: 使用 git worktree 为每个 Claude Code 会话创建独立的工作目录，实现真正的并行开发。每个会话在自己的分支上工作，互不干扰。一个人可以同时推进 4-5 个功能开发，最后分别提 PR 合并。这是单人团队效率最大化的关键技巧。
- **代码示例**:
```bash
# 创建 worktree 并在其中启动 Claude Code
git worktree add ../project-feature-auth feature/auth
git worktree add ../project-feature-api feature/api

# 在不同终端中分别启动 Claude Code
cd ../project-feature-auth && claude
cd ../project-feature-api && claude

# 完成后清理
git worktree remove ../project-feature-auth
```

## 5. CLAUDE.md 保持精简：200 行以下效果最佳
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 社区最佳实践仓库
- **摘要**: 多个社区来源一致认为 CLAUDE.md 应控制在 200 行以内。超过这个长度，Claude 的遵循度会下降。具体做法：把通用规则放主文件，路径相关规则放 `.claude/rules/` 目录下按路径加载，个人偏好放 `CLAUDE.local.md`（加入 .gitignore）。避免用 `@` 引用大文件，否则每次会话都会嵌入全文。
- **代码示例**:
```markdown
# .claude/rules/api-routes.md（仅在编辑 API 路由时加载）
所有 API 路由必须包含输入验证和错误处理
使用 zod schema 验证请求体
返回标准化的错误响应格式

# CLAUDE.local.md（个人偏好，不提交到仓库）
偏好使用中文注释
代码风格偏向函数式编程
```

## 6. 让 Claude 自动录制应用演示视频
- **来源**: [@om_patel5](https://x.com/om_patel5/article/2072396948506816895) on X | 🔥 创新用法热门长文
- **摘要**: 通过 Playwright 集成，教会 Claude Code 自动启动应用、操作 UI 并录制全流程演示视频。整个过程无需人工介入：Claude 启动开发服务器，打开浏览器，按预设脚本操作页面，同时录制视频。适合为每次 PR 自动生成功能演示，或者制作产品 demo。
- **代码示例**:
```javascript
// Claude Code 可以直接编写和执行 Playwright 脚本
const { chromium } = require('playwright');
const browser = await chromium.launch();
const context = await browser.newContext({
  recordVideo: { dir: './demo-videos/' }
});
const page = await context.newPage();
await page.goto('http://localhost:3000');
// Claude 会根据应用功能自动编写操作步骤
```

## 7. 把不可违反的规则从 CLAUDE.md 移到 Hooks
- **来源**: [abhishekray07/claude-md-templates](https://github.com/abhishekray07/claude-md-templates) on GitHub | ⭐ 模板仓库
- **摘要**: CLAUDE.md 中的规则是"建议"级别的——Claude 可能会忽略。如果某些规则必须强制执行（如代码格式化、lint 检查），应该将其配置为 hooks，由 Claude Code 运行时自动执行，而非依赖模型"记住"。典型场景：提交前自动运行 prettier 和 eslint，保存文件后自动运行类型检查。
- **代码示例**:
```json
// .claude/settings.json 中配置 hooks
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "command": "npx prettier --write $CLAUDE_FILE_PATH"
      }
    ],
    "PreCommit": [
      {
        "command": "npm run lint && npm run typecheck"
      }
    ]
  }
}
```

## 8. 粘贴长文到 Claude 会话中进行技能对比审计
- **来源**: [@PrajwalTomar_](https://x.com/PrajwalTomar_/status/2074787074641899896) on X | 🔥 PRO tip 高互动
- **摘要**: 一个高级用法：将完整的技巧文章或配置指南粘贴到 Claude Code 会话中，然后要求它"读完全文，列出我当前已安装的所有 skill，与文章清单对比，卸载重复或从未触发的 skill"。这样可以定期审计和清理自己的 Claude Code 配置，避免 skill 堆积导致上下文浪费。
- **代码示例**:
```
# 粘贴一篇技巧文章后输入：
读完这篇文章。然后列出我当前已安装的所有 skill，
与文章清单进行对比。卸载任何重复、从未触发、
或已被内置功能覆盖的 skill。
```
