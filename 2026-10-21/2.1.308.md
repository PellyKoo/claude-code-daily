# Claude Code 2.1.308 社区实用技巧 - 2026-10-21

## 1. Advisor 模式：Sonnet 干活，Opus 当顾问
- **来源**: [delost (@thedelost)](https://x.com/thedelost/status/2110109013652193621) on X | 🔥 高热度讨论
- **摘要**: 社区热议的 Advisor 模式——用便宜的 Sonnet 模型处理日常编码，仅在关键决策点自动咨询 Opus 5.5。这样每个重要判断都有 Opus 级别的质量把关，但不需要全程为 Opus 付费。启动方式是在命令行加 `--advisor` 参数，Claude Code 会自动决定何时需要顾问介入。
- **代码示例**:
```bash
# 用 Sonnet 作为主力模型，Opus 作为顾问
claude --model sonnet --advisor opus

# Opus 仅在以下场景被咨询：
# - 架构决策
# - 复杂 bug 诊断
# - 安全相关判断
# 日常编辑、重命名、格式化等由 Sonnet 独立完成
```

## 2. Workflow 脚本编排：Opus 写计划，廉价智能体执行
- **来源**: [delost (@thedelost)](https://x.com/thedelost/status/2110472847084650726) on X | 🔥 高互动技术帖
- **摘要**: 进阶玩法——让 Opus 5.5 编写编排脚本（plan），然后由一群更便宜的智能体并行执行。这样大型任务可以高效拆解，Opus 只消耗写脚本的少量 token，执行阶段的大量 token 由低成本模型承担。特别适合大规模代码审查、跨仓库重构等场景。
- **代码示例**:
```bash
# Opus 写 workflow 脚本，子智能体用更便宜的模型执行
# 在提示中使用 "ultracode" 触发 workflow 模式

> ultracode 审查所有模块的类型安全和错误处理

# Opus 自动生成编排脚本，分发给多个 Sonnet/Haiku 子智能体
# 每个子智能体独立处理一个维度，结果汇总后返回
```

## 3. Agentic Engineering Hacks（October 2026 版）
- **来源**: [Matt Van Horn (@mvanhorn)](https://x.com/mvanhorn/article/2035857346602340637) on X | 🔥 长文热帖，October 2026 更新
- **摘要**: Matt Van Horn 的 Agentic Engineering 系列在社区广泛传播。October 2026 更新版的核心建议：让一个编排智能体调度其他智能体，而不是手动管理；为重要任务用强模型，简单任务用快模型；跳过手动"计划的计划"步骤，直接用 `/ce-plan` 命令让 Claude 自动生成实施方案。强调"个人智能体"的概念——每个开发者应该有自己定制化的 Claude 工作流。
- **代码示例**:
```bash
# 使用内置的规划命令替代手动分步
/ce-plan "重构认证模块，从 JWT 迁移到 session-based"

# Claude 自动生成分步计划，包含：
# 1. 影响范围分析
# 2. 具体实施步骤
# 3. 测试策略
# 4. 回滚方案
```

## 4. 四个小改动，省 Token 又提效
- **来源**: [XDA Developers](https://www.xda-developers.com/productivity-tricks-i-learned-after-using-claude-code-since-launch-day/) | 🔥 科技媒体热文
- **摘要**: 一位从 Claude Code 发布日就开始使用的开发者分享了四个核心习惯：(1) 每次任务切换后执行 `/clear` 清除旧上下文；(2) 用 `Shift+Tab` 进入 Plan Mode 让 Claude 先规划再动手；(3) 在 CLAUDE.md 中写明具体的测试命令而非模糊的"写测试"；(4) 根据任务复杂度用 `/model` 切换模型——简单重命名用 Haiku，日常编码用 Sonnet，架构问题用 Opus。
- **代码示例**:
```bash
# 任务切换时清除上下文
/clear

# 进入规划模式（Shift+Tab 切换）
# Claude 只输出方案，不修改文件

# CLAUDE.md 中的具体命令示例
## 测试
- 单元测试: `npm test -- --testPathPattern=<模块名>`
- 类型检查: `npx tsc --noEmit`
- Lint: `npm run lint -- --fix`

# 按需切换模型
/model haiku    # 简单任务
/model sonnet   # 日常编码
/model opus     # 复杂架构
```

## 6. Claude Code Tips & Tricks 社区分享会精华
- **来源**: [AI Tinkerers - Post-Training](https://post-training.aitinkerers.org/p/claude-code-tips-and-tricks) | 🔥 社区技术分享
- **摘要**: AI Tinkerers 社区的 Claude Code 实战分享会。核心要点：(1) 用 hooks 而不是 CLAUDE.md 规则来强制执行代码规范——hooks 是确定性的，CLAUDE.md 规则有概率被忽略；(2) Git worktrees 实现真正的并行开发，每个 Claude 会话独占一个工作树和分支；(3) 自定义 skills 封装重复工作流，一个 `/review` 命令替代多步手动操作。
- **代码示例**:
```bash
# Git worktrees 并行开发
git worktree add ../feature-auth feature/auth
git worktree add ../feature-ui feature/ui

# 在不同终端分别启动 Claude Code
cd ../feature-auth && claude
cd ../feature-ui && claude

# 两个 Claude 实例独立工作，互不干扰
# 完成后合并各自分支即可
```

## 7. CLAUDE.md 精简原则：从错误中学习，逐条添加
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 持续维护的最佳实践仓库
- **摘要**: 社区公认的 CLAUDE.md 编写原则——从空文件开始，每次 Claude 犯错时才添加一条规则。目标是控制在 60-200 行以内。核心测试：删掉某条规则后如果不会导致 Claude 犯错，那这条规则就不需要存在。避免用 `@` 导入整个文件（会膨胀上下文窗口），改用条件触发加载。firm language（如 "IMPORTANT"、"YOU MUST"）比模糊建议更有效。
- **代码示例**:
```markdown
# CLAUDE.md 精简示例（约 30 行足矣）

## 命令
- 安装: `pnpm install`
- 开发: `pnpm dev`
- 测试: `pnpm test --run`
- Lint: `pnpm lint --fix`

## 架构
- API 路由在 `src/routes/` 下，业务逻辑在 `src/services/`
- 数据库操作必须通过 `src/db/` 中的 repository 层

## 规则
- IMPORTANT: 新增 API 端点必须有对应的集成测试
- YOU MUST: 修改数据库 schema 后运行 `pnpm db:generate`
- 绝不修改 `src/core/` 目录下的文件，除非明确要求
```
