# Claude Code 2.1.156 社区实用技巧 - 2026-05-28

## 1. Dynamic Workflows：一句话启动数百个并行 Agent
- **来源**: [Greg Isenberg](https://x.com/gregisenberg/status/2060072130339873093) on X | 🔥 高互动热帖
- **摘要**: Claude Code 新推出的 **Dynamic Workflows** 功能——在 effort 菜单中开启"ultracode"或在提示中提到"create a workflow"，Claude 会自动创建一个编排计划，启动数百个并行 Agent 并交叉检查彼此的工作。工作单元从"单个文件"跃升为"整个项目"级别，适合大规模重构和多模块开发。
- **代码示例**:
```
# 在提示中触发 dynamic workflow
"Create a workflow to refactor the entire authentication system across all microservices"

# 或在 effort 菜单中选择 ultracode 模式
# Claude 会自动：
# 1. 生成编排计划
# 2. 启动多个并行 agent
# 3. 各 agent 交叉验证结果
```

## 2. 非程序员的 2026 Claude Code 速查手册
- **来源**: [Ruben Hassid](https://x.com/rubenhassid/status/2059152552529391850) on X | 🔥 热门教程
- **摘要**: 面向非技术用户的 Claude Code 使用指南：① 打开 Claude 桌面端，选择 **Code 模式**（非 Chat 或 Cowork）；② 注册免费 GitHub 账户；③ 将项目文件夹拖入 Code；④ 选择 **Opus 4.7+** 模型（非 Haiku/Sonnet）以获得最佳代码质量。强调即使不会编程，也能用 Claude Code 构建完整项目。
- **代码示例**:
```
# 非程序员启动步骤
1. 打开 Claude Desktop → 点击 "Code"
2. 连接 GitHub 账户
3. 拖入项目文件夹
4. 模型选 Opus 4.7+
5. 用自然语言描述你想要的功能
```

## 3. Glob 规则懒加载：按文件类型动态注入上下文
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 55.5k stars
- **摘要**: 使用 `.claude/rules/*.md` 配合 YAML frontmatter 中的 glob 匹配模式，实现**按需加载**领域规则。比如编辑 `.tsx` 文件时自动注入 React 规范，编辑 `.sql` 文件时注入数据库约束。避免 CLAUDE.md 膨胀导致的上下文浪费，保持每个规则文件在 60 行以内。
- **代码示例**:
```yaml
# .claude/rules/react-conventions.md
---
globs: ["src/**/*.tsx", "src/**/*.jsx"]
---
- Use functional components with hooks only
- All props must have TypeScript interfaces
- Use React.memo for expensive renders

# .claude/rules/database.md
---
globs: ["**/migrations/*.sql", "src/db/**"]
---
- Always add IF NOT EXISTS to CREATE TABLE
- Include rollback migration in every file
- Index all foreign key columns
```

## 4. Git Worktrees 并行开发：多 Agent 零冲突协作
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 55.5k stars
- **摘要**: 利用 Git Worktrees 为每个 Claude 实例创建独立的工作目录，实现真正的**多 Agent 并行开发**而不产生文件冲突。Boris Cherny 本人同时运行 5 个终端 Claude + 5-10 个 Web/Mobile Claude，每个都在独立的 git checkout 中工作。这是社区公认的高效扩展模式。
- **代码示例**:
```bash
# 创建多个 worktree，每个运行一个 Claude 实例
git worktree add ../project-auth feature/auth
git worktree add ../project-api feature/api
git worktree add ../project-ui feature/ui

# 在不同终端中分别启动 Claude
# Terminal 1: cd ../project-auth && claude
# Terminal 2: cd ../project-api && claude
# Terminal 3: cd ../project-ui && claude

# 完成后合并各分支
git worktree remove ../project-auth
```

## 5. "Challenge Claude" 对抗性审查模式
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 55.5k stars
- **摘要**: 社区推崇的质量保证模式——不要让 Claude 直接提交 PR，而是要求它**先证明代码能工作**。核心理念："Grill me on changes and don't make a PR until I pass your test。"让一个独立 Agent 审查另一个 Agent 的产出（test-time compute），因为不同的 Agent 会发现不同的 bug。
- **代码示例**:
```
# 要求 Claude 自我验证
"Before creating a PR, prove this implementation works:
1. Run all existing tests
2. Write 3 new edge-case tests
3. Compare the diff against main and explain every change
4. Challenge yourself: what could go wrong in production?"

# 使用独立 agent 做交叉审查
"Review the changes in feature/auth branch as a skeptical reviewer.
Find bugs, race conditions, and missing error handling."
```

## 6. AskUserQuestion 工具：让 Claude 主动采访你
- **来源**: [Tech with Mak](https://x.com/techNmak/status/2037788648691884207) on X | 🔥 22k+ stars 相关仓库
- **摘要**: 在 CLAUDE.md 中指示 Claude 使用 `AskUserQuestion` 工具主动向你提问，而不是猜测需求。这种"采访模式"让 Claude 像产品经理一样先澄清需求、确认约束、了解偏好，再开始编码。大幅减少返工次数，尤其适合模糊需求的项目。
- **代码示例**:
```markdown
# 在 CLAUDE.md 中添加
## 工作模式
- 遇到模糊需求时，使用 AskUserQuestion 工具向我提问
- 在开始编码前，先确认以下信息：
  1. 目标用户是谁？
  2. 有哪些硬性约束？
  3. 期望的技术栈偏好？
  4. 是否有现有的类似实现可以参考？
```

## 7. Subagent 上下文隔离：保护主窗口不被污染
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 55.5k stars
- **摘要**: 将工具探索和文件搜索等高消耗操作**委托给 Subagent**，只将最终结论返回主上下文。这样主窗口保持干净，避免因大量搜索结果和文件内容导致的上下文腐烂。配合 `Command → Agent → Skill` 的三层编排架构，实现优雅的关注点分离。
- **代码示例**:
```yaml
# .claude/agents/code-explorer.md
---
name: code-explorer
description: Explore codebase and return concise findings
---
Search the codebase for the requested pattern.
Return ONLY: file paths, line numbers, and a 2-sentence summary.
Do NOT return full file contents.

# 在主会话中使用
"Use the code-explorer agent to find all API endpoints
that handle authentication, then summarize the patterns."
```

## 8. Skill 触发器设计：写"何时触发"而非"做什么"
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 55.5k stars
- **摘要**: 社区发现 Skill 的 description 字段应该写成**触发条件**（"When should I fire?"）而非功能摘要。包含脚本和库引用让 Claude 组合复用而非从头重建。同时建议维护一个"踩坑记录"（Gotchas）段落，持续记录失败模式，让 Skill 随使用越来越智能。
- **代码示例**:
```yaml
# .claude/skills/db-migration.md
---
# ❌ 错误写法（功能摘要）
# description: Creates database migrations

# ✅ 正确写法（触发条件）
description: >
  TRIGGER when: user mentions schema change, new table,
  column addition, index creation, or references a migration file.
  SKIP when: query-only operations or read-only DB access.
---
## Gotchas
- Always check for existing migration with same timestamp
- Never drop columns in production without data backup
- Run migrate:dry-run before actual migration
```
