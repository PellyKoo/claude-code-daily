## 1. Workflows 动态编排：从文件级到模块级的跃迁
- **来源**: [Greg Isenberg](https://x.com/gregisenberg/status/2060072130339873093) on X | 🔥 高互动热帖
- **摘要**: Claude Code 推出的 "dynamic workflows" 功能被认为是继 Skills 和 Subagents 之后最大的能力升级。输入 "create a workflow" 或在 effort 菜单开启 "ultracode"，即可启动数百个并行代理互相检查工作。工作交付单位从单个文件跃升到整个模块。通过 `export const meta` 定义多阶段工作流，支持 pipeline/parallel 组合编排。
- **代码示例**:
```javascript
// .claude/workflows/full-audit.js
export const meta = {
  name: 'full-audit',
  description: 'Multi-dimensional code audit',
  phases: [
    { title: 'Find', detail: 'Parallel finders by dimension' },
    { title: 'Verify', detail: 'Adversarial verification' },
  ],
}

phase('Find')
const results = await pipeline(
  DIMENSIONS,
  d => agent(d.prompt, { schema: FINDINGS, phase: 'Find' }),
  (review, _, i) => parallel(
    review.findings.map(f => () =>
      agent(`Try to refute: ${f.desc}`, { phase: 'Verify', schema: VERDICT })
    )
  )
)
```

## 2. Andrej Karpathy 四原则 CLAUDE.md —— 18.9 万星最佳实践
- **来源**: [multica-ai/andrej-karpathy-skills](https://github.com/multica-ai/andrej-karpathy-skills) on GitHub | ⭐ 189,992 stars
- **摘要**: GitHub 上最受欢迎的 Claude Code 配置资源，提炼了 LLM 编码的四大核心原则：①先思考再编码——明确假设，不确定就提问；②简洁优先——最少代码解决问题，禁止投机性功能和过度抽象；③手术刀式修改——只改必须改的，只清理自己的代码；④目标驱动执行——定义成功标准，循环验证直到通过。这四条精准命中了 LLM 生成代码最常见的失败模式。
- **代码示例**:
```markdown
<!-- CLAUDE.md - Karpathy 风格 -->
## 核心原则
1. Think Before Coding - 明确假设，不确定就问
2. Simplicity First - 最少代码解决问题，禁止投机性功能
3. Surgical Changes - 只改必须改的，保持现有风格
4. Goal-Driven - 定义成功标准，循环验证直到通过

## 测试："高级工程师会说这过度设计了吗？" 如果是，简化它。
```

## 3. Token 效率 CLAUDE.md —— 实测减少 63% 输出
- **来源**: [drona23/claude-token-efficient](https://github.com/drona23/claude-token-efficient) on GitHub | ⭐ 5,790 stars
- **摘要**: 一个专注于减少 Claude 输出冗余的 CLAUDE.md 模板，在实测中将输出词数减少 63%，代码审查输出减少 75%（120→30 词），成本节省 17.4%。核心策略包括："先读后写再测试"、偏好定向编辑而非全文重写、删除谄媚式开场白（"Sure!"、"Great question!"）和无意义收尾。但需注意：CLAUDE.md 本身会在每条消息中消耗输入 token，所以只有输出密集的工作流才能真正受益。
- **代码示例**:
```markdown
<!-- CLAUDE.md - Token 高效模板 -->
# 输出规则
- 先读文件，写完整方案，测试一次
- 保持输出简洁，不用寒暄语
- 偏好定向编辑（Edit）而非全文重写（Write）
- 不过度工程化，偏好简单直接的修复
- 禁止开头的 "Sure!"、"Great question!" 等废话
- 禁止结尾的 "I hope this helps!" 等套话
```

## 4. Hooks 全生命周期精通指南 —— 13 个钩子事件详解
- **来源**: [disler/claude-code-hooks-mastery](https://github.com/disler/claude-code-hooks-mastery) on GitHub | ⭐ 3,800 stars
- **摘要**: 覆盖 Claude Code 全部 13 个 Hook 生命周期事件的参考实现。关键发现：exit code 0 = 成功（stdout 显示在 transcript），exit code 2 = 阻断执行（stderr 反馈给 Claude），其他 = 非阻断错误。每个 Hook 使用 UV 单文件脚本，无需虚拟环境。包含 9 种 status line 变体，实时追踪上下文窗口使用率、token 成本、会话时长和 git 状态。
- **代码示例**:
```python
# .claude/hooks/block_dangerous_rm.py
import sys, json

def main():
    input_data = json.loads(sys.stdin.read())
    command = input_data.get("tool_input", {}).get("command", "")
    
    if "rm -rf /" in command or "rm -rf ~" in command:
        print("BLOCKED: 危险的 rm 命令", file=sys.stderr)
        sys.exit(2)  # exit code 2 = 阻断执行

# .claude/hooks/auto_lint.py  (PostToolUse)
# 每次文件编辑后自动运行 linter
if tool_name in ("Edit", "Write"):
    subprocess.run(["ruff", "check", "--fix", file_path])
```

## 5. 社区共识：上下文 30% 是智力分界线
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 62,165 stars
- **摘要**: 这个 6.2 万星的最佳实践仓库强调：Claude 的智力在上下文占用约 40% 时开始明显衰退。有经验的用户将关键工作控制在 30% 以下。手动 `/compact` 加提示（如 `/compact 保留认证重构方案，丢弃调试日志`）远优于自动压缩。另一个核心建议：使用 `.claude/rules/*.md` 配合 YAML frontmatter 中的 globs 实现按路径懒加载，避免在全局 CLAUDE.md 中塞入所有规则。
- **代码示例**:
```markdown
<!-- .claude/rules/payments.md -->
---
globs: ["src/payments/**", "src/billing/**"]
---
# 支付模块规则
- 所有金额使用 Decimal，禁止 float
- Stripe webhook 必须验证签名
- 退款操作需要幂等键
```

## 7. 小技巧集锦：Claude Code 隐藏功能速查

- **摘要**: 一组可以立即提升效率的小调整：①`/loop` 定时自动化——每 5 分钟处理 PR 评审、每 30 分钟检查 CI 状态，最长可运行 3 天；②自定义命令模板化重复任务——在 `.claude/commands/` 中创建 markdown 文件实现一键触发复杂流程；③Stop 钩子验证完成度——在 Claude 结束回复时自动检查工作是否真正完成；④Permission 路由钩子——将权限请求转发给 Opus 进行安全扫描后自动审批安全操作。

## 8. 生产级团队 Claude Code 集成范例
- **来源**: [Apicurio/apicurio-registry](https://github.com/Apicurio/apicurio-registry) on GitHub | ⭐ 1,300+ stars
- **摘要**: 一个成熟的开源项目（30+ Maven 模块，Java/Quarkus/React）展示了团队级 Claude Code 集成的最佳实践。核心是分层管理：`.claude/commands/` 存放团队共享的自定义命令；`.claude/rules/` 存放路径限定的编码规范（如 K&R 括号风格、禁止星号 import）；`.claude/hooks/` 实现文件保护和提交前代码风格检查；`CLAUDE.local.md`（gitignored）允许每个开发者覆盖团队默认设置。团队规则提交到仓库，个人偏好本地保留。
- **代码示例**:
```
项目结构:
.claude/
├── commands/       # 团队共享命令（git tracked）
│   ├── review.md
│   └── ticket.md
├── rules/          # 路径限定规范（git tracked）
│   ├── java.md     # globs: ["**/*.java"]
│   └── react.md    # globs: ["ui/**/*.tsx"]
├── hooks/          # 自动化守卫（git tracked）
│   ├── checkstyle-pre-commit.sh
│   └── protect-config.sh
├── settings.json   # 团队权限策略（git tracked）
CLAUDE.md           # 项目级规则（git tracked）
CLAUDE.local.md     # 个人偏好（.gitignored）
```
