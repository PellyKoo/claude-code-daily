# Claude Code 2.1.131 社区实用技巧 - 2026-05-05

## 1. 上下文腐烂阈值：保持会话精简
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 51.4k stars
- **摘要**: 在 1M 上下文模型中，当 token 使用量超过 300-400k 时，模型智能会明显下降（"上下文腐烂"）。有经验的开发者建议将上下文使用控制在 30% 以下。当上下文膨胀时，手动使用 `/compact [hint]` 并指定保留重点，比自动压缩效果更好。新任务应开启全新会话，相关任务可复用上下文。
- **代码示例**:
```bash
# 手动压缩并保留特定上下文
/compact 保留数据库迁移和API端点的相关讨论

# 在 rewind 前先让 Claude 写交接文档
> 从这里开始总结，为下一个会话写指导说明
```

## 2. 双模式工作流：初始化 Agent + 编码 Agent
- **来源**: [HackerRank](https://x.com/hackerrank/status/2016398850265935929) on X | 🔥 高互动帖文
- **摘要**: 将长期运行任务拆分为两种模式。初始化 Agent 负责项目搭建、功能清单、Git 配置和进度追踪；编码 Agent 负责读取、构建、测试、提交和更新。关键技巧：创建 JSON 格式的功能清单（含 `passes` 字段，默认 `false`），只有功能实现并通过测试后才翻转为 `true`。JSON 比 Markdown 更适合 LLM 处理结构化数据。
- **代码示例**:
```json
{
  "features": [
    {"name": "用户认证", "passes": false},
    {"name": "数据导出API", "passes": true},
    {"name": "仪表盘UI", "passes": false}
  ]
}
```

## 3. 自定义状态栏脚本
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 8.1k stars
- **摘要**: 通过自定义状态栏脚本，在 Claude Code 界面底部实时显示模型名称、当前目录、Git 分支、未提交文件数、token 使用量等关键信息。支持 10 种颜色主题，第二行显示最近一条消息，帮助你随时了解会话状态。
- **代码示例**:
```jsonc
// .claude/settings.json
{
  "statusLine": {
    "script": "echo \"$CLAUDE_MODEL | $(git branch --show-current) | tokens: $CLAUDE_TOKEN_USAGE\""
  }
}
```

## 4. 垂直切片代替水平分层开发
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 51.4k stars
- **摘要**: 让 Claude 按"垂直切片"而非"水平分层"来构建 PR：每个 PR 应贯穿所有层（数据库 + 服务 + UI），而不是按层逐一完成。这种"示踪弹"方法让每个 PR 都是独立可验证的功能单元。配合挑战式提示词（如"证明给我看这能跑"或"用你现在掌握的所有信息，实现最优雅的方案"）来激发更高质量的输出。
- **代码示例**:
```
# 推荐方式 - 垂直切片
> 实现用户注册功能：包括数据库 migration、后端 API 端点、前端表单和验证逻辑，一个 PR 搞定

# 不推荐 - 水平分层
> 先写所有数据库 migration，然后再写所有 API，最后写所有前端
```

## 5. 用 Gemini CLI 作为 Claude 的"跑腿小弟"
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 8.1k stars
- **摘要**: Claude Code 无法直接访问某些网站（如 Reddit）。解决办法是创建一个 Skill，通过 tmux 调用 Gemini CLI 来获取这些被屏蔽站点的内容，然后将结果传回 Claude。这让 Claude 拥有了"代理访问"能力，突破了内容获取限制。
- **代码示例**:
```bash
# 创建 skill: .claude/skills/fetch-reddit.md
# 使用 tmux + Gemini CLI 获取 Reddit 内容
tmux new-session -d -s gemini "gemini 'summarize the top posts from r/ClaudeAI today' > /tmp/reddit-summary.txt"
# 等待完成后读取结果
cat /tmp/reddit-summary.txt
```

## 6. 通配符权限替代 dangerously-skip-permissions
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 51.4k stars
- **摘要**: 不要使用 `--dangerously-skip-permissions` 来避免权限弹窗。更安全的做法是使用通配符权限语法，精确控制 Claude 可以执行的命令范围。`Shift+Tab` 可在 Ask → Plan → Auto 三种模式间快速切换，Auto 模式会自动分类命令安全等级。
- **代码示例**:
```jsonc
// .claude/settings.json
{
  "permissions": {
    "allow": [
      "Bash(npm run *)",
      "Bash(git *)",
      "Edit(/src/**)",
      "Edit(/docs/**)"
    ]
  }
}
```

## 7. 系统提示词瘦身：从 19k 减到 9k tokens
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 8.1k stars
- **摘要**: Claude Code 默认系统提示词约 19k tokens，通过启用工具懒加载（lazy-loading）可以削减到约 9k tokens。这意味着每次对话的可用上下文更多，响应速度更快，成本更低。适合对 token 消耗敏感的团队。
- **代码示例**:
```jsonc
// .claude/settings.json
{
  "env": {
    "ENABLE_TOOL_SEARCH": "true"
  }
}
```

## 8. tmux + 远程机器实现会话永不中断
- **来源**: [X 社区多位开发者](https://x.com/bcherny/status/2007179832300581177) on X | 🔥 高互动讨论
- **摘要**: Claude Code 在不稳定网络（如飞机 WiFi）下容易断连导致会话丢失。解决方案：先 tmux 连接到远程服务器（如 Mac Mini），Claude Code 会话运行在远程机器上，本地笔记本只是一个窗口。WiFi 断开后重连，tmux 会话完好无损，飞行途中也能持续开发。
- **代码示例**:
```bash
# 在远程机器上启动 tmux 会话
ssh my-mac-mini
tmux new -s claude-dev

# 启动 Claude Code
claude

# 断连后重新接入
ssh my-mac-mini
tmux attach -t claude-dev
# 会话完整恢复，继续工作
```

## 9. Skill 触发器设计：描述"何时触发"而非"做什么"
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 51.4k stars
- **摘要**: 创建 Skill 时，描述（description）应该写的是模型"何时应该触发"这个 Skill 的决策逻辑，而不是概述 Skill 做什么。可在 SKILL.md 中使用 `!command` 语法动态注入 shell 命令输出——Claude 只看到执行结果，不看到原始命令。用子文件夹（references/、scripts/、examples/）控制信息可见性，避免 prompt 过载。
- **代码示例**:
```markdown
<!-- .claude/skills/deploy.md -->
<!-- 好的描述：写触发条件 -->
TRIGGER: 当用户提到部署、发布、上线、CI/CD 时触发

<!-- 动态注入当前部署状态 -->
当前环境状态：!kubectl get pods --namespace production
```

## 10. 容器化运行 Claude Code 实现全自动化
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 8.1k stars
- **摘要**: 在 Docker 容器中运行 Claude Code 并使用 `--dangerously-skip-permissions` 标志，可以实现完全自主的长期运行任务，无需逐一审批每个操作。容器隔离提供了安全边界——即使 Claude 执行了危险命令，影响也局限在容器内。适合 CI/CD 流水线和批量自动化场景。
- **代码示例**:
```dockerfile
FROM node:20
RUN npm install -g @anthropic-ai/claude-code
WORKDIR /app
COPY . .
CMD ["claude", "--dangerously-skip-permissions", "-p", "运行所有测试并修复失败的用例"]
```
