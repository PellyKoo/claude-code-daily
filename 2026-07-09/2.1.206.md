## 1. Skill 审计法：让 Claude 自动清理冗余技能
- **来源**: [Prajwal Tomar](https://x.com/PrajwalTomar_/status/2074787074641899896) on X | 🔥 高互动热帖
- **摘要**: 安装了大量 skill 后，很多会互相重叠或从不触发，白白占用上下文窗口。正确做法：把技能管理的参考文章直接粘贴到会话中，让 Claude 对比你已安装的技能列表，自动卸载重叠、从未触发或已过时的 skill，再推荐替代方案。把"技能管理"本身变成 Claude 的任务，而不是手动逐个检查。
- **代码示例**:
```
# 在 Claude Code 会话中执行
> 读完这篇文章，然后列出我当前安装的所有 skill，
  对比文章中的推荐列表：
  1. 卸载任何重叠或从未触发的 skill
  2. 对每个保留的 skill 说明保留理由
  3. 推荐缺失但有价值的 skill 并安装

# 查看当前已安装的 skills
/skills
```

## 2. Workflows 最佳实践：从 Skill 到编排的进化
- **来源**: [Thariq](https://x.com/trq212/status/2061907538741006796) on X | 🔥 高互动热帖
- **摘要**: Workflows 是继 skills 和 subagents 之后 Claude Code 最大的能力升级。关键洞察：只需在提示中提及"workflow"一词，Claude 就会动态创建编排方案，按严格顺序执行每个阶段。更令人兴奋的是它为非技术任务打开的可能性——不仅是代码迁移，还可以用于内容审计、文档生成、数据清洗等场景。建议先理解 pipeline 与 parallel 的区别，再设计自己的工作流。
- **代码示例**:
```javascript
// 自定义 workflow 示例：多维度代码审查
export const meta = {
  name: 'multi-review',
  description: '多维度并行审查后汇总',
  phases: [
    { title: 'Review' },
    { title: 'Synthesize' }
  ],
}

const DIMENSIONS = ['bugs', 'perf', 'security']
phase('Review')
const results = await parallel(
  DIMENSIONS.map(d => () =>
    agent(`从 ${d} 角度审查变更`, {
      label: `review:${d}`,
      phase: 'Review'
    })
  )
)
phase('Synthesize')
const summary = await agent(
  `汇总审查结果：${JSON.stringify(results)}`
)
```

## 4. 非程序员的 Claude Code 使用指南

- **代码示例**:
```
# 非程序员的典型工作流
1. 打开 Claude Desktop → 选择 "Code"
2. 拖入项目文件夹（如营销素材目录）
3. 用自然语言描述任务：

> 帮我把 /marketing 目录下所有 Excel 文件
  合并成一个汇总表，按日期排序，
  并生成一个简单的 HTML 报告页面

# Claude 会自动：
# - 读取所有 Excel 文件
# - 编写 Python 脚本处理数据
# - 生成 HTML 报告
# - 在浏览器中预览结果
```

## 5. 日常开发效率微调清单
- **来源**: [Taylor Poindexter](https://x.com/engineering_bae/status/2074323810690478198) on X | 🔥 高互动热帖
- **摘要**: 一系列小而实用的工作流微调，累积效果显著：①为每种常见任务创建专属 slash command，省去重复输入；②善用 `/compact` 在长会话中压缩上下文；③配置 `settings.json` 中的权限白名单减少确认弹窗；④在 CLAUDE.md 中明确项目的测试命令和 lint 规则，让 Claude 自动验证每次修改。这些不是革命性功能，而是把现有能力用到位。
- **代码示例**:
```json
// .claude/settings.json - 减少权限确认弹窗
{
  "permissions": {
    "allow": [
      "Bash(npm test)",
      "Bash(npm run lint)",
      "Bash(npm run build)",
      "Bash(git status)",
      "Bash(git diff)"
    ]
  }
}
```
```markdown
<!-- CLAUDE.md 中的自动验证配置 -->
## 验证规则
- 每次修改代码后运行 `npm test`
- 提交前执行 `npm run lint --fix`
- 类型检查：`npx tsc --noEmit`
```

## 6. Claude Code Best Practice：从 Vibe Coding 到 Agentic Engineering
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 62.3k stars
- **摘要**: 社区最高星标的 Claude Code 指南（62k+ stars）持续更新。核心理念转变：从"随意对话式编程"(Vibe Coding) 升级为"代理工程"(Agentic Engineering)。关键实践：①任务拆解后用 TodoWrite 追踪进度；②给 Claude 提供验证手段（测试 + 浏览器自动化），让它自我校正，质量可提升 2-3 倍；③保持 CLAUDE.md 精简，每条规则都应有明确的触发条件和预期行为，像写代码一样写提示。
- **代码示例**:
```markdown
# CLAUDE.md 精简写法示例

## 测试
- 运行所有测试: `pytest tests/`
- 运行单个测试: `pytest tests/test_foo.py -k test_name`
- 每次修改 Python 文件后自动运行相关测试

## 代码风格
- 使用 ruff 格式化: `ruff format .`
- 类型检查: `mypy src/`
- 导入排序: `ruff check --select I --fix .`

## Git
- 分支命名: feature/xxx, fix/xxx, refactor/xxx
- 提交信息用英文，一行概述 + 空行 + 详细描述
```
