## 3. Prajwal Tomar：把配置指南直接喂给 Claude 自动对比安装
- **来源**: [Prajwal Tomar (@PrajwalTomar_)](https://x.com/PrajwalTomar_/status/2074787074641899896) on X | 🔥 高互动实用技巧
- **摘要**: 一个巧妙的 "元技巧"：找到一篇好的 Claude Code 配置指南后，不要手动逐条实施，而是把整篇文章粘贴到 Claude Code 会话中，让 Claude 自动对比你当前已安装的技能列表，找出重叠、从未触发的、以及缺失的技能，然后一键优化。这种方法的优势是 Claude 能理解上下文关联，比人工逐条比对更高效准确。
- **代码示例**:
```bash
# 步骤：
# 1. 复制一篇完整的 Claude Code 配置文章

# 2. 粘贴到 Claude Code 并给出指令：
> "通读这篇文章，然后列出我当前已安装的所有技能，
   与文章中推荐的进行对比。
   卸载重叠或从未触发的技能，
   安装文章中推荐但我还没有的。"

# 3. Claude 会自动执行：
#    - 列出当前 skills
#    - 逐条对比
#    - 给出安装/卸载建议并执行
```

## 4. Git Worktree 并行开发：.NET 开发者实战指南
- **来源**: [Mukesh Murugan (codewithmukesh)](https://codewithmukesh.com/blog/git-worktrees-claude-code/) on Blog | 🔥 高阅读量技术博客
- **摘要**: 详细讲解如何利用 Claude Code 内置的 worktree 支持实现真正的并行开发。关键发现：`claude --worktree` 创建的工作树默认从远程默认分支创建，而非当前分支；可通过 settings.json 中设置 `"worktree": {"baseRef": "head"}` 改为基于当前 HEAD。实战场景：一个 worktree 做功能开发，另一个修 bug，第三个跑测试——互不干扰，各自独立提交。作者还提醒：worktree 间共享 .git 目录，所以 hook 配置全局生效。
- **代码示例**:
```bash
# 创建带有自定义分支名的 worktree
claude --worktree feature-payments

# 修改默认基础分支（在 settings.json 中）
# { "worktree": { "baseRef": "head" } }

# 并行运行多个会话：
# Terminal 1: claude --worktree feature-auth
# Terminal 2: claude --worktree bugfix-login
# Terminal 3: claude --worktree refactor-db

# 注意事项：
# - 各 worktree 独立文件系统，互不干扰
# - .git 目录共享，hooks 全局生效
# - 完成后 worktree 自动清理（无改动时）
```

## 5. Boris Cherny 的 142+ 条 Claude Code 技巧集
- **来源**: [Boris Cherny](https://howborisusesclaudecode.com/) on 个人网站 | 🔥 社区广泛引用的参考资源
- **摘要**: TypeScript 专家 Boris Cherny（《Programming TypeScript》作者）整理的 142+ 条实用技巧，被社区视为"非官方百科全书"。精选亮点：用 `@文件名` 精确指定上下文而非让 Claude 全局搜索；在 CLAUDE.md 中用"做 X 而不是 Y"的对比格式比单独说"做 X"更有效；对于复杂任务，先 `/plan` 再执行比直接执行成功率高 2-3 倍；以及一个反直觉发现——给 Claude 更少的上下文（精确的文件引用）比更多的上下文（整个目录）产出更好的结果。
- **代码示例**:
```bash

# 在 CLAUDE.md 中用对比格式写规则
# 好: "用 dayjs 处理日期，不要用 moment"
# 差: "用 dayjs 处理日期"

# 复杂任务先规划
> /plan 重构 payment 模块，将 Stripe 集成从 v2 迁移到 v3
# 确认方案后再执行
> 执行上面的计划
```

## 6. SmartScope：Hooks + 子 Agent + 上下文管理的进阶三件套
- **来源**: [SmartScope](https://smartscope.blog/en/generative-ai/claude/claude-code-best-practices-advanced-2026/) on Blog | 🔥 深度技术文章
- **摘要**: 一篇将三个高级特性串联讲解的实战指南。核心洞察：Hooks 是"守门员"（阻止危险操作）、子 Agent 是"工人"（并行执行子任务）、上下文管理是"指挥官"（决定 Claude 看到什么）。文章特别强调了一个容易被忽视的问题：子 Agent 的摘要可能遗漏失败信息，建议搭配可验证的完成检查（如运行测试套件）而非仅依赖摘要报告。还介绍了 `/batch` 命令将任务拆分到独立 worktree 中并行处理的具体用法。
- **代码示例**:
```bash
# 三件套协同工作的示例：

# 1. Hook 守门：阻止未经测试的代码提交
# settings.json:
# "hooks": { "PreToolUse": [{
#   "matcher": "Bash",
#   "command": "if echo '$TOOL_INPUT' | grep -q 'git commit'; then
#     pnpm test --bail || (echo 'BLOCK: 测试未通过' && exit 1); fi"
# }]}

# 2. 子 Agent 并行工作
> "用 /batch 将这 5 个微服务的 API 版本升级任务分别处理"

# 3. 上下文管理：完成后验证
> "检查所有 5 个服务的测试结果，列出失败项"
# 不要仅依赖子 Agent 的摘要报告
```

## 7. 30 条 .NET 开发者专属 Claude Code 进阶技巧
- **来源**: [Mukesh Murugan (codewithmukesh)](https://codewithmukesh.com/blog/claude-code-tips-advanced/) on Blog | 🔥 垂直领域高阅读量
- **摘要**: 专为 .NET 开发者定制的 30 条进阶技巧。最有价值的几条：在 CLAUDE.md 中指定 `dotnet test --filter "Category!=Integration"` 避免每次修改都跑集成测试；用 `.claude/rules/` 按项目层分别配置规则（API 层、领域层、基础设施层各自独立）；创建专门的 skill 来处理 EF Core migration 生成流程；以及一个性能技巧——在 hook 中配置 `dotnet format` 自动格式化，避免 Claude 浪费 token 在代码风格上。这些模式同样适用于 Java/Spring 等分层架构。
- **代码示例**:
```bash
# .NET 特化的 CLAUDE.md 片段
## 命令
- 测试: `dotnet test --filter "Category!=Integration"`
- 格式化: `dotnet format`
- 构建: `dotnet build --no-restore`

## 约定
- EF Core migration 用 `dotnet ef migrations add <Name>`
- API 控制器放在 src/Api/Controllers/
- 领域模型放在 src/Domain/Entities/

# 分层规则文件
# .claude/rules/api.md      → API 层规范
# .claude/rules/domain.md   → 领域层规范
# .claude/rules/infra.md    → 基础设施层规范
```
