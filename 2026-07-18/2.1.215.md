## 1. 技能卫生：定期审计已安装的 Skills
- **来源**: [Prajwal Tomar](https://x.com/PrajwalTomar_/status/2074787074641899896) on X | 🔥 高互动热帖
- **摘要**: 把一篇 Claude Code 技巧文章粘贴到会话中，让 Claude 对比你已安装的技能列表，卸载重叠、从未触发或冗余的技能。安装几百个技能只会争抢上下文窗口空间，理想数量是 8-12 个精选技能。把你的 skill 文件夹当作精心维护的 dotfiles 仓库，而不是垃圾抽屉。
- **代码示例**:
```bash
# 将技巧文章内容粘贴后执行
> Read this article end to end. List every skill I currently
  have installed, compare against this list. Uninstall anything
  that overlaps, never triggers, or is redundant.

# 定期审计已安装技能
> /skills list
# 检查每个技能的触发频率，移除长期未使用的
```

## 2. Ultracode 模式：数百个并行 Agent 互相检查
- **来源**: [Greg Isenberg](https://x.com/gregisenberg/status/2060072130339873093) on X | 🔥 百万粉丝高互动帖
- **摘要**: 在 effort 菜单中启用 "ultracode" 或输入 "create a workflow"，可以启动数百个并行 agent 互相校验。这把可委托的工作单元从"单个文件"升级到"整个功能模块"甚至"全代码库重构"。适合大规模迁移、全面审计、跨模块重构等场景。
- **代码示例**:
```bash
# 方法一：在提示词中加入 "ultracode" 关键词
> ultracode: Audit the entire authentication module for
  security vulnerabilities. Check every endpoint, every
  token validation path, every session management flow.

# 方法二：直接要求创建工作流
> Create a workflow to migrate all API endpoints from
  REST to GraphQL. Fan out agents per module, verify
  each independently.
```

## 3. CLAUDE.md 作为"工作合同"模板
- **来源**: [jbarbier](https://github.com/jbarbier/CLAUDE.md) on GitHub | ⭐ 439 stars, 95 forks
- **摘要**: 编码 agent 没有指令时会退化为它见过的所有代码的"平均水平"——而平均水平就是平庸。这个模板把 CLAUDE.md 定位为一份"工作合同"，明确代码质量标准、何时写代码 vs 猜测、完成标准、沟通风格。支持跨工具复用——通过符号链接 `ln -s CLAUDE.md AGENTS.md` 同时适配 Cursor、Codex CLI 和 Gemini CLI。
- **代码示例**:
```markdown
<!-- CLAUDE.md "工作合同"核心结构 -->
## Code Quality Standards
- TypeScript strict mode, no `any` types
- Every public function has a JSDoc one-liner
- No file exceeds 300 lines

## Decision Rules
- If unsure about a design choice, ASK. Don't guess.
- If a test fails, fix the root cause. Never skip tests.

## Completion Criteria
- All tests pass, zero lint warnings
- Changes reviewed via `git diff` before committing
```
```bash
# 跨工具符号链接
ln -s CLAUDE.md AGENTS.md    # Cursor / Codex CLI
ln -s CLAUDE.md .gemini       # Gemini CLI
```

## 4. 83 条最佳实践：上下文窗口纪律与会话复盘
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 63,100 stars, 6,300 forks
- **摘要**: 社区最受欢迎的 Claude Code 资源，核心洞见：(1) 上下文使用率达到约 40% 时 Claude 开始变"笨"，保持会话短小精悍；(2) 每天做两次以上的操作就应该变成技能或命令；(3) 会话结束前做"复盘"——问 Claude "你学到了什么"，然后把输出路由到正确的文件：概念 → CLAUDE.md，实践 → rules，能力 → SKILL.md，架构决策 → ADR。
- **代码示例**:
```bash
# 会话复盘流程
> What did you learn in this session? Categorize into:
  1. Project concepts (-> CLAUDE.md)
  2. Coding practices (-> .claude/rules/)
  3. New abilities (-> SKILL.md)
  4. Architecture decisions (-> docs/adr/)

# 上下文监控
# 当 Claude 开始重复或遗忘时，开新会话
> /compact  # 压缩当前上下文
# 或直接开新会话并引用之前的结论
```

## 5. Hooks + Skills + Actions 完整配置参考
- **来源**: [ChrisWiles](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 6,000 stars, 563 forks
- **摘要**: 一个完整的 Claude Code 配置参考实现，展示了 hooks、skills、agents、commands 和 GitHub Actions 的最佳搭配方式。关键模式包括：(1) 用 `.claude/settings.json` 中的 hooks 实现工具执行前后的自动化；(2) 为测试、GraphQL、React UI、调试和表单处理构建领域特定技能；(3) 设置 GitHub Actions 实现自动 PR 审查、定期质量扫描和依赖审计。还演示了"智能技能评估"模式——hook 根据 prompt 分析自动推荐相关技能。
- **代码示例**:
```jsonc
// .claude/settings.json - Hook 配置示例
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "command": "echo 'Checking file safety...'"
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "command": "npm run lint --fix $FILE 2>/dev/null || true"
      }
    ]
  }
}
```

## 7. 生成 HTML 简报代替 Markdown
- **来源**: [Claude Code Community](https://x.com/claude_code/status/2053049304521265579) on X | 🔥 官方社区账号热帖
- **摘要**: 与其写 100 多行 Markdown 简报，不如让 Claude Code 生成 HTML 网页简报。可以把多个页面串联成幻灯片形式。生成的项目文档和规格说明更具视觉吸引力，更容易消化，特别适合需要向非技术团队成员展示的场景。
- **代码示例**:
```bash
# 生成 HTML 项目简报
> Create an HTML brief for the authentication module redesign.
  Include: architecture diagram (mermaid), API changes table,
  migration timeline, and risk matrix. Make it presentable
  to non-technical stakeholders.

# 多页幻灯片式文档
> Generate a 5-page HTML slide deck summarizing this sprint:
  Page 1: Key metrics and achievements
  Page 2: Architecture changes with diagrams
  Page 3: API breaking changes
  Page 4: Performance benchmarks (before/after)
  Page 5: Next sprint priorities
```

## 8. 从新手到高手的渐进式指南：用 @ 引用文件加载上下文
- **来源**: [zebbern](https://github.com/zebbern/claude-code-guide) on GitHub | ⭐ 4,400 stars, 451 forks
- **摘要**: 一个按进阶级别组织的完整指南，覆盖设置、命令、工作流、agents、skills 和 MCP 集成。社区高频引用的技巧：在 prompt 中用 `@path/to/file.ts` 直接把文件加载到上下文中，而不是依赖 Claude 自己去找。同时记录了一个新兴模式——通过 `npx skills add <name>` 以可安装包的形式分发社区技能，取代原始的 GitHub clone 方式。
- **代码示例**:
```bash
# 用 @ 语法直接加载文件到上下文
> Look at @src/auth/jwt.ts and @src/auth/session.ts,
  find the inconsistency in token expiry handling.

# 安装社区技能包
npx skills add testing-best-practices
npx skills add react-component-generator
npx skills add api-security-audit

# 查看已安装技能
> /skills list
```
