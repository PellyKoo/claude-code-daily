# Claude Code 2.1.150 社区实用技巧 - 2026-05-24

## 1. 用 Subagent 隔离上下文实现"自我 Code Review"
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 54.8k stars
- **摘要**: 利用 Claude Code 的 subagent 架构，让一个 agent 写代码、另一个 agent 在隔离上下文中审查代码。这种"测试时计算分离"策略不依赖模型能力提升，而是通过架构隔离提高整体代码质量——同一个模型在不同上下文中可以发现自己制造的 bug。
- **代码示例**:
```bash
# .claude/agents/ 目录下创建专用审查 agent
# review-agent.md - 隔离上下文，专门负责 code review
# 主 agent 写完代码后自动触发 review agent
```

## 2. 上下文窗口"笨区"管理：保持 < 30% 使用率
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 54.8k stars
- **摘要**: 社区实测发现上下文使用到约 40% 时 Claude 开始进入"笨区"（dumb zone），代码质量显著下降。高效用户会控制上下文在 30% 以下，新任务开新会话，避免上下文腐烂。每一轮对话都是分支点——根据情况选择 Continue、/rewind、/clear、/compact 或 Subagent。
- **代码示例**:
```bash
# 上下文管理决策树：
# 上下文 < 30% → 继续当前会话
# 上下文 30-40% → 使用 /compact 压缩
# 上下文 > 40% → /clear 开新会话或用 subagent 隔离
```

## 3. 垂直切片（Vertical Slice）替代水平分层开发
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 54.8k stars
- **摘要**: 不要让 Claude 按传统分层方式（DB → API → UI）逐层开发，而是用"垂直切片"方式——每次实现一个贯穿所有层的完整功能片段（tracer bullet）。每个阶段配多个测试，用分阶段门控计划推进，确保每步都可验证。
- **代码示例**:
```markdown
<!-- CLAUDE.md 中的规划指令 -->
## 开发流程
- 始终先进入 plan mode 再执行
- 用垂直切片而非水平分层
- 每个 phase 必须包含测试用例
- 用 "prove this works vs. main branch" 验证结果
```

## 4. CLAUDE.md 保持 200 行以内，用 Rules 按需加载
- **来源**: [centminmod](https://github.com/centminmod/my-claude-code-setup) on GitHub | ⭐ 2.4k stars
- **摘要**: CLAUDE.md 应控制在 200 行以内，领域专属规则拆分到 `.claude/rules/*.md`。通过 YAML frontmatter 中的 paths 字段实现按需懒加载——只有当 Claude 操作匹配路径的文件时才注入对应规则，大幅减少 token 消耗。提供三种模板变体（紧凑型 101 行、双记忆 153 行、渐进式 105 行）。
- **代码示例**:
```yaml
# .claude/rules/frontend-rules.md
---
paths:
  - "src/components/**"
  - "src/pages/**"
---
- 使用 React 函数组件 + TypeScript
- 所有组件必须有 props 类型定义
```

## 5. Git Worktree 并行开发：同时跑 10-15 个会话
- **来源**: [Boris Cherny (Claude Code 创作者)](https://mindwiredai.com/2026/03/25/claude-code-creator-workflow-claudemd/) on MindWiredAI
- **摘要**: Boris Cherny 日常同时运行 10-15 个 Claude Code 会话（5 个终端标签、5-10 个 Web 端、外加手机端），每个会话使用独立的 git worktree 避免代码冲突。这是并行开发的核心模式——让 Claude 像团队一样同时处理多个任务。
- **代码示例**:
```bash
# 为每个 Claude 会话创建独立 worktree
git worktree add ../feature-auth feature/auth
git worktree add ../feature-api feature/api
git worktree add ../bugfix-123 fix/issue-123
# 每个终端/Web 会话在对应 worktree 目录下运行 Claude Code
```

## 6. Hooks 实现 100% 确定性行为（对比 CLAUDE.md 的 80%）
- **来源**: [Boris Cherny](https://mindwiredai.com/2026/03/25/claude-code-creator-workflow-claudemd/) on MindWiredAI
- **摘要**: CLAUDE.md 是"建议性"的，Claude 大约只会 80% 的时间遵循。如果某件事必须每次都执行（格式化、lint、安全检查），应该用 Hooks 而非 CLAUDE.md。Hooks 是确定性的——100% 执行率。结合使用：CLAUDE.md 放偏好和指导，Hooks 放强制规则。
- **代码示例**:
```json
// .claude/settings.json
{
  "hooks": {
    "post-tool-use": [{
      "matcher": "Edit|Write",
      "command": "npx prettier --write $CLAUDE_FILE_PATH"
    }],
    "pre-commit": [{
      "command": "npm run lint && npm run typecheck"
    }]
  }
}
```

## 7. Showcase 模板：从 Ticket 到 PR 的全自动工作流
- **来源**: [ChrisWiles](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 5.9k stars
- **摘要**: 这个模板仓库展示了如何通过 MCP Server 集成（JIRA、GitHub、Slack、数据库），实现一条命令从读取 JIRA ticket → 实现功能 → 提交 PR → 更新 ticket 状态的全自动化流程。还包含自动化 GitHub Actions：每周代码质量审查、每月文档同步、每两周依赖审计，月成本仅 $10-$50。
- **代码示例**:
```bash
# 一条命令完成 ticket 到 PR
/implement JIRA-1234
# Claude 自动：读取 ticket → 分析需求 → 实现代码 → 跑测试 → 创建 PR → 更新 ticket 状态
```
