## 1. Opus 5.5 自主工作流 + /fast 模式：同模型 2.5 倍输出速度
- **来源**: [JulianGoldieSEO](https://x.com/JulianGoldieSEO/article/2110468166086463976) on X | 🔥 高互动长文
- **摘要**: Opus 5.5 比上代快 30%，配合 `/fast` 模式可获得约 2.5 倍的文本输出速度，且不降级到更小模型。作者分享了完整的自主工作流：在 CLAUDE.md 中设定"持续推进"规则，让 Claude 自动完成多步骤任务。适合需要大量生成的场景（重构、批量测试编写）。
- **代码示例**:
```markdown
# 在 CLAUDE.md 中添加自主工作流规则
## Autonomous Mode
- 完成一个步骤后自动继续下一个，不要停下来等确认
- 遇到问题先尝试自己解决，实在解决不了再问
- 每完成一个模块，运行测试验证后继续

# 在终端中切换 /fast 模式
/fast    # 开启快速输出（同模型，更快速度）
```

## 3. 动态 Workflow：用 "ultracode" 触发多 Agent 编排
- **来源**: [trq212](https://x.com/trq212/article/2061907337154367865) on X | 🔥 深度技术文章
- **摘要**: Claude Code 支持动态工作流，可以将复杂任务自动拆分给多个 agent 并行执行。触发方式有两种：在提示中包含 "ultracode" 关键词，或直接要求 "use a workflow"。工作流脚本支持 `parallel()`、`pipeline()` 等编排模式，每个 agent 独立运行并返回结果。
- **代码示例**:
```javascript
// 动态 workflow 脚本示例
export const meta = {
  name: 'review-and-test',
  description: 'Review code and write tests in parallel',
  phases: [{ title: 'Review' }, { title: 'Test' }],
}
const files = ['auth.ts', 'api.ts', 'db.ts']
const results = await parallel(
  files.map(f => () =>
    agent(`Review ${f} for bugs and write missing tests`, {
      label: `review:${f}`,
      phase: 'Review',
    })
  )
)
return { results }
```

## 架构决策
- 我们选择 X 而不是 Y，因为 [原因]

## 5. 非程序员的 Claude Code 2026 使用速查表
- **来源**: [Ruben Hassid (@rubenhassid)](https://x.com/rubenhassid/status/2059152552529391850) on X | 🔥 高赞非技术向指南
- **摘要**: 面向非开发者的入门指南。核心建议：使用 Claude 桌面应用中的 "Code" 模式（不是 Chat）；选择 Opus 系列模型而不是 Haiku（质量差异显著）；先把项目文件夹拖进去再开始对话；用自然语言描述需求，不需要写代码命令。降低了 Claude Code 的使用门槛。
- **代码示例**:
```
# 非程序员使用 Claude Code 的步骤
1. 打开 Claude 桌面应用
2. 点击 "Code"（不是 Chat 或 Cowork）
3. 注册免费 GitHub 账号
4. 把项目文件夹拖进 Code 界面
5. 选择 Opus 模型（而非 Haiku）
6. 用自然语言描述你想做什么
```

## 6. 把重复性提示保存为 Slash Commands 和 Skills
- **来源**: [Santiago (@svpino)](https://x.com/svpino/status/2029645889980305777) on X | 🔥 Sonar Summit 演讲精华（18条技巧）
- **摘要**: Santiago 在 Sonar Summit 分享的关键技巧：将常用的提示模板保存为自定义 slash command 或 skill。例如把"代码审查"、"写单元测试"、"重构为函数式风格"等高频操作变成一键触发的命令。同时建议用 `@filename` 或 `@src/dir/` 精确引用文件，避免 Claude 搜索整个项目浪费上下文。
- **代码示例**:
```markdown
# .claude/commands/review.md — 自定义 slash command
Review the changes in $ARGUMENTS for:
1. Logic errors and edge cases
2. Security vulnerabilities
3. Performance issues
Suggest specific fixes with code.

# 使用方式：
/project:review src/auth/login.ts
```

## 8. 从错误中积累 CLAUDE.md — 最小起步原则
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 持续更新的最佳实践仓库
- **摘要**: 不要一开始就写一个巨大的 CLAUDE.md。从空文件开始，每次 Claude 犯错时才添加对应的规则。这样每条规则都有存在的理由，文件保持精简。验证标准：如果删掉某条规则不会导致 Claude 犯错，那这条规则就不该存在。同时推荐定期审查，删除已被 linter/CI 覆盖的规则。
- **代码示例**:
```markdown
# CLAUDE.md 的演进过程
# 第1天：空文件
# 第2天：Claude 用了错误的测试框架
## Testing
- Use vitest, not jest

# 第5天：Claude 没有运行类型检查
## Verification
- Always run `npm run typecheck` before committing

# 第10天：Claude 在 API 路由中忘记了认证中间件
## Security
- All /api/* routes must use authMiddleware()
```
