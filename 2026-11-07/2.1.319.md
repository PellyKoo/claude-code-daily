## 2. Dynamic Workflows / Ultracode：数百个并行代理协同工作
- **来源**: [@gregisenberg](https://x.com/gregisenberg/status/2060072130339873093) on X | 🔥 知名创业者（高互动量）
- **摘要**: Claude Code 的 "dynamic workflows" 功能允许一次任务启动数百个并行代理，它们互相检查对方的工作。通过在 effort 菜单中开启 "ultracode" 或直接说 "create a workflow"，可以把工作单元从单个文件扩展到整个功能模块。特别适合大规模代码审查、跨文件重构等需要全局视野的任务。

```bash

# 方式二：直接请求创建 workflow
创建一个 workflow，并行检查所有控制器的输入验证

# 方式三：通过 effort 菜单开启 ultracode 模式
# Claude 会自动编排并行代理并汇总结果
```

## 3. Trail of Bits 安全导向配置：专业安全团队的 Claude Code 模板
- **来源**: [trailofbits/claude-code-config](https://github.com/trailofbits/claude-code-config) on GitHub | ⭐ 安全公司开源项目
- **摘要**: 知名安全研究公司 Trail of Bits 开源了他们的 Claude Code 配置方案。核心理念：必须始终遵守的规则放 CLAUDE.md，无论 Claude 做什么决定都必须执行的约束放 hooks。他们区分了全局配置（~/.claude/CLAUDE.md）和项目配置，并提供了安全审计、依赖检查等预配置的 hooks 和 rules。
- **代码示例**:
```
# Trail of Bits 的配置分层策略
~/.claude/CLAUDE.md          # 全局默认：代码风格、安全基线
project/CLAUDE.md            # 项目特定：架构、命令、约定
.claude/settings.json        # 权限和 hooks（强制执行）

# 关键原则：
# - CLAUDE.md 里放"规则"（Claude 应该遵守的）
# - hooks 里放"约束"（必须执行的，如安全检查）
# - settings.json 里放权限白名单
```

- **代码示例**:
```bash

/compact    # 压缩当前会话上下文，释放 token 空间

# 恢复上次会话
claude --resume              # 恢复最近一次会话
claude --resume session_id   # 恢复指定会话

# CLAUDE.md 中明确列出可执行命令
# ## Commands
# - Test: `npm test`
# - Lint: `npm run lint`
# - Type check: `npx tsc --noEmit`
# - Single test: `npm test -- --grep "test name"`
```

## 5. 技能审计：对比已安装 Skills 发现冗余和缺失
- **来源**: [@PrajwalTomar_](https://x.com/PrajwalTomar_/status/2074787074641899896) on X | 🔥 热门开发者推文
- **摘要**: 一个巧妙的自我优化方法——把 Claude Code 的完整功能清单粘贴到会话中，让 Claude 对比你当前已安装的 skills，找出重复的、从未触发的、以及缺少的。这相当于对你的 Claude Code 配置做一次"健康检查"，确保没有浪费上下文窗口在无用的 skills 上。
- **代码示例**:
```
# 在 Claude Code 会话中执行：
读取这篇文章的全部内容，然后：
1. 列出我当前已安装的所有 skills
2. 与文章推荐的 skills 列表对比
3. 卸载重叠的、从未触发的、或多余的
4. 安装缺少但有用的
```

## 7. Claude Code 深度速成课：从零到精通的项目配置指南
- **来源**: [YourAKShaw's gist](https://gist.github.com/YourAKShaw/f4a040ff0e0aacf44111a4e5782eb6c6) on GitHub | ⭐ October 2026 Edition（高收藏 Gist）
- **摘要**: 一份全面的 Claude Code 深度教程，重点强调 CLAUDE.md 应控制在 200 行以内，每条规则必须是可验证的（如明确写出具体命令而非"测试你的修改"）。推荐的项目结构包括：快速参考（栈信息、关键命令）、架构概览、编码约定、已知陷阱，以及一个 compact-instructions 区段供上下文压缩时使用。
- **代码示例**:
```markdown
<!-- CLAUDE.md 推荐结构（控制在 200 行内） -->
# Project Name

## Quick Reference
- Stack: Next.js 14, TypeScript, Prisma, PostgreSQL
- Test: `npm test`
- Lint: `npm run lint && npx tsc --noEmit`
- Dev: `npm run dev`

## Architecture
- src/app/ - Next.js App Router pages
- src/lib/ - Shared utilities and database client
- src/components/ - React components (PascalCase)

## Conventions
- All API responses use { data, error, status } shape
- Database queries go through src/lib/db.ts, never direct Prisma calls
- Error messages are user-facing, keep them helpful

## Known Gotchas
- `findUnique` doesn't support `orderBy`, use `findFirst`
- The staging DB has a 5s query timeout, test with `QUERY_TIMEOUT=5000`
```
