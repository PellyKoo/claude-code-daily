## 1. 跨模型协作：让 Codex 为 Opus 编写备选方案
- **来源**: [Vox (@Voxyz_ai)](https://x.com/Voxyz_ai/status/2107153846904451534) on X | 🔥 高互动前沿工作流帖
- **摘要**: 如果你同时有 ChatGPT 和 Claude 的订阅，不要浪费其中任何一个的额度。在进行大规模修改前，让 Codex 在终端中写出一份独立的实现方案，然后在 Claude Code 中用 `codex exec` 执行并对比。相当于引入"第二建筑师"的视角，帮助发现 Opus 可能遗漏的边界情况。社区反馈：特别适合架构决策和复杂重构场景。
- **代码示例**:
```bash
# 先让 Codex 生成方案
codex "分析这个 auth 模块的架构问题，写出重构方案"

# 在 Claude Code 中执行 Codex 的方案进行对比
> codex exec 查看刚才生成的重构方案

# 然后让 Claude 综合两个方案的优点
> "对比 Codex 的方案和你的方案，取两者的长处合并"
```

## 2. 小任务清上下文：/clear 是最被低估的命令
- **来源**: [Julio César Fernández (@jcfmunoz)](https://x.com/jcfmunoz/status/2038288124577562714) on X | 🔥 高赞实践技巧
- **摘要**: 长会话会不断累积旧上下文（文件读取、日志、工具输出），导致 token 消耗增加、响应质量下降。最佳实践是将工作拆成最小的独立任务，每完成一个就执行 `/clear`。作者分享了一个真实案例：Claude 在会话结束时主动提示"新任务？执行 /clear 可节省 412K tokens"。上下文越干净，结果越精准。
- **代码示例**:
```bash
# 推荐工作流：
# 1. 一个明确的任务
> "修复 @src/api/users.ts 中的分页 bug"
# 2. 完成它
# 3. 清除上下文
/clear
# 4. 开始下一个任务
> "给 @src/models/user.ts 添加 email 验证"

# 不推荐：在同一个会话中混合不相关的任务
# 会话越长，上下文噪声越多，响应越差
```

## 5. CLAUDE.md 最佳实践：控制在 200 行以内
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 高星最佳实践仓库
- **摘要**: 社区反复验证的关键原则：CLAUDE.md 文件应控制在 200 行以内。过长的文件会消耗宝贵的上下文窗口，且 Claude 对后面的规则遵循度明显下降。测试方法：对每条规则问"删掉它会导致 Claude 犯错吗？"——如果答案是否，就删掉。Claude 能从代码中推断出的信息不需要写进去。用 `.claude/rules/` 的路径作用域规则替代把所有东西塞进一个文件。
- **代码示例**:
```markdown
# 好的 CLAUDE.md 示例（精简有效）
## 项目概述
TypeScript monorepo，使用 pnpm workspaces

## 关键命令
- 测试: `pnpm test`
- 类型检查: `pnpm typecheck`
- lint: `pnpm lint`

## 重要约定
- 每次修改后运行 `pnpm typecheck`
- API 路由文件放在 src/routes/ 下
- 数据库 migration 用 drizzle-kit

# 不好的 CLAUDE.md：500+ 行，包含大段代码说明、
# 项目历史、已知 bug 列表等 Claude 不需要的信息
```

## 7. 用 Hooks 替代 CLAUDE.md 中的"必须"规则
- **来源**: [dduzgun-security](https://github.com/dduzgun-security/claude-code) on GitHub | ⭐ 安全研究者的配置分享
- **摘要**: 安全研究者的核心发现：CLAUDE.md 中的规则本质上是"建议"——Claude 可能在长会话中遗忘或在上下文压力下忽略。真正需要强制执行的规则应该用 Hooks 实现。PreToolUse hook 在每次工具调用前触发，不受上下文影响。典型用例：阻止 `rm -rf`、强制格式化、禁止直接 push 到 main 分支。结合 `.claude/rules/` 的路径规则，可以实现分层的安全策略。
- **代码示例**:
```json
// settings.json 中的安全 hook 配置
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "command": "echo '$TOOL_INPUT' | grep -qE 'rm -rf|git push.*--force|git checkout.*main' && echo 'BLOCK: 危险命令被拦截' && exit 1 || exit 0"
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Edit",
        "command": "npx prettier --write $FILE_PATH"
      }
    ]
  }
}
```

#  分安全、性能、可读性三个维度"

# export const meta = {

#   phases: [{title: 'Review'}, {title: 'Verify'}]
