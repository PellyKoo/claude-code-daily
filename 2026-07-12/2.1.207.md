## 1. 创始人 Boris 的"极简主义"设置哲学
- **来源**: [Boris Cherny](https://x.com/bcherny/status/2007179832300581177) on X | 🔥 高互动热帖
- **摘要**: Claude Code 创始人 Boris Cherny 公开了自己的开发设置——出乎意料的"原味"。他强调 Claude Code 开箱即用效果就很好，不需要过度定制。最关键的一条建议：给 Claude 提供自我验证能力（测试、浏览器自动化、hooks），这一个习惯就能让输出质量提升 2-3 倍。与其堆砌 skill 和插件，不如确保 Claude 能验证自己的工作。
- **代码示例**:
```markdown
<!-- CLAUDE.md - Boris 风格的极简配置 -->
# 项目说明
Node.js + TypeScript 项目

## 验证手段
- 修改代码后必须运行 `npm test`
- UI 变更用 Playwright 截图对比
- API 变更用 curl 验证端点

## 常用命令
- `npm test` - 运行测试套件
- `npm run lint` - 代码检查
- `npm run build` - 构建项目
```

## 2. Dynamic Workflows + Ultracode：数百个并行代理协同
- **来源**: [Greg Isenberg](https://x.com/gregisenberg/status/2060072130339873093) on X | 🔥 高互动热帖
- **摘要**: Claude Code 推出了 Dynamic Workflows 功能——在提示中输入"create a workflow"或在 effort 菜单中开启"ultracode"模式，即可自动启动数百个并行代理，彼此交叉检查工作成果。这意味着可以一次性交付的工作单元从"一个文件"跃升到"一个完整功能模块"。适合大规模重构、全面测试覆盖、代码审计等场景。
- **代码示例**:
```bash
# 方式一：在提示中触发
claude "创建一个 workflow: 扫描所有 API 端点，
       为每个端点生成测试，
       并行执行所有测试，
       汇总覆盖率报告"

# 方式二：通过 effort 菜单开启 ultracode
# 打开 Claude Code → Effort 菜单 → 选择 Ultracode
# 之后每个任务自动使用多代理编排

# 方式三：在提示中直接使用关键词
claude "ultracode: 重构整个 auth 模块为微服务架构"
```

## 3. Plan 模式优先：先审查意图，再执行修改
- **来源**: [DEV Community](https://dev.to/galian/claude-code-workflow-best-practices-that-ship-code-na) / [Medium](https://medium.com/data-science-collective/effective-claude-code-workflows-in-2026-what-changed-and-what-works-now-c93ebc6f8f50) | 🔥 社区共识实践
- **摘要**: 社区公认的最佳实践：大型任务开始时先进入 plan 模式（只读，不修改代码），确认计划后再执行。关键技巧——不要让 Claude 一口气跑完整个计划，而是说"做第一步，然后停下来给我看"。感觉上更慢，实际上更快，因为你在第一步就能发现错误方向，而不是等到第六步才发现跑偏了。
- **代码示例**:
```bash
# 启动时指定 plan 模式
claude --permission-mode plan

# 会话中手动进入 plan 模式
> /plan

# 分步执行大型任务（推荐）
> 先分析当前架构，制定重构计划，不要执行任何修改
# （审查计划后）
> 执行计划第 1 步，完成后停下来给我看结果
# （确认无误后）
> 继续执行第 2 步
```

## 4. 上下文 60% 规则：主动重置胜过被动压缩
- **来源**: [DEV Community](https://dev.to/galian/claude-code-workflow-best-practices-that-ship-code-na) / [Smart WebTech](https://smart-webtech.com/blog/claude-code-workflows-and-best-practices/) | 🔥 社区共识实践
- **摘要**: 上下文窗口不要超过 60% 容量。到达阈值前，主动将当前进度和计划导出为 markdown 文件，运行 `/clear` 重置会话，再在新会话中加载该文件继续工作。自动 compaction 会丢失细节，手动交接则能精确保留关键信息。这是长时间编码会话中保持质量的关键。
- **代码示例**:
```bash
# 1. 上下文接近 60% 时，导出进度
> 将当前任务进度、已完成步骤、待办事项写入
  .claude/handoff/progress-20260712.md

# 2. 重置会话
/clear

# 3. 新会话中加载进度继续
> 读取 .claude/handoff/progress-20260712.md，
  继续执行待办事项

# 4. 也可以用 /compact 做轻量压缩
/compact "保留数据库迁移的关键决策和当前进度"
```

## 5. awesome-claude-code：49.9k 星的终极资源合集
- **来源**: [hesreallyhim/awesome-claude-code](https://github.com/hesreallyhim/awesome-claude-code) on GitHub | ⭐ 49.9k stars
- **摘要**: GitHub 上最受欢迎的 Claude Code 资源集合，涵盖 skills、agents、插件、开发工具等分类。亮点项目包括：Chrome CDP 扩展（让 Claude 操控真实浏览器）、Librarian MCP（本地 Markdown 知识图谱）、showreel（自动生成带注释的截图和 GIF 文档）、llm-router（本地路由器，自动选择最便宜可用的模型）。该合集特别强调隐私优先设计——大量工具明确标注不会向外部发送数据。
- **代码示例**:
```bash
# 推荐安装的实用工具

# Chrome CDP - 让 Claude 操控你的浏览器
# 用于 UI 测试、页面分析、会话录制回放
claude plugin install chrome-cdp

# Librarian MCP - 本地 Markdown 知识库
# 三字母搜索 + 图分析，完全本地运行
claude mcp add librarian

# llm-router - 智能模型路由
# 自动将请求发送到最便宜的可用模型
claude plugin install llm-router

# showreel - 可视化文档生成
# CSS 选择器定位 → 截图/GIF/MP4
claude plugin install showreel
```
