# 2. 用 hooks 实现自动验证循环
# .claude/settings.json
{
  "hooks": {

      {

## 4. 三个必装 Hooks：防泄密、自动格式化、改动即测试
- **来源**: [MuhammadUsmanGM](https://github.com/MuhammadUsmanGM/claude-code-best-practices) on GitHub | ⭐ 64 stars，含可复现基准测试
- **摘要**: 提供三个即插即用的 hook 脚本，覆盖最常见的自动化需求：`block-secrets` 在提交前拦截凭证泄露；`format-on-write` 在文件修改后自动格式化；`test-on-stop` 在改动完成后自动验证测试。同时还提供了 11 个技术栈专用的 CLAUDE.md 模板（React、Python、Go、Rust、Rails 等），以及成本优化指南——通过模型选择和 prompt cache 控制开销。
- **代码示例**:
```jsonc
// .claude/settings.json - 三个必装 hooks
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Write|Edit",
        "command": "bash .claude/hooks/block-secrets.sh $FILE_PATH",
        "description": "拦截可能包含密钥/凭证的文件修改"
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "command": "npx prettier --write $FILE_PATH",
        "description": "自动格式化被修改的文件"
      }
    ],
    "Stop": [
      {
        "command": "npm test --silent",
        "description": "每次 Claude 停下时自动运行测试"
      }
    ]
  }
}
```

## 7. 小改动大提升：Claude 工作流微调清单
- **来源**: [Taylor Poindexter](https://x.com/engineering_bae/status/2074323810690478198) on X | 🔥 工程师博主推荐，高互动
- **摘要**: 一份经过实战验证的 Claude 工作流微调清单——每个改动都很小，但累积起来能显著提升效率。核心技巧包括：(1) 在 CLAUDE.md 中明确写出"不要做什么"而非只写"要做什么"，负面约束比正面指令更能防止 Claude 偏离轨道；(2) 每次会话开始时花 10 秒确认 Claude 读懂了项目上下文；(3) 用 `git diff` 输出作为 prompt 的一部分让 Claude 精准理解变更范围；(4) 短会话 > 长会话，质量随上下文长度衰减。
- **代码示例**:
```markdown
<!-- CLAUDE.md 中的负面约束示例 -->
## DO NOT
- Do not add comments explaining what the code does
- Do not create new abstraction layers unless explicitly asked
- Do not modify files outside the specified scope
- Do not add error handling for impossible scenarios
- Do not use any CSS framework other than Tailwind

## Session Start Checklist
# 每次新会话的前 10 秒
> Read CLAUDE.md and confirm you understand the project
  structure, tech stack, and coding conventions.
  List any ambiguities.

# 用 git diff 限定变更范围
> Here's what changed: $(git diff --stat HEAD~3)
  Review these changes for bugs and suggest improvements.
```
