# Claude Code 2.1.220 社区实用技巧 - 2026-07-25

## 1. Explore→Plan→Code→Commit 四步工作流
- **来源**: [wesammustafa/Claude-Code-Everything-You-Need-to-Know](https://github.com/wesammustafa/Claude-Code-Everything-You-Need-to-Know) on GitHub | ⭐ 2.4k stars
- **摘要**: 不要直接让 Claude Code 写代码。先用 Explore 让它阅读相关文件和上下文，再用 Plan 让它制定方案，然后 Code 实现，最后 Commit。这种四步法可以有效防止上下文漂移，避免生成与项目架构不一致的代码。
- **代码示例**:
```
# 第一步：探索
阅读 src/auth/ 下所有文件，理解当前认证架构

# 第二步：规划
基于现有架构，制定添加 OAuth2 支持的方案

# 第三步：实现
按照方案实现代码

# 第四步：提交
git add 并提交变更
```

## 2. Effort 级别是行为旋钮，不是 token 预算
- **来源**: [wesammustafa/Claude-Code-Everything-You-Need-to-Know](https://github.com/wesammustafa/Claude-Code-Everything-You-Need-to-Know) on GitHub | ⭐ 2.4k stars
- **摘要**: effort 级别（low → max → ultracode）调节的是思考深度和工具调用意愿，而非简单的 token 消耗。关键洞察：上下文质量往往比更高的 effort 更重要——一份精炼的 CLAUDE.md 或原子级任务描述，常常能让 low effort 达到 max effort 的效果。
- **代码示例**:
```
# 日常简单修改用 low，省钱且快：
/effort low
修复这个 typo

# 复杂重构才用 max：
/effort max
重构整个支付模块，保持向后兼容
```

## 3. 用 /fast 模式加速实时调试
- **来源**: [wesammustafa/Claude-Code-Everything-You-Need-to-Know](https://github.com/wesammustafa/Claude-Code-Everything-You-Need-to-Know) on GitHub | ⭐ 2.4k stars
- **摘要**: `/fast` 切换 Opus 加速模式，速度提升约 2.5 倍，成本翻倍。适合对延迟敏感的场景如实时调试、紧急修复。后台运行的任务不值得开 fast，但前台交互式调试时体验提升明显。
- **代码示例**:
```
# 开启快速模式
/fast

# 进入实时调试
这个 API 返回 500，帮我快速定位原因

# 调试完毕关闭
/fast
```

## 4. Hooks：在工具调用生命周期中植入自动化
- **来源**: [luongnv89/claude-howto](https://github.com/luongnv89/claude-howto) on GitHub | ⭐ 40.6k stars
- **摘要**: Hooks 可以在 Claude Code 的工具调用前后自动执行 shell 命令——比如写文件后自动格式化、提交前自动运行 lint、阻止访问敏感路径。但注意 hooks 以你的用户权限运行，务必审查内容。
- **代码示例**:
```jsonc
// .claude/settings.json
{
  "hooks": {
    "post_tool_use": [
      {
        "tool": "write",
        "pattern": "**/*.py",
        "command": "black $FILE_PATH"
      }
    ],
    "pre_tool_use": [
      {
        "tool": "write",
        "pattern": ".env*",
        "command": "echo 'BLOCKED: .env 文件禁止修改' && exit 1"
      }
    ]
  }
}
```

## 5. Agent Teams 最佳规模：3-5 个队友
- **来源**: [wesammustafa/Claude-Code-Everything-You-Need-to-Know](https://github.com/wesammustafa/Claude-Code-Everything-You-Need-to-Know) on GitHub | ⭐ 2.4k stars
- **摘要**: 每个会话自动形成一个隐式 Agent Team（v2.1.178+）。通过 Agent 工具的 `name` 参数生成队友，在共享任务列表上协作。实测 3-5 个队友是最佳规模——超过这个数量，协调开销会超过并行化收益。
- **代码示例**:
```
# 在 .claude/agents/ 目录下创建专用 agent
# code-reviewer.md - 专注代码审查
# test-engineer.md - 专注测试编写
# doc-writer.md - 专注文档生成

# 使用时自然分配任务，Claude 自动调度
审查 PR #42 的代码质量，同时为新增模块编写测试
```

## 6. CLAUDE.md 控制在 200 行以内，用 rules 做延迟加载
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 63.5k stars
- **摘要**: 过长的 CLAUDE.md 会被模型忽略。将核心规范控制在 200 行以内，把领域专用指令放到 `.claude/rules/*.md` 文件中，通过 frontmatter 的路径匹配实现按需加载。只有当 Claude 操作匹配路径的文件时才会加载对应规则。
- **代码示例**:
```markdown
# .claude/rules/frontend.md
---
path: "src/components/**"
---
- 使用 React Server Components 优先
- 所有组件必须有 TypeScript 类型定义
- 样式使用 Tailwind CSS，禁止 inline style

# .claude/rules/api.md
---
path: "src/api/**"
---
- 所有端点必须有 Zod schema 验证
- 错误响应遵循 RFC 7807 格式
```

## 7. 上下文窗口阈值管理：70% compact，90% clear
- **来源**: [FlorianBruniaux/claude-code-ultimate-guide](https://github.com/FlorianBruniaux/claude-code-ultimate-guide) on GitHub | ⭐ 5.6k stars
- **摘要**: Claude Code 在上下文使用达 70% 时精度开始下降，90% 以上变得不可靠。建议在 70% 时使用 `/compact` 压缩上下文（可加提示词指定保留重点），90% 时果断 `/clear` 开新会话。用自定义 status line 显示上下文使用率可以帮助你直观感知。
- **代码示例**:
```
# 70% 时带提示词 compact
/compact 保留：当前正在实现的 OAuth2 集成方案和已完成的步骤

# 90% 时果断清空
/clear

# 新会话中快速恢复上下文
读取 handoff.md，继续之前的 OAuth2 集成工作
```

## 8. MCP 安全审查：警惕恶意 Skills 和未审计的 MCP Server
- **来源**: [FlorianBruniaux/claude-code-ultimate-guide](https://github.com/FlorianBruniaux/claude-code-ultimate-guide) on GitHub | ⭐ 5.6k stars
- **摘要**: 社区已追踪到 28 个 CVE 漏洞和 655 个恶意 skill。永远不要安装来源不明的 MCP server 或 skill。建议：只使用有源码可审查的 MCP server，安装前检查 GitHub star 数和 issue 列表，对权限要求过高的 skill 保持警惕。
- **代码示例**:
```
# 安装前先审查
# 1. 检查仓库活跃度和 star 数
# 2. 阅读 README 和 issue 列表
# 3. 审查权限要求

# 在 CLAUDE.md 中添加安全策略
## MCP 安全策略
- 禁止安装未在团队白名单中的 MCP server
- 所有 MCP server 必须锁定版本号
- 每月审查已安装的 skills 和 MCP servers
```
