## 1. Vox：用 Codex 给 Opus 5.5 写"第二意见"计划
- **来源**: [Vox (@Voxyz_ai)](https://x.com/Voxyz_ai/status/2107153846904451534) on X | 🔥 高互动跨模型协作技巧
- **摘要**: 当 Opus 5.5 作为主编排器时，不要让 ChatGPT 配额闲置。在执行大型变更前，先让 Codex 独立撰写一份实施计划，然后用 Claude Code 终端中的 `codex exec` 直接运行。相当于引入"第二架构师"做独立审查。社区讨论认为这在复杂重构中尤其有价值——两个模型从不同角度思考，最终方案更健壮。
- **代码示例**:
```bash
# 1. 让 Codex 独立写计划
codex exec "分析这个代码库，为 auth 模块重构写一份实施计划"

# 2. 把 Codex 的计划交给 Claude Code 的 Opus 审查
> "读这份计划，指出你不同意的地方，然后合并成最终方案"

# 核心：两个模型独立思考 → 交叉审查 → 合并最优方案
```

- **摘要**: 展示了 Claude Code 的动态工作流功能。设置方法：将模型切换到 Opus 4.8+，effort 设为 "ultracode"，然后在提示词中使用 "workflow" 关键字。Claude 会自动编写编排脚本、生成子 Agent 集群、验证结果并汇报。这本质上是让 Claude 自己设计多 Agent 协作方案，而不是手动编排。

```bash
# 启用动态工作流：
/model opus  # 切换到高能力模型
/effort ultracode

# 在提示词中触发 workflow：
> "use a workflow to review all changed files
   across security, performance, and correctness dimensions"

# Claude 自动：
# 1. 编写编排脚本
# 2. 生成多个审查子 Agent
# 3. 各维度并行审查
# 4. 汇总结果
```

## 6. 社区共识：CLAUDE.md 瘦身原则
- **来源**: [YourAKShaw](https://gist.github.com/YourAKShaw/f4a040ff0e0aacf44111a4e5782eb6c6) on GitHub Gist + [awesome-claude-md](https://github.com/TakatoPhy/awesome-claude-md) | 🔥 多个指南共同强调
- **摘要**: 十月多份社区指南不约而同强调同一原则：CLAUDE.md 必须保持精简。建议控制在 200 行以内，每条规则都问"删掉它会导致错误吗？"——如果不会就删。具体规则优于模糊指令（写 `pnpm test` 而非"测试你的改动"）。安全相关的硬性规则不要只写在 CLAUDE.md 里，应该用 hooks 或 settings deny 规则强制执行，因为 CLAUDE.md 中的规则本质上是建议性的。
- **代码示例**:
```markdown
# CLAUDE.md 精简示例（好）：
## 命令
- 测试: `pnpm test`
- 类型检查: `pnpm typecheck`
- lint: `pnpm lint`

## 规则
- 修改后始终运行 typecheck
- 提交信息用英文，conventional commits 格式
- 不要修改 .env 文件

# 安全规则用 hooks 强制执行（不只是写在 CLAUDE.md）：
# settings.json → hooks → PreToolUse
# pattern: "rm -rf|drop table|truncate"
# action: "block"
```

## 7. AlexandrG539：完整 Claude Code 配置指南（含 Hooks 安全实践）
- **来源**: [AlexandrG539/claude-code-setup-guide](https://github.com/AlexandrG539/claude-code-setup-guide) on GitHub | 🔥 Star 数增长快的实战配置仓库
- **摘要**: 一份覆盖权限、MCP、Hooks、Skills、子 Agent 和团队协作的完整配置指南。最受关注的部分是安全实践：用 PreToolUse hook 拦截危险命令（rm -rf、force push），用 `.claude/rules/` 目录按路径加载特定规则（避免所有规则堆在一个 CLAUDE.md 里），以及用 deny 规则硬性禁止某些操作。指南还强调：单独靠 CLAUDE.md 无法阻止 Claude 读 .env 文件，必须用 hooks 配合。
- **代码示例**:
```jsonc
// .claude/settings.json - PreToolUse hook 示例
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "command": "bash -c 'echo \"$CLAUDE_TOOL_INPUT\" | grep -qE \"rm -rf|--force|--no-verify\" && echo \"BLOCKED: dangerous command\" && exit 1 || exit 0'"
      }
    ]
  }
}
```

## 8. 社区技巧合集：日常提效快捷键与命令
- **来源**: [agentsroom.dev](https://agentsroom.dev/claude-code-tips) + [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | 🔥 综合整理高赞技巧
- **摘要**: 多个社区来源汇总的日常提效小技巧：① `Ctrl+B` 将长时间运行的 bash 命令放到后台，继续其他对话；② `Esc+Esc` 打开检查点回退菜单，可恢复代码和/或对话状态；③ `/simplify` 在改动后自动运行并行 Agent 审查代码质量；④ `Ctrl+S` 暂存当前草稿提示词；⑤ 用 `claude --worktree <name>` 一键创建隔离工作环境和分支。这些小技巧单独不起眼，组合使用效率翻倍。
- **代码示例**:
```bash
# 快捷键速查：
# Ctrl+B  → 后台运行当前 bash 命令
# Esc+Esc → 打开检查点回退菜单
# Ctrl+S  → 暂存草稿提示词
# Shift+Tab → 切换 Plan Mode

# 一键创建隔离工作环境：
claude --worktree feature-auth
# 自动创建 git worktree + 新分支，完全隔离

# 改完代码后审查质量：
/simplify
# 并行 Agent 检查重用性、效率、CLAUDE.md 合规性
```
