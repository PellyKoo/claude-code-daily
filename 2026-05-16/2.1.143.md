# Claude Code 2.1.143 社区实用技巧 - 2026-05-16

## 1. Karpathy 的 CLAUDE.md 四原则：109K Star 的秘密
- **来源**: [Andrej Karpathy's CLAUDE.md](https://github.com/topics/claude-md) on GitHub | ⭐ 109,000+ stars
- **摘要**: Karpathy 的 CLAUDE.md 文件仅 65 行，却拿下 GitHub 历史级 Star 数。核心四原则：Think Before Coding（先想后写）、Simplicity First（简单优先）、Surgical Changes（精准修改）、Goal-Driven Execution（目标驱动）。社区验证这套极简规则比冗长的指令文件效果更好，Claude 的遵循率更高。
- **代码示例**:
```markdown
# CLAUDE.md (Karpathy 风格)

## Principles
- Think before coding: plan your approach before writing code
- Simplicity first: prefer the simplest solution that works
- Surgical changes: make minimal, targeted edits
- Goal-driven execution: stay focused on the task objective

## Rules
- Run tests before and after changes
- Never modify unrelated code
```

## 2. 双代理模式：长任务不丢上下文
- **来源**: [HackerRank](https://x.com/hackerrank/status/2016398850265935929) on X | 🔥 高互动技术推文
- **摘要**: 将长任务拆分为两个代理模式——"初始化代理"负责项目搭建、功能列表、Git 初始化和进度跟踪；"编码代理"负责读取规划、执行编码、运行测试。这种分离避免了单次长会话的上下文丢失问题，每个代理只需关注自己的职责，token 消耗也更可控。
- **代码示例**:
```bash
# 第一阶段：初始化代理
> 作为初始化代理，请完成以下工作：
> 1. 分析需求并创建 TODO.md
> 2. 设置项目结构和 Git
> 3. 在 PLAN.md 中写出每个功能的实现步骤

# 第二阶段：新会话，编码代理
> 阅读 PLAN.md 和 TODO.md，开始实现第一个功能。
> 每完成一个功能就更新 TODO.md 的状态。
```

## 3. 六文档上下文管理法：跨会话记忆不断档
- **来源**: [Cathryn](https://x.com/cathrynlavery/status/1950010270530585042) on X | 🔥 社区广泛转发的工作流
- **摘要**: 在每次会话开始和结束时，让 Claude 自动创建/更新六个文档：CONTEXT.md（项目状态）、PROGRESS.md（已完成工作）、TODO.md（下一步优先级）、DECISIONS.md（架构决策记录）、ISSUES.md（已知问题）、SETUP.md（环境配置）。下次开启新会话时 Claude 自动读取这些文件，无缝衔接之前的工作。
- **代码示例**:
```markdown
# 在 CLAUDE.md 中添加：

## Session Management
- At session start: read all docs in ./claude-docs/
- At session end: update CONTEXT.md, PROGRESS.md, TODO.md
- Log all architectural decisions in DECISIONS.md
- Track known issues in ISSUES.md
```

## 4. 自验证循环：让 Claude 自己检查自己的代码
- **来源**: [Boris Cherny](https://x.com/bcherny/status/2007179832300581177) on X | 🔥 Claude Code 创作者核心建议
- **摘要**: Boris（Claude Code 创作者）反复强调的头号技巧：给 Claude 提供验证自身工作的手段——测试、浏览器自动化、hooks。单靠这一个习惯就能让输出质量提升 2-3 倍。核心思路是构建"写代码→运行验证→修复问题"的自动循环，而不是写完就提交。
- **代码示例**:
```json
// .claude/settings.json - PostToolUse hook 示例
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit",
        "command": "npm run lint --fix $FILE"
      }
    ]
  }
}
```

## 5. Git Worktree 并行开发：多任务同时推进
- **来源**: [Tech with Mak](https://x.com/techNmak/status/2037788648691884207) on X | 🔥 22K+ stars 最佳实践推荐
- **摘要**: 使用 Git Worktree 让多个 Claude Code 实例在不同分支上并行工作，互不干扰。一个实例写前端，另一个写后端，第三个写测试——全部同时进行。比传统的切分支方式快数倍，特别适合需要同时推进多个功能的场景。
- **代码示例**:
```bash
# 创建 worktree 并行开发
git worktree add ../project-feature-auth feature/auth
git worktree add ../project-feature-api feature/api

# 终端1：在 auth worktree 中启动 Claude Code
cd ../project-feature-auth && claude

# 终端2：在 api worktree 中启动另一个 Claude Code
cd ../project-feature-api && claude

# 两个 Claude 实例并行工作，互不冲突
# 完成后合并
git worktree remove ../project-feature-auth
```

## 6. 一句话构建生产级工作流
- **来源**: [Alton Syn](https://x.com/WorkflowWhisper/status/2035713362445934978) on X | 🔥 热门自动化案例
- **摘要**: 用一句话描述需求，让 Claude Code 构建完整的自动化后端。实战案例：12 个生产级工作流全部由 Claude Code 生成——客户入职、欢迎邮件、Slack 通知、合同管理、发票生成等。关键技巧是描述"做什么"而不是"怎么做"，让 Claude 自主选择最佳实现方式。
- **代码示例**:
```bash
# 一句话需求示例
> 当合同签署后，自动发送欢迎邮件给客户，
> 在 Slack #new-clients 频道通知团队，
> 创建 Notion 项目页面，并设置 30 天跟进提醒。

# Claude Code 会自动：
# 1. 选择合适的框架和库
# 2. 实现完整的事件驱动架构
# 3. 添加错误处理和重试逻辑
# 4. 生成测试用例
```
