# Claude Code 2.1.220 社区实用技巧 - 2026-07-24

## 1. 用文章批量审计已安装的 Skills
- **来源**: [Prajwal Tomar](https://x.com/PrajwalTomar_/status/2074787074641899896) on X
- **摘要**: 将技巧文章整篇粘贴进 Claude Code 会话，让它逐条对比你已安装的 skills，自动卸载重复、从未触发、或被内置功能覆盖的 skill，并给出 before/after 的上下文窗口占用对比。这能显著减少 context 浪费。
- **代码示例**:
```
读完这篇文章，列出我当前所有已安装的 skill，
和文章中的列表对比。卸载重叠的、从不触发的、
或已被内置功能替代的 skill。给我 before/after 的上下文占用对比。
```

## 2. 用 HTML 代替 Markdown 做项目简报
- **来源**: [Claude Code Community](https://x.com/claude_code/status/2053049304521265579) on X
- **摘要**: 当需要向团队展示方案或做项目简报时，不要写几百行 markdown，而是让 Claude Code 直接生成 HTML 网页式简报。可以串联多页做成幻灯片形式，配合 beautiful-html-templates 模板效果更佳。
- **代码示例**:
```
把这份需求文档转成一个 HTML 简报网站，
分成 3 页幻灯片：概述、技术方案、时间线。
使用简洁现代的设计风格。
```

## 3. Dynamic Workflows + Ultracode 模式并行验证
- **来源**: [Min Choi](https://x.com/minchoi/status/2060226858994565563) on X | [Greg Isenberg](https://x.com/gregisenberg/status/2060072130339873093) on X
- **摘要**: 在 effort 菜单中开启 "ultracode" 模式，Claude Code 会自动编写编排脚本、生成数百个并行子代理互相校验。适合大规模重构或全仓库审计，能把交付单位从「一个文件」提升到「一整个功能模块」。
- **代码示例**:
```
/model opus 4.8
/effort ultracode
# 然后在 prompt 中使用 "workflow" 关键词
用 workflow 审计整个 src/ 目录的类型安全问题
```

## 4. 用 /rewind 回退而非堆叠修正指令
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 63.5k stars
- **摘要**: 当 Claude 走偏时，不要不断追加修正指令（会污染上下文），而应使用 `/rewind` 回退到出错前的状态重新提示。保持会话上下文利用率在 40% 以下可获得最佳性能。
- **代码示例**:
```
# 发现方向偏了？不要说"不对，改成xxx"
# 而是：
/rewind
# 回退后用更清晰的 prompt 重新开始
```

## 5. Subagent 隔离策略保护主上下文
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 63.5k stars
- **摘要**: 将工具调用密集的任务（如文件搜索、grep、大量读取）分派给 subagent 执行，主会话上下文保持干净。subagent 的工具调用结果不会回灌到主上下文，从而大幅延长有效会话长度。
- **代码示例**:
```
# 在 CLAUDE.md 中配置：
对于涉及超过 5 个文件的搜索任务，
使用 subagent 执行，仅将结论汇报回主会话。
```

## 6. 安装 dx 插件统一日常开发工作流
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 9.4k stars
- **摘要**: dx 插件捆绑了多个实用 skill：`/dx:gha` 自动分析 GitHub Actions 失败原因并修复，`/dx:handoff` 在切换会话时生成完整上下文交接文档。一条命令安装，立即获得一整套标准化开发体验。
- **代码示例**:
```bash
# 安装 dx 插件
/install-plugin dx

# 使用 GitHub Actions 调试
/dx:gha

# 会话交接
/dx:handoff
```

## 7. 自定义 Status Line 实时监控资源消耗
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 9.4k stars
- **摘要**: 通过自定义 status line 脚本，在终端底部实时显示当前模型、git 分支、未提交文件数和 token 使用量的可视化进度条。帮助你直观感知上下文窗口剩余空间，及时 compact 或新开会话。
- **代码示例**:
```jsonc
// ~/.claude/settings.json
{
  "status_line": {
    "script": "echo \"$(git branch --show-current) | files: $(git status -s | wc -l)\""
  }
}
```

## 8. Skill 描述写成触发器而非摘要
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 63.5k stars
- **摘要**: Skill 的 description 字段不应写成功能摘要（如"帮助部署"），而应写成触发条件描述（如"当用户提到 deploy、发布、上线时触发"）。这样模型能更准确地自动匹配和调用对应的 skill。
- **代码示例**:
```markdown
---
description: >
  Use when the user mentions deploy, release, ship,
  publish, or asks about CI/CD pipeline status.
---
# Deploy Skill
...
```
