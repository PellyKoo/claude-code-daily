## 2. CLAUDE.md 长度的"甜蜜区间"：超过 200 行规则就失效
- **来源**: [Builder.io](https://www.builder.io/blog/claude-code-tips-best-practices) on Blog | 🔥 Hacker News & daily.dev 热门
- **摘要**: Builder.io 团队（引用 Claude Code 核心开发者 Boris Cherny 的数据）给出了 CLAUDE.md 长度的精确衰减阈值：60-80 行是最佳范围，超过约 80 行规则开始丢失，超过 200 行大段内容会被整体忽略，超过 500 词的密集规则块遵守率会崩塌。解决方案：用 `@filename` 语法把细节拆到独立文件中按需加载，只在主 CLAUDE.md 里放"一段话项目简介 + 技术栈 + 构建命令 + 关键约定"。
- **代码示例**:
```markdown
# CLAUDE.md — 保持在 60-80 行以内

## 项目简介
一句话描述。

## 技术栈
Next.js 15, TypeScript, Prisma, PostgreSQL

## 命令
- 构建: pnpm build
- 测试: pnpm test
- Lint: pnpm lint

## 约定
- 使用 conventional commits
- 组件放 src/components/，按功能分目录

## 深入文档（按需加载，不占主上下文）
@docs/architecture.md
@docs/api-conventions.md
@docs/testing-guide.md
```

## 3. RTK（Rust Token Killer）：命令输出压缩 60-90%
- **来源**: [Marmelab](https://marmelab.com/blog/2026/04/24/claude-code-tips-i-wish-id-had-from-day-one.html) on Blog | 🔥 社区广泛引用
- **摘要**: Marmelab 团队推荐的一个 CLI 工具——RTK（Rust Token Killer），它在 shell 命令的输出传入 LLM 上下文之前，自动过滤和压缩冗余信息。实测在常见开发命令（npm install、docker build、test runner 输出等）上能节省 60-90% 的 token 消耗。原理是通过压缩代理重写 shell 输出，去掉重复的进度条、冗余的日志行、无用的空白等。对于需要大量运行命令的会话，这意味着你的上下文寿命几乎翻倍。
- **代码示例**:
```bash
# 安装 RTK
cargo install rtk
# 或使用预编译二进制
brew install rtk

# 在 Claude Code 中配置为 shell 输出过滤器
# RTK 会自动压缩以下类型的输出：
# - npm/pnpm install 的进度条和重复行
# - docker build 的层级缓存日志
# - test runner 的冗余堆栈信息
# - CI 日志中的重复模式

# 效果对比（示例）：
# 原始 npm install 输出: ~2000 tokens
# RTK 压缩后: ~300 tokens（节省 85%）
```

## 4. 别自己修 Bug——让 Claude 修并更新文档
- **来源**: [Marmelab](https://marmelab.com/blog/2026/04/24/claude-code-tips-i-wish-id-had-from-day-one.html) on Blog | 🔥 反直觉但高效的实践
- **摘要**: 当 Claude 引入了一个 bug 且未能自己检测到时，不要急着手动修复。正确流程是：(1) 让 Claude 自己调查 bug 原因，(2) 让它更新项目文档（CLAUDE.md 或 rules）记录这类错误的避免方法，(3) 让它修复 bug。虽然 Claude 没有跨会话记忆，但文档是持久的——下次新会话读到这些规则后，同类 bug 不会再出现。这个"教训 → 文档 → 修复"的循环，比你手动修一百个 bug 更有长期价值。
- **代码示例**:
```bash
# ❌ 错误做法：发现 bug 后自己快速修掉
vim src/auth/session.ts  # 手动修复

# ✅ 正确做法：让 Claude 走完"调查 → 记录 → 修复"循环
"这个 session 过期后没有正确清理。
请先调查根因，然后更新 CLAUDE.md 的常见陷阱部分
记录这类问题的预防规则，最后修复 bug。"

# Claude 会在 CLAUDE.md 中添加类似：
# ## 常见陷阱
# - Session 清理必须在 finally 块中执行，
#   不能依赖 try 的正常退出路径
```

## 5. Half-Clone 会话：85% 上下文时自动分叉
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 9.6k stars
- **摘要**: 当会话上下文接近极限时，ykdojo 提供了一个 `half-clone-conversation.sh` 脚本，只保留后半段对话内容来创建新会话，丢弃前半段已经过时的上下文。更进一步，可以通过 hooks 设置在上下文达到 85% 时自动触发分叉。这比 `/compact` 更激进但更有效——compact 压缩所有内容可能丢失关键细节，而 half-clone 完整保留最近的工作上下文。配合 `/branch` 或 `--fork-session` 使用。
- **代码示例**:
```bash
# 使用 dx 插件中的 half-clone 命令
/dx:half-clone

# 或手动执行分叉
# 1. 使用 /branch 创建分叉点
/branch

# 2. 在新会话中只带后半段上下文
claude --fork-session

# 3. 通过 hooks 自动化（85% 上下文触发）
# 在 settings.json 的 hooks 中配置：
# 当 token 使用率 > 85% 时自动提示用户分叉

# 4. 使用 quarter-clone 更激进地精简
/dx:quarter-clone
```

## 6. 手机远程控制 Claude Code 会话
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 9.6k stars
- **摘要**: Claude Code 支持从手机远程控制正在运行的终端会话。用 `/remote-control` 或 `/rc` 连接到当前会话，或用 `claude remote-control --spawn=worktree` 启动一个带独立 worktree 的新远程会话。这意味着你可以在通勤时从手机上继续驱动开发任务——审查 PR、运行测试、指挥重构——而笔记本电脑在家或办公室继续执行。社区称之为"真正的移动开发体验"。
- **代码示例**:
```bash
# 方法 1: 连接到当前终端的 Claude 会话
/remote-control
# 或简写
/rc
# 扫描二维码或访问链接，手机即可控制

# 方法 2: 启动一个新的远程会话（带 worktree 隔离）
claude remote-control --spawn=worktree
# 新会话在独立的 worktree 中运行，不影响主分支

# 使用场景：
# - 通勤时从手机审查 PR 并指挥修改
# - 离开工位后继续监控长时间运行的任务
# - 在会议中快速检查 CI 状态并指挥修复
```

## 7. /batch 批量迁移：一条命令扇出数百个 Agent
- **来源**: [Builder.io](https://www.builder.io/blog/claude-code-tips-best-practices) on Blog | 🔥 大规模重构利器
- **摘要**: `/batch` 是 Claude Code 面向大规模代码迁移的专用命令。它会先"采访"你——了解迁移目标、范围、每个文件的转换规则——然后自动把工作扇出到尽可能多的 worktree agent 中并行执行。可以处理几十、几百甚至更多文件。每个 agent 在独立的 worktree 中工作，互不干扰。社区用它做过：全项目 API v1→v2 迁移、React Class→Hooks 转换、import 路径重构等大规模操作。
- **代码示例**:
```bash
# 启动批量迁移
/batch

# Claude 会问你一系列问题：
# Q: 你想迁移什么？
# A: 把所有 REST API 调用从 axios 迁移到 fetch
# Q: 涉及哪些文件？
# A: src/api/ 下所有 .ts 文件
# Q: 每个文件的转换规则？
# A: 保持错误处理逻辑不变，只替换 HTTP 调用方式

# Claude 会：
# 1. 扫描所有匹配文件
# 2. 为每个文件（或文件组）创建 worktree agent
# 3. 并行执行迁移
# 4. 汇总结果和需要人工检查的边界情况
```

## 8. Ctrl+S 暂存 Prompt：中途插队不丢失
- **来源**: [Builder.io](https://www.builder.io/blog/claude-code-tips-best-practices) on Blog | 🔥 隐藏快捷键
- **摘要**: 一个很多人不知道的快捷键：在输入框中打了一半的 prompt 时，按 Ctrl+S 可以暂存当前草稿，然后你可以先问一个快速问题或执行其他操作。完成后，暂存的 prompt 会自动恢复到输入框。这解决了一个常见痛点——写到一半突然需要查点什么，以前只能 Ctrl+A 复制出去、查完再粘回来。搭配 Ctrl+B（后台运行命令）和 Esc（中断但不丢上下文）使用，形成完整的"多任务切换"体验。
- **代码示例**:
```bash
# 场景：你正在写一个复杂的重构指令...
> "把 src/auth/ 下所有使用旧版 JWT 库的文件迁移到..."
# 突然想确认一下旧库的名字

# 按 Ctrl+S → prompt 被暂存
# 输入框清空，可以问快速问题：
> "grep 一下项目中用了哪些 JWT 相关的 npm 包"
# Claude 回答后...

# 暂存的 prompt 自动恢复到输入框！
> "把 src/auth/ 下所有使用旧版 JWT 库的文件迁移到..."
# 继续补完你的指令

# 其他实用快捷键组合：
# Esc      → 中断 Claude 当前操作（不丢上下文）
# Ctrl+B   → 把当前命令放到后台执行
# Ctrl+G   → 用外部编辑器编辑长 prompt
# Esc+Esc  → 打开 /rewind 检查点恢复菜单
```
