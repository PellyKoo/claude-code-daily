# Claude Code 2.1.310 社区实用技巧 - 2026-10-23

## 1. CLAUDE.md 分层架构：全局、项目、本地三级配置
- **来源**: [abhishekray07/claude-md-templates](https://github.com/abhishekray07/claude-md-templates) on GitHub | ⭐ 高星模板仓库
- **摘要**: 社区推荐的 CLAUDE.md 最佳实践是采用三层架构：全局个人文件（`~/.claude/CLAUDE.md`）放个人偏好和通用规则；项目级文件提交到仓库，包含技术栈、代码风格、测试命令等团队共享规则；本地 `.claude/CLAUDE.local.md`（gitignore）放个人 MCP 配置和本地环境变量。子目录还可以放自己的 CLAUDE.md，Claude 会优先使用最具体的那个。
- **代码示例**:
```
~/.claude/CLAUDE.md          # 全局：个人偏好（编辑器、语言等）
project/CLAUDE.md             # 项目：技术栈、命令、代码规范（提交到 git）
project/.claude/CLAUDE.local.md  # 本地：个人 MCP、环境变量（gitignore）
project/src/api/CLAUDE.md     # 子目录：API 层特定规则
```

## 2. 用 Hooks 替代 CLAUDE.md 中的强制步骤
- **来源**: [r/ClaudeAI 社区讨论](https://www.morphllm.com/claude-code-reddit) on Reddit | 🔥 高赞共识帖
- **摘要**: 社区达成的重要共识：CLAUDE.md 中的指令是"建议"级别的，Claude 可能会忽略。如果某个动作必须每次都执行（比如编辑后自动格式化、提交前跑 lint），应该用 hooks 而不是 CLAUDE.md。Hooks 由系统确定性执行，不依赖模型的"记性"。典型用例包括：保存后自动运行 prettier、提交前检查敏感文件、工具调用后记录日志。
- **代码示例**:
```json
// .claude/settings.json
{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "command": "npx prettier --write $CLAUDE_FILE_PATH"
      }
    ],
    "PreCommit": [
      {
        "command": "npm run lint && npm test"
      }
    ]
  }
}
```

## 3. 回退而非修补：用 /clear 和 Esc+Esc 保持上下文干净
- **来源**: [marmelab 博客](https://marmelab.com/blog/2026/04/24/claude-code-tips-i-wish-id-had-from-day-one.html) | 🔥 开发者社区热文
- **摘要**: 这篇"早知道就好了"的博文在社区引起强烈共鸣。核心观点：当 Claude 给出错误结果时，不要在同一上下文里反复修补——错误回复留在上下文中会污染后续生成。正确做法是按 `Esc+Esc` 打开回退菜单回到上一个好的状态，或者在任务切换时用 `/clear` 清空上下文重新开始。保持上下文干净比试图"纠正" Claude 更高效。
- **代码示例**:
```bash
# 方法一：回退到上一个正确状态
# 按 Esc+Esc 打开回退菜单，选择要回到的节点

# 方法二：任务切换时清除上下文
/clear

# 方法三：恢复之前的会话
claude --resume    # 选择之前的会话继续

# 反面教材：不要这样做
> "不对，你搞错了，应该是..."  # 错误上下文仍在，影响后续输出
```

## 4. 并行会话 + Git Worktree：多任务并行开发
- **来源**: [Matt Van Horn (@mvanhorn)](https://x.com/mvanhorn/article/2035857346602340637) on X | 🔥 October 2026 更新长文
- **摘要**: 高产开发者的核心工作流——同时运行 4-6 个 Claude Code 会话，每个处理不同任务。关键是用 `git worktree` 为每个会话创建独立的工作目录，避免文件冲突。每个会话专注一个范围明确的任务，完成后合并。这比在单个会话中串行处理多个任务效率高得多，因为上下文不会混乱。
- **代码示例**:
```bash
# 创建独立的 worktree 分支
git worktree add ../project-auth feature/auth-refactor
git worktree add ../project-api feature/api-v2
git worktree add ../project-tests feature/add-e2e-tests

# 在不同终端窗口分别启动 Claude Code
cd ../project-auth && claude
cd ../project-api && claude
cd ../project-tests && claude

# 每个会话有独立的文件系统，互不干扰
# 完成后合并并清理
git worktree remove ../project-auth
```

## 5. CLAUDE.md 写法：具体命令胜过模糊描述
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 综合示例仓库
- **摘要**: 社区反复验证的规律：CLAUDE.md 中写 "写好测试" 几乎没用，但写 `npm test -- --testPathPattern=<模块名>` 就能让 Claude 精确执行。好的 CLAUDE.md 应该像给新同事的 onboarding 文档——具体的命令、明确的约束、实际的代码风格示例。一条经验法则：如果删掉某行 Claude 仍然表现一样，那就删掉它。
- **代码示例**:
```markdown
## 测试命令（Claude 可直接执行）
- 单元测试: `npm test -- --testPathPattern=<模块名>`
- 类型检查: `npx tsc --noEmit`
- 单文件 lint: `npx eslint --fix <文件路径>`

## 代码风格（具体而非笼统）
- 错误处理: 用 Result<T, E> 类型，不要 try/catch
- 命名: 布尔变量用 is/has/should 前缀
- 导入: 按 stdlib → 第三方 → 本地 分组排序

## 不要做的事
- 不要修改 migrations/ 目录下的已有文件
- 不要在 PR 中改动 package-lock.json 以外的锁文件
```

## 6. 语音输入 + Claude Code：解放双手的高效工作流
- **来源**: [dictaflow.io 博客](https://dictaflow.io/blog/claude-code-tips-voice-dictation-2026.html) | 🔥 社区广泛转发
- **摘要**: 被称为"没人谈论的第一名 hack"——用语音输入替代打字来给 Claude Code 下指令。语音描述需求天然更详细、更有上下文，而详细的提示正是 Claude 最需要的。常用工具包括 macOS 原生听写、Monologue 和 WhisperFlow。特别适合描述复杂需求、代码审查口述反馈、以及在散步时构思架构。
- **代码示例**:
```bash
# macOS 原生方案：按两下 Fn 键激活听写
# 直接对着麦克风描述需求，文字自动输入到终端

# 使用 Monologue（开源语音转文字工具）
# 安装后设置快捷键，语音自动转为终端输入

# 工作流示例：
# 1. 语音："重构 auth 模块，把 JWT 验证从中间件抽出来
#     做成独立的 service，要支持 token 刷新和黑名单"
# 2. Claude 收到详细的自然语言描述
# 3. 比打字快 3-4 倍，且描述通常更完整
```

## 7. /compact 手动压缩上下文：长会话的续命技巧
- **来源**: [r/ClaudeAI 社区讨论](https://www.morphllm.com/claude-code-reddit) on Reddit | 🔥 高赞实用贴
- **摘要**: 长会话中 Claude 变慢或开始"忘事"是因为上下文窗口快满了。社区发现 `/compact` 命令可以手动触发上下文压缩，保留关键信息同时释放空间。最佳实践是在每完成一个子任务后主动执行一次 `/compact`，而不是等到 Claude 自动压缩（那时可能已经丢失了重要细节）。配合 `/compact <自定义摘要提示>` 还能指定保留哪些信息。
- **代码示例**:
```bash
# 基本用法：手动压缩当前上下文
/compact

# 高级用法：指定压缩时保留的重点
/compact "保留所有关于数据库 schema 变更的讨论和已做的决定"

# 推荐工作流：
# 1. 完成子任务 A → /compact
# 2. 完成子任务 B → /compact
# 3. 每次压缩后上下文更精炼，Claude 响应更准确

# 搭配 --resume 使用
claude --resume    # 恢复之前的会话，已压缩的上下文仍有效
```

## 8. 按模型能力分配任务：省钱又高效的模型切换策略
- **来源**: [f22labs 博客](https://www.f22labs.com/blogs/10-claude-code-productivity-tips-for-every-developer/) | 🔥 开发者社区热门指南
- **摘要**: 不是所有任务都需要最强模型。社区总结的模型分配策略：Haiku 处理简单重命名、格式化、生成样板代码；Sonnet 处理日常功能开发、bug 修复、代码审查；Opus 专门用于复杂架构设计、跨模块重构、安全审计。用 `/model` 命令随时切换，或用 `--advisor` 参数让 Sonnet 自动在关键时刻咨询 Opus。这样月度费用可以降低 60-70%。
- **代码示例**:
```bash
# 在会话中随时切换模型
/model haiku     # 简单任务：重命名变量、格式化代码
/model sonnet    # 日常任务：实现功能、修复 bug
/model opus      # 复杂任务：架构设计、安全审计

# 混合模式：Sonnet 主力 + Opus 顾问
claude --model sonnet --advisor opus

# 任务-模型匹配示例：
# "把这个文件里的 var 改成 const"    → Haiku
# "给这个 API 加分页功能"            → Sonnet
# "重新设计整个认证架构"             → Opus
```
