## 1. Skill 审计法：用文章反查已安装 Skill 的冗余与遗漏
- **来源**: [Prajwal Tomar](https://x.com/PrajwalTomar_/status/2074787074641899896) on X | 🔥 高互动热推
- **摘要**: 社区开发者分享了一个巧妙的 Skill 管理技巧：将任何 Claude Code 技巧文章直接粘贴到会话中，然后让 Claude 列出当前已安装的所有 Skill，与文章内容逐一对比，卸载重叠的、从未触发过的、或已过时的 Skill。这种"审计式"清理方法能显著减少 Skill 膨胀导致的注意力预算浪费。
- **代码示例**:
```
# 将技巧文章粘贴到 Claude Code 会话后输入：
"Read this article end to end. Then list every skill I currently
have installed, and compare it against this list. Uninstall anything
that overlaps, never triggers, or is outdated."
```

## 2. Workflows 非技术场景实践：不只是写代码
- **来源**: [Thariq](https://x.com/trq212/status/2061907538741006796) on X | 🔥 高互动讨论
- **摘要**: 社区深度用户指出 Workflows 不仅适用于代码编排，还能用于非技术任务——如批量研究、文档审计、多角度竞品分析等。关键发现：Workflow 的确定性控制流（循环、条件判断、fan-out）让 Claude 在处理大规模、多步骤的调研和内容生成任务时不会遗漏步骤或重复工作，比单纯对话式提示可靠得多。
- **代码示例**:
```
# 非代码场景的 Workflow 示例
ultracode 请对以下 10 个竞品进行全面分析：
1. 每个竞品派一个 Agent 独立调研（定价、功能、用户评价）
2. 汇总所有调研结果后去重
3. 生成对比矩阵和推荐建议

# Claude 会自动创建 Workflow 编排 10+ 个并行 Agent
```

## 3. claude-code-showcase：全栈配置参考模板
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 6k stars, 565 forks
- **摘要**: 这个仓库提供了目前社区最完整的 Claude Code 项目配置参考，涵盖 Hooks（PreToolUse 拦截主分支编辑、PostToolUse 自动格式化和测试）、Skills（测试方法论、React 模式、GraphQL 设计）、Agents（专用 Code Reviewer 和 GitHub Workflow Agent）、以及 Slash Commands（/onboard、/ticket、/pr-review 等）。特别值得关注的是其 UserPromptSubmit Hook——能根据用户提示词内容智能推荐相关 Skill。
- **代码示例**:
```json
// .claude/settings.json - Hook 配置示例
{
  "hooks": {
    "PreToolUse": [{
      "matcher": "Edit|Write",
      "command": "bash -c 'if git branch --show-current | grep -q main; then echo \"blocked: do not edit on main\"; exit 1; fi'"
    }],
    "PostToolUse": [{
      "matcher": "Edit|Write",
      "command": "npx prettier --write $CLAUDE_FILE_PATH && npx eslint --fix $CLAUDE_FILE_PATH"
    }]
  }
}
```

## 4. CLAUDE.md 注意力预算：80 行是天花板，60 行是最佳
- **来源**: [abhishekray07/claude-md-templates](https://github.com/abhishekray07/claude-md-templates) on GitHub | ⭐ 315 stars
- **摘要**: 社区研究发现一个被大多数人忽视的关键限制：Claude Code 的系统提示词本身已包含约 50 条指令，而前沿模型能可靠遵循的指令上限约为 150-200 条。这意味着你的 CLAUDE.md 实际可用的"注意力预算"远比想象的少。超过 80 行后，Claude 会开始选择性忽略部分指令。HumanLayer 团队将其控制在 60 行以内作为标杆。
- **代码示例**:
```markdown
<!-- CLAUDE.md 精简原则 -->
<!-- ❌ 不要放的内容 -->
- 人格设定（浪费 token）
- 完整文档（用链接代替）
- 格式化规则（用 linter 代替）
- 跨层级重复的规则

<!-- ✅ 应该放的内容 -->
- 项目架构一句话描述
- 包管理器和测试框架
- 关键编码约定（仅非标准的）
- 常见错误和 gotchas
```

## 5. 自我改进循环：让 CLAUDE.md 自动进化
- **来源**: [abhishekray07/claude-md-templates](https://github.com/abhishekray07/claude-md-templates) on GitHub | ⭐ 315 stars
- **摘要**: 社区推崇的一个强大工作模式：每次纠正 Claude 的错误后，在指令末尾加上"Update CLAUDE.md so you don't make that mistake again"。这会让 Claude 将纠正内容持久化到项目配置中，形成一个自我迭代的规则集。随着时间推移，CLAUDE.md 会积累团队的真实编码偏好和项目特有的陷阱，变成一份"活的"项目知识库。
- **代码示例**:
```
# 纠正后触发自我改进
"这里应该用 zustand 而不是 Redux，请修复。
然后更新 CLAUDE.md，确保以后不再犯这个错误。"

# Claude 会自动在 CLAUDE.md 中添加类似：
# ## State Management
# - Use zustand for all state management, NOT Redux
# - Store definitions go in src/stores/
```

## 6. 10 个 Slash 命令速查：像 Power User 一样使用 Claude Code
- **来源**: [Avi Chawla](https://x.com/_avichawla/status/2043086745231892982) on X | 🔥 高互动图文
- **摘要**: 开发者 Avi Chawla 整理了 10 个最实用的 Slash 命令及其完整用法。社区反馈最高的几个：`/init` 生成项目 CLAUDE.md（一次配置终身受益）、`/compact` 压缩上下文但保留关键信息、`/memory` 保存跨项目的个人偏好、`/review` 对当前 diff 进行代码审查、`/loop` 设置定时任务循环执行。这些命令的组合使用能将日常开发效率提升数倍。
- **代码示例**:
```bash
# 高频 Slash 命令组合
/init              # 首次使用：生成 CLAUDE.md
/memory            # 保存个人偏好（跨项目持久化）
/compact           # 上下文过大时压缩
/review            # 对当前 git diff 做代码审查
/loop 5m /review   # 每 5 分钟自动审查一次（CI 监控）
Shift+Tab          # 切换 Plan/Act 模式
```

## 7. 多 Claude 账号快速切换：个人与工作实例分离
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 9.6k stars, 762 forks
- **摘要**: 这个 9.6K star 的技巧合集新增了一个实用技巧：通过环境变量和 macOS Keychain 管理多个 Claude 账号，实现个人账号和工作账号的快速切换。这对于需要在不同组织、不同权限模式下工作的开发者特别有用，避免了反复登录登出的麻烦。
- **代码示例**:
```bash
# 在 .zshrc 中配置账号切换别名
alias claude-personal='CLAUDE_ACCOUNT=personal claude'
alias claude-work='CLAUDE_ACCOUNT=work claude'

# 或使用环境变量切换
export CLAUDE_CONFIG_DIR=~/.claude-work
claude  # 使用工作账号配置启动
```

## 8. 模块级 CLAUDE.md：子目录分层扩展项目知识
- **来源**: [abhishekray07/claude-md-templates](https://github.com/abhishekray07/claude-md-templates) on GitHub | ⭐ 315 stars
- **摘要**: 当根目录 CLAUDE.md 接近 80 行上限时，社区推荐的扩展方案：在子目录中放置模块专属的 CLAUDE.md 文件。Claude Code 会根据当前工作的文件路径自动加载对应目录的 CLAUDE.md，实现"按需加载"的知识分层。例如 `src/auth/CLAUDE.md` 只在编辑认证相关代码时生效，不会占用其他模块的注意力预算。
- **代码示例**:
```
# 推荐的 CLAUDE.md 分层结构
~/.claude/CLAUDE.md          # 全局：个人偏好（vim 键位、语言等）
./CLAUDE.md                  # 项目级：架构、约定、包管理器
./CLAUDE.local.md            # 本地覆盖：gitignore，个人调试偏好
./src/auth/CLAUDE.md         # 模块级：认证相关的特殊规则
./src/api/CLAUDE.md          # 模块级：API 设计约定
./.claude/rules/*.md         # 规则文件：自动加载，适合大项目
```
