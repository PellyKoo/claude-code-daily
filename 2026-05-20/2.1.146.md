# Claude Code 2.1.146 社区实用技巧 - 2026-05-20

## 1. 上下文腐烂监控——40% 是质量悬崖
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 54.2k stars
- **摘要**: 社区实测发现，当上下文窗口使用超过 40% 时，Claude 的输出质量开始明显下降（"context rot"）。最佳实践是将每次会话的上下文使用率控制在 30-40% 以内，一旦接近阈值就开启新会话，而不是在同一会话中硬撑。配合 `/compact` 可以延长有效工作时间。
- **代码示例**:
```
# 会话中观察到以下信号时，立即开新会话：
# 1. Claude 开始重复之前的错误
# 2. 输出变得泛泛而谈，缺少具体细节
# 3. 忘记之前讨论过的约束条件

# 推荐节奏：每完成一个独立功能模块就开新会话
# 新会话 = 新任务，保持上下文干净
```

## 2. `/rewind` 回退术——失败尝试不污染上下文
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 54.2k stars
- **摘要**: 当 Claude 的某次尝试走错方向时，不要在原有对话中纠正（纠正本身也会消耗上下文），而是使用 `/rewind` 回退到出错之前的节点重新开始。这样失败的尝试不会留在上下文中干扰后续推理，保持上下文的"信噪比"。
- **代码示例**:
```bash
# 场景：Claude 用了错误的方案重构了代码
# 错误做法：在对话中说"不对，撤销刚才的修改，换个方案"
# 正确做法：
/rewind
# 回退到出错前的节点，然后给出更明确的指令：
"用策略模式而不是继承来重构这段代码，保持现有接口不变"
```

## 3. 垂直切片规划法——先通后精
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 54.2k stars
- **摘要**: 将需求拆分为垂直切片（tracer bullet），每个切片贯穿所有层（UI → API → DB），而不是按水平分层实现。这样每完成一个切片就有端到端可运行的功能，能尽早获得反馈。社区建议"快速构建 20-30 个版本，而不是写详细规格文档"——因为 Claude Code 让构建成本极低。
- **代码示例**:
```
# 错误：水平分层（先做完所有 DB，再做所有 API，最后 UI）
第一周：设计所有数据库表
第二周：实现所有 API 端点
第三周：构建所有前端页面

# 正确：垂直切片（每次贯穿全栈）
切片1：用户注册（注册表单 → /api/register → users 表）
切片2：用户登录（登录页面 → /api/login → JWT 认证）
切片3：用户资料（资料页面 → /api/profile → 查询/更新）
# 每个切片完成后都可以独立测试和演示
```

## 4. PreToolUse Hook 防护——禁止在主分支上编辑
- **来源**: [ChrisWiles](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 5.9k stars
- **摘要**: 利用 PreToolUse Hook 在 Claude 执行编辑操作前自动检查当前 Git 分支，如果是 main/master 分支则直接拦截并返回错误信息。这是比 CLAUDE.md 中写"不要修改主分支"更可靠的方式——Hook 是确定性执行的，不会被 Claude 忽略。
- **代码示例**:
```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Edit|Write",
        "hooks": [{
          "type": "command",
          "command": "bash -c 'branch=$(git rev-parse --abbrev-ref HEAD); if [ \"$branch\" = \"main\" ] || [ \"$branch\" = \"master\" ]; then echo \"BLOCKED: 请先创建功能分支再编辑代码\" >&2; exit 1; fi'"
        }]
      }
    ]
  }
}
```

## 5. 规则文件按需加载——CLAUDE.md 瘦身到 200 行以内
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 54.2k stars
- **摘要**: CLAUDE.md 超过 80 行后 Claude 就开始忽略部分内容。解决方案：CLAUDE.md 只保留全局通用规则（200 行以内），将领域特定知识拆分到 `.claude/rules/*.md` 文件中，并使用 YAML frontmatter 声明触发条件，让 Claude 按需加载而非一次性全部读取。
- **代码示例**:
```markdown
# .claude/rules/react-patterns.md
---
description: React 组件开发规范
globs: ["src/components/**/*.tsx", "src/hooks/**/*.ts"]
---

- 使用函数组件 + Hooks，禁止 class 组件
- 自定义 Hook 必须以 use 开头
- 组件 Props 必须定义 TypeScript 接口
```

## 6. Subagent 隔离——中间过程不污染主上下文
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 54.2k stars
- **摘要**: 在 Skill 中使用 `context: fork` 启动子代理，让搜索、分析等中间工作在隔离的上下文中运行。主上下文只接收子代理的最终报告，不会被大量中间工具调用和搜索结果撑满，有效延长主会话的可用寿命。
- **代码示例**:
```yaml
# .claude/skills/deep-research.md
---
description: 深度代码调研（不污染主上下文）
context: fork
---

搜索整个代码库中与当前问题相关的所有实现，
分析依赖关系和调用链，最终只返回：
1. 关键文件列表（路径 + 行号）
2. 推荐的修改方案
3. 潜在的风险点
```

## 7. MCP Server 串联——从工单到代码一条龙
- **来源**: [ChrisWiles](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 5.9k stars
- **摘要**: 通过 MCP Server 配置将 JIRA/Linear、GitHub、Slack 等外部工具连接到 Claude Code，实现"读取工单 → 实现功能 → 提交 PR → 更新工单状态"的全自动化工作流。环境变量支持凭证注入，无需硬编码密钥。
- **代码示例**:
```json
{
  "mcpServers": {
    "jira": {
      "command": "npx",
      "args": ["@anthropic/mcp-jira"],
      "env": {
        "JIRA_URL": "${JIRA_URL}",
        "JIRA_TOKEN": "${JIRA_TOKEN}"
      }
    },
    "github": {
      "command": "npx",
      "args": ["@anthropic/mcp-github"],
      "env": {
        "GITHUB_TOKEN": "${GITHUB_TOKEN}"
      }
    }
  }
}
```

## 8. Skill 智能触发——Prompt 关键词自动匹配技能
- **来源**: [ChrisWiles](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 5.9k stars
- **摘要**: 在用户提交 Prompt 时通过 Hook 自动分析输入内容，检测关键词、文件路径和意图模式，然后自动建议或加载相关的 Skill。每个建议带有置信度评分，按相关性排序，实现"说什么就自动知道用什么工具"的智能体验。
- **代码示例**:
```json
{
  "hooks": {
    "UserPromptSubmit": [
      {
        "hooks": [{
          "type": "command",
          "command": "python3 .claude/scripts/skill-evaluator.py"
        }]
      }
    ]
  }
}
```
```python
# .claude/scripts/skill-evaluator.py 核心逻辑
import json, sys

SKILL_TRIGGERS = {
    "react-patterns": ["component", "hook", "jsx", "tsx"],
    "api-design": ["endpoint", "REST", "GraphQL", "API"],
    "testing": ["test", "spec", "coverage", "mock"]
}

prompt = json.loads(sys.stdin.read()).get("prompt", "")
matches = []
for skill, keywords in SKILL_TRIGGERS.items():
    score = sum(1 for k in keywords if k.lower() in prompt.lower())
    if score > 0:
        matches.append({"skill": skill, "confidence": score / len(keywords)})

matches.sort(key=lambda x: x["confidence"], reverse=True)
```
