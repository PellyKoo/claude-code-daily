# Claude Code 2.1.302 社区实用技巧 - 2026-10-16

## 1. 小任务 + /clear：保持上下文清洁
- **来源**: [Julio César Fernández (@jcfmunoz)](https://x.com/jcfmunoz/status/2038288124577562714) on X | 🔥 高互动长文帖
- **摘要**: 将工作拆分为最小的独立任务。长会话会拖着旧上下文（文件读取、日志、工具输出），导致 token 消耗增加、响应质量下降。建议流程：一个明确任务 → 完成 → `/clear` → 开始下一个。作者最后一次会话结束时 Claude 自己提示"新任务？/clear 可节省 412K tokens"。
- **代码示例**:
```
# 推荐工作流
1. 明确一个任务
2. 完成它
3. /clear
4. 开始下一个任务
```

## 2. Plan Mode：复杂任务先规划再动手
- **来源**: [Matt Van Horn (@mvanhorn)](https://x.com/mvanhorn/article/2035857346602340637) on X | 🔥 热门长文（Every Claude Code Hack I Know）
- **摘要**: 对非平凡任务，先进入 Plan Mode（按两次 Shift+Tab）。Claude 会进入只读思考模式，生成计划但不修改文件，等你审批后再执行。这样可以避免 Claude 一上来就改代码导致方向跑偏。
- **代码示例**:
```
# 按 Shift+Tab 两次进入 Plan Mode
# Claude 会输出计划但不会编辑任何文件
# 审批后再执行
```

## 3. Git Worktree 并行会话：多任务不冲突
- **来源**: [Prajwal Tomar (@PrajwalTomar_)](https://x.com/PrajwalTomar_/article/2063238968125333581) on X | 🔥 热门长文（Full Playbook）
- **摘要**: 使用 `claude --worktree feature-name` 为每个任务创建隔离的工作副本和新分支。可以同时运行 3-5 个 Claude 会话，各自在不同 worktree 上工作互不干扰。建议新手从 2 个并行会话开始。
- **代码示例**:
```bash
# 创建隔离 worktree 并启动新会话
claude --worktree feature-auth
claude --worktree feature-dashboard
# 每个会话在独立分支上工作，互不影响
```

## 4. 让 Claude 自动更新 CLAUDE.md：错误纠正的复利效应
- **来源**: [Prajwal Tomar (@PrajwalTomar_)](https://x.com/PrajwalTomar_/status/2074787074641899896) on X | 🔥 高互动推文
- **摘要**: 每次纠正 Claude 的错误后，让它把教训写入 CLAUDE.md。这样错误不会重复出现，形成复利效应。也可以在 PR review 中 @claude 让它自动把反馈加入规则。但注意：CLAUDE.md 是建议性的（约 80% 遵守率），关键规则应该用 hooks 强制执行。
- **代码示例**:
```
# 纠正后告诉 Claude：
"把这条规则加到 CLAUDE.md 里，以后不要再犯同样的错误"

# 关键规则用 hook 强制（100% 执行率）：
# .claude/settings.json 中配置 hooks
```

## 5. Dynamic Workflows：用 ultracode 启动多智能体编排
- **来源**: [Min Choi (@minchoi)](https://x.com/minchoi/status/2060226858994565563) on X | 🔥 高互动推文
- **摘要**: 将 `/model` 设为 opus，`/effort` 设为 ultracode，然后在 prompt 中使用 "workflow" 关键词。Claude 会编写编排脚本，启动并行子智能体集群，交叉验证结果后汇报。注意：这个功能非常消耗 token。
- **代码示例**:
```
# 1. 设置模型和努力级别
/model opus
# 2. 在提示中包含 "workflow"
"create a workflow to review all changed files for bugs and performance"
# Claude 会自动生成编排脚本并启动多个并行 agent
```

## 6. CLAUDE.md 保持精简：超过 80-200 行会被忽略
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 社区最佳实践仓库
- **摘要**: 社区经验表明 CLAUDE.md 超过一定行数后 Claude 会开始忽略部分内容。建议每个文件控制在 200 行以内，大型项目拆分为子目录的 CLAUDE.md 或使用 `.claude/rules/` 目录。用 `paths:` frontmatter 让规则只在触及相关文件时加载，减少上下文噪音。
- **代码示例**:
```markdown
# .claude/rules/frontend.md
---
paths:
  - "src/components/**"
  - "src/pages/**"
---
- 使用 TypeScript strict mode
- 组件命名用 PascalCase
```
