## 2. 完整项目配置展示：hooks + skills + agents + GitHub Actions
- **来源**: [ChrisWiles/claude-code-showcase](https://github.com/ChrisWiles/claude-code-showcase) on GitHub | ⭐ 热门配置示例仓库
- **摘要**: 这是目前社区最完整的 Claude Code 项目配置参考仓库。包含 `.claude/settings.json` 全套 hooks 配置、自定义 skills、agent 定义、以及与 GitHub Actions 的集成工作流。特别展示了如何用 `PreToolUse` / `PostToolUse` hooks 替代 CLAUDE.md 中不可靠的"软规则"，实现格式化和 lint 的 100% 确定性执行。
- **代码示例**:
```json
// .claude/settings.json 完整结构示例
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "Bash",
        "command": "echo 'Checking command safety...'"
      }
    ],
    "PostToolUse": [
      {
        "matcher": "Edit|Write",
        "command": "npx prettier --write $CLAUDE_FILE_PATH"
      }
    ]
  },
  "permissions": {
    "allow": ["Bash(npm test)", "Bash(npm run lint)"]
  }
}
```

## 4. .claude/rules/ 路径作用域规则：按需加载上下文
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 持续更新的最佳实践仓库
- **摘要**: 进阶技巧——使用 `.claude/rules/` 目录下的 Markdown 文件配合 YAML `paths:` 前置元数据，实现规则按文件路径懒加载。比如前端规则只在修改 `src/components/` 时加载，数据库规则只在碰 migration 文件时触发。这大幅减少了无关上下文的注入，提升了 Claude 对相关规则的遵循度。
- **代码示例**:
```yaml
# .claude/rules/database.md
---
paths:
  - "prisma/**"
  - "src/db/**"
  - "migrations/**"
---
- 所有数据库变更必须创建 migration 文件
- 索引变更需要在 CLAUDE.md 中记录性能影响
- 使用事务包裹多表操作
- 测试: `npx prisma migrate dev --name test`
```

## 5. Compact Instructions：控制压缩后保留的关键信息
- **来源**: [Claude Code Tips Gist by serpro69](https://gist.github.com/serpro69/48b20129d14072b730c60670c0bb1c75) on GitHub | 🔥 社区精选技巧 Gist
- **摘要**: 在 CLAUDE.md 中添加专门的 "Compact Instructions" 区段，告诉 Claude 在执行 `/compact` 压缩时必须保留哪些信息。这解决了长会话中 Claude "遗忘"关键约束的痛点。配合在上下文约 60% 时主动执行 `/compact "聚焦指令"` 的策略，可以有效维持整个会话的指令一致性。
- **代码示例**:
```markdown
# 在 CLAUDE.md 末尾添加
## Compact Instructions
当执行 /compact 时，必须保留以下信息：
- 当前任务目标和已完成的步骤
- 所有修改过的文件路径
- 关键的架构决策和原因
- 未完成的 TODO 项
```

## 6. 深度解读 CLAUDE.md：October 2026 Crash Course
- **来源**: [YourAKShaw Gist - Claude Code Deep-Dive](https://gist.github.com/YourAKShaw/f4a040ff0e0aacf44111a4e5782eb6c6) on GitHub | 🔥 October 2026 最新长文
- **摘要**: 这是一份 October 2026 的最新深度指南，覆盖 CLI 配置、仓库设置、高级用法全链路。核心观点：CLAUDE.md 中每条规则都应该是"可检验的"——具体命令优于模糊描述（如 `npm test` 优于"测试你的代码"）。对 settings.json 与 CLAUDE.md 的职责划分做了清晰定义：确定性行为（权限、归属、模型选择）放 settings.json，指导性建议放 CLAUDE.md。
- **代码示例**:
```bash
# settings.json vs CLAUDE.md 职责分离

# settings.json: 确定性配置（必须执行）
# - 权限白名单
# - hooks（格式化、lint）
# - 模型选择
# - 环境变量

# CLAUDE.md: 指导性规则（建议执行）
# - 架构决策
# - 代码风格偏好
# - 工作流建议
# - 项目上下文
```

## 7. 50 条 Claude Code 实战技巧精选
- **来源**: [DZone - 50 Claude Code Tips](https://dzone.com/articles/claude-code-tips-boost-coding-productivity) | 🔥 开发者社区热文
- **摘要**: DZone 上的高阅读量文章，从 50 条技巧中精选的实用建议包括：使用 `!command` 前缀直接在 shell 执行命令节省 token；用 `@filename` 精确引用文件避免 Claude 全局搜索；在 CLAUDE.md 中写"在编码前先描述方案并等待确认"来强制 Claude 先规划再动手；以及使用 `/cost` 命令实时监控 token 消耗避免预算超支。
- **代码示例**:
```bash
# 高频实用操作
!git status              # 用 ! 前缀直接跑 shell，不消耗 AI token
@src/auth/login.ts       # 精确引用文件，避免 Claude 猜测搜索
/cost                    # 查看当前会话 token 消耗
/model                   # 切换模型（如 opus/sonnet）
```
