## 1. 自定义状态栏脚本：实时掌握会话状态
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | 🔥 8.1k stars
- **摘要**: 通过自定义 Bash 脚本打造个性化状态栏，在屏幕底部实时显示当前模型、目录、Git 分支、未提交文件数、Token 用量及可视化进度条。帮助开发者在长会话中随时掌握资源消耗情况，避免上下文溢出。
- **代码示例**:
```bash
# 在 ~/.claude/settings.json 中配置 status line
{
  "statusLine": {
    "command": "echo \"$(git branch --show-current) | files: $(git status -s | wc -l)\""
  }
}
```

## 2. 上下文利用率控制在 30% 以下：保持 Claude 智能水平
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | 🔥 51.6k stars（GitHub Trending #1）
- **摘要**: 经验丰富的开发者建议将上下文利用率控制在 30% 以下（最多不超过 40%），因为上下文窗口填充越多，Claude 的推理质量越低。使用 `/compact` 加提示词主动压缩，而非依赖自动压缩。遇到失败尝试时用 `/rewind` 回退，避免错误信息污染上下文。
- **代码示例**:
```
# 主动压缩上下文，附带重点提示
/compact 保留数据库迁移相关的所有决策和当前进度

# 回退到上一步，而非让失败结果留在上下文中
/rewind
```

## 3. 垂直切片开发：用"示踪子弹"贯穿所有层
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | 🔥 51.6k stars
- **摘要**: 不要按水平分层（先做所有模型、再做所有 API、最后做前端）让 Claude 开发功能，而是采用垂直切片方式——一次贯穿从数据库到前端的完整流程。这样每完成一个切片就能端到端验证，Claude 也能获得即时反馈来修正后续实现。
- **代码示例**:
```markdown
<!-- .claude/commands/vertical-slice.md -->
实现 $FEATURE 功能，按以下垂直切片顺序：
1. 数据库 migration + model
2. API endpoint + 验证逻辑
3. 前端组件 + 路由
4. 端到端测试

每完成一层立即运行测试验证，确认通过后再进入下一层。
```

## 4. 测试驱动开发（TDD）+ Claude Code：先写失败测试再实现
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | 🔥 8.1k stars
- **摘要**: 先手动编写描述期望行为的失败测试并提交到 Git，然后让 Claude Code 编写通过这些测试的实现代码。这种方式为 Claude 提供了明确的"完成标准"，避免了模糊需求导致的反复修改，同时确保代码始终有测试覆盖。
- **代码示例**:
```bash
# 1. 先写失败测试并提交
git add tests/test_auth.py
git commit -m "test: add failing tests for OAuth flow"

# 2. 让 Claude 实现代码使测试通过
# 在 Claude Code 中输入：
# "实现 OAuth 认证流程，确保 tests/test_auth.py 中的所有测试通过"
```

## 5. DX 插件一键集成：GitHub Actions 调试 + 会话交接
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | 🔥 8.1k stars
- **摘要**: 安装 dx（Developer Experience）插件可一次获得多个实用工具：`/dx:gha` 自动分析 CI 失败原因、`/dx:handoff` 生成会话交接文档、`/dx:clone` 分支对话、`/dx:half-clone` 半克隆仓库。特别适合团队协作和 CI/CD 调试场景。
- **代码示例**:
```bash
# 安装 dx 插件
claude plugins install dx

# CI 失败时自动分析
/dx:gha

# 生成交接文档供下一个会话继续
/dx:handoff
```

## 6. 用容器隔离高风险实验任务
- **来源**: [ykdojo/claude-code-tips](https://github.com/ykdojo/claude-code-tips) on GitHub | 🔥 8.1k stars
- **摘要**: 对于高风险操作或长时间运行的实验性任务，在 Docker 容器中运行 Claude Code 并使用 `--dangerously-skip-permissions` 标志，既能跳过权限确认提高效率，又将潜在破坏限制在容器内，不影响主系统。
- **代码示例**:
```bash
# 在容器中运行 Claude Code（隔离环境下可安全跳过权限）
docker run -it \
  -v $(pwd):/workspace \
  -e ANTHROPIC_API_KEY=$ANTHROPIC_API_KEY \
  claude-code --dangerously-skip-permissions \
  "重构整个测试套件并运行全部测试"
```

## 7. 自教学循环：让 Claude 从错误中自动学习
- **来源**: [Boris Cherny](https://mindwiredai.com/2026/03/25/claude-code-creator-workflow-claudemd/) on MindwiredAI/Twitter | 🔥 高热度传播
- **摘要**: Claude Code 创作者 Boris Cherny 的工作流核心：每次 Claude 犯错被纠正后，让它把教训写入 `lessons.md` 文件。下次会话自动读取这些规则，避免重复犯同样的错误。Claude 字面意义上在"教自己"变得更懂你的项目。
- **代码示例**:
```markdown
<!-- lessons.md（由 Claude 自动更新）-->
# 项目经验教训

- 本项目使用 pnpm 而非 npm，所有安装命令用 pnpm
- API 路由文件放在 src/routes/ 而非 src/api/
- 测试文件必须以 .spec.ts 结尾，不用 .test.ts
- 环境变量从 .env.local 读取，不是 .env
```

## 8. CLAUDE.md 保持精简：60-80 行是黄金标准
- **来源**: [shanraisshan/claude-code-best-practice](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | 🔥 51.6k stars
- **摘要**: 社区实测发现 CLAUDE.md 超过 80 行后，Claude 会开始忽略部分指令。HumanLayer 团队将其控制在 60 行以内。每条规则都应经过"删掉它 Claude 会犯错吗？"的检验。冗余的 CLAUDE.md 反而降低指令遵从率。使用层级文件结构（全局 / 项目 / 本地）分散配置。
- **代码示例**:
```
# 三层 CLAUDE.md 配置
~/.claude/CLAUDE.md          # 全局：个人偏好（语言、风格）
.claude/CLAUDE.md            # 项目：团队共享规则（提交到 Git）
./CLAUDE.local.md            # 本地：个人覆盖（加入 .gitignore）
```
