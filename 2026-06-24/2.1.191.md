## 1. Dynamic Workflows + Ultracode：让数百个 Agent 并行协作
- **来源**: [Greg Isenberg](https://x.com/gregisenberg/status/2060072130339873093) on X | 🔥 高互动推文
- **摘要**: Claude Code 新增的 Dynamic Workflows 功能允许你输入"create a workflow"或在 effort 菜单中开启 `ultracode` 模式，系统会自动拆解复杂任务、并行启动数百个子 Agent、彼此交叉验证结果后再汇总输出。Ultracode 不只是提高推理强度——它会自动判断何时需要编排多 Agent 工作流。Jarred Sumner 用此功能在 11 天内将 Bun 运行时从 Zig 移植到 Rust（约 75 万行代码）。注意：该功能 token 消耗远高于普通会话，建议从小任务开始。
- **代码示例**:
```bash
# 方法一：直接告诉 Claude 创建工作流
# 在对话中输入：
"create a workflow to refactor all API endpoints to use the new auth middleware"

# 方法二：开启 ultracode 模式（自动决策是否使用工作流）
# 在 effort 菜单中选择 ultracode
# Claude 会自动拆分任务 → 并行执行 → 交叉验证 → 汇总结果
```

## 2. 并行 Worktree 开发：同时运行 3-5 个 Claude 会话
- **来源**: [Boris Cherny (Claude Code 创始人)](https://x.com/bcherny/status/2017742741636321619) on X | 🔥 高互动推文，[Shruti](https://x.com/heyshrutimishra/status/2018368588432978151) 解读
- **摘要**: Claude Code 团队内部最大的生产力秘诀：利用 git worktree 为每个并行的 Claude 会话创建独立的工作目录。每个 worktree 是一个隔离的 git checkout，多个 Agent 不会互相踩文件。开发完成后合并回主分支即可。在 Dynamic Workflows 中使用 `isolation: 'worktree'` 参数可自动完成这一流程。
- **代码示例**:
```bash
# 手动创建多个 worktree 并行开发
git worktree add ../feature-auth feature/auth
git worktree add ../feature-api feature/api
git worktree add ../bugfix-login bugfix/login

# 在每个 worktree 中启动独立的 Claude 会话
cd ../feature-auth && claude
cd ../feature-api && claude
cd ../bugfix-login && claude

# 开发完毕后合并并清理
git worktree remove ../feature-auth
```

## 3. 关闭 Auto Memory 防止上下文污染
- **来源**: [kunchenguid](https://x.com/kunchenguid/status/2067728608584675465) on X | 🔥 热门讨论
- **摘要**: Claude Code 的自动记忆功能会在会话中自动保存"经验"到 CLAUDE.md，但有时会写入错误或过时的结论，导致后续会话被误导。社区建议关闭该功能，改为手动管理记忆文件，确保只保留经过验证的、真正有用的规则。
- **代码示例**:
```bash
# 方法一：在会话中关闭
/memory
# 然后选择关闭 auto memory

# 方法二：通过环境变量全局关闭
export CLAUDE_CODE_DISABLE_AUTO_MEMORY=1

# 方法三：在 settings.json 中配置
# ~/.claude/settings.json
{
  "autoMemory": false
}

# 推荐做法：手动维护 CLAUDE.md，只写入验证过的规则
```

## 4. CLAUDE.md 黄金法则：先描述方案，等批准后再写代码
- **来源**: [Santiago](https://x.com/svpino/status/2018682144361734368) on X | 🔥 高互动推文
- **摘要**: 在 CLAUDE.md 中添加流程控制规则，让 Claude 在动手写代码之前先描述实现方案并等待你的确认。这避免了 Claude 直接生成大量你不想要的代码，节省 token 和时间。同时要求 Claude 在需求模糊时主动提问，而非自行假设。
- **代码示例**:
```markdown
<!-- 添加到 CLAUDE.md -->
## 工作流程规则
1. 在写任何代码之前，先描述你的实现方案并等待我的批准
2. 如果需求不明确，先提出澄清问题，不要自行假设
3. 如果一个任务需要修改多个文件，先列出所有要修改的文件和理由
4. 重构时先展示 before/after 的关键代码对比
```

## 5. 五个最实用的内置斜杠命令
- **来源**: [Vaibhav Sisinty](https://x.com/VaibhavSisinty/status/2067234559721361699) on X | 🔥 高互动推文
- **摘要**: 大多数人从来不打斜杠命令，但这五个命令能真正改变工作方式：`/compact` 在上下文膨胀时压缩摘要；`/loop` 让 Claude 按固定间隔重复执行某个提示词（如每 5 分钟检查部署状态）；`/schedule` 创建云端定时任务，笔记本关机也能跑；`/deep-research` 执行多源交叉验证的深度研究；`/init` 根据项目结构自动生成 CLAUDE.md 起始文件。
- **代码示例**:
```bash
# 1. /compact - 上下文快满时压缩
/compact

# 2. /loop - 重复执行任务（默认 10 分钟间隔）
/loop 5m "检查 CI 状态并报告失败的测试"

# 3. /schedule - 创建云端定时任务
/schedule "每天早上 9 点检查依赖更新"

# 4. /deep-research - 深度研究
/deep-research "比较 Drizzle ORM 和 Prisma 在大规模项目中的性能"

# 5. /init - 初始化项目文档
/init
```

## 6. Loop Engineering：设计自主 Agent 工作流而非手写提示词
- **来源**: [TechTimes](https://www.techtimes.com/articles/318828/20260622/claude-code-loop-engineering-stop-prompting-start-designing-autonomous-agent-workflows.htm) | 🔥 技术社区热议
- **摘要**: 社区提出的"Loop Engineering"概念：停止逐条编写提示词，转而设计可自主运行的 Agent 循环。核心思路是给 Claude 设定明确的退出条件（如"直到所有测试通过"或"直到连续两轮没有新发现"），让它在循环中自主执行、自我纠错。配合 `plan.md` 文件作为持久化上下文，Claude 可以像一个自主工程师一样工作。
- **代码示例**:
```bash
# 在 Claude Code 中使用自主循环模式
# 配合 plan.md 记录任务状态

claude --loop "
1. 读取 plan.md 了解当前任务
2. 执行下一个未完成的任务
3. 运行测试验证
4. 更新 plan.md 标记完成
5. 如果还有未完成任务，继续
6. 所有任务完成后退出
"
```
```markdown
<!-- plan.md 示例 -->
# 重构计划

- [x] 将 UserService 拆分为 AuthService 和 ProfileService
- [x] 更新所有 import 路径
- [ ] 迁移单元测试
- [ ] 更新 API 路由
- [ ] 运行完整测试套件
```
