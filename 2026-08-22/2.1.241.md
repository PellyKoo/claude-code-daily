# Claude Code 2.1.241 社区实用技巧 - 2026-08-22

## 1. 上下文窗口的"智商衰退区"——保持 30% 以下最佳
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 64.9k stars
- **摘要**: 在 1M 上下文模型中，当 token 使用量达到 300-400k 时，模型智能会明显下降（称为"Context Rot"）。实测发现约 40% 上下文使用率时性能开始衰减，建议将敏感工作控制在 30% 以下，60% 为绝对上限。关键操作：用 `/compact` 压缩上下文，用 `/clear` 重新开始。
- **代码示例**:
```
# 每次 Claude 回复后，根据上下文状态选择操作：
# - 继续：上下文仍清晰
# - /rewind：撤销失败的尝试（比纠正更好，避免污染上下文）
# - /compact：压缩上下文
# - /clear：完全重新开始
# - Subagent：将任务卸载到子上下文
```

## 2. 用 Subagent 做"上下文卫生"——只带结论回来
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 64.9k stars
- **摘要**: 将文件读取、grep 搜索、探索性死胡同等任务交给 Subagent 处理，只让最终结论返回到父上下文。这样可以避免大量中间过程信息污染主会话的上下文窗口，保持主对话的清晰度和模型性能。
- **代码示例**:
```
# 在 Claude Code 中，直接描述任务并指定使用 subagent：
> 用一个 subagent 去搜索所有使用了 deprecated API 的文件，
> 只返回文件名和行号列表
```

## 3. HANDOFF.md 文档——跨会话的记忆传递
- **来源**: [ykdojo](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 9.9k stars
- **摘要**: 在长时间实验或复杂任务中，会话结束前让 Claude 生成一个 HANDOFF.md 文件，记录"做了什么、什么有效、什么无效、下一步计划"。新会话启动时指向该文件，新 agent 可以无缝接续，不需要从头了解上下文。
- **代码示例**:
```bash
# 在会话结束前：
> 把当前进展写入 experiments/auth-refactor/HANDOFF.md

# 新会话开始时：
> 阅读 experiments/auth-refactor/HANDOFF.md 然后继续下一步
```

## 4. 竖切（Vertical Slices）替代水平分层——更快获得端到端反馈
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 64.9k stars
- **摘要**: AI 默认会按水平层（先做所有数据库，再做所有服务，再做所有 UI）来拆分任务，但这会延迟端到端的反馈。正确做法是用"竖切"方式：每个任务贯穿 DB → Service → UI 所有层，形成一个可验证的完整功能切片。这样每完成一个切片就能立即测试和验证。
- **代码示例**:
```
# ❌ 水平拆分（AI 默认方式）
Phase 1: 所有数据库表
Phase 2: 所有 API 端点
Phase 3: 所有前端页面

# ✅ 竖切拆分（推荐方式）
Slice 1: 用户注册 (DB表 + API + 注册页面)
Slice 2: 用户登录 (DB查询 + API + 登录页面)
Slice 3: 用户资料 (DB更新 + API + 资料页面)
```

## 5. 半克隆对话（Half-Clone）——保留最新上下文
- **来源**: [ykdojo](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 9.9k stars
- **摘要**: 当上下文窗口快满时，与其完全丢弃或手动总结，不如使用 half-clone 技术：只保留对话的后半部分，自动标记 `[HALF-CLONE timestamp]` 以保持连续性。这比 `/compact` 更精确地保留了最近的工作上下文。
- **代码示例**:
```bash
# 使用 ykdojo 的 dx 插件中的 half-clone 命令
> /dx:half-clone

# 或使用独立脚本
bash half-clone-conversation.sh
# 输出：[HALF-CLONE 2026-08-22T15:30:00Z] 已保留最近 50% 对话
```

## 6. Skills 目录的渐进式披露——用子目录替代巨型文件
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 64.9k stars
- **摘要**: 将 Skill 从单个 .md 文件改为文件夹结构，使用 `references/`、`scripts/`、`examples/` 子目录做渐进式加载。Skill 的描述（description）应该像触发器一样写——面向模型回答"什么时候应该触发我？"，而不是写人类阅读的摘要。
- **代码示例**:
```
.claude/skills/
  deploy/
    SKILL.md              # 主入口，简短描述 + 触发条件
    references/
      aws-config.md       # 按需加载的参考文档
    scripts/
      health-check.sh     # 辅助脚本
    examples/
      rollback.md         # 示例场景
```

## 7. 自定义状态栏——实时掌控会话状态
- **来源**: [ykdojo](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 9.9k stars
- **摘要**: 自定义 Claude Code 底部状态栏，显示当前模型、工作目录、Git 分支、未提交文件数、token 使用量和进度条。提供 10 种配色主题，通过 bash 脚本实现，帮助开发者实时了解会话状态，尤其是 token 消耗情况，与"上下文智商衰退区"技巧配合使用效果更佳。
- **代码示例**:
```json
// .claude/settings.json
{
  "statusLine": {
    "script": ".claude/scripts/status-line.sh",
    "refreshInterval": 5000
  }
}
```

## 8. /gha 自动排查 CI 失败——DevOps 自动化利器
- **来源**: [ykdojo](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 9.9k stars
- **摘要**: 当 GitHub Actions CI 失败时，直接使用 `/gha` 命令让 Claude 自动调查失败原因。它会检查是否是 flaky test、定位引起失败的 commit、并建议修复方案。这个命令也可通过 dx 插件获取（`/dx:gha`），是日常 DevOps 工作流中最节省时间的功能之一。
- **代码示例**:
```bash
# CI 失败时，在 Claude Code 中直接运行：
> /gha

# 或使用 dx 插件版本：
> /dx:gha

# Claude 会自动：
# 1. 拉取失败的 workflow 日志
# 2. 检查是否为间歇性失败(flaky)
# 3. 定位引起失败的代码变更
# 4. 提出修复建议
```
