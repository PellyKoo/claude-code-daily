# Claude Code v2.1.165 社区实用技巧 - 2026-06-04

## 1. 上下文管理：保持在40%以下
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 56.5k stars
- **摘要**: 保持上下文使用率在40%以下以维持高质量输出，经验丰富的用户目标是30%以下。当使用率达到40-60%时，模型会进入"变笨区"，此时应手动执行 `/compact` 并附带提示词，而非依赖自动压缩。
- **代码示例**:
```
/compact 请保留当前任务的关键上下文：正在修复的bug、已尝试的方案、待验证的测试用例
```

## 2. 主动创建交接文档代替自动压缩
- **来源**: [ykdojo](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 8.6k stars
- **摘要**: 在开始新对话前，主动让 Claude 创建交接文档（HANDOFF.md），记录已完成的工作、尝试过的方案、成功和失败的经验。新会话直接引用该文档即可恢复上下文，比自动压缩更精准。
- **代码示例**:
```
> Put the rest of the plan in HANDOFF.md. Explain what you
> have tried, what worked, what didn't work...

# 新会话中引用：
> Read experiments/handoff/HANDOFF.md and continue from where we left off
```

## 3. 垂直切片而非水平分层
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 56.5k stars
- **摘要**: 将需求按"穿透所有层"的方式组织（数据库→服务→UI），而非按水平阶段依次完成。这样可以更早获得端到端反馈，避免到最后阶段才发现集成问题。
- **代码示例**:
```markdown
# 好的做法 - 垂直切片
## Feature: 用户注册
- [ ] DB: 创建 users 表
- [ ] API: POST /register 端点
- [ ] UI: 注册表单组件
- [ ] Test: 端到端测试

# 避免 - 水平分层
## Phase 1: 所有数据库表
## Phase 2: 所有API端点
## Phase 3: 所有UI页面
```

## 4. 精简系统提示词：从19k减到9k tokens
- **来源**: [ykdojo](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 8.6k stars
- **摘要**: 通过补丁脚本精简冗余的工具定义，将系统提示词从约19k tokens减少到约9k tokens。更少的系统提示词意味着每次请求消耗更少的token，长会话中节省显著。
- **代码示例**:
```bash
# 使用 ykdojo 提供的补丁脚本
cd claude-code-tips/system-prompt
# 查看并应用精简补丁
cat slim-prompt.patch
```

## 5. 子代理驱动的上下文控制
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 56.5k stars
- **摘要**: 将研究密集型任务（文件读取、搜索、试错）委托给子代理，只将结论返回主上下文。这样可以保护主会话的"智能容量"用于核心决策，避免被大量中间结果污染。
- **代码示例**:
```
# 在 CLAUDE.md 中配置子代理策略
当需要搜索超过3个文件时，使用 subagent 进行探索，
只将关键发现汇报到主会话。
```

## 6. 测试驱动开发工作流
- **来源**: [ykdojo](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 8.6k stars
- **摘要**: 先写测试并确保测试失败，提交后再让 Claude Code 实现功能。这种方式给 Claude 提供了明确的成功标准，避免模型"自以为完成"但实际不符合需求的情况。
- **代码示例**:
```bash
# 步骤1：写测试并确认失败
> Write a failing test for the user authentication feature
> Run the test to confirm it fails

# 步骤2：提交失败的测试
git add -A && git commit -m "Add failing auth tests"

# 步骤3：让 Claude 实现功能
> Make all tests pass
```

## 7. 始终从 Plan Mode 开始
- **来源**: [shanraisshan](https://github.com/shanraisshan/claude-code-best-practice) on GitHub | ⭐ 56.5k stars
- **摘要**: 让一个 Claude 会话先制定计划，再用第二个会话"以高级工程师身份"审查计划，最后才进入执行阶段。直接跳入编码是最常见的错误。
- **代码示例**:
```
# 会话1 - 制定计划
> /plan 重构认证模块，需要支持 OAuth2 和 SAML

# 会话2 - 审查计划
> Review this plan as a staff engineer. Challenge assumptions
> and identify risks: @plan.md
```

## 8. DX 插件：一键安装多种实用工具
- **来源**: [ykdojo](https://github.com/ykdojo/claude-code-tips) on GitHub | ⭐ 8.6k stars
- **摘要**: 安装 DX 插件可一次性获得多个实用命令，包括 GitHub Actions 调试（`/dx:gha`）、仓库克隆（`/dx:clone`）、交接文档生成（`/dx:handoff`）等，大幅提升日常开发效率。
- **代码示例**:
```bash
# 安装 DX 插件
claude plugin marketplace add ykdojo/claude-code-tips
claude plugin install dx@ykdojo

# 使用示例
/dx:gha <CI失败的URL>    # 自动分析CI失败原因
/dx:handoff               # 生成交接文档
/dx:half-clone            # 轻量级克隆仓库
```
